## 1. 引言

### 1.1 编写目的

本文档对软件测试平台进行概要设计，阐明系统整体架构（含 AI 智能辅助能力域的总体架构）、模块划分、核心数据模型、关键机制及部署视图，为后续详细设计与开发提供依据。

### 1.2 范围

平台包含**系统管理模块**与**业务功能模块**两大部分，面向系统管理员和业务用户两类角色。本文档覆盖全平台架构设计，重点描述模块关系、数据流转及核心机制。其中，AI 智能辅助能力域覆盖：

1. AI 基础设施（AI 网关、模型接入、审计、限流）；
2. 智能测试用例生成（用例子树生成、步骤补全、优先级推荐、轻量需求池）；
3. AI 辅助评审与覆盖度分析；
4. 缺陷智能分析与去重（含向量检索基建）；
5. 全局智能助手（ChatBot 与工具调用）；
6. 测试计划与风险评估（执行顺序推荐、用例规划智能推荐）。

## 2. 系统总体设计

### 2.1 架构风格

系统采用 **B/S 架构**，**前后端分离**。整体分为三层：

    ┌─────────────────────────────┐
    │        前端（SPA）           │
    │  ┌────────┐  ┌────────────┐ │
    │  │管理端  │  │  业务端    │ │
    │  └────────┘  └────────────┘ │
    └─────────────┬───────────────┘
                  │ HTTP / WS
    ┌─────────────┴───────────────┐
    │       网关层（Gateway）      │
    │  认证、上下文注入、路由转发  │
    └─────────────┬───────────────┘
                  │
    ┌─────────────┴───────────────┐
    │          服务层              │
    │  ┌─────────┐ ┌───────────┐ │
    │  │管理服务 │ │ 业务服务  │ │
    │  └─────────┘ └───────────┘ │
    │  ┌───────────────────────┐ │
    │  │   WebSocket 服务      │ │
    │  └───────────────────────┘ │
    └─────────────┬───────────────┘
                  │
    ┌─────────────┴───────────────┐
    │          数据层              │
    │  ┌──────┐ ┌──────┐ ┌──────┐│
    │  │关系库│ │缓存  │ │文件  ││
    │  └──────┘ └──────┘ └──────┘│
    └─────────────────────────────┘

AI 能力以**服务层新增子域 + 数据层扩展**的方式集成到上述三层架构（前端 SPA → 服务层 → 数据层），不引入独立部署单元：

    ┌───────────────────────────────────────────┐
    │              前端（SPA）                    │
    │  既有页面 + AI 交互组件：                    │
    │  ┌──────────┐ ┌──────────┐ ┌────────────┐ │
    │  │脑图 AI   │ │表单/面板  │ │全局助手     │ │
    │  │工具栏/预览│ │AI 建议   │ │悬浮窗       │ │
    │  └──────────┘ └──────────┘ └────────────┘ │
    └──────────────┬────────────────────────────┘
                   │ HTTP / SSE / WS（复用既有通道）
    ┌──────────────┴────────────────────────────┐
    │                服务层                       │
    │  既有业务服务（Controller/Service 不变）      │
    │  ┌──────────────────────────────────────┐ │
    │  │        AI 子域（新增）                 │ │
    │  │  AI 网关（Provider 适配/Prompt 组装/   │ │
    │  │  流式输出/结构化校验/限流/审计）         │ │
    │  │  ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │
    │  │  │生成服务  │ │分析服务  │ │助手服务  │ │ │
    │  │  └─────────┘ └─────────┘ └─────────┘ │ │
    │  │  ┌─────────────────────────────────┐ │ │
    │  │  │ 工具注册表 → 调用既有 Service 层  │ │ │
    │  │  └─────────────────────────────────┘ │ │
    │  └──────────────┬───────────────────────┘ │
    └─────────────────┼─────────────────────────┘
                      │ HTTPS
              ┌───────┴────────┐        ┌──────────────────┐
              │ 外部 LLM 服务   │        │ 数据层            │
              │（对话/Embedding）│        │ PostgreSQL        │
              └────────────────┘        │  + pgvector 扩展  │
                                        │ Redis（限流）      │
                                        └──────────────────┘

### 2.2 前后端职责

* **前端**：
  * 管理端：独立路由树，仅拥有系统角色的用户可见。
  * 业务端：根据活跃工作空间动态加载数据，包含工作空间管理、项目管理、脑图编辑器、测试评审、测试计划、缺陷管理界面。
  * 脑图编辑器支持 WebSocket 实时协作。
* **后端**：
  * 提供 RESTful API，分为管理接口（`/api/admin`）和业务接口（`/api/workspace` 和 `/api/project`）。
  * WebSocket 服务负责脑图文档的实时协作消息广播与持久化。
  * 中间件统一处理 JWT 认证、活跃工作空间/项目上下文注入与校验。

### 2.3 系统初始化流程

系统首次部署后需经过初始化才能使用。初始化在认证流程之前，无需登录即可访问。

```
用户首次访问 → 登录页
  ↓
检查初始化状态 GET /api/auth/init/status
  ↓
未初始化 → /init 初始化页面 → 设置管理员密码 → POST /api/auth/init/setup
  ↓
已初始化 → 正常登录流程
```

初始化会创建 admin 账号并分配系统管理员角色（预置 UUID `b0000000-...-001`），用户使用 admin 和设置的密码登录。

### 2.4 关键架构决策

| 决策 | 内容 | 理由 |
| ---- | ---- | ---- |
| AD-1 | AI 能力内嵌于既有单体服务，不拆分独立 AI 微服务 | 与仓库单体架构一致，避免运维复杂度；LLM 调用为 IO 密集，异步化即可 |
| AD-2 | 前端不直连 LLM，一切经后端 AI 网关 | 密钥不出后端；统一审计、限流与上下文校验 |
| AD-3 | AI 生成的脑图节点由**前端**通过既有编辑内核挂载，不新增后端批量写接口 | 复用脑图 diff 持久化 + Yjs 协同链路，落库、广播、撤销重做零改造 |
| AD-4 | 向量检索采用 PostgreSQL pgvector 扩展，不引入独立向量库/搜索引擎 | 不新增中间件；缺陷量级（项目内千级）pgvector 完全够用 |
| AD-5 | 向量化范围覆盖缺陷库与用例库，需求池不建向量索引 | 缺陷查重/聚类与用例语义匹配（遗漏分析、用例规划推荐语义升级）均需向量；需求池是输入上下文而非检索语料（见 SRS 3.2.4） |
| AD-6 | AI 写操作一律"预览-确认-执行"，AI 不拥有独立身份与权限 | 所有工具调用以当前 LoginUser 走 Service 层，权限与审计天然复用 |
| AD-7 | 流式输出采用 SSE，不复用文档协作 WebSocket | 生成类交互是请求-响应模型，SSE 更契合；避免与协同通道耦合 |

### 2.5 AI 能力降级

* AI 配置缺失、关闭或健康检查失败时，后端能力开关接口返回不可用，前端隐藏全部 AI 入口。
* LLM 调用失败/超时不影响任何既有业务流程；异步任务失败保留失败状态供重试。
* Embedding 写入失败不阻断缺陷增改，由异步补偿任务重建索引（详见 4.11）。
* Embedding 模型或向量维度变更后触发向量索引全量重建；重建完成前，语义检索类能力（查重、聚类、语义匹配）自动降级为关键词匹配并向用户明示。能力开关接口支持此类**部分降级**状态（AI 整体可用、语义检索降级）。Embedding 未配置（如所选对话模型厂商不提供 Embedding 接口且未另配）时，语义检索类能力同样处于此降级状态。

### 2.6 技术选型概要

整体技术选型：

| 组件    | 选型方向                                     |
| ----- | ---------------------------------------- |
| 前端框架  | 现代 SPA 框架（React / Vue / Angular）         |
| 脑图编辑器 | 自研或基于开源库扩展，需支持自定义数据模型                    |
| 后端框架  | 主流 Web 框架（Spring Boot / Express / Gin 等） |
| 数据库   | 关系型数据库（MySQL / PostgreSQL）               |
| 缓存    | Redis                                    |
| 实时通信  | WebSocket（Socket.IO 或原生实现）               |

AI 能力技术选型：

| 组件 | 选型方向 | 说明 |
| ---- | ---- | ---- |
| LLM 接入 | 兼容 OpenAI 协议的 HTTP 客户端封装 | 具体依赖选型在详细设计阶段经团队讨论确定，接口层先行抽象为 Provider 适配器；适配器仅使用协议标准参数集，厂商非标参数（如思考开关）经配置项透传，响应中的非标字段宽容忽略 |
| 流式输出 | SSE（服务端单向流式推送） | 生成类接口统一支持 |
| 向量检索 | pgvector（余弦相似度） | 数据库扩展，随版本化数据库迁移脚本启用；向量维度为配置项，保存时校验取值范围 |
| Embedding | OpenAI 兼容 Embedding 接口，与对话模型分组独立配置 | 服务地址、密钥、模型名、向量维度均独立于对话模型，支持与对话模型使用不同厂商（部分厂商不提供 Embedding 接口） |
| 异步任务 | 既有异步执行能力 + 任务状态表 | 不引入消息队列 |
| 限流 | 用户维度限流计数（复用既有 Redis） | 复用既有基础设施 |
| 前端图表 | 缺陷聚类分布图所需图表方案在详细设计阶段确定 | 受依赖管控约束，优先评估轻量方案 |

### 3.2 模块职责简述

* **用户管理**：账号生命周期维护，分配系统角色。
* **全局工作空间管理**：工作空间的创建、解散，全平台成员分配。
* **系统角色与权限管理**：定义系统级角色及其管理端权限，系统管理员可配置。
* **我的工作空间**：查看用户归属的工作空间列表，切换活跃空间，编辑基本信息。
* **工作空间成员管理**：管理当前工作空间内成员，可邀请/移除，并可设置空间管理员。
* **项目管理**：当前工作空间下项目的 CRUD 与归档。
* **测试用例管理**：模块树管理 + 脑图实时协作编辑 + 用例列表。
* **测试评审管理**：发起用例评审，基于快照进行节点标记/评论，支持记录、同步与调整规划用例。
* **测试计划管理**：创建计划，基于快照跟踪执行，支持多次执行记录、同步与调整规划用例。
* **缺陷管理**：缺陷全生命周期管理，关联用例与计划。
* **AI 配置**：系统管理员维护**多个对话模型配置**（每个模型独立的显示名、供应商选择、地址、密钥、模型名与附加参数，可分别启用/停用与连通性测试）并指定唯一的**系统默认对话模型**；Embedding 保持单一配置（供应商、地址、密钥、模型名、向量维度），与对话模型组相互独立；供应商预设内置于代码（含默认地址与厂商独有配置项模板），选择供应商后按预设引导填写，独有配置项作为附加参数透传，另提供通用 OpenAI 兼容模式；系统配置项（限流阈值、相似度阈值、保留期等）以**表单形式完整展示并逐项维护**（不提供裸配置编辑）；提供连通性测试（真实调用验证连通性，Embedding 组同时校验返回向量维度与配置一致）与调用量统计视图（支持按模型维度聚合）。
* **智能体**：每个 AI 功能对应一个智能体，即一个提示词模板位（功能类型枚举唯一键）。默认模板随代码内置；管理员自定义后落库覆盖，可一键恢复默认（删除自定义记录即回退内置）。模板按「角色指令段 / 输出格式约束段」两段存储，格式约束段编辑受高级开关控制（默认关闭锁定）；变更操作入审计日志。
* **AI 网关**：所有 LLM/Embedding 调用的唯一出口。职责：Provider 适配、Prompt 模板组装（加载顺序：自定义模板 → 内置默认；系统指令与用户数据隔离）、上下文裁剪与分批、流式转发、输出 JSON Schema 校验、失败重试。
* **调用审计与限流**：每次调用记录审计日志（用户/空间/项目/功能/耗时/token/状态）；Redis 用户级限流。
* **异步分析任务管理**：评审检查、缺陷聚类等长任务的创建、状态跟踪（pending/running/success/failed/cancelled）、结果存取与重试；评审离开「评审中」状态或用户主动取消时，进行中的检查任务联动终止并置为 cancelled，已产出结果仍可查看。
* **智能用例生成**：接收需求描述（或需求池条目引用），产出结构化用例树 JSON（含类型与优先级标记），由前端预览确认后挂载。优先级推荐采用**规则前置 + LLM 兜底**的混合策略：关键词规则命中时即时给出推荐（不发起 LLM 调用）；未命中时发起 LLM 调用，结果以非侵入提示回填，全程不阻塞用户手工标记。
* **轻量需求池**：项目级需求条目 CRUD、归档/取消归档（状态仅 active/archived 两态）、标题关键字检索、文档-条目关联维护（关联仅限 active 条目）。
* **脑图智能编辑**：自然语言 → 脑图操作指令集（DSL）翻译服务。执行均在前端。
* **AI 评审辅助**：快照树完整性检查（异步分批）；评审完成后统计聚合（SQL）+ 文字总结（LLM）。检查与摘要均仅评审发起人可发起。摘要生成完成后以结果快照持久化（复用分析任务结果存储），重复生成覆盖上一份。
* **覆盖度分析**：关键词/需求条目 vs 用例库比对，输出遗漏测试点；需求输入 → 用例库检索 → 用例规划推荐清单（供评审/计划「调整用例」流程带入）。
* **缺陷 AI 增强**：表单建议（同步单次调用）；语义查重（Embedding + pgvector Top-K，排除 closed）；聚类分析（异步任务）。
* **执行顺序推荐**：确定性加权评分（历史缺陷关联数、优先级、模块缺陷密度），LLM 仅生成理由文本；仅计划负责人/执行人可发起与查看。
* **全局智能助手**：多轮会话管理；Function Calling 循环（LLM 决策 → 工具执行 → 结果回填）；工具注册表统一声明工具的 schema、读写属性与所需权限。

### 3.3 前端组件规划

| 组件域 | 内容 |
| ---- | ---- |
| 脑图 AI 交互 | 工具栏「AI 生成用例」入口、右键菜单「AI 补全步骤」、生成结果预览树（勾选取舍）、挂载执行器（经既有编辑内核挂载，一次操作入撤销栈）、AI 标识徽标渲染（复用既有徽标体系） |
| 需求池 | 项目工作区需求池管理页 + 文档关联选择器 + AI 入口内的条目选取器 |

## 4. 核心机制设计

### 4.1 角色与权限模型

#### 4.1.1 角色分类

* **系统角色**：由系统管理员在管理端创建和管理，用于控制管理端（`/api/admin`）功能权限。系统预置"系统管理员"角色，拥有全部管理权限且不可删除。系统角色仅分配管理端权限。存储于 `sys_role` 表，`type='system'`。
* **工作空间角色**：存储于 `sys_role` 表，`type='workspace'`。预置 `workspace_admin`（空间管理员）和 `workspace_member`（普通成员）两条记录，不可删除、不可由管理员创建。工作空间角色通过 `workspace_user.workspace_role`（UUID）关联到用户-工作空间对，由 `WorkspaceRoleInterceptor` 在请求进入时加载到 `LoginUser.authorities` 中。
* 业务用户的最终权限 = 系统角色权限 ∪ 工作空间角色权限。

#### 4.1.2 多角色支持

* 一个用户可以同时拥有多个系统角色，且在不同工作空间中各自拥有一个工作空间角色。
* 用户的最终权限是所有角色权限的并集（系统角色权限 ∪ 当前工作空间角色权限）。
* 系统管理员在用户管理中只能分配和调整**系统角色**；工作空间角色由工作空间管理员在成员管理中设置（提升/降级）。

#### 4.1.3 工作空间内角色

* 工作空间角色统一存储于 `sys_role` 表，`type='workspace'`，预置 `workspace_admin`（空间管理员）和 `workspace_member`（普通成员）两条记录，不可删除、不可由管理员创建。
* 用户-工作空间关联表 `workspace_user.workspace_role` 存储角色 ID（UUID），引用 `sys_role.id`，默认值为预置的 `workspace_member` 角色 ID。
* 系统管理员在全局工作空间管理界面添加成员时，可勾选设为空间管理员；后续空间管理员也可在"工作空间成员管理"中提升或降级成员。
* 空间管理员拥有该工作空间内更高的业务权限（具体权限在业务模块详细设计中定义）。
* 工作空间角色的权限通过 `sys_role.permissions`（JSONB 数组）存储，格式与系统角色一致。

#### 4.1.4 权限作用域与全量权限

* 每个角色（`sys_role`）具有 `scope` 字段（`global` / `workspace`），限定其权限码的作用域范围。
* 角色可设置 `full_access`（布尔值），表示拥有对应作用域下的所有权限码，运行时由拦截器自动注入，无需手动配置。
* 每个权限点（`sys_permission`）具有 `scope` 字段（`global` / `workspace`），标识该权限属于系统级还是空间级。
* 权限码格式为 `模块:操作`（如 `user:view`、`case:create`），模块前缀区分作用域。

### 4.2 认证与上下文

* 初始化：系统首次部署后，访问任何页面时先检查初始化状态（`GET /api/auth/init/status`），未初始化则引导至 `/init` 设置管理员密码（`POST /api/auth/init/setup`），完成后跳转至登录页。
* 登录后颁发 JWT（短期访问令牌 + 长期刷新令牌）。
* 登录响应包含用户信息及是否拥有工作空间（`hasWorkspace`），前端据此决定登录后跳转目标：有工作空间→工作空间列表，无工作空间+系统权限→系统管理仪表盘，无工作空间+无系统权限→工作空间列表。
* 网关中间件验证 Token，提取用户 ID、所有角色及合并后的权限列表。
* 管理端请求：仅需验证用户拥有至少一个系统角色，通过后即可访问。
* 业务端请求：必须携带 `X-Active-Workspace`，中间件校验用户是否属于该工作空间；项目内操作另需 `X-Active-Project`。`WorkspaceRoleInterceptor` 读取工作空间角色并注入权限码到 `LoginUser.authorities`，供后续授权判断使用。
* 角色或权限变更后，工作空间权限通过拦截器实时注入，无需重新登录。
* 前端通过 `POST /api/auth/permissions` 获取当前用户的合并权限码列表，用于菜单和按钮的显隐控制。

### 4.3 数据隔离

* 管理端接口不注入工作空间上下文，全局查询。
* 业务接口在数据库查询层自动附加 `workspace_id` 或 `project_id` 过滤条件，防止越权访问。

### 4.4 脑图实时协作

* 用户进入文档后建立 WebSocket 连接，加入文档房间。
* 编辑操作以增量消息发送服务端，校验权限与工作空间归属后持久化并广播。
* 冲突处理采用乐观锁或 CRDT 算法保证最终一致性。

### 4.5 快照机制

* **生成**：评审或计划发起/关联用例时，复制当前项目完整模块树 + 涉及文档的全部脑图节点。
* **存储**：存入专用快照表，与原始数据解耦。
* **裁剪展示**：前端请求时，服务端根据关联节点向上找祖先、向下找子孙，仅返回关联节点树；多文档时按文档快照树逐文档切换展示。
* **同步**：手动触发，用原始节点 ID 匹配更新快照；已删除节点标记为失效。
* **调整**：评审/计划未结束时可重新选择关联用例，按差量更新快照——新增文档生成快照、移除文档删除快照（已产生的标记/执行记录保留）、保留文档补入新增节点并重刷关联状态。

### 4.6 评审与执行记录

* **评审记录**：每次标记/评论生成一条记录，并同步更新快照节点的最后标记字段（标记支持通过/不通过/待评审三态，全部关联用例通过后方可完成评审）。
* **执行记录**：每次执行生成一条记录，并同步更新快照节点的最后执行结果字段（结果支持通过/失败/阻塞/待执行）。
* **历史追溯**：通过记录表按时间排序获取完整历史。

### 4.7 AI 调用链路

按交互形态分三类，全部经 AI 网关：

* **同步调用**（表单建议、优先级推荐的 LLM 兜底、DSL 翻译）：REST 请求 → 网关组装 Prompt → LLM → JSON Schema 校验 → 返回。超时阈值短（10s 级），失败即返回错误。优先级推荐的关键词规则命中时直接返回，不经本链路（见 3.2）。
* **流式调用**（用例生成、评审摘要、助手对话）：REST 请求建立 SSE → 网关流式转发增量内容 → 结束帧携带完整结构化结果（生成类）→ 前端预览。客户端断开即取消上游调用。
* **异步任务**（评审检查、缺陷聚类、存量向量回填）：创建任务记录 → 异步执行（内部可多轮分批调用 LLM）→ 更新任务状态与结果 → 前端轮询任务状态接口。同一目标对象同时只允许一个进行中任务。

所有链路统一行为：调用前限流检查 → 调用后写审计日志（含实际调用的模型）；Prompt 中系统指令与用户数据/业务数据分离（防注入）；结构化输出以提示词格式约束 + 结构化输出参数（厂商支持时）+ 网关侧 JSON Schema 校验兜底，校验失败带错误信息自动重试一次；输出最终未通过结构化校验时按失败处理，不降级为裸文本入库。

模型选取规则：交互式功能（同步/流式链路中用户直接发起的调用）请求可携带对话模型标识，网关校验其存在且已启用后使用，否则回退系统默认模型；异步任务与建议类功能固定使用系统默认模型。用户的模型选择在浏览器本地记忆，不在服务端持久化。

性能约束（承接 SRS 4.1，作为详细设计输入）：流式调用首内容返回以 3 秒为目标值，超 10 秒提示用户可取消或重试；语义查重检索（不含向量化耗时）500 毫秒内返回；表单内嵌 AI 能力不得阻塞用户输入与提交。

### 4.8 AI 生成节点挂载机制（关键机制）

AI 生成的用例子树进入脑图**不走后端直写**，完整链路为：

```
后端生成结构化用例树（含类型/优先级标记）
  ↓ 流式返回
前端预览面板（树形展示，可勾选取舍）
  ↓ 用户确认
前端经既有编辑内核挂载节点（写入类型/优先级/AI 标识）
  ↓ 触发既有内容变更事件
协同实时广播（协同用户即时可见）
  + 走既有 diff 持久化通道落库
  + 整批操作作为单条撤销历史
```

设计要点：

* 生成的节点携带 AI 来源标记字段，脑图以徽标渲染（复用既有节点徽标渲染体系）；除该字段外数据模型与手工节点完全一致；
* AI 标识随节点数据进入评审/计划快照；用户可经节点标记操作手动移除（移除后不可重新添加，该标识仅由 AI 生成动作赋予），不影响任何业务规则；
* 挂载前校验目标节点仍存在（可能被协同用户删除），不存在则提示重选；
* 「AI 补全步骤」「对话式编辑」复用同一挂载执行器（新增节点同样写入 AI 标识）。

### 4.9 脑图操作指令集（DSL）

对话式脑图编辑使用一套受限 DSL：

* **结构**：`{ selector, action }` 数组。selector 支持按类型/优先级/文本关键字/子树范围筛选；action 限定为标记类型、标记优先级、高亮、移动（文档内）、新增子节点。
* **分工**：LLM 仅做自然语言 → DSL 翻译（同步调用，带 Schema 校验）；命中节点计算与执行由前端确定性代码完成。
* **安全**：执行前展示命中预览（数量与清单）；翻译置信不足（LLM 声明歧义或校验失败）时要求用户改写；本版本不支持跨文档操作。

### 4.10 全局助手与工具调用

* **会话模型**：会话（conversation）→ 消息（message）两级，归属用户、按工作空间隔离；上下文窗口取最近 N 轮。
* **工具注册表**：每个工具声明名称、参数 Schema、读/写属性、所需权限码。注册表声明工具全集；写工具的**启用白名单为系统配置项**（首期默认仅开放创建缺陷、创建计划草稿两项低风险操作）。工具实现直接调用既有 Service 层方法，以当前 LoginUser 身份执行——权限校验、数据隔离、业务规则、审计全部复用。
* **执行循环**：用户消息 → LLM（附工具清单）→ 若返回工具调用：只读工具直接执行并回填结果继续循环；**写工具中断循环**，向前端返回操作预览卡片 → 用户确认后执行 → 结果回填 → LLM 生成最终答复。确认请求带一次性令牌与超时，超时/取消则放弃。
* **页面上下文桥**：脑图编辑页将当前文档 ID、选中节点注入助手请求上下文；对话式编辑指令翻译为 DSL 后交前端挂载执行器处理（同 4.8/4.9）。
* **使用指引**：平台操作手册以静态知识片段内置，指引类问题由 LLM 基于知识片段作答并附路由链接；知识外问题明确拒答。

### 4.11 向量检索机制（缺陷语义查重与聚类）

* **索引对象**：缺陷标题 + 描述拼接文本的 Embedding，存于独立向量表（与缺陷记录一对一，无物理外键）。
* **写入时机**：缺陷创建/标题/描述变更时，事务提交后异步生成 Embedding 写入；失败进入补偿队列（定时任务扫描缺失/过期索引重建），不阻断业务。
* **存量回填与重建**：向量基建上线或 Embedding 模型/维度变更时，通过一次性异步任务批量回填/重建；维度变更时随重建同步调整向量数据与索引（重建期间降级行为见 2.5）。
* **查重查询**：输入文本 → Embedding → pgvector 余弦相似度 Top-K → 过滤条件：当前项目 + 状态 ≠ closed + 相似度阈值 → 返回卡片数据。前端防抖（500ms 级）触发。
* **聚类分析**：取项目未关闭缺陷全量（千级以内），基于向量近邻 + LLM 归纳标签与根因，输出聚类结果快照存表，面板读取渲染；手动刷新重新计算。
* **范围约束**：向量化覆盖缺陷库与用例库；用例向量供遗漏测试点分析与用例规划推荐的语义匹配使用（对应 SRS 梯队三语义升级），其索引对象与写入时机在详细设计确定；需求池条目不建向量索引（AD-5）。

### 4.12 执行顺序推荐评分

* 推荐执行指数 = w1·历史关联缺陷数（按缺陷与用例关联聚合）+ w2·用例优先级权重 + w3·所属模块缺陷密度，权重配置化，计算为纯 SQL/内存运算，结果确定可复现。
* LLM 仅在用户展开明细时按需生成推荐理由文本，不参与排序。
* 结果与计划快照版本绑定，同步快照后失效需重算；脑图节点以徽标渲染序号（复用既有徽标渲染体系）。

### 4.13 限流、审计与配额

* 限流：Redis 滑动窗口，用户 × 功能类别两级阈值（阈值为系统配置项）；超限返回明确错误码，前端提示。
* 审计：AI 调用日志独立成表（用户、空间、项目、功能类型、模型、耗时、token 用量、状态），管理端提供聚合统计视图；日志写入异步化，不影响调用主链路。

| CaseEmbedding | 用例语义向量：与用例节点一对一；供遗漏测试点分析与用例规划推荐的语义匹配使用，随语义升级梯队启用（见 AD-5 / 4.11） |
| AiConversation | 助手会话（用户 + 工作空间归属）：标题、最后活跃时间 |
| AiMessage | 会话消息：角色（user/assistant/tool）、内容、工具调用载荷 |
| AiAnalysisTask | 异步任务：类型（评审检查/评审摘要/缺陷聚类/向量回填）、目标对象、状态（含 cancelled）、进度、结果快照、失败原因；评审摘要虽经 SSE 流式生成，其最终结果同样落入本表结果快照，供事后查看与覆盖式重新生成 |
| AiInvocationLog | 调用审计：用户/空间/项目归属、功能类型、模型、耗时、token 用量、状态 |

AI 能力域全部数据表遵循平台数据库规范：必含 `id`、`created_at`、`updated_at`、`is_deleted`（逻辑删除），主键类型与索引规范沿用平台既有约定，禁止物理外键；业务归属字段（项目 / 工作空间）用于数据隔离过滤。向量表按语义相似度检索需要建立向量索引，具体索引类型在详细设计确定。

### 5.3 数据隔离与生命周期

业务数据通过所属项目 → 工作空间间接隔离，查询时强制附加上下文条件。管理端无此限制。

AI 能力域数据的隔离与生命周期：

* 需求池、分析任务、向量索引按项目隔离；助手会话按用户 + 工作空间隔离；审计日志全局存储、按空间过滤查询。
* 需求池条目随项目删除而删除；BugEmbedding 随缺陷删除而删除；会话支持用户清空；分析任务结果可被同类型新任务覆盖。
* AI 调用审计与会话历史按系统配置的保留期限归档清理；语义查重/聚类检索排除已逻辑删除的缺陷。

## 6. 接口设计概要

### 6.1 接口风格与约定

* 协议：HTTPS，数据格式 JSON。
* 认证：请求头 `Authorization: Bearer <token>`。
* 接口分类：
  * 管理接口：`/api/admin`，需要系统角色。
  * 工作空间级业务接口：`/api/workspace`，需头 `X-Active-Workspace`。
  * 项目内业务接口：`/api/project`，需头 `X-Active-Project`。
* 上下文传递：工作空间和项目 ID 通过请求头传递，不在 URL 中暴露。
* 通用响应格式：`{ "code": 200, "message": "success", "data": {...} }`
* AI 能力遵循上述约定；经 AI 网关的能力按归属范围归入项目内业务接口与工作空间级接口（助手），管理端 AI 配置归入管理端接口；具体路径在详细设计阶段定义。
* 需求池为常规业务实体（不经 AI 网关），归入常规项目业务路径，AI 功能仅将其作为上下文消费，以免受 AI 整体降级开关影响；相应地，**需求池入口不随 AI 开关隐藏**，AI 不可用时条目管理照常可用（与 SRS 3.2.4 业务规则对齐）。
* 流式接口以 `text/event-stream` 响应。

### 6.2 认证与初始化接口

* **初始化状态**：`GET /api/auth/init/status`，返回 `{ initialized: boolean }`，无需认证。
* **初始化设置**：`POST /api/auth/init/setup`，提交管理员密码创建 admin 账号，无需认证。
* **登录**：`POST /api/auth/login`，返回双令牌及用户信息。
* **刷新令牌**：`POST /api/auth/refresh`，通过刷新令牌延长会话。
* **修改密码**：`POST /api/auth/change-password`，需认证。

### 6.3 管理端接口概要

* **用户管理**：CRUD，支持多系统角色分配。
* **工作空间管理**：创建、解散、成员管理（含设置空间管理员）。
* **系统角色管理**：CRUD，权限配置（仅系统角色）。
* **权限点树**：获取管理端权限树（按模块分组）。

### 6.4 业务端接口概要

* **我的工作空间**：查看归属列表、切换活跃空间、编辑信息。
* **工作空间成员管理**：邀请、移除、设置空间管理员。
* **项目管理**：CRUD、归档。
* **测试用例**：模块树、脑图节点、用例详情。
* **测试评审**：发起、快照树、模块快照树、评审记录、同步、调整用例。
* **测试计划**：创建、快照树、模块快照树、执行记录、同步、调整用例。
* **缺陷管理**：CRUD、状态流转。

详细端点定义参见《API 详细设计文档》。

### 6.5 AI 能力接口分组概要

* **能力开关**：查询 AI 可用性（前端据此显隐入口），随同下发可供用户切换的对话模型清单（仅标识与显示名，脱敏）。
* **管理端**：AI 配置（总开关 / Embedding / 系统配置项）、对话模型管理（增删改查 / 设默认 / 启停）、连通性测试、调用量统计、智能体提示词模板（查看含默认值/自定义覆盖/恢复默认/格式约束段编辑开关）。
* **生成类（SSE）**：用例子树生成、步骤补全、评审摘要生成。
* **同步建议类**：优先级推荐、缺陷标题优化与等级建议、DSL 翻译、执行顺序推荐（含理由生成）。
* **检索类**：缺陷语义查重、遗漏测试点分析、用例规划推荐。
* **异步任务类**：创建任务（评审检查/缺陷聚类）、查询任务状态与结果、重试。
* **需求池**：条目 CRUD、归档/取消归档、关键字检索、文档关联维护（常规业务接口，不经 AI 网关，见 6.1）。
* **助手（SSE）**：会话 CRUD、发送消息（流式回复 + 工具调用事件）、写操作确认/取消。

详细端点、请求/响应结构在详细设计阶段定义（先后端后前端，经 OpenAPI 同步）。

### 6.6 WebSocket 接口概要

* 端点：`/ws/documents/:docId`
* 认证：连接时通过查询参数传递 Token。
* 消息基于 JSON，支持节点增删改移、布局更新。
* 广播至同一文档的在线用户。
* 文档协作 WebSocket 保持既有设计：AI 生成节点经前端挂载后走既有编辑帧持久化（AD-3），协同广播复用既有二进制帧。

## 7. 部署视图

### 7.1 前后端分离部署（方案 A）

* 前端静态资源部署到 CDN/Nginx，后端服务集群可水平扩展。
* 适用于大规模独立迭代。

### 7.2 前后端合并打包部署（方案 B）

* 前端构建产物嵌入后端服务，统一部署。
* 适用于中小团队快速交付。

拓扑图同常规。

### 7.3 AI 能力环境依赖与运行约束

* 方案 A 与方案 B 均适用，AI 能力引入两项环境依赖：
  * **外部 LLM 服务**：出网 HTTPS 访问（或内网私有化模型端点），地址与密钥经管理端配置、加密落库；
  * **pgvector 扩展**：PostgreSQL 启用 `CREATE EXTENSION vector`，随数据库迁移脚本执行。
* 无新增部署单元、无消息队列；异步任务随应用进程运行，多实例部署时任务表带执行者标记防重复消费。
* 分离部署（前后端经反向代理）时，SSE 流式接口需反向代理支持流式透传（关闭响应缓冲、放宽读超时），具体配置在部署说明中给出。

## 8. 安全设计

* 全链路 HTTPS / WSS。
* 多角色权限并集计算；角色或权限变更后强制 Token 失效。
* 管理接口仅限拥有系统角色的用户访问。
* 业务接口强制校验工作空间归属及工作空间内角色。
* 防暴力破解、CSRF、XSS。
* WebSocket 连接验证 Token 及工作空间上下文。
* **密钥管理**：LLM 密钥加密存储，仅 AI 网关运行时解密使用，禁止出现在日志、接口响应与前端。
* **权限复用**：AI 接口全部经既有认证链与工作空间权限校验；工具调用以当前登录用户身份走 Service 层，禁止绕过业务校验（对应 AD-6）。
* **Prompt 注入防护**：系统指令与用户输入/业务数据分段隔离；对来自业务数据的上下文（节点文本、缺陷描述、需求条目）不作为指令解析。
* **自定义提示词防护**：仅系统管理员可编辑；输出格式约束段默认锁定（高级开关显式开启后方可编辑）；无论模板如何自定义，输出 JSON Schema 校验始终强制执行，校验失败按调用失败处理并提示检查模板；模板变更入审计日志。
* **输出防护**：LLM 输出一律经 JSON Schema + 枚举/长度校验后方可执行或落库；助手回复中的链接仅允许平台内路由。
* **会话可见性**：助手会话内容仅本人可见；审计权限用户仅可见调用元数据，不可见对话内容。
* **写操作防护**：写工具白名单 + 一次性确认令牌 + 超时失效；确认动作本身入审计。
* **数据出域**：送入 LLM 的业务数据经上下文裁剪，仅包含完成当次任务所需最小集合。

## 9. 设计约束与原则

* **角色分离**：系统角色仅用于管理端，业务角色和工作空间角色用于业务端，权限边界清晰。
* **快照独立性**：快照表与业务表独立，不建立外键引用。
* **权限扩展性**：权限点树形管理，新增功能追加节点即可。
* **上下文集中管理**：工作空间与项目上下文通过请求头统一注入，路由简洁。
* **零侵入原则**：AI 能力对既有业务模块只增不改；AI 整体可关闭且关闭后平台行为与不含 AI 能力时完全一致。
* **前端挂载原则**：AI 产出进入脑图一律经前端编辑内核，复用协同/持久化/撤销链路，后端不提供绕过编辑通道的批量写入口（AD-3）。
* **确定性优先原则**：能用规则/SQL 确定性计算的（统计、评分、DSL 执行）不交给 LLM；LLM 只承担生成、翻译与归纳。
* **人在环原则**：一切写操作预览-确认-执行；一切建议非侵入呈现、可忽略。
* **基建收敛原则**：不新增中间件（向量走 pgvector、限流走 Redis、任务走既有异步执行能力）；新增外部依赖仅 LLM 服务一项。
* **向量范围约束**：向量化覆盖缺陷库与用例库，需求池不建向量索引（AD-5）。
