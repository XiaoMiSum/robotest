# docs/AGENTS.md — 文档约定

> 本文件适用于 `docs/` 目录。总则见根目录 `AGENTS.md`，全局共享约定以总则为准。
> 本 AGENT **只负责文档相关操作**，不介入任何业务代码开发。

---

## 技术栈

- **格式**：Markdown（GFM）
- **绘图**：Mermaid（流程图/时序图/类图）
- **目录**：按业务域分 `需求/`、`概要/`、`详细设计/`、`交互设计/`、`架构/`、`spec/`
- **版本管理**：归档基线（`archive/<版本>/`）+ 工作目录迭代

## 文档架构

```
docs/
├── archive/
│   └── v1.0/                ← 已冻结的历史基线（格式模板）
├── spec/                    ← 工程规范（持续更新，不参与版本管理）
├── 需求/                     ← 需求规格说明书
├── 概要/                     ← 概要设计说明书
├── 架构/                     ← 架构设计
├── 详细设计/                  ← 详细设计说明书
├── 交互设计/                  ← 交互设计
└── AGENTS.md                ← 本文档
```

## 核心约定

| 编号 | 规则 | 检查方式 |
| --- | ---- | -------- |
| D1 | `docs/archive/` 下的所有归档文件只读，禁止修改 | 文件检查 |
| D2 | 新需求对应的工作目录无文档时，参照归档目录中对应文件格式新建 | 文件检查 |
| D3 | 文档元信息头必须包含版本、日期、状态三项 | 代码审查 |
| D4 | 进入新基线：归档当前版本 → 合并补齐归档内容 → 建新版 | 文件检查 |

## 边界

- 只修改 `docs/` 目录下的文档文件，不碰 `web/` 或 `server/` 代码
- 不介入任何业务代码开发、测试编写、构建配置等非文档任务
- `docs/spec/` 内的工程规范不参与版本归档，直接在原位更新
- 当被要求编写代码时，拒绝并告知应换用对应端（`web/` / `server/`）的 AGENT

## 文档版本生命周期

基线归档于 `docs/archive/<版本>/`，工作目录中为当前迭代版本。归档只读，当前版本在对应工作目录中修改。

| 位置 | 含义 | 可修改 |
| ---- | ---- | ------ |
| `docs/archive/<版本>/` | 已冻结的历史基线（格式模板） | ❌ 只读 |
| `docs/需求/`、`docs/概要/` 等 | 当前迭代版本 | ✅ 可改 |

### 未归档文件（原位直接修改）

以下文件无归档副本，不参与归档基线切换，直接在原位更新：

- `docs/架构/项目分层与技术架构设计.md`
- `docs/交互设计/全局导航与菜单交互系统设计.md`
- `docs/交互设计/视觉设计.md`
- `docs/详细设计/脑图组件详细设计.md`

## 文档操作

支持三种操作场景，按需选择。

### 一、同一基线内的修改

直接编辑文件内容，版本号不变，不追加变更记录。

### 二、进入新基线

当前版本的开发告一段落，需要开启下一版本时：

1. **归档** — 将工作目录中当前版本的文件复制到 `docs/archive/<当前版本>/`
2. **合并整理** — 将上一个归档版本的内容合并到新建的归档中，确保归档文档内容完整
3. **创建新版本** — 在对应的工作目录中新建文件，文件头标记新版本：

```markdown
**文档版本**：V<新版本>
**日期**：<当前日期>
**状态**：起草中
```

### 三、从归档模板新建

工作目录中无对应文档（如当前是空白目录），参照 `docs/archive/<版本>/` 中对应文件的章节结构和格式风格新建，文件头同上。

## 禁止行为

- ❌ 修改 `docs/archive/` 下的任何归档文件
- ❌ 删除归档文件
- ❌ 编写任何业务代码（这是其他 AGENT 的职责）
- ❌ 已有当前版本时仍引用归档基线做决策依据
