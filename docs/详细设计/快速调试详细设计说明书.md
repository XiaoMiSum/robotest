## 1. 引言

### 1.1 编写目的

本文档对软件测试平台 V1.2 接口测试业务域的**快速调试**进行详细设计，定义单请求调试（服务端执行）、cURL 命令解析与调试记录管理的数据结构、接口规范与业务逻辑，为开发实现提供完整依据。

### 1.2 范围

覆盖 SRS 3.1（快速调试）与概要设计第 3.1 章对应模块：

- **单请求调试**：服务端执行；
- **cURL 命令解析**：cURL 命令粘贴解析，回填请求构造；
- **调试记录管理**：调试历史记录的自动保存、查询、删除、重命名与恢复。

> 实施边界说明：本模块 V1.2 仅实现 `http` 协议（jdbc 取样器随测试场景模块提供）；「保存为接口定义」（3.1.3）依赖接口管理模块的表结构与资产模型，接口契约先行定义，实现随《接口管理详细设计说明书》模块一并交付；「本地执行」依赖独立交付的本地代理客户端，前端入口随客户端交付后启用。

接口定义、导入等接口资产的管理详见《接口管理详细设计说明书》（`docs/详细设计/接口管理详细设计说明书.md`）。

所有接口测试接口的鉴权、上下文传递沿用平台既有约定（C4），详见《API 测试基础设施详细设计说明书》3.1。

## 2. 数据设计

### 2.1 数据库表设计

#### 2.1.1 调试记录表（api_debug_record）

调试记录表 `api_debug_record` 定义于《API 测试基础设施详细设计说明书》（`docs/详细设计/API测试基础设施详细设计说明书.md`）2.1，本模块直接复用其 DDL 与索引，不重复定义。

调试记录的写入由 `POST /api/project/debug/execute` 服务端执行触发（详见 4.1 调试记录自动保存）。

快速调试模块复用《API 测试基础设施详细设计说明书》2.2 定义的错误码号段（7001–7099），本模块使用以下错误码：

| 错误码 | 常量名 | 说明 |
| ------ | ------ | ---- |
| 7013 | API_DEBUG_RECORD_NOT_FOUND | 调试记录不存在 |

## 3. 接口详细设计

### 3.1 快速调试接口

#### 3.1.1 执行调试请求（服务端）

- **路径**：`POST /api/project/debug/execute`
- **请求体**：

```json
{
  "protocol": "http",
  "method": "POST",
  "url": "https://staging.example.com/api/auth/login",
  "headers": [
    { "key": "Content-Type", "value": "application/json", "enabled": true }
  ],
  "body": {
    "type": "json",
    "content": { "username": "admin", "password": "123456" }
  },
  "params": [],
  "processors": [],
  "timeoutMs": 30000,
  "environmentId": "018f..."
}
```

- **说明**：
  - 服务端执行：由平台执行引擎发起请求，结果持久化为调试记录（自动保存，无需用户手动操作）。
  - `url` 支持完整 URL（含域名）或相对路径（与所选环境的 HTTP 配置 `baseUrl` 拼接）；`environmentId` 为执行引用的环境（变量引用与环境拼接的来源），缺省时使用项目默认环境。
  - 执行完成后自动将请求快照与响应结果保存为历史记录，保留最近 200 条（超出自动淘汰最旧记录，自动保存规则详见 4.1）。
- **响应**：

```json
{
  "debugRecordId": "018f...",
  "status": "success",
  "responseStatus": 200,
  "responseHeaders": { "Content-Type": "application/json" },
  "responseBody": { "code": 200, "data": { "token": "xxx" } },
  "durationMs": 230,
  "size": 2300
}
```

#### 3.1.2 从 cURL 导入

- **说明**：cURL 命令解析在**前端**完成（`curlParser`），解析规则详见 4.2，无后端接口；解析结果直接回填当前激活标签的请求编辑器（method、URL、headers、body），不执行命令。
- 兼容 Windows CMD 复制格式：`^` 续行符与 `^"` 转义引号在解析前归一化。

#### 3.1.3 保存调试记录为接口定义

- **路径**：`POST /api/project/debug/records/:id/save-as-interface`
- **请求体**：`{ "name": "用户登录", "moduleId": "018f..." }`
- **说明**：将调试记录的请求快照保存为接口定义资产（接口定义的维护详见《接口管理详细设计说明书》3.2）。
- **响应**：`{ "interfaceId": "018f..." }`

#### 3.1.4 查询调试记录列表

- **路径**：`GET /api/project/debug-records?page=1&pageSize=20`
- **说明**：仅返回当前用户的调试记录。
- **响应**：详见《API 测试基础设施详细设计说明书》3.3.1。

#### 3.1.5 删除调试记录

- **路径**：`DELETE /api/project/debug-records/:id`
- **响应**：`{ "success": true }`

#### 3.1.6 重命名调试记录

- **路径**：`PUT /api/project/debug-records/:id`
- **请求体**：`{ "name": "用户登录调试" }`
- **说明**：更新调试记录名称（4.1 记录命名中「用户可手动重命名」的服务端支撑）。
- **响应**：`{ "success": true }`

#### 3.1.7 恢复调试记录到当前标签

- **路径**：`GET /api/project/debug-records/:id/restore`
- **说明**：返回该次调试记录的完整请求快照与响应结果，前端据此回填当前标签的请求构造区并展示响应。
- **响应**：

```json
{
  "debugRecordId": "018f...",
  "request": {
    "protocol": "http",
    "method": "POST",
    "url": "https://staging.example.com/api/auth/login",
    "headers": [
      { "key": "Content-Type", "value": "application/json", "enabled": true }
    ],
    "body": {
      "type": "json",
      "content": { "username": "admin", "password": "123456" }
    },
    "params": []
  },
  "response": {
    "statusCode": 200,
    "headers": { "Content-Type": "application/json" },
    "body": { "code": 200, "message": "success", "data": { "token": "..." } },
    "elapsed": 125,
    "size": 2300
  },
  "createdAt": "2026-08-17T10:30:00Z"
}
```

## 4. 业务逻辑设计

### 4.1 调试记录自动保存

每次服务端执行完成后，自动将请求快照与响应结果保存为历史记录：

- **触发时机**：`POST /api/project/debug/execute` 返回成功响应后，异步写入 `api_debug_record` 表。
- **保存内容**：请求快照（方法、URL、请求头、请求体）+ 响应结果（状态码、响应头、响应体、耗时、大小）。
- **记录上限**：保留最近 200 条，超出后按 `created_at` 升序物理删除最旧记录。
- **恢复逻辑**：前端调用 `GET /api/project/debug-records/:id/restore` 获取完整快照，回填当前标签的请求构造区并展示响应。
- **记录命名**：自动保存的记录初始名称为「方法 + URL 路径末段」（如 `POST /api/auth/login`），用户可手动重命名。

### 4.2 cURL 解析规则

> 实现位置：**前端**（`web/src/pages/project/debug/curlParser.ts`），仅文本解析不执行命令；后端无对应解析逻辑。

cURL 命令解析支持以下要素提取：

| cURL 参数 | 前端映射 |
| --------- | -------- |
| `-X` / `--request` | method |
| URL 参数 | url |
| `-H` / `--header` | headers（数组） |
| `-d` / `--data` / `--data-raw` | body.content（type=json） |
| `-F` / `--form` | body.content（type=form） |
| `-b` / `--cookie` | headers（Cookie） |

不支持的参数（如 `--proxy`、`--cert`）在解析结果中忽略，不报错。

- **方法缺省**：存在请求体（`-d`/`-F`）且未指定 `-X` 时默认 `POST`，否则默认 `GET`。
- **负载降级**：`-d` 值无法解析为 JSON 时，`body.type` 降级为 `raw` 按原始文本回填。
- **Windows CMD 兼容**：仅当命令包含 `^` 续行（`^` + 换行）或 `^"` 转义引号标记时才做归一化——`^` + 换行折叠为空格、`^X` 还原为字面 `X`（`^"` → `"`、`^^` → `^`），避免误伤含字面 `^` 的 bash 命令；`^"tag="verbatim"` 形式的标签参数不做支持（解析结果中忽略）。

## 5. 前端设计

### 5.1 调试面板

- **调试标签栏**：页面顶部横向标签栏，每个标签代表一个独立调试会话；标签显示请求方法图标 + 简短名称 + 关闭按钮；末尾 `[+]` 按钮新建空白标签；最多 10 个标签。标签栏末尾固定一个不可关闭的「历史记录」标签，点击切换为全宽历史记录视图（与《快速调试交互设计》2.1 中「请求区左栏内嵌列表」方案不一致，本设计为准，交互分册待同步修订）。
- **环境选择器**：置于参数页签行最右侧（非 URL 栏下方），其余说明同前文；相对 URL 拼接与 `${变量名}` 引用均基于所选环境。
- **暂缓项**：「本地执行」按钮依赖本地代理客户端（实施分期第三梯队），随对应交付物启用。
- **标签状态管理**：首次执行后自动以「方法 + URL 路径末段」命名；双击标签名称进入行内编辑态；关闭标签不二次确认，直接关闭并切换到相邻标签。
- **历史记录视图**：点击「历史记录」标签后，主内容区切换为全宽历史记录视图（搜索框 + 按时间分组的记录列表 + 行内重命名/删除）；点击条目自动创建新调试标签并回填请求快照与响应结果；`Ctrl+Shift+H` 快速切换到历史记录标签。
- **请求编辑器**：方法选择、URL 输入、参数页签切换（Params/Body/Headers/Auth）。URL 栏右侧提供 **[发送]**（服务端执行）与 **[保存]**（保存为接口定义）。
- **键值对编辑器（Params/Headers/请求体）**：默认呈现一行空行，行内容（Key 或 Value）输入后自动追加新的空行，保证始终有一行可编辑；删除行后同样自动补足空行。Headers 的 Key 支持常用头名下拉选择与自定义输入（`allow-create`）。Rows 提交执行时丢弃空行。
- **Ryze 映射**：请求编辑器各页签对应引擎解析口径（与详细设计 3.1.3 一致）——Params 页签 → Ryze `query`（URL 查询参数）；`x-www-form-urlencoded` 请求体 → Ryze `data`；raw 请求体 → Ryze `body`。
- **请求体类型行**：`none` / `x-www-form-urlencoded` / `raw`。
  - `x-www-form-urlencoded`：键值对编辑器，提交时映射为后端 `body.type=form`（引擎 `data` 语义），内容以 `k=v&k=v` 编码串提交；若用户未手工设置 `Content-Type` 头则自动注入 `application/x-www-form-urlencoded`。
  - `raw`：文本编辑器；子类型选择器（Text/JSON/XML/HTML/JavaScript）置于类型行右侧同一行；选择 JSON/XML/HTML/JavaScript 子类型并按用户未手工设置时自动注入对应 `Content-Type` 头（`application/json`、`application/xml`、`text/html`、`text/javascript`）。`raw` 一律按原始文本提交（`body.type=raw`），前端不做 JSON 对象化。
  - 类型切换保留各类型已填内容（`bodyType` 字段记录当前激活类型）。
- **认证页签**：类型下拉置顶，支持 No Auth / Bearer Token / API Key / Basic Auth / Digest Auth（Digest 暂停用置灰）。认证不单独持久化——Bearer 换算为 `Authorization: Bearer <token>`，API Key 换算为自定义请求头（默认键 `X-API-Key`，可编辑），Basic 换算为 `Authorization: Basic base64(user:pass)`，均在提交执行时由前端注入请求头（密码、Token 脱敏展示）；从历史恢复时无法区分认证头与手工头，降级还原为普通请求头。
- **响应查看器（对齐 Postman）**：状态码（按成功/失败着色，悬停显示描述）、耗时、大小与状态码同行展示；顶部页签 [Body]/[Headers]/[Cookies]：
  - Body 内 Pretty/Raw/Preview 三态 + 格式类型下拉（JSON/XML/HTML/Text/JavaScript，按 `Content-Type` 自动检测）；JSON 在 Pretty 态语法高亮且节点可折叠，Raw 展示原始文本，Preview 对 HTML 用 `iframe srcdoc` 渲染、其余等同 Raw；
  - Headers 为响应头键值表；Cookies 从响应头 `Set-Cookie` 解析（客户端解析，无内存态 cookie 语义，仅展示）；
  - 搜索（`Ctrl+F` 聚焦，`Ctrl+G`/`Ctrl+Shift+G` 上一个/下一个，全部匹配高亮 + `n/m` 计数）；复制响应体。
- **保存为接口**：URL 栏 [保存] 按钮，依赖服务端执行产出的调试记录（`debugRecordId`）——未执行/本地执行时置灰。点击打开保存弹窗（新建接口/归属已有接口，见交互设计 2.6），调用 `POST /api/project/debug-records/:id/save-as-interface`（详细设计 3.1.3，`mode=create|attach`）。
- **cURL 粘贴**：支持从剪贴板粘贴 cURL 命令，由前端（`curlParser`，见 4.2）自动解析填充当前激活标签的请求编辑器，不执行命令。
