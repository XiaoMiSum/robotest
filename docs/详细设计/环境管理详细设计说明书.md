## 2. 数据设计

### 2.1 数据库表设计

#### 2.1.1 环境表（api_environment）

项目级环境配置集合，配置项与 Ryze 配置元件对齐。

| 字段 | 类型 | 约束 | 说明 |
| ---- | ---- | ---- | ---- |
| id | UUID | PK | 主键 |
| project_id | UUID | NOT NULL | 归属项目（project 维度，项目模块树详见《项目模块详细设计说明书》） |
| name | VARCHAR(100) | NOT NULL | 环境名称（如「测试环境」「预发环境」） |
| description | VARCHAR(500) | NULL | 环境描述 |
| scope | VARCHAR(10) | NOT NULL DEFAULT 'project' | 环境归属范围：project（项目级）/ global（全局级，V1.2 预留扩展） |
| is_default | BOOLEAN | NOT NULL DEFAULT FALSE | 是否默认环境（项目内唯一） |
| sort_order | INT | NOT NULL DEFAULT 0 | 排序序号 |
| is_deleted | BOOLEAN | NOT NULL DEFAULT FALSE | 是否删除 |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_env_project` (project_id)

> **全局环境（预留扩展）**：V1.2 环境均为项目级（`scope = project`），界面与接口为全局环境保留扩展位（类型徽标「全局」样式与展示位），维护入口与切换逻辑待后续版本补充（见 `docs/交互设计/环境管理交互设计.md` 2.4）。

#### 2.1.2 环境 HTTP 配置表（api_environment_http）

环境的 HTTP 配置，支持多个（如：内部系统、外部系统、第三方 API 等不同目标系统的 HTTP 配置），与数据源（api_data_source）模式一致。

| 字段 | 类型 | 约束 | 说明 |
| ---- | ---- | ---- | ---- |
| id | UUID | PK | 主键 |
| environment_id | UUID | NOT NULL | 归属环境（api_environment.id） |
| name | VARCHAR(100) | NOT NULL | 配置名称（如：「内部 API」「第三方支付」） |
| ref_name | VARCHAR(100) | NOT NULL | 引用名称（对应 Ryze `ref_name`，用于步骤中引用该配置） |
| base_url | VARCHAR(2000) | NOT NULL | Base URL（如：`https://api.internal.com`） |
| default_method | VARCHAR(10) | NULL | 默认 HTTP 方法 |
| default_headers | JSONB | NOT NULL DEFAULT '[]' | 默认请求头 `[{key, value, enabled}]` |
| timeout_ms | INT | NOT NULL DEFAULT 30000 | 请求超时（毫秒） |
| connect_timeout_ms | INT | NOT NULL DEFAULT 10000 | 连接超时（毫秒） |
| follow_redirects | BOOLEAN | NOT NULL DEFAULT TRUE | 是否跟随重定向 |
| verify_ssl | BOOLEAN | NOT NULL DEFAULT TRUE | 是否验证 SSL |
| is_default | BOOLEAN | NOT NULL DEFAULT FALSE | 是否为默认 HTTP 配置（每个环境有且仅有一个） |
| is_deleted | BOOLEAN | NOT NULL DEFAULT FALSE | 是否删除 |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_ehttp_env` (environment_id)

> 每个环境至少有一个 HTTP 配置（创建环境时自动生成默认配置）。步骤中通过 `http_config_id` 关联使用哪个 HTTP 配置。

## 3. 接口详细设计

### 3.1 环境管理

#### 3.1.1 查询环境列表

- **路径**：`GET /api/project/environments?keyword=xxx`
- **参数**：`keyword` 环境名称模糊搜索（前端输入防抖 300ms 后触发请求）。
- **响应**：

```json
[
  {
    "id": "018f...",
    "name": "测试环境",
    "description": "日常测试",
    "isDefault": true,
    "sortOrder": 0,
    "variableCount": 5,
    "dataSourceCount": 2,
    "processorCount": 1
  }
]
```

#### 3.1.2 查询环境详情

- **路径**：`GET /api/project/environments/:id`
- **响应**：包含 HTTP 配置列表、变量列表、数据源列表（脱敏）、处理器列表。

#### 3.1.3 创建环境

- **路径**：`POST /api/project/environments`
- **请求体**：

```json
{
  "name": "测试环境",
  "description": "日常测试",
  "isDefault": true,
  "httpConfigs": [
    {
      "name": "内部 API",
      "refName": "http_1",
      "baseUrl": "https://staging.example.com",
      "defaultMethod": "GET",
      "headers": [{ "key": "Content-Type", "value": "application/json", "enabled": true }],
      "timeoutMs": 30000,
      "connectTimeoutMs": 10000,
      "followRedirects": true,
      "verifySsl": true,
      "isDefault": true
    }
  ],
  "variables": [
    { "name": "TEST_PASSWORD", "value": "123456", "description": "测试密码", "type": "text" }
  ],
  "dataSources": [
    {
      "name": "测试库",
      "refName": "db_1",
      "driver": "com.mysql.cj.jdbc.Driver",
      "url": "jdbc:mysql://staging-db:3306/test?user=test_user&password=123456",
      "connectionProperties": {},
      "maxPoolSize": 5
    }
  ],
  "processors": []
}
```

- **响应**：`{ "id": "018f..." }`

#### 3.1.4 更新环境

- **路径**：`PUT /api/project/environments/:id`
- **请求体**：同 3.1.3。

#### 3.1.5 删除环境

- **路径**：`DELETE /api/project/environments/:id`
- **校验**：若环境被场景引用，返回错误码 7402（`API_ENV_REFERENCED`）；若环境被定时任务绑定，返回错误码 7404（`API_ENV_TASK_BOUND`），需先在定时任务中解除绑定。

#### 3.1.6 设置默认环境

- **路径**：`PATCH /api/project/environments/:id/set-default`
- **响应**：`{ "success": true }`

#### 3.1.7 测试数据源连接

- **路径**：`POST /api/project/environments/:id/data-sources/:dsId/test`
- **说明**：尝试建立 JDBC 连接，成功返回连接信息，失败返回错误码 7403（`API_DATASOURCE_CONN_FAILED`）并附带详细错误。URL 以 `redis://` 或 `rediss://` 开头的数据源不走 JDBC、不校验驱动：按 RESP 协议建立连接后发送 `PING` 验证连通性（复用框架内置 Redis 客户端），成功时通过 `INFO server` 提取 `redis_version` 填入 `databaseVersion`。JDBC 数据源仅放行服务端内置驱动，其余拒绝测试。
- **响应**：

```json
{
  "success": true,
  "message": "连接成功",
  "databaseVersion": "MySQL 8.0.35"
}
```

Redis 数据源成功响应示例：

```json
{
  "success": true,
  "message": "连接成功",
  "databaseVersion": "Redis 7.2.4"
}
```

#### 3.1.8 测试 HTTP 连接

- **路径**：`POST /api/project/environments/:id/http-configs/:httpId/test`
- **说明**：向配置的 base_url 发送 GET 请求，验证连通性。
- **响应**：

```json
{
  "success": true,
  "message": "连接成功",
  "statusCode": 200,
  "durationMs": 125
}
```

#### 3.1.9 导出环境

- **路径**：`GET /api/project/environments/:id/export`
- **说明**：导出环境配置为 JSON 文件（敏感字段脱敏）。数据源段整段排除：凭据内嵌于连接 URL 无法部分脱敏，遵循需求 3.7.1「导出环境时敏感信息脱敏」；导入端亦不消费该段，环境导入后需重新配置数据源。

#### 3.1.10 导入环境

- **路径**：`POST /api/project/environments/import`
- **Content-Type**：`multipart/form-data`
- **请求参数**：`file`（环境配置 JSON 文件）、`overwrite`（重名处理：`true` 覆盖 / `false` 跳过）。
- **说明**：导入环境配置 JSON 文件；重名环境按 `overwrite` 开关处理：开启时覆盖，关闭时跳过（不新增）。文件中的 `dataSources` 段被忽略（见 3.1.9 导出脱敏规则），敏感变量值不导入、需重新填写。
- **响应**：

```json
{
  "createdCount": 1,
  "overwrittenCount": 0,
  "skippedCount": 1
}
```

#### 3.1.11 复制环境

- **路径**：`POST /api/project/environments/:id/copy`
- **请求体**：

```json
{
  "name": "测试环境（副本）"
}
```

- **说明**：复制环境，内容含 HTTP 配置、变量与处理器；敏感变量值不复制，需重新填写（见需求 3.5）。
- **响应**：`{ "id": "018f..." }`

#### 3.1.12 调整环境排序

- **路径**：`PATCH /api/project/environments/:id/sort`
- **请求体**：

```json
{
  "sortOrder": 1
}
```

- **说明**：调整环境排序序号，列表按 `sort_order` 升序展示（默认环境置顶）。

### 3.2 全局处理器管理

环境级处理器的 CRUD 通过环境详情接口（3.1.2/3.1.3/3.1.4）统一管理，处理器列表嵌入环境配置中。独立管理接口：

#### 3.2.1 查询环境处理器列表

- **路径**：`GET /api/project/environments/:id/processors?processorType=preprocessor`
- **响应**：

```json
[
  {
    "id": "018f...",
    "processorType": "preprocessor",
    "name": "Token 预置",
    "config": { "processorType": "groovy", "script": "..." },
    "sortOrder": 0,
    "enabled": true
  }
]
```

#### 3.2.2 创建处理器

- **路径**：`POST /api/project/environments/:id/processors`
- **请求体**：

```json
{
  "processorType": "preprocessor",
  "name": "Token 预置",
  "config": { "processorType": "groovy", "script": "var token = context.getVar('token'); request.addHeader('Authorization', 'Bearer ' + token);" },
  "sortOrder": 0,
  "enabled": true
}
```

#### 3.2.3 更新/删除处理器

- **路径**：`PUT /api/project/environments/:id/processors/:procId` / `DELETE /api/project/environments/:id/processors/:procId`

### 3.3 环境变量管理

环境变量列表随环境详情接口（3.1.2）返回，独立管理接口如下：

#### 3.3.1 批量更新环境变量

- **路径**：`PUT /api/project/environments/:id/variables`
- **请求体**：

```json
{
  "variables": [
    { "name": "BASE_URL", "value": "https://staging.example.com", "type": "text", "description": "默认地址" },
    { "name": "TEST_PASSWORD", "value": "123456", "type": "sensitive", "description": "测试密码" }
  ]
}
```

- **说明**：全量更新环境变量表；变量名校验仅字母/数字/下划线且不得重名；数字类型（number）值非数字时返回校验错误；敏感值（sensitive）前端不回显明文。

#### 3.3.2 从执行结果添加变量

- **路径**：`POST /api/project/environments/:id/variables`
- **请求体**：

```json
{
  "name": "orderNo",
  "value": "SO-20260817",
  "type": "text",
  "description": "从执行结果添加",
  "sourceStepId": "018f...",
  "sourceReportId": "018f..."
}
```

- **说明**：用于「从执行结果快速添加」：单步骤调试结果浮层或报告详情选中响应片段后写入环境变量；`source_step_id` / `source_report_id` 记录来源便于追溯。
- **校验**：变量名重名时返回校验错误（提示「变量已存在」）。

#### 3.3.3 批量导入环境变量

- **路径**：`POST /api/project/environments/:id/variables/import`
- **请求体**：

```json
{
  "variables": [
    { "name": "userId", "value": "1001", "type": "number", "description": "用户 ID" }
  ],
  "overwrite": false
}
```

- **说明**：批量导入环境变量 JSON；`overwrite` 控制重名处理：`true` 覆盖 / `false` 跳过（不新增）。
- **响应**：

```json
{
  "createdCount": 1,
  "overwrittenCount": 0,
  "skippedCount": 1
}
```

#### 3.3.4 导出环境变量

- **路径**：`GET /api/project/environments/:id/variables/export`
- **说明**：导出环境变量为 JSON 文件；敏感值（type 为 sensitive）脱敏导出。

## 4. 业务逻辑设计

### 4.1 变量解析优先级

环境变量与场景变量、步骤级变量、步骤提取器变量、运行时覆盖同名时，按从低到高优先级取值（与 `docs/详细设计/测试场景详细设计说明书.md` 4.1 一致）：

```
内置函数 < 环境变量 < 场景变量 < 步骤级变量 < 步骤提取器变量 < 运行时覆盖
```

环境变量作为次低优先级，仅高于内置函数；场景级、步骤级同名变量依次覆盖环境变量（见需求 3.5「参数优先级」规则）。

### 4.2 数据源连接池

数据源连接采用 HikariCP 连接池，每个环境每个数据源独立连接池。连接池参数：
- `maximumPoolSize`：由 `api_data_source.max_pool_size` 控制（默认 5）。
- `minimumIdle`：1。
- `connectionTimeout`：10000ms。
- `idleTimeout`：600000ms（10 分钟）。

Redis 数据源不建立 HikariCP 连接池（`max_pool_size` 对其无意义）：连接测试按需创建 RESP 直连并在用毕关闭；Redis 取样器执行属多协议扩展预留（见需求「多协议扩展」），届时再评估长连接复用策略。

## 5. 前端设计

### 5.1 环境配置页

- **环境列表**：左侧环境列表，支持新建、排序、设为默认。
- **HTTP 配置列表**：类数据源模式，多个 HTTP 配置的列表 + 编辑表单（引用名称、Base URL、方法、请求头、超时等）+ 连接测试按钮。
- **变量编辑器**：表格编辑器（变量名、值、类型 text/number/sensitive、描述），支持批量导入/导出与从执行结果添加变量。
- **数据源配置**：数据源列表 + 编辑表单（引用名称、驱动、URL、最大连接池）+ 连接测试按钮；切换驱动时自动填充对应数据库类型的URL示例（含用户名密码占位符）。Redis 选项免驱动选择，按 `redis://` 协议识别。
- **全局处理器配置**：前置/后置处理器的列表编辑器。

## 6. 实施说明

### 6.1 数据源连接池

连接池设计见 4.2，实现注意点：
- 数据源连接失败抛出 `BusinessException`（错误码 7403），不影响环境保存与删除。
- 连接池按「环境 + 数据源」维度缓存，环境更新或数据源删除后释放对应连接池。

### 6.2 敏感数据加密

- 敏感变量值（type 为 sensitive）加密存储，不以下发明文至前端。数据源密码直接写入连接 URL，不在表单中独立存储。
- 环境导入导出、场景执行报告均不输出敏感值明文（见需求 3.5）。

### 6.3 环境删除保护

- 删除环境前校验场景引用（错误码 7402）与定时任务绑定（错误码 7404），被引用或绑定时禁止删除，需先解除引用/绑定。
