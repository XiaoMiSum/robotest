## 1. 引言

### 1.1 编写目的

本文档定义项目级统一模块树（`project_module`）的详细设计。统一模块树替代原有的三套独立模块表（功能测试 `test_case_module`、接口管理 `api_interface_module`、测试场景 `api_scenario_module`），实现一个项目一棵模块树、所有测试资产共享组织结构。用例作为独立资产挂载在模块树下，其数据表、接口与迁移设计见 `docs/详细设计/文档管理详细设计说明书.md`。

### 1.2 与基线的关系

本文档为 V1.2 新增文档，替代以下已有设计：

| 原设计 | 位置 | 替代方式 |
| --- | --- | --- |
| `test_case_module`（功能测试模块） | `docs/archive/v1.1/详细设计/项目工作区详细设计说明书.md` 2.1.1 | 目录节点（type=directory）迁移至 `project_module`；文档节点（type=document）迁移至 `test_case_document`，见 `docs/详细设计/文档管理详细设计说明书.md` |
| `api_interface_module`（接口模块） | `docs/详细设计/接口管理详细设计说明书.md` 2.1.1 | 废弃，引用 `project_module` |
| `api_scenario_module`（场景模块） | `docs/详细设计/测试场景详细设计说明书.md` 2.1.1 | 废弃，引用 `project_module` |

> 用例资产（`test_case_document`）的详细设计独立成文，见 `docs/详细设计/文档管理详细设计说明书.md`。

### 1.3 定义与缩写

| 术语 | 定义 |
| --- | --- |
| 模块（Module） | 项目下按业务域组织测试资产的树形目录节点，支持多级嵌套 |
| 未分组 | 模块 ID 为 NULL 时的默认归类，适用于不属于任何模块的资产 |

## 2. 数据设计

数据库字段使用 snake_case，接口 JSON 使用 camelCase。所有表遵循 C5（UUID 主键、`created_at`/`updated_at`/`is_deleted`，禁止物理外键）。

### 2.1 项目模块表（project_module）

项目级统一模块树，所有测试资产（功能用例文档、接口定义、测试场景）共享此树进行组织。

| 字段 | 类型 | 约束 | 说明 |
| ---- | ---- | ---- | ---- |
| id | UUID | PK | 主键 |
| project_id | UUID | NOT NULL | 归属项目 |
| parent_id | UUID | NULL | 父模块 ID（null 为根模块） |
| name | VARCHAR(100) | NOT NULL | 模块名称 |
| sort_order | INT | NOT NULL DEFAULT 0 | 排序序号 |
| is_deleted | BOOLEAN | NOT NULL DEFAULT FALSE | 是否删除 |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_pmod_project` (project_id), `idx_pmod_parent` (parent_id)

> 根模块 `parent_id` 为 NULL，查询某项目的根模块列表走 `idx_pmod_project`；子模块查询走 `idx_pmod_parent`。合计 2 个索引，符合 C9。

**唯一约束**：模块名称在同级父模块下唯一（应用层校验，错误码 7051）。

### 2.2 其他资产引用模块的方式

各资产表通过 `module_id` 字段引用 `project_module.id`，null 表示未分组：

| 资产表 | 引用字段 | 说明 |
| --- | --- | --- |
| `api_interface` | `module_id` → `project_module.id` | 接口定义归属模块 |
| `api_scene` | `module_id` → `project_module.id` | 测试场景归属模块 |
| `bug` | `module_id` → `project_module.id` | 缺陷归属模块（沿用现有） |

> 用例资产 `test_case_document.module_id` 同样引用 `project_module.id`，其表结构与接口设计见 `docs/详细设计/文档管理详细设计说明书.md`。

### 2.3 资产计数（按需统计）

模块树查询时按 `assetType` 参数统计对应资产数量，返回给前端展示计数徽标。不建议在 `project_module` 表上冗余计数字段，因为写入频率高（每次增删资产都要更新）。推荐查询时实时聚合或使用缓存。

## 3. 接口详细设计

所有接口通过 `X-Active-Project` 请求头传递项目上下文（C4），不出现在 URL 或请求体中。

### 3.1 模块管理

#### 3.1.1 查询模块树

```
GET /api/project/modules
```

**Query 参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| assetType | String | 否 | 资产类型：testcase / interface / scene，用于统计对应计数 |

**响应** `200 OK`：

```json
[
  {
    "id": "uuid-1",
    "parentId": null,
    "name": "用户模块",
    "sortOrder": 0,
    "children": [
      {
        "id": "uuid-2",
        "parentId": "uuid-1",
        "name": "登录",
        "sortOrder": 0,
        "children": []
      }
    ],
    "count": 3
  },
  {
    "id": "uuid-3",
    "parentId": null,
    "name": "订单模块",
    "sortOrder": 1,
    "children": [],
    "count": 1
  }
]
```

> `count` 为可选字段，仅当 `assetType` 参数存在时返回，统计对应资产表中 `module_id` 匹配的记录数。

#### 3.1.2 创建模块

```
POST /api/project/modules
```

**请求体**：

```json
{
  "parentId": "uuid-parent",
  "name": "支付模块"
}
```

> `parentId` 为 null 时创建根模块。

**响应** `201 Created`：

```json
{
  "id": "uuid-new",
  "parentId": "uuid-parent",
  "name": "支付模块",
  "sortOrder": 3
}
```

**校验规则**：
- `parentId` 若非 null，必须指向同项目的已有模块
- 同级父模块下名称唯一（错误码 7051）

#### 3.1.3 更新模块

```
PUT /api/project/modules/{id}
```

**请求体**（二选一或同时）：

```json
{
  "name": "新名称",
  "targetIndex": 2
}
```

> 仅 `name` → 重命名；仅 `targetIndex` → 移动到目标位置；两者同时 → 重命名并移动。

**移动规则**：
- 目标父模块必须是 `directory` 类型节点（即非文档），在同项目内
- 不允许移动到自身或自身后代下（循环检测）
- 移动后重写目标层级的 `sort_order`（从 0 递增）

**响应** `200 OK`：

```json
{
  "id": "uuid",
  "name": "新名称",
  "parentId": "uuid-target-parent",
  "sortOrder": 2
}
```

**错误码**：
- 7051：同级名称重复
- 7052：目标父模块不存在或不在同项目
- 7053：移动产生循环

#### 3.1.4 删除模块

```
DELETE /api/project/modules/{id}
```

**删除语义**：

| 情况 | 行为 |
| --- | --- |
| 有子模块 | 拒绝删除（错误码 7054） |
| 有关联用例 | 拒绝删除（错误码 7054） |
| 有关联接口 | 接口 `module_id` 置为 null（移入未分组） |
| 有关联场景 | 场景 `module_id` 置为 null（移入未分组） |
| 无任何关联 | 直接删除 |

> 接口和场景使用"移入未分组"策略，因为它们是轻量级资产；用例使用"拒绝删除"策略，因为用例内容（脑图节点）较重，误删代价高。

**响应** `200 OK`：

```json
{ "success": true }
```

**错误码**：7054 模块非空（有子模块或用例）

## 4. 业务逻辑设计

### 4.1 错误码

| 错误码 | 含义 | 场景 |
| --- | --- | --- |
| 7051 | 模块名称重复 | 同级父模块下已存在同名模块 |
| 7052 | 目标父模块无效 | 移动时目标父模块不存在或不在同项目 |
| 7053 | 移动产生循环 | 移动到自身或自身后代下 |
| 7054 | 模块非空 | 删除有子模块或用例的模块 |

> 错误码号段 7051–7059 预留给模块管理，与现有 7001–7049（API 测试）和 7201–7209（场景管理）不冲突。7055（用例名称重复）由用例管理使用，见 `docs/详细设计/文档管理详细设计说明书.md` 4.1。

### 4.2 业务规则

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| BR-M01 | 模块树每项目一棵 | 不支持多棵树，`project_id` 确定唯一树 |
| BR-M02 | 模块名同级唯一 | 应用层校验，数据库无唯一索引（因 is_deleted 软删除） |
| BR-M03 | 删除模块不级联资产 | 接口/场景移入未分组；用例拒绝删除（需先手动处理） |
| BR-M05 | 模块移动后重写排序 | 目标层级的 `sort_order` 从 0 递增重写 |
| BR-M06 | 未分组为隐式根 | `module_id = NULL` 表示资产不属于任何模块，无需显式创建"未分组"节点 |

> BR-M04（创建用例自动创建根节点）归属于用例管理，见 `docs/详细设计/文档管理详细设计说明书.md` 4.2。

### 4.3 与现有功能测试模块的兼容

现有 `test_case_module` 表包含 `type` 字段（directory/document），统一后：
- `type=directory` 的行 → 迁移到 `project_module`（结构完全一致）
- `type=document` 的行 → 迁移到 `test_case_document` 表（新增 `module_id` 字段指向原 `parent_id` 对应的 `project_module` 节点），详见 `docs/详细设计/文档管理详细设计说明书.md`
- `test_case_node.document_id` → 更新为新 `test_case_document.id`

## 5. 前端设计

### 5.1 统一模块树组件

所有测试页面（功能测试、接口管理、测试场景）左侧复用同一模块树组件 `ProjectModuleTree`：

```
┌──────────────┬────────────────────────────────────┐
│  模块树面板    │  资产列表面板                       │
│  30% 宽度     │  flex: 1                           │
│              │                                    │
│  [+ 新建模块] │  搜索 | 筛选 | 新建资产 | 刷新       │
│              │                                    │
│  ▼ 全部      │  ┌──────┬──────┬──────┐            │
│  ▼ 用户模块  │  │ 名称  │ 状态  │ 操作  │            │
│    ├ 登录    │  ├──────┼──────┼──────┤            │
│    └ 注册    │  │ ...  │      │      │            │
│  ▶ 订单模块  │  └──────┴──────┴──────┘            │
│  未分组      │                                    │
└──────────────┴────────────────────────────────────┘
```

**展开/收起行为**：

| 功能 | 说明 |
| --- | --- |
| 点击 ▶/▼ 箭头 | 展开或收起子模块 |
| 选中模块 | 自动展开父级路径，高亮选中项 |
| 初始状态 | 默认全部收起，仅显示根模块 |
| 展开状态持久化 | localStorage 记忆用户展开状态，刷新后恢复 |

### 5.2 各页面的差异

| 页面 | 模块树行为 | 右侧列表 | "新建"按钮 |
| --- | --- | --- | --- |
| 功能测试 | 展示全部模块，计数仅统计用例 | 展示当前模块下的用例列表 | + 新建用例 |
| 接口管理 | 展示全部模块，计数仅统计接口 | 展示当前模块下的接口列表 | + 新建接口 |
| 测试场景 | 展示全部模块，计数仅统计场景 | 展示当前模块下的场景列表 | + 新建场景 |

> 三页面共享同一棵树，但右侧列表展示不同资产类型。选中模块时按 `module_id` 筛选对应资产表。
> 功能测试页的"新建用例"入口归属于用例管理，其接口见 `docs/详细设计/文档管理详细设计说明书.md` 3.1。

### 5.3 计数徽标

模块名右侧展示当前资产类型的计数徽标，格式：

```
用户模块  (3)
```

> 计数仅显示当前页面对应的资产类型数量，不同页面显示不同数字。

## 6. 实施说明

### 6.1 数据迁移

**Phase 1：创建新表**

```sql
-- 创建 project_module 表
CREATE TABLE project_module (
    id UUID PRIMARY KEY,
    project_id UUID NOT NULL,
    parent_id UUID NULL,
    name VARCHAR(100) NOT NULL,
    sort_order INT NOT NULL DEFAULT 0,
    is_deleted BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_pmod_project ON project_module(project_id);
CREATE INDEX idx_pmod_parent ON project_module(parent_id);
```

> `test_case_document` 表及其索引的 DDL 见 `docs/详细设计/文档管理详细设计说明书.md` 6.1。

**Phase 2：数据迁移**

```sql
-- 1. test_case_module (type=directory) → project_module
INSERT INTO project_module (id, project_id, parent_id, name, sort_order, is_deleted, created_at, updated_at)
SELECT id, project_id, parent_id, name, sort_order, is_deleted, created_at, updated_at
FROM test_case_module WHERE type = 'directory' AND is_deleted = 0;

-- 3. api_interface_module → project_module（需生成新 UUID，保留原 ID 映射）
-- 4. api_scenario_module → project_module（同上）
```

> 步骤 2（test_case_module type=document → test_case_document）及布局回填（步骤 2.1）见 `docs/详细设计/文档管理详细设计说明书.md` 6.1。Phase 2 中步骤 3-4 需要 ID 映射表，因为 `api_interface.module_id` 和 `api_scene.module_id` 需要更新为新 ID。实际迁移脚本需在应用层执行，确保事务一致性。步骤 1 必须先于步骤 2 执行（`test_case_document.module_id` 引用迁移后的 `project_module.id`）。

**Phase 3：更新引用**

```sql
-- 更新 api_interface.module_id 映射
UPDATE api_interface SET module_id = (映射后的 project_module.id) WHERE module_id IS NOT NULL;

-- 更新 api_scene.module_id 映射
UPDATE api_scene SET module_id = (映射后的 project_module.id) WHERE module_id IS NOT NULL;

-- 更新 bug.module_id 映射（如有）
UPDATE bug SET module_id = (映射后的 project_module.id) WHERE module_id IS NOT NULL;
```

**Phase 4：废弃旧表**

```sql
-- 确认所有引用已更新后，删除旧表
DROP TABLE api_interface_module;
DROP TABLE api_scenario_module;
-- test_case_module 保留只读或直接删除
```

> `test_case_document_layout` 的废弃（布局数据回填至 `test_case_document.layout` 之后）见 `docs/详细设计/文档管理详细设计说明书.md` 6.1。

### 6.2 迁移注意事项

1. **ID 映射**：`api_interface_module` 和 `api_scenario_module` 的 UUID 与 `test_case_module` 的 binary(16) 主键格式不同，迁移时需在应用层转换
2. **索引**：新表索引命名遵循 `idx_{table}_{field}` 规范（C9）
3. **软删除**：`is_deleted` 字段确保迁移期间的并发安全
4. **回滚方案**：保留旧表数据至确认新表稳定后再清理

### 6.3 错误码号段分配

| 号段 | 用途 |
| --- | --- |
| 7001–7049 | API 测试（接口管理、调试、导入） |
| 7051–7059 | 模块管理（本文档） |
| 7101–7199 | Mock 服务 |
| 7201–7299 | 测试场景管理 |

> 7055（用例名称重复）归属于文档管理，定义见 `docs/详细设计/文档管理详细设计说明书.md` 4.1。
