## 1. 引言

### 1.1 编写目的

本文档对软件测试平台 V1.2 接口测试业务域的**测试场景编排与环境管理**进行详细设计，定义场景、步骤、参数、处理器、环境、数据源的数据结构、接口规范与业务逻辑，为开发实现提供完整依据。

### 1.2 范围

覆盖 SRS 3.4（测试场景）、3.5（环境管理）、3.8（前置与后置处理器）、3.9（断言）、3.10（内置函数与变量引用）与概要设计第 3.1 章对应模块：

- **测试场景**：场景 CRUD、步骤编排（http/jdbc 取样器）、参数管理、处理器配置、复制与链接引用、执行历史与变更历史；
- **环境管理**：环境 CRUD、默认配置（http 默认配置）、数据源配置、全局变量、全局前置/后置处理器、环境导入导出；
- **处理器与断言**：前置处理器、后置处理器、验证器（断言）、提取器的配置模型与执行语义。

## 2. 数据设计

### 2.1 数据库表设计

#### 2.1.1 测试场景表（api_scene）

场景为多步骤编排的自动化测试单元，可选关联一个接口定义作为虚拟包组织标签。

| 字段 | 类型 | 约束 | 说明 |
| ---- | ---- | ---- | ---- |
| id | UUID | PK | 主键 |
| project_id | UUID | NOT NULL | 归属项目 |
| module_id | UUID | NULL | 归属模块（api_interface_module.id，复用接口模块树） |
| interface_id | UUID | NULL | 关联接口定义（虚拟包，可选） |
| name | VARCHAR(200) | NOT NULL | 场景名称 |
| description | TEXT | NULL | 场景描述 |
| environment_id | UUID | NULL | 默认执行环境（api_environment.id，可选） |
| fail_rule | VARCHAR(20) | NOT NULL DEFAULT 'all' | 失败规则：all（任一步骤失败则停止）/ continue（继续执行） |
| variables | JSONB | NOT NULL DEFAULT '[]' | 场景参数列表 `[{name, value, description}]` |
| processors | JSONB | NOT NULL DEFAULT '[]' | 场景级处理器列表 |
| cookie_config | JSONB | NULL | Cookie 配置 |
| change_version | INT | NOT NULL DEFAULT 1 | 变更版本号（每次保存递增，乐观锁） |
| is_deleted | BOOLEAN | NOT NULL DEFAULT FALSE | 是否删除 |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_scene_project` (project_id), `idx_scene_module` (module_id), `idx_scene_interface` (interface_id)

> `idx_scene_interface` 支撑虚拟包下场景批量查询。合计 3 个索引，符合 C9。

#### 2.1.2 场景步骤表（api_scene_step）

场景步骤即取样器（http/jdbc 两种类型），支持从接口定义导入系统请求、创建自定义请求、添加公共步骤。

| 字段 | 类型 | 约束 | 说明 |
| ---- | ---- | ---- | ---- |
| id | UUID | PK | 主键 |
| scene_id | UUID | NOT NULL | 归属场景（api_scene.id） |
| name | VARCHAR(200) | NOT NULL | 步骤名称 |
| step_type | VARCHAR(20) | NOT NULL | 步骤类型：http / jdbc |
| sort_order | INT | NOT NULL DEFAULT 0 | 排序序号 |
| enabled | BOOLEAN | NOT NULL DEFAULT TRUE | 启用状态 |
| source_type | VARCHAR(20) | NULL | 来源类型：system（系统请求）/ custom（自定义）/ public_step（公共步骤）/ copy（复制）/ link（链接引用） |
| source_id | UUID | NULL | 来源对象 ID（接口定义 ID 或公共步骤 ID） |
| source_snapshot | JSONB | NULL | 来源快照（链接引用时记录创建时的快照，用于源被删除后展示） |
| request_config | JSONB | NOT NULL | 请求配置（http: method/url/headers/body/query/rest/auth；jdbc: datasourceId/sql/queryType） |
| processors | JSONB | NOT NULL DEFAULT '[]' | 步骤级处理器列表 |
| validators | JSONB | NOT NULL DEFAULT '[]' | 验证器（断言）列表 |
| extractors | JSONB | NOT NULL DEFAULT '[]' | 提取器列表 |
| timeout_ms | INT | NULL | 请求超时（毫秒，null 使用环境默认值） |
| is_deleted | BOOLEAN | NOT NULL DEFAULT FALSE | 是否删除 |
| created_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | NOT NULL DEFAULT CURRENT_TIMESTAMP | 更新时间 |

**索引**：`idx_sstep_scene` (scene_id)

#### 2.1.3 场景参数表（api_scenario_param）

场景参数用于步骤间的变量传递与数据驱动。

| 字段 | 类型 | 约束 | 说明 |

#### 2.1.4 环境表（api_environment）

项目级环境配置集合，配置项与 Ryze 配置元件对齐。

## 3. 接口详细设计

### 3.1 场景管理

#### 3.1.1 查询场景列表

- **路径**：`GET /api/project/api/scenes?moduleId=&search=&page=1&pageSize=20`
- **响应**：

```json
{
  "records": [
    {
      "id": "018f...",
      "name": "登录流程测试",
      "moduleId": "018e...",
      "interfaceId": "018d...",
      "environmentId": "018c...",

      "lastStatus": "success",

  "total": 18
}
```

#### 3.1.2 查询场景详情

- **路径**：`GET /api/project/api/scenes/:id`
- **响应**：包含完整步骤列表、参数列表、处理器列表。

```json
{
  "id": "018f...",

    {
      "id": "018a...",
      "name": "发送登录请求",

      "sourceId": "018b...",
```

#### 3.1.3 创建场景

- **路径**：`POST /api/project/api/scenes`
- **请求体**：同 3.1.2 响应结构（不含 id、steps）。

#### 3.1.4 更新场景

- **路径**：`PUT /api/project/api/scenes/:id`
- **请求体**：同 3.1.2 响应结构。
- **乐观锁**：请求体需包含 `changeVersion`，服务端校验版本号一致性，冲突返回 409。

#### 3.1.5 删除场景

- **路径**：`DELETE /api/project/api/scenes/:id`
- **校验**：若场景被定时任务引用，返回错误码 7203（`API_SCENE_REFERENCED`）。

#### 3.1.6 复制场景

- **路径**：`POST /api/project/api/scenes/:id/copy`
- **请求体**：`{ "name": "登录流程测试（副本）" }`
- **说明**：复制场景及其下全部步骤（复制模式，非链接引用）。

### 3.2 步骤管理

#### 3.2.1 创建步骤

- **路径**：`POST /api/project/api/scenes/:sceneId/steps`
- **请求体**：

```json
{
  "name": "发送登录请求",
  "stepType": "http",
  "sortOrder": 0,
  "enabled": true,
  "sourceType": "custom",
  "sourceId": null,
  "requestConfig": {
    "method": "POST",
    "url": "/api/auth/login",
    "headers": [{ "key": "Content-Type", "value": "application/json", "enabled": true }],
    "bodyType": "json",
    "body": { "username": "${username}", "password": "${password}" },
    "queryParams": [],
    "restParams": [],
    "authConfig": null
  },
  "processors": [],
  "validators": [
    { "type": "status", "expression": "eq 200" }
  ],
  "extractors": [],
  "timeoutMs": null
}
```

- **响应**：`{ "id": "018f..." }`

#### 3.2.2 从接口定义导入步骤

- **路径**：`POST /api/project/api/scenes/:sceneId/steps/import`
- **请求体**：

```json
{
  "interfaceId": "018f...",
  "mode": "copy",
  "paramStrategy": "preferCurrent",
  "environmentStrategy": "preferCurrent"
}
```

- `mode`：`copy`（复制）或 `link`（链接引用）。
- `paramStrategy`：`preferOriginal`（优先原接口参数）/ `preferCurrent`（优先当前场景参数）。
- `environmentStrategy`：`preferOriginal`（使用原接口环境）/ `preferCurrent`（使用当前环境）。
- **响应**：返回创建的步骤列表。

#### 3.2.3 添加公共步骤

- **路径**：`POST /api/project/api/scenes/:sceneId/steps/public-step`
- **请求体**：

```json
{
  "publicStepId": "018f...",
  "mode": "link",
  "sortOrder": 2
}
```

#### 3.2.4 更新步骤

- **路径**：`PUT /api/project/api/scenes/:sceneId/steps/:stepId`
- **请求体**：同 3.2.1。

#### 3.2.5 删除步骤

- **路径**：`DELETE /api/project/api/scenes/:sceneId/steps/:stepId`

#### 3.2.6 步骤排序

- **路径**：`PUT /api/project/api/scenes/:sceneId/steps/reorder`
- **请求体**：

```json
{
  "stepIds": ["018f...", "018g...", "018h..."]
}
```

- **说明**：数组顺序即为新的排序。

```json
[
  {
```

#### 3.4.3 创建环境

- **路径**：`POST /api/project/api/environments`
- **请求体**：

```json
{
  "name": "测试环境",

  "isDefault": true,

    { "name": "TEST_PASSWORD", "value": "123456", "description": "测试密码", "isSecret": false }
  ],
  "dataSources": [
    {
      "name": "测试库",
      "driver": "com.mysql.cj.jdbc.Driver",
      "url": "jdbc:mysql://staging-db:3306/test",
      "username": "test_user",
      "password": "123456",
      "connectionProperties": {},
      "maxPoolSize": 5
    }
  ],
  "processors": []
}
```

- **响应**：`{ "id": "018f..." }`

#### 3.4.4 更新环境

- **路径**：`PUT /api/project/api/environments/:id`
- **请求体**：同 3.4.3。

#### 3.4.5 删除环境

- **路径**：`DELETE /api/project/api/environments/:id`
- **校验**：若环境被场景引用，返回错误码 7402（`API_ENV_REFERENCED`）。

#### 3.4.6 设置默认环境

- **路径**：`PATCH /api/project/api/environments/:id/set-default`
- **响应**：`{ "success": true }`

#### 3.4.7 测试数据源连接

- **路径**：`POST /api/project/api/environments/:id/data-sources/:dsId/test`
- **说明**：尝试建立 JDBC 连接，成功返回连接信息，失败返回错误码 7403（`API_DATASOURCE_CONN_FAILED`）并附带详细错误。
- **响应**：

```json
{
  "success": true,
  "message": "连接成功",
  "databaseVersion": "MySQL 8.0.35"
}
```

#### 3.4.8 导出环境

- **路径**：`GET /api/project/api/environments/:id/export`
- **说明**：导出环境配置为 JSON 文件（敏感字段脱敏）。

#### 3.4.9 导入环境

- **路径**：`POST /api/project/api/environments/import`
- **Content-Type**：`multipart/form-data`
- **说明**：导入环境配置 JSON 文件，创建新环境。

### 3.5 全局处理器管理

#### 3.5.1 查询环境处理器列表

- **路径**：`GET /api/project/api/environments/:id/processors?processorType=preprocessor`
- **响应**：

```json
[
```

## 4. 业务逻辑设计

### 4.1 变量引用与内置函数

变量引用语法与 Ryze 框架保持一致，使用 `${变量名}` 语法。

**变量解析优先级**（从低到高）：

```
内置函数 < 环境变量 < 场景参数 < 步骤提取器变量 < 运行时覆盖
```

**内置函数**：

| 函数 | 说明 | 示例 |
| ---- | ---- | ---- |
| `${uuid()}` | 生成 UUID v7 | `${uuid()}` |
| `${timestamp()}` | 当前时间戳（毫秒） | `${timestamp()}` |
| `${timestamp_s()}` | 当前时间戳（秒） | `${timestamp_s()}` |
| `${date(format)}` | 当前日期（Java SimpleDateFormat） | `${date(yyyy-MM-dd)}` |
| `${random(min, max)}` | 随机整数 | `${random(1, 100)}` |
| `${randomString(length)}` | 随机字符串 | `${randomString(16)}` |
| `${env:VAR_NAME}` | 读取环境变量 | `${env:BASE_URL}` |
| `${var:VAR_NAME}` | 读取场景参数 | `${var:username}` |
| `${data:VAR_NAME}` | 读取数据源查询结果 | `${data:user_id}` |

### 4.2 验证器（断言）配置模型

验证器配置为 JSON 对象，结构统一：

```json
{
  "type": "status|json|header|body|regex|xpath",
  "expression": "<表达式>",
  "operator": "eq|ne|gt|lt|gte|lte|contains|not_contains|starts_with|ends_with|matches",
  "expected": "<期望值>",
  "description": "<断言描述（可选）>"
}
```

| type | expression 说明 | 示例 |
| ---- | --------------- | ---- |
| status | HTTP 状态码 | `"expression": "eq 200"` |
| json | JSONPath 表达式 | `"expression": "$.code"`, `"expected": "200"` |
| header | 响应头名 | `"expression": "Content-Type"`, `"expected": "application/json"` |
| body | 响应体文本 | `"expression": "contains"`, `"expected": "success"` |
| regex | 正则匹配响应体 | `"expression": "\"token\":\"([^\"]+)\""` |
| xpath | XPath 表达式（XML 响应） | `"expression": "//status"`, `"expected": "ok"` |

### 4.3 提取器配置模型

提取器从响应中提取数据并存入变量，供后续步骤引用：

```json
{
  "type": "json|header|body|regex",
  "expression": "<表达式>",
  "variableName": "<目标变量名>",
  "description": "<提取描述（可选）>"
}
```

| type | expression 说明 | 示例 |
| ---- | --------------- | ---- |
| json | JSONPath 表达式 | `"expression": "$.data.token"`, `"variableName": "token"` |
| header | 响应头名 | `"expression": "Set-Cookie"`, `"variableName": "cookie"` |
| body | 响应体全文 | `"variableName": "responseBody"` |
| regex | 正则捕获组 | `"expression": "\"id\":(\\d+)"`, `"variableName": "userId"` |

### 4.4 复制与链接引用语义

详见《概要设计说明书》4.3。实现要点：

**复制（copy）**：
- 创建步骤的完整独立副本（`source_type = "copy"`）。
- 后续修改互不影响。
- 源被删除后，复制步骤仍可编辑（`source_id` 置灰无法跳转）。

**链接引用（link）**：
- 步骤内容（`request_config`、`validators`、`extractors`）跟随源变化同步更新（`source_type = "link"`）。
- 当前场景中的 `enabled` 状态、参数值可独立调整。
- 源被删除时，引用步骤置灰并仅支持「移除」操作。
- 引用步骤的 `source_snapshot` 记录创建时的快照，用于源被删除后的展示。

**刷新机制**：链接引用步骤在执行时实时拉取源最新内容；若拉取失败（源已删除），使用 `source_snapshot` 快照降级执行。

### 4.5 配置继承与合并

执行时，平台将环境配置、场景配置、步骤配置按优先级合并后生成 Ryze 运行时配置：

```
环境默认配置 < 场景级配置 < 步骤级配置
```

同名配置项以高优先级覆盖低优先级。合并范围包括：
- 请求头（env.headers + scene.processors + step.headers）
- 超时配置（env.timeout_ms → step.timeout_ms）
- 认证配置（env.auth → scene.auth → step.auth）
- 变量（env.variables → scene.variables → step.extractors 产出）

## 5. 前端设计

### 5.1 场景编排器

核心交互组件，以可视化步骤画布为中心：

- **步骤画布**：垂直排列的步骤卡片列表，支持拖拽排序。每个步骤卡片包含：类型标识（http/jdbc）、名称、启用开关、展开/折叠。
- **步骤导入选择器**：点击「添加步骤」弹出选择器，支持三种来源：
  - 系统请求：从接口定义列表选择，导入为步骤。
  - 公共步骤：从当前项目接口定义下的公共步骤列表选择。
  - 自定义请求：直接在步骤卡片内编辑请求。
- **参数编辑器**：场景参数的表格编辑器（参数名、值、描述）。
- **处理器配置面板**：场景级前置/后置处理器的列表编辑器。
- **Cookie 设置面板**：Cookie 键值对编辑器。

### 5.2 环境配置页

- **环境列表**：左侧环境列表，支持新建、排序、设为默认。
- **默认配置编辑**：http 默认配置项表单（Base URL、方法、请求头、超时等）。
- **变量编辑器**：表格编辑器（变量名、值、描述、敏感标记）。
- **数据源配置**：数据源列表 + 编辑表单（驱动、URL、用户名、密码）+ 连接测试按钮。
- **全局处理器配置**：前置/后置处理器的列表编辑器。

## 6. 实施说明

### 6.1 Ryze 变量映射

平台场景参数与 Ryze variables 的映射为直接一对一（`name` → key，`value` → value）。内置函数在平台层解析后传入 Ryze 引擎，Ryze 引擎不感知平台内置函数。

### 6.2 链接引用刷新策略

链接引用步骤在执行前实时拉取源最新内容。拉取逻辑：
1. 根据 `source_id` 查询源对象（接口定义步骤或公共步骤）。
2. 若源存在，使用源最新内容覆盖步骤的 `request_config`、`validators`、`extractors`。
3. 若源不存在（已删除），使用 `source_snapshot` 快照降级执行。
4. 执行结果中标注「源已删除，使用快照」。

### 6.3 数据源连接池

数据源连接采用 HikariCP 连接池，每个环境每个数据源独立连接池。连接池参数：
- `maximumPoolSize`：由 `api_data_source.max_pool_size` 控制（默认 5）。
- `minimumIdle`：1。
- `connectionTimeout`：10000ms。
- `idleTimeout`：600000ms（10 分钟）。
