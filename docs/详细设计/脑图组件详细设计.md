# 软件测试平台——脑图组件详细设计

**文档版本**：V1.0
**日期**：2026-07-28
**状态**：已发布

---

## 1. 概述

> 本文档为 V1.0 组件级设计文档（非归档文件，原位更新），章节按组件设计组织（概述 → 技术选型 → 组件架构 → 数据模型 → 各功能模块），与 V1.1 详细设计的统一骨架（引言 → 数据设计 → 接口详细设计 → 业务逻辑设计 → 前端设计 → 实施说明）不一致，属 V1.0 既有格式，沿用不改。

脑图组件是功能测试模块的核心组件，用于测试用例的可视化编辑、评审与执行跟踪。采用 **kityminder-core** 作为脑图渲染引擎，通过 **Yjs** 实现多人实时协作。按业务场景拆分为三个独立组件，公共能力下沉至 `minder/` 基座：

- **CaseMindMap（编辑）**：完整的节点增删改、类型标记、优先级标记，数据实时同步至 `test_case_node` 表。
- **ReviewMindMap（评审）**：基于快照只读脑图，提供评审标记（通过/不通过/待评审）和评论功能，数据写入 `test_review_record` 表并更新快照节点状态。
- **PlanMindMap（计划）**：基于快照只读脑图，提供执行结果标记（通过/失败/阻塞/未执行），数据写入 `test_plan_execution_record` 表并更新快照节点状态。

## 2. 技术选型

| 组件    | 技术                                            | 说明                            |
| ----- | --------------------------------------------- | ----------------------------- |
| 脑图核心  | kityminder-core                               | 基于 SVG 的脑图编辑器，支持节点增删改、拖拽、主题定制 |
| 数据绑定  | kityminder-core 的 `importData` / `exportData` | JSON 格式数据中间层                  |
| 实时协作  | Yjs (y-websocket)                             | 编辑模式下增量同步，评审/计划模式不使用          |
| 前端框架  | Vue 3 + Composition API                       | 封装为 Vue 组件，管理生命周期和交互          |
| UI 增强 | Element Plus (弹出菜单、工具栏、评论抽屉)                  | 节点右键菜单、悬浮工具栏、评论抽屉             |

## 3. 组件架构

```
web/src/components/project/
├── CaseMindMap.vue    编辑组件（props: docId）
│     ├── 编辑工具栏（类型/优先级标记、节点增删、撤销重做、布局模板、整理布局）
│     ├── 编辑内核 KMEditor（原位编辑/撤销重做，见 3.1）
│     ├── Yjs 实时协作 + WebSocket 持久化（文本帧落库）
│     ├── 协作状态指示器（在线用户头像）与断线提示横幅
│     └── 编辑右键菜单（节点操作/标记类型/标记优先级/删除）
├── ReviewMindMap.vue  评审组件（props: reviewId）
│     ├── 评审工具栏（通过/不通过/待评审、评论）
│     ├── 快照只读画布（minder.disable()）
│     ├── 评论抽屉
│     └── 评审右键菜单（标记评审结果/添加评论）
├── PlanMindMap.vue    计划组件（props: planId）
│     ├── 执行工具栏（通过/失败/阻塞/未执行）
│     ├── 快照只读画布（minder.disable()）
│     └── 执行右键菜单（标记执行结果）
└── minder/            公共基座与编辑内核
      ├── loader.ts     引擎加载：经典 script 标签加载 kity/kityminder-core 并注册徽标模块
      ├── useMinderInstance.ts  实例骨架：容器/加载态/实例引用、竞态令牌、销毁、选中状态维护
      ├── useContextMenu.ts     右键菜单状态：定位、全局关闭监听（mousedown/Esc/wheel）
      ├── MinderContextMenu.vue 右键菜单壳（teleport + 菜单样式，菜单项经 slot 传入）
      ├── minder-base.scss      共享结构样式（容器/工具栏/画布）
      ├── fsm.ts        状态机：normal ⇄ input
      ├── receiver.ts   contenteditable 键盘接收器（IME 支持）
      ├── input.ts      原位内联编辑（定位/提交/取消/跟随重定位）
      ├── jumping.ts    F2 编辑、Enter/Esc 拦截、Ctrl+Z/Y（双击编辑在 input.ts）
      ├── history.ts    JSON-Patch diff + applyPatches 增量撤销重做
      ├── badges.ts     自定义渲染模块：类型/优先级彩色徽标（三组件均注册）
      ├── adapter.ts    后端节点树 ⇄ kityminder JSON 映射
      ├── editor.ts     编辑内核入口 KMEditor（仅 CaseMindMap 使用）
      └── MinderNavigator.vue  导航器（缩放条/定位根节点/抓手/缩略图/全屏，三组件共用）
```

拆分原则：三组件仅共享"实例骨架 + 引擎加载 + 右键菜单壳 + 结构样式"这类与业务无关的能力；数据获取、工具栏、标记提交等业务逻辑各自独立，互不感知，避免单组件内 `mode` 分支蔓延。

### 3.1 编辑内核关键机制

- **原位编辑**：contenteditable 接收器平时隐藏且只接收键盘；进入 input 态时按 `getRenderBox('TextRenderer')` 叠加到节点文本上形成原位编辑框，支持 IME、跟随视图缩放/平移重定位。Enter/blur 提交（走 `execCommand('text')` → `contentchange` → Yjs 同步 + 落库），Esc 取消；符合既定交互规范：原位编辑、禁止弹窗。
- **双击编辑**：双击节点或 F2/工具栏/右键菜单进入原位编辑，光标定位到文本末端（不全选）；普通打字不触发编辑。
- **自由拖拽摆放与布局持久化**：拖拽命中 drop/排序目标时换父/调序；未命中时 core 保留 layout_*_offset 偏移，节点停留在拖放位置（自由摆放）。模板名与全部节点偏移经 `update_layout` 帧整体 upsert 到 `test_case_document.layout` JSON 列，加载时回填偏移并应用模板；工具栏"整理布局"（core `resetlayout`）可一键清除全部偏移恢复自动排版。
- **撤销重做**：core 无 Undo/Redo 命令，由 history.ts 实现：`contentchange` 时与上一快照 diff 生成反向 JSON-Patch 入栈（上限 100），undo/redo 调 core 原生 `minder.applyPatches()` 增量回放、仅局部重渲染；回放自动触发 `contentchange`，现有同步/落库管道零改动生效（patchLock 门闩防止回放再入栈）。
- **协同隔离**：远端 Yjs 变更回放期间（applyingRemote）不入本地撤销栈，避免撤销掉他人的编辑；review/plan 只读模式不启用编辑内核。
- **WS 心跳保活**：y-websocket 硬编码 30 秒假死检测（30 秒无入站消息即断开重连），而服务端二进制帧仅转发给房间内其他成员，单人编辑时客户端永远收不到消息，会陷入每 ~30 秒一轮的断连重连循环。修复分两端：服务端收到二进制帧后向发送者回 3 字节空 awareness 帧 `{0x01, 0x01, 0x00}`（客户端解码零副作用），借客户端每 ≤15 秒的 awareness 心跳实现回帧保活；前端截流的文本帧（业务确认帧）不经过 y-websocket 原生 onmessage，需手动刷新 `wsLastMessageReceived`（lib0 的 getUnixTime 即 Date.now，毫秒）。
- **离开文档确认**：处于文档中时切换文档（ModuleTree 内确认，取消后需 `setCurrentKey` 回退 el-tree 抢先高亮）、离开页面（TestCasePage `onBeforeRouteLeave` 守卫）、切换功能测试页子页面（子页面经 `activeMenu` + v-if 切换不走路由，FunctionalTestingPage 在菜单 select 时调 TestCasePage expose 的 `confirmLeave()` 拦截，取消后需 `updateActiveIndex` 回退 el-menu 抢先高亮）均弹窗二次确认；文档内容实时自动保存，弹窗定位为防误触打断编辑。

## 4. 数据模型与模式映射

### 4.1 节点类型定义与彩色徽标视觉规范

节点类型与优先级直接以彩色徽标标注在节点文本左侧（badges.ts 自定义渲染模块绘制，kity 圆角色块 + 白色文字），三种模式（edit/review/plan）均可见：

| 类型值            | 含义          | 徽标文案 | 徽标颜色           |
| -------------- | ----------- | ---- | -------------- |
| `normal`       | 普通节点（无特殊标记） | 不显示  | —              |
| `precondition` | 前置条件        | 前置   | 蓝 `#409EFF`   |
| `step`         | 执行步骤        | 步骤   | 绿 `#67C23A`   |
| `expected`     | 预期结果        | 预期   | 橙 `#E6A23C`   |
| `case`         | 测试用例        | 用例   | 紫 `#A464FF`，另显示优先级徽标 |

优先级徽标文字直显 `P0`-`P3`：

| 优先级  | 徽标颜色         |
| ---- | ------------ |
| `P0` | 红 `#F56C6C` |
| `P1` | 橙 `#E6A23C` |
| `P2` | 蓝 `#409EFF` |
| `P3` | 灰 `#909399` |

实现约束：不借用 core 内置 priority/resource 渲染（前者只能显示数字 1-9，后者颜色随机不可控），注册时以同名模块覆盖禁用内置 PriorityModule（其对 `'P0'` 字符串判真会渲染隐形占位图标）；落库字段格式不变（仍为 `'P0'-'P3'` 与原 type 枚举）；徽标模块须在 `new Minder` 之前注册（`Module.register` 是全局模块池）。

### 4.2 数据来源与节点结构

文档的脑图数据以嵌套的根节点对象形式从后端获取。根节点是创建文档时自动生成的默认节点，其 `children` 数组包含用户在脑图中创建的所有子节点，每个子节点可继续嵌套。

**后端接口响应格式**（`GET /api/project/documents/:docId/nodes`）：

```json

    "id": 1,
    "parentId": null,
    "type": "normal",
    "title": "登录用例集",
    "priority": null,
    "sortOrder": 0,
    "version": 1,
    "children": [
      {
        "id": 2,
        "parentId": 1,
        "type": "case",
        "title": "邮箱登录",
        "priority": "P1",
        "sortOrder": 0,
        "version": 1,
        "children": [
          {
            "id": 3,
            "parentId": 2,
            "type": "precondition",
            "title": "用户已注册且处于登录页",
            "priority": null,
            "sortOrder": 0,
            "version": 1,
            "children": []
          },
          {
            "id": 4,
            "parentId": 2,
            "type": "step",
            "title": "输入邮箱和密码",
            "priority": null,
            "sortOrder": 1,
            "version": 1,
            "children": []
          },
          {
            "id": 5,
            "parentId": 2,
            "type": "expected",
            "title": "成功跳转到首页",
            "priority": null,
            "sortOrder": 2,
            "version": 1,
            "children": []
          }
        ]
      }
    ]
  },
  "layout": { "...": "..." }
}
```

评审快照树（`GET /api/project/reviews/:id/tree`）和计划快照树（`GET /api/project/plans/:id/tree`）的节点部分采用相同结构，额外包含 `reviewStatus`、`executionStatus`、`relatedBugIds`、`comments` 等快照特有字段。

### 4.3 kityminder 节点数据结构（统一模型）

```json
{
  "data": {
    "id": "node-uuid",
    "text": "登录用例集",
    "type": "case",
    "priority": "P2",
    "reviewStatus": { "result": "pass", "reviewer": "张三", "time": "2026-07-06T10:30:00Z" },
    "executionStatus": { "result": "pass", "executor": "李四", "time": "2026-07-05T14:20:00Z" },
    "relatedBugIds": [101, 102],
    "comments": [
      { "author": "王五", "content": "步骤需要补充", "time": "2026-07-04T09:15:00Z" }
    ]
  },
  "children": [...]
}
```

### 4.4 三种模式的数据来源与操作目标

| 模式         | 数据来源                                                  | 可编辑字段                             | 操作目标表                                                                        |
| ---------- | ----------------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------- |
| **edit**   | `GET /api/project/documents/:docId/nodes` 返回的嵌套根节点与布局 | 全部字段（type, priority, text 等）      | `test_case_node`（通过 WebSocket 异步持久化）                                         |
| **review** | `GET /api/project/reviews/:id/tree` 返回的快照节点树          | `reviewStatus`（标记）、`comments`（评论） | `test_review_node_snapshot`（更新 last_mark），`test_review_record`（新增记录）         |
| **plan**   | `GET /api/project/plans/:id/tree` 返回的快照节点树            | `executionStatus`（执行结果）           | `test_plan_node_snapshot`（更新 last_result），`test_plan_execution_record`（新增记录） |

在评审/计划模式下，`type`、`priority`、`text` 等原始用例字段为只读，来自快照表，不可通过脑图修改。评审/计划模式下的状态字段由后端在加载快照树时填充，前端提交标记后即时更新。

## 5. 工具栏设计

工具栏位于脑图画布顶部，水平居中，背景半透明磨砂，占位流式。编辑模式为两行：第一行核心编辑操作，第二行（右侧）AI 入口。各组件拥有独立的工具栏。

### 5.1 编辑（CaseMindMap）

| 按钮                | 功能                | 快捷键             | 说明      |
| ----------------- | ----------------- | --------------- | ------- |
| 标记为测试用例           | 标记为测试用例，无优先级时默认P2 | —               |         |
| 标记为前置条件           | 标记为前置条件           | —               |         |
| 标记为执行步骤           | 标记为执行步骤           | —               |         |
| 标记为预期结果           | 标记为预期结果           | —               |         |
| P0 / P1 / P2 / P3 | 设置优先级并自动标记为测试用例   | —               |         |
| ──────────        |                   |                 |         |
| 编辑内容              | 选中节点原位编辑文本        | F2 / 双击        | 光标定位到文本末端，不全选 |
| 添加子节点             | 新增子节点，默认名称"分支主题"  | Tab             |         |
| 添加兄弟节点            | 新增兄弟节点，默认名称"分支主题" | Enter           |         |
| 删除节点              | 删除选中节点            | Delete          |         |
| ──────────        |                   |                 |         |
| 撤销 / 重做           | JSON-Patch 增量撤销重做  | Ctrl+Z / Ctrl+Y（或 Ctrl+Shift+Z） | 无可撤销/重做内容时按钮置灰 |
| ──────────        |                   |                 |         |
| 布局模板下拉            | 切换 core 原生 6 模板：右侧分布(right,默认)/思维导图(default)/组织结构(structure)/目录(filetree)/鱼骨图(fish-bone)/天盘(tianpan) | — | 走 `execCommand('template')`，可撤销，随文档持久化 |
| 整理布局              | 清除全部手动拖拽偏移，恢复自动排版 | Ctrl+Shift+L | 走 core `resetlayout`，执行前先清空选区保证作用于全树 |

缩放、定位、抓手、全屏不再占用工具栏，统一由导航器提供（见 5.4）。

**标记联动规则**：

- **标记为测试用例**：`type` 设为 `case`；若 `priority` 为空，自动设为 `"P2"`。
- **标记优先级（P0-P3）**：设置 `priority` 为所选值；若 `type` 不为 `case`，自动改为 `case`。
- **标记为前置条件/步骤/预期结果**：`type` 设为对应值；`priority` 保持不变。

### 5.2 评审（ReviewMindMap）

| 按钮         | 功能                                               | 说明                   |
| ---------- | ------------------------------------------------ | -------------------- |
| ✅ 通过       | 标记通过，提交至 `POST /api/project/reviews/:id/records` | 仅 case 节点可用，高亮当前评审结果 |
| ❌ 不通过      | 标记不通过，同上                                         |                      |
| ❓ 待评审      | 清除标记，同上                                          |                      |
| 💬 评论      | 打开评论抽屉，查看/添加评论，提交至同一接口                           | 所有节点可用               |

缩放与抓手由导航器提供（见 5.4，命令均 enableReadOnly，只读态可用）。

### 5.3 计划（PlanMindMap）

| 按钮         | 功能                                             | 说明                   |
| ---------- | ---------------------------------------------- | -------------------- |
| ✅ 通过       | 标记通过，提交至 `POST /api/project/plans/:id/records` | 仅 case 节点可用，高亮当前执行结果 |
| ❌ 失败       | 标记失败，同上                                        |                      |
| ❓ 阻塞       | 标记阻塞，同上                                        |                      |
| 🔄 未执行     | 重置为未执行，同上                                      |                      |

缩放与抓手由导航器提供（见 5.4）。

### 5.4 导航器（MinderNavigator）

悬浮于画布左下角，三种模式共用（所接命令均 enableReadOnly，review/plan 只读态同样可用）；切换文档重建 minder 实例时随组件重建。

| 功能     | 实现                                                                 |
| ------ | ------------------------------------------------------------------ |
| 缩放条    | 放大/缩小按钮接 `zoomin`/`zoomout` 命令（kityminder-core 实际注册名，无连字符），滑条指示器监听 `zoom` 事件按档位（10-200）映射位置，点击原点回到 100% |
| 定位根节点  | `execCommand('camera', root, 600)` 平滑移动视野到根节点                        |
| 抓手     | core 原生 `hand` 命令，监听 `statuschange` 事件同步激活态高亮                        |
| 缩略图    | kity.Paper 缩略渲染（节点盒 + 连线路径 + 红框可视区域），监听 `layout`/`viewchange` 增量更新；点击/拖动缩略图移动画布视野；可开关，状态记忆于 localStorage |
| 全屏     | 原生 Fullscreen API 对脑图容器全屏（保留工具栏），零新增依赖                             |

## 6. 右键菜单设计

右键菜单仅在选中节点时展示（右键节点时先选中再弹出，空白处右键不弹菜单）；编辑模式下也可对选中节点按空格键唤醒，菜单定位到节点下方。关闭时机：点击菜单项、点击菜单外任意位置、按 Esc、滚轮滚动（视图变化后菜单会错位）；鼠标划过离开菜单不关闭。

### 6.1 编辑模式

- 编辑内容
- 新建子节点（默认名称"分支主题"）
- 新建兄弟节点（默认名称"分支主题"）
- ──────────
- 标记类型 ▸ 普通 / 前置条件 / 执行步骤 / 预期结果 / 测试用例
- 标记优先级 ▸ P0 / P1 / P2 / P3 / 清除优先级
- ──────────
- 删除节点

### 6.2 评审模式

- 标记评审结果 ▸ 通过 / 不通过 / 待评审
- 添加评论
- ──────────
- 查看详情

### 6.3 计划模式

- 标记执行结果 ▸ 通过 / 失败 / 阻塞 / 未执行
- ──────────
- 查看详情

只读快照状态下仅显示“查看详情”。

## 8. 关联 Bug 链接标签

- **显示条件**：节点 `data.relatedBugIds` 不为空，且至少含有一个有效 Bug ID。
- **渲染位置**：在节点文本下方，水平排列多个可点击的链接标签。
- **标签样式**：小型标签，浅红色背景，文字为 `#101` 形式，悬停时背景加深并显示手型光标。
- **点击行为**：调用 `window.open('/workspace/projects/bugs/' + bugId, '_blank')` 在新标签页打开 Bug 详情页。点击事件必须调用 `event.stopPropagation()` 防止触发节点选中。
- **数据来源**：编辑模式从 `test_case_node` 表关联查询获得；评审/计划模式从快照表的冗余字段获得。
- **实现方式**：扩展 kityminder 的节点渲染模板，使用 SVG `foreignObject` 嵌入 HTML 标签，并绑定点击事件。

## 10. 初始化加载流程

### 10.1 编辑模式加载

1. 用户点击模块树中的文档节点。
2. 前端调用 `GET /api/project/documents/:docId/nodes`，获取嵌套的根节点对象和布局 JSON（`{ template, offsets }`）。
3. 前端将嵌套的根节点对象转换为 kityminder 所需的 JSON 格式（根节点作为画布中心节点，其 children 递归展开），并按 offsets 把各节点的 layout_*_offset 偏移回填进节点 data。
4. 使用 `minder.importJson(json)` 渲染脑图，应用布局 JSON 中的模板（缺省 right）与节点偏移。
5. 建立 WebSocket 连接，加入文档房间。

### 10.2 评审模式加载

1. 用户进入评审详情页。
2. 前端调用 `GET /api/project/reviews/:id/tree`，获取裁剪后的快照树（嵌套根节点对象格式）。
3. 转换为 kityminder JSON 渲染只读脑图。
4. 工具栏切换为评审操作按钮。
5. 不建立 WebSocket 连接，标记和评论通过 HTTP 提交。

### 10.3 计划模式加载

1. 用户进入计划详情页。
2. 前端调用 `GET /api/project/plans/:id/tree`，获取裁剪后的快照树（嵌套根节点对象格式）。
3. 转换为 kityminder JSON 渲染只读脑图。
4. 工具栏切换为执行操作按钮。
5. 不建立 WebSocket 连接，执行结果通过 HTTP 提交。

## 11. 实时协作设计（基于 Yjs）

### 11.1 协作数据模型

- 使用单个 Y.Doc 存储文档状态，`ydoc.getMap('mindmap')` **按节点分片**存储，保证 CRDT 合并与网络传输的粒度为单个节点：
  - `n:<nodeId>`：节点数据快照（kityminder `node.data` 全量字段：text/type/priority/aiGenerated/expandState/自由拖拽偏移等）；
  - `order`：嵌套 `Y.Map<父节点id, Y.Array<子节点id>>`，维护各父节点下的兄弟顺序；
  - `root` / `template` / `theme`：根节点 id 与布局模板标量键。
- 本地 `contentchange` 后，将画布 `exportJson()` 结果与 Yjs 当前分片状态做树级 diff，**仅写入变化的分片**（单 `transact` 原子提交），网络只传输增量而非全量 JSON。

### 11.2 冲突处理与远端回放

- CRDT 合并粒度 = 节点分片：不同节点的并发编辑互不覆盖；同一节点字段的并发修改以最后写入胜出；同一父节点下的并发结构变更由 `Y.Array` 位置合并算法收敛。
- 远端事务经 `observeDeep` 通知后，从分片重建目标 JSON，与本地画布树**按节点 id 对齐 diff**，翻译为内核原语增量应用（`setText`/`setData`/`createNode`/`removeNode`/`useTemplate`），全程不整树重建、保留选中态与视口；diff 无法对齐（如根节点不一致）或应用异常时，兜底回退 `importJson` 全量重建。
- 内核无原子 move 原语，移动类结构变更以「摘除 + 重插」表达，仅重建被移动子树的 DOM。

### 11.3 协作感知

- 通过 `y-websocket` 连接到 `/ws/documents/{docId}`，服务端广播 Yjs 更新。
- 其他用户的光标/选中节点通过 Yjs Awareness 协议共享，在脑图上渲染彩色光标。
- 在线用户头像显示在顶部工具栏右侧。

### 11.4 编辑模式保存

编辑模式下不通过 HTTP 接口手动保存。Yjs 二进制帧仅做实时协同转发、不落库；节点增删改经同一 WebSocket 连接的 JSON 文本帧（`add_node`/`update_attrs`/`move_node`/`delete_node`/`update_layout`）提交，后端 `DocumentPersistenceHandler` 与数据库现有节点差异化比对后更新 `test_case_node` 表，并整体 upsert `test_case_document.layout` JSON 列。远端变更由发起方负责落库，接收端仅对齐本地 diff 基线，不重复提交。

## 14. 实施要点

1. **组件选用**：页面按业务直接使用对应组件并传入 ID（CaseMindMap→docId、ReviewMindMap→reviewId、PlanMindMap→planId），各组件加载各自数据源。
2. **数据加载**：编辑模式调用文档节点接口获取嵌套根节点对象；评审/计划模式调用快照树接口获取相同结构的数据。前端将嵌套对象转换为 kityminder JSON 后渲染。
3. **数据隔离**：编辑模式与快照模式使用不同的 Yjs 房间或禁用协作（快照模式下无需实时同步，标记通过 HTTP 提交）。
4. **权限控制**：评审模式仅参与者可标记/评论；计划模式仅负责人/执行人可标记结果。前端通过传入的 `editable` 标记控制，后端接口校验。
5. **kityminder 扩展**：自定义节点渲染模板，显示 Bug 链接标签、评审/执行图标；使用 `foreignObject` 嵌入 HTML 元素。类型/优先级彩色徽标由 badges.ts 以 `Module.register` 自定义渲染模块实现（写法参照 core 自身 priority 模块），须在 `new Minder` 之前注册。
6. **工具栏状态响应**：监听 kityminder 的 `selectionchange` 事件，更新按钮高亮；撤销/重做按钮置灰态由 history 的 onChange 回调驱动。
7. **右键菜单**：仅选中节点时展示（编辑模式下空格键亦可唤醒），根据当前模式动态渲染菜单项。
8. **抓手模式**：接 core 原生 `hand` 命令（enableReadOnly，只读态可用），由导航器切换并监听 `statuschange` 同步激活态。
9. **原位编辑接入**：编辑内核创建 minder 时传 `enableKeyReceiver: false` 禁用 core 内置接收器，由 receiver.ts 的 contenteditable 元素统一接管键盘；命令执行后 `fire('receiverfocus')` 保证快捷键持续可用。
10. **WebSocket 持久化**：后端接收到 Yjs 更新后，递归解析嵌套的文档 JSON 树，比对数据库现有节点，执行新增、更新、删除操作，并更新布局。布局（模板 + 节点偏移）由前端 diff 后经 `update_layout` 文本帧 `{ type, payload: { template, offsets } }` 整体 upsert 到 `test_case_document.layout` JSON 列。
11. **Bug 链接跳转**：点击关联 Bug 标签时，以新窗口打开缺陷详情页，路径为 `/workspace/projects/bugs/:bugId`。
