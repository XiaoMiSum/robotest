## 1. 引言

### 1.1 编写目的

本文档对接口测试业务域的 **接口测试报告**进行详细设计，定义报告生成、分享、批量删除、状态同步、清理的业务逻辑与前端行为，为开发实现提供完整依据。报告的数据表（`api_report`）与报告接口（列表、详情、分享、删除）在《API 测试基础设施详细设计说明书》中定义，本文档不重复描述。Mock 服务相关设计见《Mock 服务详细设计说明书》（`docs/详细设计/Mock服务详细设计说明书.md`）。

## 2. 数据设计

### 2.1 数据库表设计

#### 2.1.1 报告表（api_report）

报告表（`api_report`）的完整字段定义、索引与说明见《API 测试基础设施详细设计说明书》2.1.4，此处不重复描述。本文档涉及的关键字段：

| 字段 | 说明 |
| ---- | ---- |
| id | 报告主键 |
| project_id | 归属项目 |
| execution_record_id | 关联执行记录（api_execution_record.id）。场景报告 1:1；套件报告对应多条执行记录，此字段为空 |
| report_type | 报告粒度：`scene`（场景报告，单场景）/ `suite`（套件报告，定时任务含立即执行聚合多场景） |
| external_id | 外部关联 ID，随 `report_type`：`suite` = 任务 ID；`scene` = 场景 ID |
| name | 报告名称（场景报告 = 场景名 + 执行时间戳；套件报告 = 任务名 + 执行时间戳，生成时固化） |
| execution_mode | 执行方式：platform（平台内执行） |
| status | success / failed / partial（场景报告）；套件报告按整体判定 |
| source | 报告来源：scene / schedule |
| summary | 结果汇总（场景报告 `{total, passed, failed, skipped, duration_ms}`；套件报告含场景级汇总，见 2.3） |
| result | 结果明细数据集（场景数据集 / 套件数据集，字段结构见 2.3） |
| ryze_snapshot | 执行时的 Ryze 结果树序列化快照 |
| share_token | 分享链接令牌 |
| share_expires_at | 分享链接过期时间 |
| share_user_id | 生成分享链接的用户（分享者），用于分享记录展示与复制文本 |

**结果数据集**：`api_report.result` 按 `report_type` 存储场景/套件两种数据集，字段结构见 **2.3 结果数据集模型**（含步骤状态枚举、验证器明细、提取器结果结构）。

**索引**：见《API 测试基础设施详细设计说明书》2.1.4（`idx_report_type_external`、`idx_report_project_created`、`idx_report_share_token` UNIQUE、`idx_report_share_user`）。

> `idx_report_share_token` 支撑分享访问按 token 查询（见 4.2.2）。

#### 2.1.2 全局资产表（global_asset）

全局资产表（`global_asset`）的字段定义见《API 测试基础设施详细设计说明书》2.1.5。

### 2.2 错误码引用

| 错误码 | 常量名 | 说明 | 定义位置 |
| ------ | ------ | ---- | -------- |
| **7009** | API_SHARE_EXPIRED | 分享链接无效或已过期 | 《API 测试基础设施详细设计说明书》2.2 |

> 权限不足（非执行者本人且非项目维护者）返回 HTTP 403，不占用业务错误码号段。

### 2.3 结果数据集模型

`api_report.result`（JSONB）按 `report_type` 存储两类数据集，均由执行引擎基于 **Ryze 结果树**（`io.github.xiaomisum.ryze`，见 `D:\Github\ryze\docs\developer\result.md`）构建：`SampleResult` → 步骤，`AssertionResult` → 验证器，`ExtractorResult` → 提取器。`result` 本身为平台结构化视图，**不包含** ryze 快照（快照独立存于 `api_report.ryze_snapshot`）。

#### 2.3.1 场景数据集（report_type = 'scene'）

单个场景执行结果的平面化结构：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| sceneId | UUID | 场景 ID（external_id） |
| sceneName | String | 场景名称快照 |
| status | String | success / failed / partial / cancelled |
| summary | Object | 见下文场景汇总 |
| environmentName | String/null | 环境名称快照 |
| executedAt | String | 执行时间（ISO-8601 UTC） |
| steps | Array | 步骤明细（见步骤元素） |
| preprocessors | Array | 场景前置处理器执行明细（元素形状同步骤元素，渲染规则复用步骤明细；无处理器时为空数组） |
| postprocessors | Array | 场景后置处理器执行明细（元素形状同步骤元素；无处理器时为空数组） |

**场景汇总** `summary`：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| total | int | 启用步骤总数 |
| passed | int | 通过数（所有验证器通过） |
| failed | int | 失败数（任一验证器失败） |
| skipped | int | 跳过数（禁用/后续跳过） |
| durationMs | long | 执行耗时 |

**步骤元素**（`steps[]`，对应 ryze `SampleResult`）：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| stepId | String | 步骤 ID（平台步骤 ID） |
| name | String | 步骤名称 |
| type | String | 协议类型（HTTP / JDBC / Redis / WebSocket / …，取请求元数据） |
| status | String | passed / failed / skipped / not_executed |
| durationMs | long | 步骤耗时 |
| request | Object | 请求快照（Real*Request 按协议 getter 序列化，如 url/method/query/headers/body/format） |
| response | Object | 响应快照（Real*Response 按协议 getter 序列化，如 status/headers/body/format/bodyBytes 截断） |
| assertions | Array | 验证器明细（AssertionResult） |
| extractors | Array | 提取器明细（ExtractorResult） |
| errorMessage | String/null | 异常/失败信息 |

**验证器明细**（`assertions[]`）：`{field, rule, expected, actual, status, message}`——验证字段、规则（`==`/`contains` 等）、期望值（已求值）、实际值、状态（passed/failed/skipped）、失败消息。

**提取器明细**（`extractors[]`）：`{refName, field, value, defaultValue|boolean, message}`——变量名、提取表达式（JSONPath/正则）、提取值、是否走默认值分支、失败信息。

#### 2.3.2 套件数据集（report_type = 'suite'）

定时任务（含立即执行）执行多个场景聚合生成，内嵌多个场景形成「场景 → 步骤」两级：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| reportType | String | 固定 `suite` |
| taskId | UUID | 关联任务 ID（external_id） |
| taskName | String | 任务名称快照（报告名称来源） |
| source | String | 报告来源：schedule（定时任务含立即执行） |
| status | String | success / failed / partial——任一场景 failed 则整体 failed |
| summary | Object | 见下文套件汇总 |
| environmentName | String/null | 环境名称快照（任务绑定环境） |
| triggeredAt | String | 触发时间（ISO-8601 UTC） |
| scenes | Array | 场景明细数组，每项即 **2.3.1 场景数据集** |
| preprocessors | Array | 环境前置处理器执行明细（任务绑定环境处理器，挂顶层 suite 执行一次；元素形状同步骤元素） |
| postprocessors | Array | 环境后置处理器执行明细（任务绑定环境处理器，挂顶层 suite 执行一次；元素形状同步骤元素） |

**套件汇总** `summary`：

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| totalScenes | int | 执行场景总数 |
| passedScenes | int | 通过场景数 |
| failedScenes | int | 失败场景数 |
| totalSteps | int | 全部场景启用步骤总数 |
| passedSteps | int | 通过步骤总数 |
| failedSteps | int | 失败步骤总数 |
| skippedSteps | int | 跳过步骤总数 |
| durationMs | long | 一次触发总耗时 |

> 套件数据集（report_type='suite'）通过 `external_id`（任务 ID）与共享 `report_id` 关联各场景执行记录；报告列表一行一报告（名称 = 任务名 + 执行时间戳）。

## 3. 接口详细设计

报告基础接口（报告列表、详情、生成分享链接、访问分享报告、删除）见《API 测试基础设施详细设计说明书》3.4，本文档不重复描述。本文档补充列表筛选参数、批量删除与状态刷新接口。

### 3.1 报告列表筛选参数

`GET /api/project/reports` 在《API 测试基础设施详细设计说明书》3.4.1 基础上补充以下筛选参数：

| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| executionMode | string | 否 | 执行方式筛选：platform |
| reportType | string | 否 | 报告粒度筛选：scene / suite |
| keyword | string | 否 | 搜索关键字：模糊匹配报告名称（场景报告的场景名 / 套件报告的任务名） |

**列表范围**：场景页 [运行] 直接产生的报告（`source = 'scene'`、`report_type = 'scene'`）不进列表；定时任务（含调度页"立即执行"，`source = 'schedule'`，聚合为套件报告）正常展示。列表查询按 `source` 过滤（见《API 测试基础设施详细设计说明书》3.4.1）。

列表响应在 3.4.1 基础上补充字段：

| 字段 | 说明 |
| ---- | ---- |
| name | 报告名称（场景报告：场景名 + 执行时间戳；套件报告：任务名 + 执行时间戳） |
| reportType | 报告粒度：scene / suite |
| sceneName | 场景报告时场景名称快照；套件报告为 null |

### 3.2 批量删除报告

- **路径**：`POST /api/project/reports/batch-delete`
- **请求体**：

```json
{
  "ids": ["018f...", "019a..."]
}
```

- **响应**：`{ "success": true }`
- **权限**：项目维护者。

### 3.3 刷新报告状态

- **路径**：`POST /api/project/reports/:id/refresh`
- **说明**：报告状态为 `pending_sync` 时调用，重新拉取执行结果并更新报告状态与汇总；成功后状态更新为 `success` / `failed` / `partial`。
- **响应**：更新后的报告状态与汇总。
- **权限**：执行者本人或项目维护者。

## 4. 业务逻辑设计

### 4.1 报告生成

- 场景报告（`source = 'scene'`）：场景执行完成后由执行引擎生成，`report_type = 'scene'`，`result` 存场景数据集：

1. **步骤级结果收集**：从 Ryze 结果树收集每个步骤的请求/响应快照（Real* 序列化）、验证器结果、提取器结果、耗时。
2. **结果汇总计算**：总步骤数、通过数、失败数、跳过数、总耗时。
3. **报告写入**：`report_type='scene'`、`external_id` = 场景 ID、`name` = 场景名 + 执行时间戳，`result` 填充场景数据集，同时更新 `api_execution_record.report_id`。
4. **Ryze 快照保存**：平台内执行时保存序列化后的完整 Ryze 结果树至 `api_report.ryze_snapshot`。

- 套件报告（`source = 'schedule'`）：测试计划任务（含立即执行）执行多个场景后聚合生成，`report_type = 'suite'`，`result` 存套件数据集：

1. **场景结果收集**：遍历本次执行各场景的最终结果（各场景执行记录已生成）。
2. **套件汇总计算**：场景数、通过/失败场景数、全部场景步骤总数与通过/失败/跳过数、总耗时。
3. **报告写入**：`report_type='suite'`、`external_id` = 任务 ID、`name` = 任务名 + 执行时间戳，`result` 的 `scenes[]` 填充各场景数据集；将该套件报告 ID 回写至本套件内各场景执行记录的 `report_id`（共享）。
4. **Ryze 快照保存**：平台内执行时聚合生成套件树序列化至 `ryze_snapshot`。

**报告状态判定**：
- 场景报告：
  - `success`：所有启用步骤的所有验证器均通过。
  - `failed`：任一验证器失败或引擎异常。
  - `partial`：部分步骤被跳过（disabled），其余通过。
- 套件报告：
  - `success`：全部场景通过。
  - `failed`：任一场景失败。
  - `partial`：有场景部分通过且无失败场景。

**验证器解析失败规则**：验证器表达式解析失败按验证失败处理，该验证器 `result = failed` 并在 `error` 字段记录解析错误信息；报告状态判定不受影响（仍按任一验证器失败计为 `failed`）。

### 4.2 分享机制

#### 4.2.1 分享链接生成

分享不设全局开关，具备报告查看/分享权限（`api-report:view`）的成员即可生成；有效期在生成时选择（参照邀请链接的过期时间选择），`expiresInDays` 缺省 7 天。

1. 校验当前用户具备报告查看/分享权限（非执行者本人需为项目维护者，见 4.4）。
2. 生成唯一 `share_token`（UUID v4，32 字符十六进制）。
3. 设置过期时间（`share_expires_at = now + expiresInDays`，缺省 7 天）。
4. 记录分享者 `share_user_id = currentUser`（部分更新，不整行覆盖）。
5. 返回完整分享 URL 与 `shareBy`（分享者 username）。

> **复用已有分享**：生成接口本身每次重新生成 token 并覆盖旧记录；前端在打开分享弹窗时优先复用**未过期**的现有分享——报告详情接口携带 `share`（`{shareUrl, expiresAt, shareBy}`，未过期才返回，否则 `null`），弹窗直接展示记录并提供 [复制]；仅在无分享/已过期时走生成流程，[重新生成] 按钮显式覆盖旧分享（含分享者更新为当前用户）。

#### 4.2.2 分享访问校验

1. 通过 `share_token` 查询报告（`idx_report_share_token` 唯一索引）。
2. 校验 `share_expires_at > now`，未匹配/已过期统一返回错误码 7009（`API_SHARE_EXPIRED`）。
3. 校验报告未被删除。
4. 返回报告内容（场景报告返回场景数据集；套件报告返回套件数据集，不含 Ryze 快照）。

#### 4.2.3 分享记录展示与复制

- 详情接口（`GET /api/project/reports/:id`）响应在存在未过期分享时附带 `share`：`{shareUrl, expiresAt, shareBy}`。
- 分享弹窗打开时有未过期分享 → 直接展示记录（分享链接、有效期至、分享人）+ [复制]，不重复生成。
- [复制] 写入剪贴板的为带描述文本，包含报告名称、链接、有效期、分享者：

```
【测试报告分享】
报告名称：{报告名称}
分享链接：{完整 URL（站点前缀 + shareUrl）}
有效期至：{share_expires_at 本地时间}
分享人：{shareBy}
```

- 无未过期分享 → 弹窗两步式（选有效期 → 生成），生成成功即落盘（详情接口的 `share` 随刷新返回）。

### 4.3 报告清理

复用《API 测试基础设施详细设计说明书》4.3 定义的数据清理策略：
- 报告与执行记录保留期限默认 90 天（系统配置项）。
- 清理后执行记录保留元数据，报告详情置为「执行结果被清理」。
- `api_report.ryze_snapshot` 随报告一起清理。

### 4.4 权限设计

报告按项目隔离，权限规则：

| 操作 | 权限 |
| ---- | ---- |
| 查看 / 分享 / 刷新状态 | 执行者本人或项目维护者 |
| 删除 / 批量删除 | 项目维护者 |

**403 处理**：非执行者本人且非项目维护者访问报告接口返回 HTTP 403；前端展示 403 页面「无权限访问该报告」。

### 4.5 场景执行记录弹窗查看报告

场景页执行记录中的 [报告] 按钮不再跳转报告页，改为在弹窗中直接展示报告明细（`GET /api/project/reports/:id`）：

- 场景页 [运行] 产生的报告（`source = 'scene'`，`report_type = 'scene'`）虽不进报告列表，但可通过执行记录弹窗查看。
- 弹窗内容与场景报告详情一致：Hero 概览、统计卡、场景卡（处理器 Tab + 步骤卡，展开查看请求/响应快照、验证器明细、提取器结果）。
- 定时任务的场景执行记录（共享套件报告）：弹窗展示该记录的步骤明细（从套件数据集 `result.scenes[]` 按 `sceneId` 定位），并提供「查看完整套件报告」跳转套件详情。

## 5. 前端设计

### 5.1 报告查看页

- **报告列表**：分页、筛选（状态/报告类型/执行方式/时间范围）、搜索（报告名称关键字）。
  - 列表列：报告名称（场景报告：场景名 + 时间戳；套件报告：任务名 + 时间戳）、报告类型、状态、通过率、耗时、创建时间、操作。
  - 状态列：通过（绿）/ 失败（红）/ 部分通过（黄）。
  - 批量操作：勾选后批量删除（二次确认）。
  - 列表仅展示定时任务报告（scene 报告不进列表，见 3.1）；场景页 [运行] 直接产生的报告通过场景执行记录弹窗查看（见 4.5）。
- **报告详情**（统一由 `ReportResultView.vue` 渲染，接收报告详情与可选 `focusSceneId`，内部复用处理器区组件与步骤卡组件；详情页/分享页/执行记录弹窗三者复用同一套展示）：
  - **顶部概览（Hero）**：渐变淡绿卡片——报告名称 + 状态章（执行成功/失败）+ 来源章（定时任务/平台内执行）；元信息：环境、执行/触发时间、总耗时、场景 ID / Task ID（等宽）。
  - **执行概览（5 项统计卡）**：场景报告与套件定位单场景为步骤口径（总步骤/通过/失败/通过率/总耗时）；套件报告整体为场景口径（场景总数/通过场景/失败场景/通过率/总耗时）。
  - **处理器 Tab**（环境级/场景级复用 `ReportProcessorsTabs.vue`）：前置/后置 Tab（数量角标 + 状态圆点）+ 执行顺序提示链 + 处理器小卡（可折叠，含请求头表、Query/请求体/响应体格式化 code、提取器表）。
  - **步骤卡**（`ReportStepCard.vue`）：序号、名称、方法 chip、状态徽标、耗时、验证器数（失败红）；展开含请求块（方法+URL、请求头表、Query/请求体）、响应块（状态码、HTTP 版本·Content-Type·耗时、响应体、响应头表）、验证器表、提取器表；失败/错误步骤默认展开，提供「全部展开/收起」。
  - **场景输出**：
    - 场景报告：Hero + 统计卡 + 单场景卡（默认折叠：mini 统计 + 场景处理器 Tab + 步骤区）。
    - 套件报告：Hero + 场景口径统计卡 + 环境处理器卡（任务前置/后置）+ 场景卡列表（自上而下平铺，含「查看完整套件 / 返回当前场景」定位）。
  - 组件职责：`ReportResultView.ts` 编排数据，`ReportProcessorsTabs.ts` / `ReportStepCard.ts` 纯展示（颜色语义引用视觉设计 CSS 变量）。
- **分享操作**：[分享] 按钮位于 Hero 右上角（始终可用，权限不足由后端返回 403）。打开弹窗时若报告存在**未过期分享**（详情接口 `share` 非空）→ 直接展示现有记录（分享链接、有效期至、分享人）+ [复制]；复制内容为带描述文本（报告名称/链接/有效期/分享人，见 4.2.3）。无未过期分享 → 弹窗两步式（选有效期，缺省 7 天 → 生成链接），生成后展示并支持复制；[重新生成] 显式覆盖旧分享。
- **刷新操作**：报告行内 [刷新]，按钮 loading → 调用刷新接口（见 3.3）→ 成功后更新状态徽标。

### 5.2 执行记录弹窗查看报告

场景执行记录中的 [报告] 按钮打开弹窗（复用 5.1 `ReportResultView.vue`：Hero + 统计卡 + 场景卡/环境处理器），弹窗内调用报告详情接口（见 4.5）。场景报告展示单场景步骤；套件执行记录弹窗从套件数据集定位该场景展示，并提供「查看完整套件报告」入口。报告详情渲染的通用前端约定见《API 测试基础设施详细设计说明书》5.2。
