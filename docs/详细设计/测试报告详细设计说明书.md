## 1. 引言

### 1.1 编写目的

本文档对软件测试平台 V1.2 接口测试业务域的 **接口测试报告**进行详细设计，定义报告生成、分享、导出、批量操作、状态同步、清理的业务逻辑与前端行为，为开发实现提供完整依据。报告的数据表（`api_report`）与报告接口（列表、详情、分享、导出、删除）在《API 测试基础设施详细设计说明书》中定义，本文档不重复描述。Mock 服务相关设计见《Mock 服务详细设计说明书》（`docs/详细设计/Mock服务详细设计说明书.md`）。

- **接口测试报告**：报告列表与详情、分享链接、导出（JSON/HTML）、批量导出/批量删除、状态刷新、报告清理；
- **全局资产**：项目级可复用组件资产库（前置处理器、后置处理器、验证器、提取器）的管理与复制（表结构与接口见《API 测试基础设施详细设计说明书》2.1.5 与 3.5–3.6）。

## 2. 数据设计

### 2.1 数据库表设计

#### 2.1.1 报告表（api_report）

报告表（`api_report`）的完整字段定义、索引与说明见《API 测试基础设施详细设计说明书》2.1.4，此处不重复描述。本文档涉及的关键字段：

| 字段 | 说明 |
| ---- | ---- |
| id | 报告主键 |
| project_id | 归属项目 |
| execution_record_id | 关联执行记录（api_execution_record.id，1:1） |
| name | 报告名称（场景名 + 执行时间戳，生成时固化） |
| scene_name | 场景名称快照（执行时固化） |
| execution_mode | 执行方式：platform（平台内执行）/ pipeline（仓库流水线执行） |
| status | success / failed / partial / pending_sync（结果待同步，流水线执行时初始状态） |
| summary | 结果汇总 `{total, passed, failed, skipped, duration_ms}` |
| step_results | 步骤级结果明细数组 `[{stepId, name, type, status, request, response, duration_ms, validators, extractors, assertions}]` |
| ryze_snapshot | 执行时的 Ryze 标准 JSON 快照（仅平台内执行保留） |
| share_enabled | 分享是否开启 |
| share_token | 分享链接令牌 |
| share_expires_at | 分享链接过期时间 |

**步骤状态枚举**（`step_results[].status`）：

| 状态 | 说明 |
| ---- | ---- |
| passed | 通过：所有验证器通过 |
| failed | 失败：任一验证器失败 |
| skipped | 跳过：步骤被禁用（disabled） |
| not_executed | 未执行：步骤未执行（如前置步骤失败导致后续步骤未执行） |

**断言明细结构**（`step_results[].assertions[]`）：

| 字段 | 说明 |
| ---- | ---- |
| name | 断言描述（验证器配置的断言描述） |
| target | 验证目标：返回码 / JSON 字段 / 响应头 / 响应体 / 正则匹配 / XPath / Groovy 脚本 |
| expression | 表达式（JSONPath / XPath / 正则 / 响应头名，视目标而定） |
| condition | 比较条件：等于 / 不等于 / 大于 / 小于 / 大于等于 / 小于等于 / 包含 / 不包含 / 以...开头 / 以...结尾 / 匹配正则 |
| expected | 期望值 |
| actual | 实际值 |
| result | 结果：passed / failed |
| error | 解析错误信息（断言表达式解析失败时记录，按断言失败处理） |

**提取器结果结构**（`step_results[].extractors[]`）：

| 字段 | 说明 |
| ---- | ---- |
| name | 提取的变量名 |
| value | 提取的变量值 |

**索引**：`idx_report_scene_id` (scene_id)、`idx_report_project_created` (project_id, created_at DESC)、`idx_report_share_token` UNIQUE (share_token) WHERE share_token IS NOT NULL

> `idx_report_share_token` 支撑分享访问按 token 查询（见 4.2.2）。

#### 2.1.2 全局资产表（global_asset）

全局资产表（`global_asset`）的字段定义见《API 测试基础设施详细设计说明书》2.1.5。

### 2.2 错误码引用

| 错误码 | 常量名 | 说明 | 定义位置 |
| ------ | ------ | ---- | -------- |
| **7008** | API_SHARE_NOT_ENABLED | 报告分享未开启 | 《API 测试基础设施详细设计说明书》2.2 |
| **7009** | API_SHARE_EXPIRED | 分享链接已过期 | 《API 测试基础设施详细设计说明书》2.2 |

> 权限不足（非执行者本人且非项目维护者）返回 HTTP 403，不占用业务错误码号段。

## 3. 接口详细设计

报告基础接口（报告列表、详情、生成分享链接、访问分享报告、导出、删除）见《API 测试基础设施详细设计说明书》3.4，本文档不重复描述。本文档补充列表筛选参数、批量操作与状态刷新接口。

### 3.1 报告列表筛选参数

`GET /api/project/reports` 在《API 测试基础设施详细设计说明书》3.4.1 基础上补充以下筛选参数：

| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| executionMode | string | 否 | 执行方式筛选：platform / pipeline |
| keyword | string | 否 | 搜索关键字：模糊匹配报告名称或场景名称 |

列表响应在 3.4.1 基础上补充字段：

| 字段 | 说明 |
| ---- | ---- |
| name | 报告名称（场景名 + 执行时间戳） |
| pipelineUrl | 流水线链接（pipeline 执行时返回，取自执行记录） |

### 3.2 批量导出报告

- **路径**：`POST /api/project/reports/batch-export`
- **请求体**：

```json
{
  "ids": ["018f...", "019a..."],
  "format": "json"
}
```

- **说明**：`format` 支持 `json` / `html`；响应为打包下载文件（zip）。
- **权限**：执行者本人或项目维护者。

### 3.3 批量删除报告

- **路径**：`POST /api/project/reports/batch-delete`
- **请求体**：

```json
{
  "ids": ["018f...", "019a..."]
}
```

- **响应**：`{ "success": true }`
- **权限**：项目维护者。

### 3.4 刷新报告状态（结果待同步）

- **路径**：`POST /api/project/reports/:id/refresh`
- **说明**：报告状态为 `pending_sync`（流水线执行）时调用，重新拉取流水线执行结果并更新报告状态与汇总；成功后状态更新为 `success` / `failed` / `partial`。
- **响应**：更新后的报告状态与汇总。
- **权限**：执行者本人或项目维护者。

## 4. 业务逻辑设计

### 4.1 报告生成

场景执行完成后，执行引擎生成报告：

1. **步骤级结果收集**：每个步骤的请求/响应快照、验证器结果、提取器结果、耗时。
2. **结果汇总计算**：总步骤数、通过数（所有验证器通过）、失败数（任一验证器失败）、跳过数（步骤 disabled）、总耗时。
3. **报告写入**：将结果写入 `api_report` 表，同时更新 `api_execution_record.report_id`。
4. **Ryze 快照保存**：平台内执行时保存完整 Ryze JSON 至 `api_report.ryze_snapshot`。

**报告状态判定**：
- `success`：所有启用步骤的所有验证器均通过。
- `failed`：任一验证器失败。
- `partial`：部分步骤被跳过（disabled），其余通过。
- `pending_sync`：流水线执行时报告生成后的初始状态（结果待同步），待刷新接口（见 3.4）拉取流水线结果后更新为终态。

**断言解析失败规则**：断言表达式解析失败按断言失败处理，该断言 `result = failed` 并在 `error` 字段记录解析错误信息；报告状态判定不受影响（仍按任一验证器失败计为 `failed`）。

### 4.2 分享机制

#### 4.2.1 分享链接生成

1. 校验项目设置中是否开启分享功能（未开启返回错误码 7008；项目设置读写见《项目设置详细设计说明书》）。
2. 生成唯一 `share_token`（UUID v4，32 字符十六进制）。
3. 设置过期时间（`share_expires_at = now + expiresInDays`）。
4. 返回完整分享 URL。

#### 4.2.2 分享访问校验

1. 通过 `share_token` 查询报告（`idx_report_share_token` 唯一索引）。
2. 校验 `share_expires_at > now`，过期返回错误码 7009（`API_SHARE_EXPIRED`）。
3. 校验报告未被删除。
4. 返回报告内容（步骤级结果，不含 Ryze 快照）。

### 4.3 导出

#### 4.3.1 JSON 导出

将报告完整内容导出为 JSON 文件，包含：
- 报告元数据（场景名称、执行时间、环境、状态）。
- 结果汇总。
- 步骤级结果明细（请求/响应快照）。

#### 4.3.2 HTML 导出

生成独立 HTML 文件（内联 CSS，不依赖外部资源），包含：
- 报告头部信息（场景名称、执行时间、状态、环境）。
- 结果汇总卡片（通过/失败/跳过/耗时）。
- 步骤列表（可折叠展开），每步展示：名称、状态、请求/响应、验证器结果。
- 支持打印友好样式。

### 4.4 报告清理

复用《API 测试基础设施详细设计说明书》4.3 定义的数据清理策略：
- 报告与执行记录保留期限默认 90 天（系统配置项）。
- 清理后执行记录保留元数据，报告详情置为「执行结果被清理」。
- `api_report.ryze_snapshot` 随报告一起清理。

### 4.5 权限设计

报告按项目隔离，权限规则：

| 操作 | 权限 |
| ---- | ---- |
| 查看 / 分享 / 导出 / 刷新状态 | 执行者本人或项目维护者 |
| 删除 / 批量删除 | 项目维护者 |

**403 处理**：非执行者本人且非项目维护者访问报告接口返回 HTTP 403；前端展示 403 页面「无权限访问该报告」。

## 5. 前端设计

### 5.1 报告查看页

- **报告列表**：分页、筛选（状态/场景/执行方式/时间范围）、搜索（报告名称/场景名称关键字）。
  - 列表列：报告名称（场景名 + 执行时间戳）、场景名称、状态、通过率、耗时、创建时间、操作。
  - 状态列：通过（绿）/ 失败（红）/ 部分通过（黄）；流水线执行展示来源标记与流水线链接；结果待同步展示「结果待同步」+ [刷新]。
  - 批量操作：勾选后批量导出（打包下载）、批量删除（二次确认）。
- **报告详情**：
  - 头部：报告名称、场景名称、执行时间、环境、状态、耗时、执行方式。
  - 汇总卡片：通过/失败/跳过数字。
  - 步骤结果表：序号、步骤名称、接口、状态、耗时、断言、操作；点击行展开请求/响应快照、提取器结果、断言明细。
  - 断言明细：每条断言的字段、规则、期望值、实际值、结果；失败项红色高亮并展示解析错误提示。
  - 提取器结果：提取的变量名与值。
- **分享操作**：生成分享链接按钮（默认禁止时按钮禁用，提示需管理员开启）。
- **导出操作**：选择导出格式（JSON/HTML），下载文件。
- **刷新操作**：状态为「结果待同步」的报告行内 [刷新]，按钮 loading → 调用刷新接口（见 3.4）→ 成功后更新状态徽标。

> 报告详情渲染的通用前端约定见《API 测试基础设施详细设计说明书》5.2。

## 6. 实施说明

### 6.1 HTML 报告模板

HTML 报告使用内联 CSS 的静态模板（Thymeleaf 或手写字符串模板），不依赖外部 CDN。模板包含：
- 响应式布局（桌面/打印）。
- JSON 响应体格式化（`<pre><code>` + JS 语法高亮）。
- 步骤卡片折叠/展开交互。
