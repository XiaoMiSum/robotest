# 软件测试平台——业务功能核心机制

**文档版本**：V1.0
**日期**：2026-09-23
**状态**：起草中

---

## 1. 数据隔离

* 管理端接口不注入工作空间上下文，全局查询。
* 业务接口在数据库查询层自动附加 `workspace_id` 或 `project_id` 过滤条件，防止越权访问。

---

## 2. 脑图实时协作

* 用户进入文档后建立 WebSocket 连接，加入文档房间。
* 编辑操作以增量消息发送服务端，校验权限与工作空间归属后持久化并广播。
* 冲突处理采用乐观锁或 CRDT 算法保证最终一致性。

---

## 3. 快照机制

* **生成**：评审或计划发起/关联用例时，复制当前项目完整模块树 + 涉及文档的全部脑图节点。
* **存储**：存入专用快照表，与原始数据解耦。
* **裁剪展示**：前端请求时，服务端根据关联节点向上找祖先、向下找子孙，仅返回关联节点树；多文档时按文档快照树逐文档切换展示。
* **同步**：手动触发，用原始节点 ID 匹配更新快照；已删除节点标记为失效。
* **调整**：评审/计划未结束时可重新选择关联用例，按差量更新快照——新增文档生成快照、移除文档删除快照（已产生的标记/执行记录保留）、保留文档补入新增节点并重刷关联状态。

---

## 4. 评审与执行记录

* **评审记录**：每次标记/评论生成一条记录，并同步更新快照节点的最后标记字段（标记支持通过/不通过/待评审三态，全部关联用例通过后方可完成评审）。
* **执行记录**：每次执行生成一条记录，并同步更新快照节点的最后执行结果字段（结果支持通过/失败/阻塞/待执行）。
* **历史追溯**：通过记录表按时间排序获取完整历史。
