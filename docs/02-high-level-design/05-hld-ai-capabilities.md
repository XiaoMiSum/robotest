## 1. AI 调用链路

按交互形态分三类，全部经 AI 网关：

* **同步调用**（表单建议、优先级推荐的 LLM 兜底、DSL 翻译）：REST 请求 → 网关组装 Prompt → LLM → JSON Schema 校验 → 返回。超时阈值短（10s 级），失败即返回错误。优先级推荐的关键词规则命中时直接返回，不经本链路（见 3.2）。
* **流式调用**（用例生成、评审摘要、助手对话）：REST 请求建立 SSE → 网关流式转发增量内容 → 结束帧携带完整结构化结果（生成类）→ 前端预览。客户端断开即取消上游调用。
* **异步任务**（评审检查、缺陷聚类、存量向量回填）：创建任务记录 → 异步执行（内部可多轮分批调用 LLM）→ 更新任务状态与结果 → 前端轮询任务状态接口。同一目标对象同时只允许一个进行中任务。

所有链路统一行为：调用前限流检查 → 调用后写审计日志（含实际调用的模型）；Prompt 中系统指令与用户数据/业务数据分离（防注入）；结构化输出以提示词格式约束 + 结构化输出参数（厂商支持时）+ 网关侧 JSON Schema 校验兜底，校验失败带错误信息自动重试一次；输出最终未通过结构化校验时按失败处理，不降级为裸文本入库。

模型选取规则：交互式功能（同步/流式链路中用户直接发起的调用）请求可携带对话模型标识，网关校验其存在且已启用后使用，否则回退系统默认模型；异步任务与建议类功能固定使用系统默认模型。用户的模型选择在浏览器本地记忆，不在服务端持久化。

性能约束（承接 SRS 4.1，作为详细设计输入）：流式调用首内容返回以 3 秒为目标值，超 10 秒提示用户可取消或重试；语义查重检索（不含向量化耗时）500 毫秒内返回；表单内嵌 AI 能力不得阻塞用户输入与提交。

## 2. AI 生成节点挂载机制（关键机制）

AI 生成的用例子树进入脑图**不走后端直写**，完整链路为：

```
后端生成结构化用例树（含类型/优先级标记）
  ↓ 流式返回
前端预览面板（树形展示，可勾选取舍）
  ↓ 用户确认
前端经既有编辑内核挂载节点（写入类型/优先级/AI 标识）
  ↓ 触发既有内容变更事件
协同实时广播（协同用户即时可见）
  + 走既有 diff 持久化通道落库
  + 整批操作作为单条撤销历史
```

设计要点：

* 生成的节点携带 AI 来源标记字段，脑图以徽标渲染（复用既有节点徽标渲染体系）；除该字段外数据模型与手工节点完全一致；
* AI 标识随节点数据进入评审/计划快照；用户可经节点标记操作手动移除（移除后不可重新添加，该标识仅由 AI 生成动作赋予），不影响任何业务规则；
* 挂载前校验目标节点仍存在（可能被协同用户删除），不存在则提示重选；
* 「AI 补全步骤」「对话式编辑」复用同一挂载执行器（新增节点同样写入 AI 标识）。

## 3. 脑图操作指令集（DSL）

对话式脑图编辑使用一套受限 DSL：

* **结构**：`{ selector, action }` 数组。selector 支持按类型/优先级/文本关键字/子树范围筛选；action 限定为标记类型、标记优先级、高亮、移动（文档内）、新增子节点。
* **分工**：LLM 仅做自然语言 → DSL 翻译（同步调用，带 Schema 校验）；命中节点计算与执行由前端确定性代码完成。
* **安全**：执行前展示命中预览（数量与清单）；翻译置信不足（LLM 声明歧义或校验失败）时要求用户改写；本版本不支持跨文档操作。

## 4. 向量检索机制（缺陷语义查重与聚类）

* **索引对象**：缺陷标题 + 描述拼接文本的 Embedding，存于独立向量表（与缺陷记录一对一，无物理外键）。
* **写入时机**：缺陷创建/标题/描述变更时，事务提交后异步生成 Embedding 写入；失败进入补偿队列（定时任务扫描缺失/过期索引重建），不阻断业务。
* **存量回填与重建**：向量基建上线或 Embedding 模型/维度变更时，通过一次性异步任务批量回填/重建；维度变更时随重建同步调整向量数据与索引（重建期间降级行为见 2.5）。
* **查重查询**：输入文本 → Embedding → pgvector 余弦相似度 Top-K → 过滤条件：当前项目 + 状态 ≠ closed + 相似度阈值 → 返回卡片数据。前端防抖（500ms 级）触发。
* **聚类分析**：取项目未关闭缺陷全量（千级以内），基于向量近邻 + LLM 归纳标签与根因，输出聚类结果快照存表，面板读取渲染；手动刷新重新计算。
* **范围约束**：向量化覆盖缺陷库与用例库；用例向量供遗漏测试点分析与用例规划推荐的语义匹配使用（对应 SRS 梯队三语义升级），其索引对象与写入时机在详细设计确定；需求池条目不建向量索引（AD-5）。

---

## 5. 执行顺序推荐评分

* 推荐执行指数 = w1·历史关联缺陷数（按缺陷与用例关联聚合）+ w2·用例优先级权重 + w3·所属模块缺陷密度，权重配置化，计算为纯 SQL/内存运算，结果确定可复现。
* LLM 仅在用户展开明细时按需生成推荐理由文本，不参与排序。
* 结果与计划快照版本绑定，同步快照后失效需重算；脑图节点以徽标渲染序号（复用既有徽标渲染体系）。

---

## 6. 限流、审计与配额

* 限流：Redis 滑动窗口，用户 × 功能类别两级阈值（阈值为系统配置项）；超限返回明确错误码，前端提示。
* 审计：AI 调用日志独立成表（用户、空间、项目、功能类型、模型、耗时、token 用量、状态），管理端提供聚合统计视图；日志写入异步化，不影响调用主链路。
