## 1. 引言

### 1.1 编写目的

本文档对软件测试平台进行概要设计，阐明系统整体架构（含 AI 智能辅助能力域的总体架构）、模块划分、核心数据模型、关键机制及部署视图，为后续详细设计与开发提供依据。

### 1.2 范围

平台包含**系统管理模块**与**业务功能模块**两大部分，面向系统管理员和业务用户两类角色。本文档覆盖全平台架构设计，重点描述模块关系、数据流转及核心机制。其中，AI 智能辅助能力域覆盖：

1. AI 基础设施（AI 网关、模型接入、审计、限流）；
2. 智能测试用例生成（用例子树生成、步骤补全、优先级推荐、轻量需求池）；
3. AI 辅助评审与覆盖度分析；
4. 缺陷智能分析与去重（含向量检索基建）；
5. 全局智能助手（ChatBot 与工具调用）；
6. 测试计划与风险评估（执行顺序推荐、用例规划智能推荐）。

## 2. 系统总体设计

### 2.1 架构风格

系统采用 **B/S 架构**，**前后端分离**。整体分为三层：

    ┌─────────────────────────────┐
    │        前端（SPA）           │
    │  ┌────────┐  ┌────────────┐ │
    │  │管理端  │  │  业务端    │ │
    │  └────────┘  └────────────┘ │
    └─────────────┬───────────────┘
                  │ HTTP / WS
    ┌─────────────┴───────────────┐
    │       网关层（Gateway）      │
    │  认证、上下文注入、路由转发  │
    └─────────────┬───────────────┘
                  │
    ┌─────────────┴───────────────┐
    │          服务层              │
    │  ┌─────────┐ ┌───────────┐ │
    │  │管理服务 │ │ 业务服务  │ │
    │  └─────────┘ └───────────┘ │
    │  ┌───────────────────────┐ │
    │  │   WebSocket 服务      │ │
    │  └───────────────────────┘ │
    └─────────────┬───────────────┘
                  │
    ┌─────────────┴───────────────┐
    │          数据层              │
    │  ┌──────┐ ┌──────┐ ┌──────┐│
    │  │关系库│ │缓存  │ │文件  ││
    │  └──────┘ └──────┘ └──────┘│
    └─────────────────────────────┘

AI 能力以**服务层新增子域 + 数据层扩展**的方式集成到上述三层架构（前端 SPA → 服务层 → 数据层），不引入独立部署单元：

    ┌───────────────────────────────────────────┐
    │              前端（SPA）                    │
    │  既有页面 + AI 交互组件：                    │
    │  ┌──────────┐ ┌──────────┐ ┌────────────┐ │
    │  │脑图 AI   │ │表单/面板  │ │全局助手     │ │
    │  │工具栏/预览│ │AI 建议   │ │悬浮窗       │ │
    │  └──────────┘ └──────────┘ └────────────┘ │
    └──────────────┬────────────────────────────┘
                   │ HTTP / SSE / WS（复用既有通道）
    ┌──────────────┴────────────────────────────┐
    │                服务层                       │
    │  既有业务服务（Controller/Service 不变）      │
    │  ┌──────────────────────────────────────┐ │
    │  │        AI 子域（新增）                 │ │
    │  │  AI 网关（Provider 适配/Prompt 组装/   │ │
    │  │  流式输出/结构化校验/限流/审计）         │ │
    │  │  ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │
    │  │  │生成服务  │ │分析服务  │ │助手服务  │ │ │
    │  │  └─────────┘ └─────────┘ └─────────┘ │ │
    │  │  ┌─────────────────────────────────┐ │ │
    │  │  │ 工具注册表 → 调用既有 Service 层  │ │ │
    │  │  └─────────────────────────────────┘ │ │
    │  └──────────────┬───────────────────────┘ │
    └─────────────────┼─────────────────────────┘
                      │ HTTPS
              ┌───────┴────────┐        ┌──────────────────┐
              │ 外部 LLM 服务   │        │ 数据层            │
              │（对话/Embedding）│        │ PostgreSQL        │
              └────────────────┘        │  + pgvector 扩展  │
                                        │ Redis（限流）      │
                                        └──────────────────┘

### 2.2 前后端职责

* **前端**：
  * 管理端：独立路由树，仅拥有系统角色的用户可见。
  * 业务端：根据活跃工作空间动态加载数据，包含工作空间管理、项目管理、脑图编辑器、测试评审、测试计划、缺陷管理界面。
  * 脑图编辑器支持 WebSocket 实时协作。
* **后端**：
  * 提供 RESTful API，分为管理接口（`/api/admin`）和业务接口（`/api/workspace` 和 `/api/project`）。
  * WebSocket 服务负责脑图文档的实时协作消息广播与持久化。
  * 中间件统一处理 JWT 认证、活跃工作空间/项目上下文注入与校验。

### 2.3 系统初始化流程

系统首次部署后需经过初始化才能使用。初始化在认证流程之前，无需登录即可访问。

```
用户首次访问 → 登录页
  ↓
检查初始化状态 GET /api/auth/init/status
  ↓
未初始化 → /init 初始化页面 → 设置管理员密码 → POST /api/auth/init/setup
  ↓
已初始化 → 正常登录流程
```

初始化会创建 admin 账号并分配系统管理员角色（预置 UUID `b0000000-...-001`），用户使用 admin 和设置的密码登录。

### 2.4 关键架构决策

| 决策 | 内容 | 理由 |
| ---- | ---- | ---- |
| AD-1 | AI 能力内嵌于既有单体服务，不拆分独立 AI 微服务 | 与仓库单体架构一致，避免运维复杂度；LLM 调用为 IO 密集，异步化即可 |
| AD-2 | 前端不直连 LLM，一切经后端 AI 网关 | 密钥不出后端；统一审计、限流与上下文校验 |
| AD-3 | AI 生成的脑图节点由**前端**通过既有编辑内核挂载，不新增后端批量写接口 | 复用脑图 diff 持久化 + Yjs 协同链路，落库、广播、撤销重做零改造 |
| AD-4 | 向量检索采用 PostgreSQL pgvector 扩展，不引入独立向量库/搜索引擎 | 不新增中间件；缺陷量级（项目内千级）pgvector 完全够用 |
| AD-5 | 向量化范围覆盖缺陷库与用例库，需求池不建向量索引 | 缺陷查重/聚类与用例语义匹配（遗漏分析、用例规划推荐语义升级）均需向量；需求池是输入上下文而非检索语料（见 SRS 3.2.4） |
| AD-6 | AI 写操作一律"预览-确认-执行"，AI 不拥有独立身份与权限 | 所有工具调用以当前 LoginUser 走 Service 层，权限与审计天然复用 |
| AD-7 | 流式输出采用 SSE，不复用文档协作 WebSocket | 生成类交互是请求-响应模型，SSE 更契合；避免与协同通道耦合 |

### 2.5 AI 能力降级

* AI 配置缺失、关闭或健康检查失败时，后端能力开关接口返回不可用，前端隐藏全部 AI 入口。
* LLM 调用失败/超时不影响任何既有业务流程；异步任务失败保留失败状态供重试。
* Embedding 写入失败不阻断缺陷增改，由异步补偿任务重建索引（详见 4.11）。
* Embedding 模型或向量维度变更后触发向量索引全量重建；重建完成前，语义检索类能力（查重、聚类、语义匹配）自动降级为关键词匹配并向用户明示。能力开关接口支持此类**部分降级**状态（AI 整体可用、语义检索降级）。Embedding 未配置（如所选对话模型厂商不提供 Embedding 接口且未另配）时，语义检索类能力同样处于此降级状态。

### 2.6 技术选型概要

整体技术选型：

| 组件    | 选型方向                                     |
| ----- | ---------------------------------------- |
| 前端框架  | 现代 SPA 框架（React / Vue / Angular）         |
| 脑图编辑器 | 自研或基于开源库扩展，需支持自定义数据模型                    |
| 后端框架  | 主流 Web 框架（Spring Boot / Express / Gin 等） |
| 数据库   | 关系型数据库（MySQL / PostgreSQL）               |
| 缓存    | Redis                                    |
| 实时通信  | WebSocket（Socket.IO 或原生实现）               |

AI 能力技术选型：

| 组件 | 选型方向 | 说明 |
| ---- | ---- | ---- |
| LLM 接入 | 兼容 OpenAI 协议的 HTTP 客户端封装 | 具体依赖选型在详细设计阶段经团队讨论确定，接口层先行抽象为 Provider 适配器；适配器仅使用协议标准参数集，厂商非标参数（如思考开关）经配置项透传，响应中的非标字段宽容忽略 |
| 流式输出 | SSE（服务端单向流式推送） | 生成类接口统一支持 |
| 向量检索 | pgvector（余弦相似度） | 数据库扩展，随版本化数据库迁移脚本启用；向量维度为配置项，保存时校验取值范围 |
| Embedding | OpenAI 兼容 Embedding 接口，与对话模型分组独立配置 | 服务地址、密钥、模型名、向量维度均独立于对话模型，支持与对话模型使用不同厂商（部分厂商不提供 Embedding 接口） |
| 异步任务 | 既有异步执行能力 + 任务状态表 | 不引入消息队列 |
| 限流 | 用户维度限流计数（复用既有 Redis） | 复用既有基础设施 |
| 前端图表 | 缺陷聚类分布图所需图表方案在详细设计阶段确定 | 受依赖管控约束，优先评估轻量方案 |

### 3.2 模块职责简述

* **用户管理**：账号生命周期维护（启用/禁用/锁定三态），分配系统角色。
* **数据概览**：平台关键指标（用户、工作空间、项目、登录与活跃趋势）聚合展示，为管理端默认落地页。
* **全局工作空间管理**：工作空间的创建、归档与重新启用，全平台成员分配；归档仅冻结状态，成员归属保留。
* **系统角色与权限管理**：定义系统级角色及其管理端权限，系统管理员可配置。
* **我的空间**：按名称检索用户归属的工作空间，按“全部 / 我管理的 / 已归档”筛选并查看真实规模统计，按最近访问排序；切换活跃空间或编辑基本信息，具备全局创建权限时可在当前页发起创建。
* **工作空间成员管理**：管理当前工作空间内成员，可邀请/移除，并可设置空间管理员。
* **项目管理**：当前工作空间下项目的 CRUD 与归档。
* **测试用例管理**：模块树管理 + 脑图实时协作编辑 + 用例列表。
* **测试评审管理**：发起用例评审，基于快照进行节点标记/评论，支持记录、同步与调整规划用例。
* **测试计划管理**：创建计划，基于快照跟踪执行，支持多次执行记录、同步与调整规划用例。
* **缺陷管理**：缺陷全生命周期管理，关联用例与计划。
* **AI 配置**：系统管理员维护**多个对话模型配置**（每个模型独立的显示名、供应商选择、地址、密钥、模型名与附加参数，可分别启用/停用与连通性测试）并指定唯一的**系统默认对话模型**；Embedding 保持单一配置（供应商、地址、密钥、模型名、向量维度），与对话模型组相互独立；供应商预设内置于代码（含默认地址与厂商独有配置项模板），选择供应商后按预设引导填写，独有配置项作为附加参数透传，另提供通用 OpenAI 兼容模式；系统配置项（限流阈值、相似度阈值、保留期等）以**表单形式完整展示并逐项维护**（不提供裸配置编辑）；提供连通性测试（真实调用验证连通性，Embedding 组同时校验返回向量维度与配置一致）与调用量统计视图（支持按模型维度聚合）。
* **智能体**：每个 AI 功能对应一个智能体，即一个提示词模板位（功能类型枚举唯一键）。默认模板随代码内置；管理员自定义后落库覆盖，可一键恢复默认（删除自定义记录即回退内置）。模板按「角色指令段 / 输出格式约束段」两段存储，格式约束段编辑受高级开关控制（默认关闭锁定）；变更操作入审计日志。
* **AI 网关**：所有 LLM/Embedding 调用的唯一出口。职责：Provider 适配、Prompt 模板组装（加载顺序：自定义模板 → 内置默认；系统指令与用户数据隔离）、上下文裁剪与分批、流式转发、输出 JSON Schema 校验、失败重试。
* **调用审计与限流**：每次调用记录审计日志（用户/空间/项目/功能/耗时/token/状态）；Redis 用户级限流。
* **异步分析任务管理**：评审检查、缺陷聚类等长任务的创建、状态跟踪（pending/running/success/failed/cancelled）、结果存取与重试；评审离开「评审中」状态或用户主动取消时，进行中的检查任务联动终止并置为 cancelled，已产出结果仍可查看。
* **智能用例生成**：接收需求描述（或需求池条目引用），产出结构化用例树 JSON（含类型与优先级标记），由前端预览确认后挂载。优先级推荐采用**规则前置 + LLM 兜底**的混合策略：关键词规则命中时即时给出推荐（不发起 LLM 调用）；未命中时发起 LLM 调用，结果以非侵入提示回填，全程不阻塞用户手工标记。
* **轻量需求池**：项目级需求条目 CRUD、归档/取消归档（状态仅 active/archived 两态）、标题关键字检索、文档-条目关联维护（关联仅限 active 条目）。
* **脑图智能编辑**：自然语言 → 脑图操作指令集（DSL）翻译服务。执行均在前端。
* **AI 评审辅助**：快照树完整性检查（异步分批）；评审完成后统计聚合（SQL）+ 文字总结（LLM）。检查与摘要均仅评审发起人可发起。摘要生成完成后以结果快照持久化（复用分析任务结果存储），重复生成覆盖上一份。
* **覆盖度分析**：关键词/需求条目 vs 用例库比对，输出遗漏测试点；需求输入 → 用例库检索 → 用例规划推荐清单（供评审/计划「调整用例」流程带入）。
* **缺陷 AI 增强**：表单建议（同步单次调用）；语义查重（Embedding + pgvector Top-K，排除 closed）；聚类分析（异步任务）。
* **执行顺序推荐**：确定性加权评分（历史缺陷关联数、优先级、模块缺陷密度），LLM 仅生成理由文本；仅计划负责人/执行人可发起与查看。
* **全局智能助手**：多轮会话管理；Function Calling 循环（LLM 决策 → 工具执行 → 结果回填）；工具注册表统一声明工具的 schema、读写属性与所需权限。

### 3.3 前端组件规划
