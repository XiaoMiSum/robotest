## 1. 部署视图

### 1.1 前后端分离部署（方案 A）

* 前端静态资源部署到 CDN/Nginx，后端服务集群可水平扩展。
* 适用于大规模独立迭代。

### 1.2 前后端合并打包部署（方案 B）

* 前端构建产物嵌入后端服务，统一部署。
* 适用于中小团队快速交付。

拓扑图同常规。

### 1.3 AI 能力环境依赖与运行约束

* 方案 A 与方案 B 均适用，AI 能力引入两项环境依赖：
  * **外部 LLM 服务**：出网 HTTPS 访问（或内网私有化模型端点），地址与密钥经管理端配置、加密落库；
  * **pgvector 扩展**：PostgreSQL 启用 `CREATE EXTENSION vector`，随数据库迁移脚本执行。
* 无新增部署单元、无消息队列；异步任务随应用进程运行，多实例部署时任务表带执行者标记防重复消费。
* 分离部署（前后端经反向代理）时，SSE 流式接口需反向代理支持流式透传（关闭响应缓冲、放宽读超时），具体配置在部署说明中给出。

## 2. 安全设计

* 全链路 HTTPS / WSS。
* 多角色权限并集计算；角色或权限变更后强制 Token 失效。
* 管理接口仅限拥有系统角色的用户访问。
* 业务接口强制校验工作空间归属及工作空间内角色。
* 防暴力破解、CSRF、XSS。
* WebSocket 连接验证 Token 及工作空间上下文。
* **密钥管理**：LLM 密钥加密存储，仅 AI 网关运行时解密使用，禁止出现在日志、接口响应与前端。
* **权限复用**：AI 接口全部经既有认证链与工作空间权限校验；工具调用以当前登录用户身份走 Service 层，禁止绕过业务校验（对应 AD-6）。
* **Prompt 注入防护**：系统指令与用户输入/业务数据分段隔离；对来自业务数据的上下文（节点文本、缺陷描述、需求条目）不作为指令解析。
* **自定义提示词防护**：仅系统管理员可编辑；输出格式约束段默认锁定（高级开关显式开启后方可编辑）；无论模板如何自定义，输出 JSON Schema 校验始终强制执行，校验失败按调用失败处理并提示检查模板；模板变更入审计日志。
* **输出防护**：LLM 输出一律经 JSON Schema + 枚举/长度校验后方可执行或落库；助手回复中的链接仅允许平台内路由。
* **会话可见性**：助手会话内容仅本人可见；审计权限用户仅可见调用元数据，不可见对话内容。
* **写操作防护**：写工具白名单 + 一次性确认令牌 + 超时失效；确认动作本身入审计。
* **数据出域**：送入 LLM 的业务数据经上下文裁剪，仅包含完成当次任务所需最小集合。

## 3. 设计约束与原则

* **角色分离**：系统角色仅用于管理端，业务角色和工作空间角色用于业务端，权限边界清晰。
* **快照独立性**：快照表与业务表独立，不建立外键引用。
* **权限扩展性**：权限点树形管理，新增功能追加节点即可。
* **上下文集中管理**：工作空间与项目上下文通过请求头统一注入，路由简洁。
* **零侵入原则**：AI 能力对既有业务模块只增不改；AI 整体可关闭且关闭后平台行为与不含 AI 能力时完全一致。
* **前端挂载原则**：AI 产出进入脑图一律经前端编辑内核，复用协同/持久化/撤销链路，后端不提供绕过编辑通道的批量写入口（AD-3）。
* **确定性优先原则**：能用规则/SQL 确定性计算的（统计、评分、DSL 执行）不交给 LLM；LLM 只承担生成、翻译与归纳。
* **人在环原则**：一切写操作预览-确认-执行；一切建议非侵入呈现、可忽略。
* **基建收敛原则**：不新增中间件（向量走 pgvector、限流走 Redis、任务走既有异步执行能力）；新增外部依赖仅 LLM 服务一项。
* **向量范围约束**：向量化覆盖缺陷库与用例库，需求池不建向量索引（AD-5）。
