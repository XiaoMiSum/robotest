## 1. 引言

### 1.1 编写目的

对接口测试模块的跨子模块公共机制进行概要设计，明确请求参数与认证模型、处理器与验证器、变量与内置函数、执行引擎的核心机制与职责边界，为各子模块详细设计提供统一依据。

### 1.2 范围与对应需求

对应需求分册 `docs/01-requirements/05-api-testing/09-api-srs-common.md`（请求参数与认证、前置与后置处理器、验证器、内置函数与变量引用、执行引擎）；模块总览见 `docs/02-high-level-design/05-api-testing/02-hld-api-overview.md`。公共组件资产的管理与引入见 `docs/02-high-level-design/05-api-testing/10-hld-api-project-settings.md`，环境级配置载体见同一分册。

### 1.3 定义与缩写

| 术语 | 定义 |
| ---- | ---- |
| 前置处理器 | 测试组件执行前运行的处理器，用于数据准备、环境初始化、认证获取（沿用需求分册定义） |
| 后置处理器 | 测试组件执行后运行的处理器，用于数据清理、状态恢复、结果验证（沿用需求分册定义） |
| 提取器 | 从响应中提取值存储为变量供后续步骤使用的组件（沿用需求分册定义） |
| 验证器 | 对响应进行校验、失败则步骤判定失败的组件（沿用需求分册定义） |
| 取样器 | 执行一次请求的最小测试单元（沿用需求分册定义） |
| 资源池 | 承载服务端执行任务、支持并发的运行单元（沿用需求分册定义） |

## 2. 模块划分

### 2.1 机制构成

    公共机制（跨子模块）
    ├── 请求参数与认证模型（请求头 / 请求体 / Query / 认证）
    ├── 前置与后置处理器（层级执行顺序、失败语义）
    ├── 验证器（类型、规则、且关系）
    ├── 内置函数与变量引用（`${}` 求值、快捷使用帮助）
    └── 执行引擎（并发队列、格式转换、结果收集）

### 2.2 职责边界

* 本分册只定义机制与统一口径，不重复各子模块的页面与资产管理职责。
* 函数能力以 Ryze 框架为准，平台不维护独立函数实现，只提供浏览与插入的快捷使用帮助。
* 处理器、验证器、提取器的资产化管理（公共组件）归项目设置子模块，配置与执行语义归本分册。

## 3. 核心机制设计

### 3.1 请求参数与认证模型

* 请求模型由请求头、请求体、Query 参数与认证四部分构成，被快速调试、接口管理与场景自定义请求共用。
* 请求体类型互斥（none / x-www-form-urlencoded / raw），切换类型时保留各类型已填内容，切回恢复；Query 参数与 URL 已带查询串执行时合并去重（以参数区为准）。
* 认证支持 No Auth、Bearer Token、API Key、Basic Auth（Digest 暂不开放）；Bearer Token 与 API Key 在提交执行时换算为请求头，不新增独立存储字段；认证信息加密存储，不下发前端明文。
* 路径参数与占位符一一对应，未提供值时按字面占位发送并提示；跟随重定向默认关闭，重定向响应按实际响应展示。

### 3.2 处理器层级与失败语义

* 处理器结构与 Ryze 对齐（类型、配置、启用、排序），首期支持 http 与 jdbc 两类，配置位置分环境级、场景级、步骤级，下级继承上级并可覆盖。
* 执行顺序：前置按「环境级 → 场景级 → 步骤级」，后置按相反顺序；多处理器按配置顺序执行。
* 任一前置处理器失败则其所属组件不执行并标记失败；后置处理器失败不改变组件成败，但记录失败信息。
* 处理器可携带提取器，提取的变量进入执行期变量层，遵循 Ryze 变量作用域；jdbc 处理器依赖环境数据源，连接失败明确提示。

### 3.3 验证器

* 类型以 Ryze 为准：JSON（JSONPath 校验内容）、HTTP（状态码 / 响应头 / 响应体）、结果（响应时间等结果属性）。
* 配置于取样器级或后置处理器中；多个验证器为「且」关系，任一失败则步骤失败并记录失败明细。
* 表达式解析失败按验证失败处理并在报告中给出解析错误提示；字段与期望值支持变量与函数，验证前求值。
* 内置验证器不能满足时，基于 Ryze 扩展机制的自定义验证器为预留能力，平台不实现平行语义。

### 3.4 变量与内置函数

* 统一 `${变量名}` 语法，变量定义于环境级、场景级与步骤级（执行期由提取器 / 前置处理器产生），子级继承父级并可覆盖；同名取值优先级为执行期 > 场景参数 > 环境参数。
* 求值时机：请求发送前先执行函数生成变量值、再做变量替换；引用不存在的变量时保留字面量并在执行日志给出警告，不阻断执行。
* 函数库为 Ryze 内置能力，按能力域分组（安全加密、数据生成、日期时间、数据处理）；平台提供浏览、参数说明、示例与一键插入的快捷使用帮助。
* 函数与变量在请求参数、请求头、处理器、验证器与 Mock 响应中均可用。

### 3.5 执行引擎

* 执行模式：平台内执行由资源池在服务端完成，支持多任务并发；本地执行经本机代理发起，不经资源池（暂缓交付）。
* 并发控制：最大并发数为系统配置项（默认 5），同一项目共享配额；超限排队，队列长度可配置（默认 100），超长拒绝并提示。
* 格式转换：执行时将平台自有模型转换为 Ryze 标准 JSON，对用户无感；转换失败即拒绝执行、不产生部分结果，错误信息可定位。
* 结果收集：引擎结果树回收步骤级请求 / 响应、耗时、验证与提取结果，汇总后生成报告并回写执行历史；Ryze 结果树随报告留存快照。
* 超时与审计：执行超时按请求级「响应超时」控制，超时标记失败并记录；执行任务量纳入审计日志（本地执行仅记录操作行为）。

## 4. 数据设计

公共机制不新增独立实体，配置与执行数据分别由各子模块实体承载（实体清单见 `docs/02-high-level-design/05-api-testing/02-hld-api-overview.md` 第 4 节）：

| 机制 | 数据载体 |
| ---- | ---- |
| 请求参数与认证 | 调试记录、接口定义、场景步骤的请求配置 |
| 处理器 / 验证器 / 提取器 | 环境（环境级）、场景与步骤（场景 / 步骤级）、公共组件（资产库） |
| 变量与内置函数 | 环境变量、场景参数、执行期变量（执行时生成，随报告快照留存） |
| 执行引擎 | 执行历史、报告（含 Ryze 结果树快照） |

字段、DDL 与索引见 `docs/04-detailed-design/05-api-testing/02-api-testing-infra-overview.md`。

## 5. 接口设计概要

资源与职责划分（路径、方法与报文留详细设计）：

| 资源 | 职责 | 归属 |
| ---- | ---- | ---- |
| 执行引擎 | 触发执行、查询执行状态、取消执行 | 项目级（项目上下文） |
| 调试记录 | 服务端调试执行与历史记录 | 项目级（项目上下文） |
| 变更历史 | 接口与场景的变更记录查询 | 项目级（项目上下文） |
| 函数帮助 | 内置函数清单、参数说明与示例 | 项目级（项目上下文） |

上下文标识通过请求头传递，不出现在 URL 中；执行状态查询供各子模块复用，不各自另设轮询通道。

## 6. 设计约束与原则

* 平台不实现与 Ryze 语义不一致的平行能力：函数、验证器、提取器、处理器语义一律以 Ryze 为准，扩展走 Ryze 扩展机制（预留）。
* 平台自有模型为唯一持久化事实源，不持久化 Ryze 文档；转换失败即拒绝执行。
* 认证等凭据配置加密存储、不下发前端明文；环境变量值明文存储与展示（无敏感值概念）。
* 执行引擎故障不影响平台其他功能；执行失败不自动重试（默认），可手动补跑。
* 变量求值不阻断执行：未定义变量保留字面量并记警告。
* 所有异常经统一错误码抛出，错误码为 10 位（框架全局错误码除外）；上下文标识只经请求头传递（C4）。
