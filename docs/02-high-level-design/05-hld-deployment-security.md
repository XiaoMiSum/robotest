## 1. 部署视图

### 1.1 前后端分离部署（方案 A）

* 前端静态资源部署到 CDN/Nginx，后端服务集群可水平扩展。
* 适用于大规模独立迭代。

### 1.2 前后端合并打包部署（方案 B）

* 前端构建产物嵌入后端服务，统一部署。
* 适用于中小团队快速交付。

拓扑图同常规。

## 2. 安全设计

* 全链路 HTTPS / WSS。
* 多角色权限并集计算（用于系统管理、空间管理、项目管理）；角色或权限变更后强制 Token 失效；功能测试、需求管理、接口测试、缺陷管理、AI 能力免 RBAC 权限码校验。
* 管理接口仅限拥有系统角色的用户访问。
* 业务接口强制校验工作空间归属与项目 / 文档成员归属；功能测试、需求管理、接口测试、缺陷管理、AI 能力免 RBAC 权限码校验，系统管理 / 空间管理 / 项目管理仍按权限码授权。
* 防暴力破解、XSS；CSRF 不适用于 Bearer Header 场景，Cookie 场景再启用（见 `docs/00-spec/40-security/01-security.md` 6.2 节）。
* WebSocket 连接验证 Token 及工作空间上下文。

## 3. 设计约束与原则

* **角色分离**：系统角色用于管理端，空间角色用于空间管理与项目管理；功能测试、需求管理、接口测试、缺陷管理、AI 能力免 RBAC 权限码校验，仅保留成员归属校验。
* **快照独立性**：快照表与业务表独立，不建立外键引用。
* **权限扩展性**：权限点树形管理，供系统管理 / 空间管理 / 项目管理追加节点；业务模块免 RBAC 权限码校验。
* **上下文集中管理**：工作空间与项目上下文通过请求头统一注入，路由简洁。
