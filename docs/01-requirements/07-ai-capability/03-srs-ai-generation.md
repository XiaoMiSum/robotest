## 1. AI+需求 生成链

### 1.1 总体描述

生成链将 AI 贯穿需求到测试评审 / 测试计划的完整链路：

- `AI + 需求 = 模块 + 脑图用例文档 + 测试用例`：一次生成产出三层派生物，并建立派生追溯边；
- `AI + 需求 + 模块 + 脑图用例文档 + 测试用例 = 测试评审 或 测试计划`：基于全链路上下文推荐评审 / 计划的圈选范围，产出挂到用例级快照引用边。

输入为需求管理模块中**已确认的需求**（见 `docs/01-requirements/06-requirement-management/02-srs-requirement-management.md`）。生成以后台任务执行，产物为待确认态，任务与确认的通用口径见总册 1.5（`docs/01-requirements/07-ai-capability/02-srs-ai-capability.md`），本分册不重复定义。

### 1.2 发起生成（US-AI-005）

**功能描述**：选择已确认的需求，发起测试设计生成任务。  
**功能点**：

- 入口一：需求列表 / 需求详情中多选需求 → 「AI 生成测试设计」。
- 入口二：在需求列表按模块批量选中需求，一键发起。
- 发起时可配置：目标项目与模块落位（新建顶级目录 / 挂到既有模块节点）、生成范围（所选需求）、用例粒度偏好（精简 / 标准 / 详细）。
- 提交后立即创建后台任务并跳转任务进度页，不阻塞当前操作。

**业务规则**：

- 仅已确认需求可作为输入；草稿、已变更、已归档需求不可选，入口对不可选需求置灰并说明原因。
- 任务执行期间输入需求被变更时，任务按发起时的需求快照继续执行，产物确认时提示「来源需求已变更」，由人工决定采纳或驳回。

### 1.3 生成过程与进度（US-AI-006）

**功能描述**：展示生成任务的阶段进度与结果。  
**功能点**：

- 任务进度页按阶段展示：解析需求 → 生成模块结构 → 生成脑图文档 → 标记用例节点 → 填充用例属性 → 建立追溯边。
- 展示各阶段进度、已产出产物数量与失败原因摘要。
- 支持取消进行中的任务；失败任务可重试，重试保留原任务记录。

**业务规则**：

- 取消或失败的任务不产生任何落库数据，不建立追溯边。
- 已完成任务的产物进入待确认态等待审核（见 1.4）。

### 1.4 产物审核与确认（US-AI-007）

**功能描述**：审核三层生成产物，确认后落库并建立派生追溯边。  
**功能点**：

- 产物以三层树预览：模块（建议）→ 脑图文档（建议）→ 脑图节点（其中标记为用例的节点附用例属性建议：优先级、前置条件、测试步骤、预期结果、标签）。
- 审核操作：单条采纳、整树采纳、编辑后采纳、驳回；驳回可附反馈重新生成该子树。
- 采纳时指定落库的目标项目与模块位置；采纳后落库为正式模块、脑图文档与测试用例。
- 采纳同时建立派生追溯边，初始状态为「AI 建立」，可在矩阵视图中转为「人工确认」（见总册 1.4）。
- 每个标记为用例的脑图节点对应生成一条测试用例实体，可回溯到脑图节点路径。

**业务规则**：

- 未采纳的产物不落库，驳回产物保留记录供审计。
- 采纳以新增方式落库，不覆盖既有模块与用例；与既有数据疑似重复时提示人工处理。
- 确认后 AI 不再自动覆盖；人工编辑过的产物仅在显式重新生成并二次确认后可被覆盖（总册 1.5）。

### 1.5 评审与计划圈选建议（US-AI-008）

**功能描述**：基于全链路上下文，推荐测试评审与测试计划的圈选范围。  
**功能点**：

- 对已确认的测试用例，AI 结合需求、模块归属与用例内容，推荐两类圈选：
  - **评审圈选**：建议纳入本次评审的用例子集，附建议理由（如新增需求覆盖、高风险模块）；
  - **计划圈选**：建议纳入计划执行的用例子集，可按轮次给出建议分组。
- 建议为待确认态：可采纳、调整后采纳（增删用例）、驳回。
- 确认后沿用既有评审 / 计划创建流程生成快照；评审意见与计划项挂到用例级快照引用边，记录引用时的用例版本。
- 执行顺序建议由辅助功能分册定义（`docs/01-requirements/07-ai-capability/06-srs-ai-assisted-features.md`），此处不重复。

**业务规则**：

- 圈选建议不自动创建评审或计划，确认后走既有创建流程与快照语义，AI 不改变既有快照机制。
- 引用边记录版本；上游用例变更后引用边标记「待重新确认」（总册 1.4）。

### 1.6 矩阵视图与影响处置（US-AI-009）

**功能描述**：查看追溯矩阵与链路视图，处置影响分析结果。  
**功能点**：

- 矩阵视图与链路视图的呈现能力见总册 1.4；本模块提供从项目工作区进入的入口与生成链相关操作。
- 缺口列表：未覆盖需求、孤儿用例（无上游需求）、未经评审用例、未纳入计划用例；每项提供「发起生成 / 发起评审 / 加入计划」的引导操作。
- 影响处置：需求变更产生受影响项列表后，逐项选择处置方式：重新生成建议、标记需重新评审、确认无影响。

**业务规则**：

- 处置动作只改变追溯边状态与标记，不直接修改下游内容本身。
- 「确认无影响」记录操作人与理由，该关联脱离本次影响标记。
