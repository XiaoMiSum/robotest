## 1. AI 辅助功能

### 1.1 总体描述

辅助功能面向脑图用例编辑与测试计划执行，提供三项轻量 AI 能力：**用例优化**、**测试用例执行顺序推荐**、**脑图生成用例**。三项能力均为交互式建议，遵循总册 1.5 的采纳口径（`docs/01-requirements/07-ai-capability/02-srs-ai-capability.md`）：建议不直接生效，经人工采纳后落库，人工编辑过的内容 AI 不自动覆盖。脑图生成用例的采纳在脑图面板完成（勾选提案插入当前文档），任务详情只回看、不提供审核操作。

**权限**：业务模块免 RBAC 权限码校验，保留项目成员归属校验：当前项目成员可使用三项能力，范围限于当前项目。

### 1.2 用例优化（US-AI-017）

**功能描述**：对选中的用例节点生成一组可定位到具体节点的优化操作，采纳后原地更新或新增节点内容。  
**功能点**：

- 在脑图编辑器中选中用例节点 → 「AI 优化」，基于节点文本、所在节点子树与上游需求上下文，生成针对具体节点的操作指令。
- 操作指令两类：`更新`（按节点 ID 定位，改写该节点内容）与 `新增`（按父节点 ID 定位，在其下新增子节点）。
- 更新范围：用例标题、前置条件、操作步骤、预期结果节点的文本，以及用例节点的优先级（P0 / P1 / P2 / P3）与标签；更新类指令须给出理由，优先级理由引用上游需求的重要程度，建议值与当前值一致时同样产出并正常展示。
- 新增范围：在用例或其任一后代节点下新增前置条件 / 步骤 / 预期 / 普通节点，不新增用例节点；新增时给出节点类型与内容。
- 操作以对照形式展示（节点路径：现有内容 vs 建议内容 / 新增内容），采纳或驳回；每个选中节点产出一条提案，内容包含其全部操作指令。采纳按当前核对节点提交，提交后自动推进到下一个待处理节点。
- 生成经任务框架执行，超过交互等待时间时展示任务详情入口（总册 1.5）。
- 同一用例节点复用最近一次任务（不限文档查看会话，项目内任意成员发起的任务均可复用）：执行中（`running`）回显进度或已有提案，不新建任务或执行；已终止（`aborted`）时展示原因并可「再次执行」，沿用原任务新建执行实例；已产出提案（`proposals_ready`）或已处理完毕（`closed`）时展示提案并提供「重新执行」，按同一输入新建任务，原任务及其提案与采纳记录保留只读回看，不被覆盖。

**业务规则**：

- 采纳在脑图当前树上按操作指令定位节点执行：`更新` 原地改写目标节点内容（节点 ID 与层级不变），`新增` 在指定父节点下创建新节点；不采用删除原节点再插入的方式，保留既有节点 ID 与协同引用。
- 操作指令涉及的所有节点（目标节点与父节点）须与被优化用例同属一个文档，非法引用在提案生成阶段丢弃；采纳时目标节点或父节点已不存在则跳过该条指令。
- 提案中的现有值仅供人工核对，不作为写入前置条件；采纳以脑图当前树为准，人工在提案生成后对节点的改动不被回退。
- 优先级与标签默认不被覆盖，AI 只提供更新建议，须人工显式采纳；未被采纳的指令不落库。
- 采纳结果即时反映到脑图并持久化；同值更新项照常展示，采纳后节点内容与向量索引保持一致。
- 推荐仅基于平台内的上游需求数据，不引入外部数据，也不参考历史缺陷热点。

### 1.3 执行顺序推荐（US-AI-018）

**功能描述**：为测试计划的关联用例推荐执行顺序，并在计划执行时按该顺序引导。  
**功能点**：

- 对计划详情关联节点树中的用例，AI 给出执行顺序建议，依据：用例间依赖线索（前置条件与步骤引用）、历史失败率高的用例前置、风险与优先级。生成建议时实际读取计划内用例的前置条件 / 步骤 / 预期、祖先路径与历史执行记录，使上述依据可追溯；依据缺失时留空，不臆造。
- 以排序建议列表 / 拖拽序号形式展示，可预览建议调整前后的对比。
- 采纳后更新计划内用例的执行排序；人工可继续手动调整，最终以人工顺序为准。
- 计划详情页按当前执行排序在脑图用例节点上显示序号，并提供「下一个待执行用例」引导：按排序定位并高亮当前应执行的未执行用例，标记结果后自动推进；引导仅作辅助，用户仍可自由点选任意用例标记。
- 入口按当前测试计划查询最近一次任务（不限页面查看会话，项目内任意成员发起的任务均可复用）：命中则回显任务进度或排序建议及审核结果，不新建任务；未命中才发起新任务。
- 命中任务的面板提供「重新执行」：执行中（`running`）仅回显进度、不新建任务或执行实例；已终止（`aborted`）展示原因并可「再次执行」，沿用原任务新建执行实例；已产出提案（`proposals_ready`）或已处理完毕（`closed`）展示提案、采纳 / 驳回状态与驳回原因，并可「重新执行」，按当前计划新建任务，原任务及其提案、采纳记录保留只读回看。

**业务规则**：

- 按计划复用仅取最近一次任务，按 `planId` 定位且范围限当前项目；查询失败只提示错误、不自动发起，更早任务仍可在任务中心回看。
- 执行顺序推荐不改变计划的关联用例集合与快照内容，仅调整展示与执行次序。
- 建议采纳前不生效；推荐为辅助参考，阻塞关系仍以用例前置条件的人工维护为准。
- 采纳或人工调整后的执行排序为计划的稳定排序：同步最新用例、编辑重规划与差量调整用例时保留已调整的顺序，仅对补入的用例按原始顺序补位，不被原始用例顺序覆盖。
- 执行引导不改变执行记录的提交方式，仍由用户对所选用例逐条标记；排序仅决定引导次序与展示序号。

### 1.4 脑图生成用例（US-AI-019）

**功能描述**：在测试用例脑图编辑器中，基于一条已确认需求生成测试用例提案，勾选后插入当前文档。  
**功能点**：

- 入口：脑图编辑器工具栏最右侧「AI覆盖雷达」按钮（悬浮提示「扫描需求测试用例覆盖率并补齐缺漏」）；点击先查询当前文档最近一次生成任务，命中则直接打开 AI 面板回显进度或结果，未命中才经「选择需求」单选弹窗选定一条需求，确认后打开面板并发起生成任务。
- 任务输入为当前文档 id 与所选需求 id；提交后立即创建任务，执行过程与结果在 AI 面板内展示，不跳转任务详情页。
- 生成的每条用例包含完整标题、前置条件、执行步骤、预期结果、优先级（P0–P3）与标签，以脑图形式回显并支持勾选与全选；用例选择器复用既有选择器组件，以脑图层级展示提案的节点结构。
- 勾选后点「采纳」，对尚未采纳的用例通过既有节点操作把所选用例及其前置 / 步骤 / 预期子节点追加到当前文档根节点下，并标记 AI 生成，同时自动把每条新用例关联到其来源需求；已采纳用例不重复插入脑图，仅保留既有采纳状态；操作成功后关闭面板，脑图即时反映并持久化。
- 重复打开已完成任务的面板时，已采纳用例默认不展示；可勾选「展示已采纳用例」查看，展示时这些用例默认勾选且不可取消，作为只读回看项。
- 任务详情页只回看执行过程与提案，不提供采纳、编辑后采纳、驳回等审核操作；采纳状态由脑图面板的采纳动作记录。
- AI 未启用或未配置模型时入口隐藏；需求不满足条件（非已确认、不属当前项目）时不可选择或提交时拒绝。

**业务规则**：

- 仅已确认需求可作为输入；草稿、已变更、已归档需求不可选。
- 当前文档已有生成任务时复用最近一次任务回显进度或提案，不重复弹出需求选择；查询失败只提示错误、不自动发起，更早任务仍在任务中心可回看。
- 已命中任务的「重新执行」按任务状态分叉：执行中（`running`）仅回显进度；已终止（`aborted`）沿用原任务新建执行实例；已产出提案（`proposals_ready`）或已处理完毕（`closed`）按原输入（当前文档与来源需求）新建任务，原任务及其提案、采纳记录保留只读回看，不被覆盖。
- 提案在勾选插入前不落库，不产生正式用例节点；插入为新增，不覆盖既有节点。
- 来源需求在任务执行期间变更时按发起时快照继续，面板提示来源已变更，由人工决定是否采纳。
- 任务被中止、执行错误或预算耗尽时不产生提案与节点；面板展示原因并提供再次执行。
- 插入的用例节点及其子节点均带 AI 生成标识；插入经脑图既有协同与持久化管道落库。
- 已采纳（含编辑后采纳）用例为只读回看项：可展示、可计入勾选，但不参与脑图插入，也不重复回传采纳状态；重复打开或重复点击「采纳」不得生成重复节点。
- 「采纳」只作用于本次新勾选的未采纳用例：先建节点，再回传采纳状态；无新用例时不执行插入。
- 采纳时按提案来源引用自动建立用例与需求的关联；提案无来源引用时按任务输入需求关联，需求须属于当前项目。关联失败时提示用户，已插入的脑图节点与采纳状态保留，不自动回滚。
