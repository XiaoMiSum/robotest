## 1. AI 能力

### 1.1 总体描述

AI 能力是平台级基础能力，四大能力域构建其上：

| 能力域 | 分册 | 一句话定位 |
| ---- | ---- | ---- |
| AI+需求 生成链 | `docs/01-requirements/07-ai-capability/03-srs-ai-generation.md` | AI 将已确认的需求条目生成模块、脑图用例文档与测试用例，并推荐评审/计划圈选 |
| 智能助手 | `docs/01-requirements/07-ai-capability/04-srs-ai-assistant.md` | 一句话下达任务，经确认后将数据落库（测试用例、测试评审、测试计划） |
| 缺陷分析 | `docs/01-requirements/07-ai-capability/05-srs-ai-defect-analysis.md` | 缺陷趋势与质量度量、自动分类分诊、重复缺陷检测 |
| 辅助功能 | `docs/01-requirements/07-ai-capability/06-srs-ai-assisted-features.md` | 用例补全、用例级别推荐、测试用例执行顺序推荐 |

追溯链的起点是需求管理模块的需求条目，需求条目的管理行为见 `docs/01-requirements/06-requirement-management/02-srs-requirement-management.md`；测试评审与测试计划的快照机制沿用既有口径，见 `docs/01-requirements/03-function-testing/02-srs-business-features.md`。

**两条全局原则**：

- **后台异步任务**：AI 生成、批量分析等耗时操作一律以后台任务执行，提交即返回任务入口，进度可见，完成通知发起人，不阻塞用户当前操作。
- **生成物待确认**：AI 产出的模块、脑图、用例、圈选建议、分类建议等一律为**待确认态**，不直接落为正式数据；人工逐项或批量审核确认后才生效。确认后 AI 不覆盖人工修改过的内容。

**定义与缩写**：

| 术语 | 定义 |
| ---- | ---- |
| 模型配置 | 对单个大模型接入的登记（地址、密钥、能力声明、启用状态），平台可配置多个，供给方式不锁定，可为云端 API 或私有化部署端点 |
| 向量 API | 将文本转化为向量表示的独立接入配置，可与模型配置来自不同供应商 |
| 提示词 | 针对特定业务场景编排的模型指令模板，可按场景自定义覆盖默认值 |
| AI 任务 | 一次后台异步执行的 AI 操作，具有类型、状态、进度与产物清单 |
| 生成物 | AI 任务产出的结构化结果，处于待确认态，经人工确认后落库 |
| 待确认态 | AI 产出未生效的状态，可逐项采纳、修改后采纳、批量采纳或驳回 |
| 向量化 | 将文本等内容转化为向量表示，供相似检索使用 |
| RAG | 检索增强生成：生成前先检索平台内相关业务数据，并在产出中给出来源引用 |
| 多模态 | AI 输入不仅限于文本，还包括图片、文档附件等 |
| 追溯矩阵 | 记录需求条目到测试全链路派生与引用关系的矩阵，支持覆盖统计与双向回溯 |
| 派生边 | 需求条目 → 模块 → 脑图文档 → 用例节点 → 测试用例的纵向派生关系 |
| 快照引用边 | 测试用例 ⇢ 测试评审 / 测试计划的横向引用关系，为带版本的部分快照 |
| 影响分析 | 上游变更后识别下游受影响项并供逐项处置的能力 |

### 1.2 AI 配置与使用分析（US-AI-001）

**功能描述**：系统管理端提供 AI 能力的全局开关、模型与向量 API 配置、业务场景提示词维护与使用情况分析。  
**功能点**：

- **总开关**：全局开启 / 关闭 AI 功能；关闭后全平台 AI 功能入口不可用并提示「AI 功能已关闭」，已生成的数据、确认记录与追溯关系保留可查。
- **多模型配置**：可配置多个模型条目，每条含名称、能力声明（文本生成 / 多模态解析）、接入地址、密钥与启用状态；可指定默认模型，各能力域（生成链、助手、缺陷分析、辅助功能）可分别覆盖默认模型；每条模型提供连通性测试与启用 / 停用。
- **向量 API 配置**：向量化 API 独立配置（接入地址、密钥、模型标识），可与模型配置来自不同供应商；提供连通性测试；未配置时依赖检索的能力（RAG、相似检测）不可用。
- **业务场景提示词配置**：按业务场景维护提示词模板（测试用例生成、需求拆解、助手意图解析、缺陷分类分诊、缺陷重复检测、用例补全、覆盖分析等），支持查看默认提示词、自定义覆盖与恢复默认；场景随能力域扩展，未自定义的场景使用默认提示词。
- **使用情况分析**：按时间范围、模型、能力域统计调用次数、成功 / 失败分布与失败原因、平均响应时延、token 消耗（模型服务上报时）；提供趋势图与异常提示（如失败率突增）；可下钻查看对应的 AI 任务列表。

**业务规则**：

- 配置与使用分析仅系统管理端可见可用，业务用户不可见；全部配置操作记审计。
- 关闭总开关时，进行中的 AI 任务停止并置为失败（原因：AI 功能已关闭），已确认产物不受影响。
- 密钥保存后不可回显，仅支持替换。
- 未配置任何启用状态的模型或向量 API 时，对应 AI 能力入口可见但不可用，并引导至配置页。
- 提示词自定义仅影响其对应场景的后续 AI 调用，不改变已生成的产物。
- 模型调用失败（不可用、超时、限流）时，AI 任务置失败并给出原因，可重试；平台非 AI 功能不受影响。

### 1.3 知识与检索能力（US-AI-002）

**功能描述**：AI 的生成与问答基于平台内业务数据的向量化检索（RAG），并支持多模态输入。  
**功能点**：

- 平台内指定范围的文本类业务数据（需求条目、测试用例、缺陷、评审记录等）可被向量化索引，供相似检索与生成引用。
- AI 产出（生成物、回答、建议）必须携带来源引用，引用指向具体业务对象，可点击跳转定位。
- 多模态输入：支持将用户上传的图片与文档附件作为 AI 输入解析（如需求导入的截图、附件中的需求文本）。
- 检索范围严格限定：仅检索当前用户有权限访问的范围（当前工作空间及其项目），无权限数据不得进入 AI 上下文。

**业务规则**：

- 向量索引随业务数据变更同步更新；已归档、逻辑删除的数据不再被检索。
- 检索能力不可用时，依赖检索的 AI 功能提示不可用，不降级为无引用的生成。
- 来源引用缺失的 AI 产出视为不合格产出，不得进入待确认态供采纳。

### 1.4 追溯矩阵（US-AI-003）

**功能描述**：以结构化关联记录测试全链路的派生与引用关系，支持覆盖统计、双向回溯与变更感知。  
**功能点**：

- **派生链**：需求条目 → 模块 → 脑图文档（用例节点）→ 测试用例。AI 生成时为每个下游节点显式记录其来源需求，关联为结构化数据，不依赖标题文本推断。
- **引用边**：测试用例 ⇢ 测试评审 / 测试计划，为**版本化部分快照**——记录被引用用例的标识与引用时版本，评审意见与计划项挂到用例级引用边（追溯粒度为单条测试用例）。
- **矩阵视图**：以需求条目为行、下游对象（模块 / 用例 / 评审 / 计划）为列；单元格的**覆盖状态由 AI 覆盖分析判定**，而非凭关联边存在机械判定——AI 对需求与相关用例做语义比对，判断需求的要求点是否被用例实质覆盖，输出**已覆盖 / 部分覆盖 / 未覆盖**；支持覆盖率统计与缺口列表（未覆盖需求、孤儿用例、未经评审的用例、未纳入计划的用例）。
- **覆盖分析**：以后台任务执行（人工发起、上游数据变更或需求重新确认时触发），每条需求的分析结论附依据（判定其覆盖的用例集合与理由，可下钻核验）；结论可由人工复核修正，人工判定优先于 AI。
- **链路视图**：从任意节点向上回溯到需求条目、向下下钻到评审/计划执行，双向全链路可见。
- **变更感知**：上游内容变更后，受影响的引用边标记「待重新确认」，矩阵中高亮展示。
- **人工修正**：追溯边可由人工改挂、断开与新建；每条关联有三态：**AI 建立**、**人工确认**、**存在冲突**（AI 建立与人工判断不一致时）。
- **影响分析**：需求条目变更后，AI 沿派生边与引用边标记下游受影响项列表，供逐项处置（重新生成 / 重新评审 / 确认无影响）。

**业务规则**：

- 覆盖状态是 AI 分析结论而非结构推断：一条需求需其全部要求点被用例共同覆盖才计为已覆盖，仅存在个别关联用例计为部分覆盖。
- 无分析结论（未分析 / 分析中）的需求标注为「待分析」，不计入覆盖或未覆盖；覆盖率以需求总数为分母，部分覆盖单独计数。
- 人工修正后的覆盖结论以人工为准，后续 AI 分析不得自动覆盖人工判定。
- 人工修正优先于 AI 判断：人工改挂或断开后，AI 不得自动恢复或重建该关联。
- 追溯边仅记录关系与版本，不复制下游内容本身；快照语义沿用既有口径（见 `docs/01-requirements/03-function-testing/02-srs-business-features.md`）。

### 1.5 AI 任务通用规则（US-AI-004）

**功能描述**：所有能力域的 AI 操作遵循统一的任务执行、确认与审计口径。  
**功能点**：

- AI 任务状态：排队 → 进行中 → 已完成 / 已失败；任务列表展示类型、输入来源、进度与结果摘要，完成后通知发起人。
- 生成物确认操作：单条采纳、批量采纳、修改后采纳、驳回；驳回可附反馈重新生成（局部重生成）。
- 人工编辑保护：已被人工编辑过的生成物，AI 仅在用户显式发起重新生成并二次确认后才可覆盖。
- 审计：每次任务发起、采纳、修改、驳回均记录操作人、时间与内容摘要，可在任务详情回看。
- 权限：AI 操作与确认遵循与界面操作完全相同的权限校验，含活跃工作空间上下文；AI 不绕过任何既有权限与业务校验。

**业务规则**：

- 同一批输入存在进行中的同类任务时，重复发起需提示。
- 任务失败不产生任何落库数据；已确认的产物不受后续任务失败影响。

### 1.6 非功能需求

- 交互式 AI 建议（补全、级别推荐、重复检测等）应在 10 秒内给出首屏反馈；未及时响应时展示进行中状态与取消入口。
- 后台 AI 任务进度实时可见；完成后通知发起人。
- AI 产出的来源引用 100% 可跳转定位。
- 使用云端模型时，出站内容仅限任务必需的上下文，由系统管理员决定是否启用云端接入；密钥不落日志。
- 配置的模型或向量 API 不可用时，平台核心测试功能不受影响，AI 入口降级提示。
- AI 上下文严格限于当前用户有权限的数据（见 1.3），跨工作空间数据不得进入任何 AI 任务。

### 1.7 数据需求

**功能描述**：定义 AI 能力涉及的数据实体及其关系（实体级，不含表结构）。  
**功能点**：

- **AI 任务**：任务类型、输入来源（如需求条目集）、状态、进度、产物清单、发起人、起止时间、失败原因。
- **追溯边**：类型（派生 / 快照引用）、源标识、目标标识、目标版本、状态（AI 建立 / 人工确认 / 存在冲突 / 待重新确认）、建立人、建立时间。
- **生成物确认记录**：所属任务、产物标识、采纳方式（单条 / 批量 / 修改后 / 驳回）、操作人、时间。
- **AI 配置**：总开关状态、模型配置（接入信息、能力声明、默认标记、启用状态，可多条）、向量 API 配置、业务场景提示词（默认值与自定义值）。
- **AI 使用统计**：按时间、模型、能力域聚合的调用量、成功 / 失败与失败原因、响应时延、token 消耗。
- **向量索引条目**：来源业务对象标识、所属工作空间、索引状态。
- **AI 助手会话与消息**：定义见智能助手分册。

**业务规则**：

- 所有实体通过所属项目或工作空间归属进行隔离，遵循既有数据隔离约定。
- 追溯边是追溯矩阵的唯一事实源，矩阵视图与链路视图均由其派生展示。
