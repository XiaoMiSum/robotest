# 软件测试平台——AI 执行（UI 自动化测试）

## 1. 引言

### 1.1 编写目的

本文档定义 AI 执行（UI 自动化测试）能力的需求：用户仅维护自然语言测试用例（前置条件、测试步骤、预期结果，不含操作细节），由 AI 在执行过程中自主决策具体操作，自动完成测试计划中用例的执行与判定，交付用例判定结论与按步骤锚定的动作轨迹证据。本文只描述行为、规则、边界与验收口径，架构、数据结构、接口与协议留概要 / 详细设计。

### 1.2 范围

- 纯 UI 自动化测试，与接口测试域零耦合。
- 入口为测试计划详情页**新增**的「AI 执行」（非既有入口）。
- 交付物：用例判定（通过 / 失败 / 阻塞 / 跳过）+ 按步骤锚定的动作轨迹证据。
- V1 非目标（升级项与待定项）见 6.1、6.2。

### 1.3 与基线关系

- 本文转写自设计暂存稿 `ai-ui-testing-design-v1.1.md`，转写以既有文档口径为准；已修正的差异：入口为新增；计划快照含用例正文、计划详情基于快照展示；AI 执行与手动执行一致，以计划快照为冻结源，未同步的脑图修改不进本次执行。
- 与 `docs/01-requirements/03-function-testing/02-srs-business-features.md`：测试计划、执行记录、进度统计等既有能力沿用，该分册同步对齐执行结果（新增“跳过”）与执行环境（关联功能测试环境）语义。
- 与 `docs/01-requirements/07-ai-capability/02-srs-ai-capability.md`（AI 能力总册）：批次复用 AI 任务通用机制（状态、进度、治理、记账），任务状态沿用总册「执行中 → 待采纳 → 已结束 / 已终止」表述，UI 执行批次不产生提案、正常结束直接进入已结束；按本能力专项口径为 UI 执行批次落过程补充记录——中断阶段、已处理条目、token 消耗、中断原因可在任务详情回看，已写入数据不回滚、不清理；其他 AI 能力维持总册口径不变。AI 执行的判定结果不属生成物 / 提案，直接生效并计入执行记录、人工可随时改判，不绕过采纳入口。

### 1.4 与既有功能的关系

本能力与既有功能的边界及联动口径集中如下，概设 / 详设与实现须整体遵循：

- **沿用（不新增、不改动）**：
  - 执行记录链路：AI 判定回写复用手动执行同一链路，进度与通过率统计自动生效（见 3.6）。
  - 计划快照：快照按节点类型保存用例内容（用例 / 前置 / 步骤 / 预期）、计划详情基于快照展示、同步用例规则不变；发起执行时冻结该结构化内容，调用模型时才拼装为正文；手动执行沿用既有快照口径（见 3.3）。
  - AI 任务通用机制：任务状态、失活治理、用量记账、总开关与模型可用性降级均沿用总册口径；进度经现有 REST 接口呈现（见 3.9、4.2）。
- **扩展（既有能力新增取值或来源）**：
  - 执行结果枚举新增"跳过"，仅 AI 执行产生；节点状态图标为五态；进度统计将跳过计为已执行、不计入通过（见 3.6）。
  - 执行记录新增来源标记（人工 / AI），人工改判后来源记为人工（见 3.6、5.1）。
- **变更（既有行为语义改变）**：
  - 计划「执行环境」由自由文本改为关联功能测试环境，展示取环境名称（见 3.2、5.1）。
  - AI 执行批次失败 / 取消（已终止）落过程补充记录（中断阶段、已处理条目、token 消耗、中断原因），可在任务详情回看、已写数据不回滚不清理；本能力不产生提案，过程补充记录只含轨迹与判定明细，不走采纳流程；仅本能力批次适用，其他 AI 能力维持总册口径（见 `docs/01-requirements/07-ai-capability/02-srs-ai-capability.md` 1.5）。
- **迁移（存量数据与兼容）**：
  - 本期不考虑存量自由文本执行环境的转换；计划执行环境列改为 UUID 关联功能测试环境，存量值不做回填（见 5.2）。
  - 既有执行记录来源默认为人工，结果值兼容既有四态（见 5.2）。

### 1.5 定义与缩写

| 术语 | 定义 |
| ---- | ---- |
| AI 执行批次 | 一次「AI 执行」发起的完整执行过程，对应一个 AI 任务实例 |
| 执行上下文 | 批次开始时一次性固化的用例正文、模块锚点、环境内容与预算 |
| 模块锚点 | 用例归属模块的树路径，用作 AI 导航的业务域先验 |
| 动作原语 | 执行端允许执行的受控操作单元，清单白名单制 |
| 观察 | 执行过程中对页面可见状态的采集结果（可见元素、页面语义、截图） |
| 轨迹 | 按用例与步骤归档的动作、失败与判定记录 |
| 凭据占位符 | 密码位置的占位标记，明文密码从不进入模型上下文与轨迹 |
| 预置动作 | 确定性动作序列，由执行端直接执行、不经模型；项目级为默认配置，环境级三态可选继承 / 覆盖 / 禁用 |
| 步级预算 | 单个步骤允许的最多动作次数 |
| 批次预算 | 单个批次允许的模型调用次数、token 与成本上限，与步级预算同时生效、先到者终止 |
| 执行端 | 在浏览器中执行动作、回传观察的组件；不决策、不判定、不持有模型凭据与长期密钥 |

## 2. 总体描述

### 2.1 业务背景与目标

- 用户只维护自然语言用例；UI 改版等操作细节变化由 AI 在执行时消化，用户不维护任何操作脚本与定位细节。
- 目标：自动完成测试计划中用例的执行与判定，产出可信、可回放、可人工改判的结果。
- 一步到位优先：能用一个动作原语完成的操作不拆解为多动作组合；业务语义由 AI 组合决策，执行端不理解业务。

### 2.2 用户角色与场景

| 角色 | 场景 |
| ---- | ---- |
| 发起人 | 在测试计划详情页发起 AI 执行，经确认弹窗配置后开跑，可随时取消批次 |
| 查看与改判人 | 查看批次进度、轨迹与判定依据，通过既有执行记录入口人工改判 |
| 环境维护者 | 配置功能测试环境（入口、账号、预置动作、执行参数） |

权限口径见 3.1、3.2 业务规则：仅校验当前用户是否为当前项目成员，不新增 RBAC 权限码、不校验项目角色；前端显隐按成员归属与业务状态呈现，不按权限码显隐。**已接受风险**：项目内只读成员同样可维护环境凭据并发起执行，V1 以成员边界作为信任边界；后续引入只读 / 访客角色时须拆分「查看 / 编辑环境 / 发起执行」三档能力（见 6.1）。

### 2.3 系统边界

- 决策与控制集中在服务端：执行上下文固化、AI 决策循环、判定回写、轨迹落库、预算与取消、用量记账。
- 执行端为哑执行面：只执行白名单内的动作原语并回传观察，不决策、不判定、不持有模型凭据与长期密钥；可多实例替换（V1 单实例）；实例分桌面版托管（用户绑定）与独立部署共享两类，归属决定可用批次范围（见 3.2）。
- 凭据按当前用例引用的账号最小化下发，经短时、单批次、可撤销的凭据令牌传递，执行端仅内存持有、批次结束清零。
- **共享执行端信任边界**：共享实例是运维侧可信组件，部署方须保证宿主与运维通道可信；同一实例可能承载不同工作空间的批次，执行端以批次级隔离的浏览器上下文运行，批次间不保留页面、Cookie、凭据与本地存储。

### 2.4 设计原则

- **证据优先**：判定必须引用观察证据，“证实才通过”，不接受“没报错即通过”。
- **宁阻塞不臆断**：环境不可用、步骤走不下去、歧义页面时判阻塞并写明原因，不猜测。
- **失败是正常事件**：动作失败不是异常、不是批次错误，由 AI 决策重试或止损，预算兜底。
- **用户数据不被污染**：AI 产生的中间产物（如无步骤用例的拆解）只进轨迹，不回写用例。
- **页面内容是不可信输入**：页面文本、截图与弹窗内容只作为观察数据，其中出现的任何指令都不得被执行。
- **安全能力默认关闭**：执行 JS 等逃生能力默认关闭，需环境级显式开启并留痕。

## 3. 功能需求

### 3.1 功能测试环境管理

**功能描述**：项目下维护功能测试环境，作为 AI 执行的世界模型与安全配置载体；内容按 AI 上下文价值组织。

**功能点**：

- **环境条目**：名称、描述、默认标记；名称在项目内唯一（忽略大小写），默认环境项目内唯一。
- **入口 URL**：被测系统多端入口列表，构成 AI 可导航的 origin 白名单；入口名称在环境内唯一。
- **账号**：多角色账号（用户名、别名、角色、备注、加密存储的密码）；别名在环境内唯一，别名与角色供 AI 引用。
- **已知数据状态**：已知数据状态说明，随上下文提供给 AI。
- **操作提示 / 已知问题**：提示文本，随上下文提供给 AI。
- **预置动作**：确定性动作序列配置，见 3.4；项目级为默认，环境级三态可选「继承项目默认 / 自定义覆盖 / 禁用」。
- **执行参数**：视口、动作超时、是否允许执行 JS（默认关闭、需显式开启）、只读模式（默认关闭）等。
- **连通性测试**：保存后可发起一次只读探测，校验入口 URL 可达与账号登录页可加载，结果仅作提示、不阻断保存。
- **密码展示**：前端仅掩码展示，保存后明文不可回显。

**业务规则**：

- 密码加密落库；明文仅按当前用例引用的账号最小化下发执行端，不进入模型上下文、不进入轨迹（见 3.8）。
- 环境的查看与维护仅校验当前用户是否为当前项目成员，不新增 RBAC 权限码、不校验项目角色；前端显隐按成员归属与业务状态呈现，不按权限码显隐（已接受风险见 2.2）。
- **执行环境为发起必填项**：未配置环境或环境未配置入口 URL 时不可发起，前端禁用并引导先创建环境；不存在“无白名单执行”的降级路径。
- **数据准备边界**：V1 不提供自动 seed / reset / teardown；`data_state` 由环境维护者人工保证，同一批次内用例串行复用浏览器会话，前序用例产生的数据影响由维护者通过环境配置与用例顺序规避（自动重置列为升级项，见 6.1）。
- **只读模式**：开启后 AI 不得执行删除、支付、提交等破坏性动作，识别到即判阻塞并写明原因；该模式是业务约束，不替代动作白名单。

### 3.2 AI 执行发起

**功能描述**：计划详情页新增「AI 执行」入口（Web 版与桌面版双端提供），经确认弹窗配置后发起批次；执行端可用性由后端在发起前置校验中强制把关。

**功能点**：

- **入口（双端）**：计划详情页「AI 执行」按钮，Web 版与桌面版一致渲染；AI 总开关关闭或无可用模型时入口不可用并提示（沿总册口径）；执行端不可用时提示并禁用发起（见业务规则）。
- **模型选择**：提供模型选择项，默认系统默认模型；选择结果作为 `modelId` 提交，服务端校验其可用性并作为本批次实际执行模型（决策与判定同模型）。
- **用例范围**：勾选计划关联用例；不勾选 = 计划关联的全部用例。
- **环境**：必填，默认回显计划绑定的执行环境，可改选。
- **批次参数**：显示步级上限等参数，可调部分开放（默认值见 3.7）。
- **提交**：确认后开跑，进入执行中呈现（3.9）；无计划预览，无逐步确认（V1 全自动）。

**业务规则**：

- **客户端形态**：平台提供 Web 版与桌面版（Electron 壳包裹同一前端）两种形态；AI 执行发起入口与批次查看能力双端一致，测试环境管理属配置能力、双端均可用。入口显隐为前端呈现策略而非安全边界，服务端仅校验当前用户是否为当前项目成员及执行端可用性，不新增 RBAC 权限码、不校验项目角色、不区分客户端形态；前端按成员归属与业务状态呈现入口，不按权限码显隐。
- **执行端归属与分派**：桌面版随登录托管本机执行端实例，注册为该用户的专属实例——仅该用户的批次可分派到其本机；独立部署的命令行执行端为共享实例，任意用户的批次均可分派。分派顺序为**共享实例优先、专属实例兜底**；发起前置校验要求存在在线共享实例或发起人本人的在线专属实例，皆无则发起被拒绝并给出可操作提示，不消耗 AI 预算。
- **执行端忙闲**：V1 不排队——目标实例无空闲容量时直接拒绝发起并提示「执行端忙，请稍后重试」，不创建批次；预检结果同步返回忙闲状态，避免“预检通过、提交失败”。
- 发起权限：仅校验当前用户是否为当前项目成员，不新增 RBAC 权限码、不校验项目角色；批次执行身份记为提交人。
- 计划状态前置：已阻塞、已完成、已关闭的计划不可发起（与既有标记执行结果的状态约束一致）。
- 同一计划存在执行中批次时，服务端在提交时拒绝再次发起并给出重复发起提示；前端预检查仅作提前呈现。
- 执行环境必填且须属于当前项目；未选择环境、环境不存在或环境未配置入口 URL 时拒绝发起（见 3.1）。
- 计划执行环境列为 UUID、关联功能测试环境后回显名称；环境已删除或未绑定时显示「已删除环境」（见 5.2）。

### 3.3 执行批次与上下文固化

**功能描述**：一次 AI 执行为一个批次实例，按计划内用例顺序线性推进；批次开始时一次性固化执行上下文。

**功能点**：

- **批次与推进**：用例级循环（前置阶段 → 逐步执行 → 验证阶段 → 判定回写 → 止损检查）套动作级循环（观察 → AI 决策下一动作 → 执行 → 再观察）；每个动作对应一次模型调用。
- **进度语义**：按“第 N/M 条用例 · 当前用例 · 步骤 x/y · 已执行 a 个动作”呈现进度。
- **上下文固化**：发起即冻结当前计划用例快照，未同步的脑图修改不进本次执行；用例正文按快照节点的 `case / precondition / step / expected` 类型组装，模块锚点取计划模块快照路径，环境内容与预算一并冻结，中途编辑不影响进行中批次、判定可回放。
- **模块锚点**：以用例归属模块树路径作为 AI 导航先验；文档未关联模块时仅凭用例标题与环境提示导航，发现多个相似页面无法确定唯一目标时不操作、判阻塞并写明歧义。
- **会话**：批次内复用同一浏览器会话（真实连续）；是否换账号由用例前置条件决定。
- **取消**：可随时取消（任务状态为已终止）；当前动作完成后停止，已写入的判定与轨迹保留，并落存过程补充记录、可在任务详情回看（仅 UI 执行批次口径）。
- **止损**：批次总时长上限 4 小时；连续 3 条用例阻塞时自动停批并在状态中标注原因；停批或超时后可重新发起（口径见下）。
- **任务治理**：批次在等待动作与模型调用期间持续刷新任务心跳（间隔不超过 60 秒），进度上报活跃的批次不被既有任务失活清扫误杀；失活清扫的 600 秒无心跳阈值与 4 小时批次总时长上限相互独立。

**业务规则**：

- 中途用例被编辑不影响执行中批次；未同步到计划快照的脑图修改不进本次执行（固化语义）。
- 同一计划已有进行中批次时，服务端在提交时拒绝再次发起并给出重复发起提示；前端预检查仅作提前呈现。
- **停批后重新发起**：默认仅重跑「未执行」与「阻塞」用例，通过 / 失败用例不重跑；用户可在发起弹窗显式勾选覆盖。每次重发为独立批次与独立执行记录，历史批次的判定与轨迹保留不回滚，计划统计按用例最新判定聚合。
- 无步骤用例拆解只进轨迹、不回写用例；拆解轨迹按执行轨迹事件留痕（见 3.4）。
- 歧义页面不操作（宁阻塞不臆断）。
- 取消与停批（已终止）不回滚已写结果；过程补充记录可在任务详情回看，本能力不产生提案（仅 UI 执行批次口径）。

### 3.4 步骤执行与动作原语

**功能描述**：以用例步骤为执行骨架，AI 在白名单动作原语范围内自主决策、逐步执行。

**功能点**：

- **步骤骨架**：进度按步骤显示（步骤 x/y）、轨迹按步骤归档、预算按步骤配额；全部步骤完成后进入验证阶段。
- **无步骤用例拆解**：AI 在执行时拆解为步骤序列（至多 10 步）；拆解结果只进轨迹留痕，不回写用例。
- **动作原语（V1 共 15 个执行原语 + 1 个服务端语义出口）**：
  - 导航类：打开地址（限环境入口白名单）、后退、切换标签、关闭标签；
  - 元素交互类：点击、填充（密码位置为占位符）、按键、下拉选择、悬停、滚动；
  - 查询与观察类：按文本定位滚动、等待（单次至多 10 秒，计预算）、截图；
  - 系统类：处理原生确认 / 提示弹窗、执行 JS（逃生舱，见下）；
  - 结束：提交判定（判定值 + 依据）——由服务端消费模型输出后转为会话结束，不下发执行端，故执行端可执行原语为 15 个。
- **白名单即边界**：清单外动作一律拒绝；V1 不提供文件上传、拖拽、富文本专用动作、坐标点击（依赖文件上传的用例按 3.6 判跳过；拖拽与富文本场景在开启 JS 的环境可由逃生舱部分兜底）。
- **JS 逃生舱**：默认关闭，需环境级显式开启；开启后仅当元素级动作无法完成时使用（如画布、组件内部交互）；执行的源码逐字进轨迹，留痕不可配置关闭；仅由 AI 运行时产生，预置动作不含 JS。关闭时下发 JS 动作一律拒绝并按动作失败处理。
- **预置动作**：确定性动作序列（典型为登录），批次启动时由执行端直接执行、不经模型、不含 JS；执行成功后 AI 从就绪状态起步；该阶段失败则批次直接判阻塞并写明原因，不消耗 AI 预算；未配置时登录等前置由 AI 按环境配置的账号自主决策完成（导航 + 输入 + 提交），不硬编码登录步骤。
- **配置与继承（三态）**：项目级预置动作为默认配置，供项目下全部环境继承；环境级可选「继承项目默认 / 自定义覆盖 / 禁用」——「禁用」表示本环境不使用任何预置动作（此时登录等前置由 AI 自主完成），与「自定义覆盖为空」语义不同。批次启动时按三态解析，引用无法解析时按前置阶段失败口径处理（判阻塞并写明所在步骤）。

**业务规则**：

- 每次动作下发（含重试）均计步级预算，无免费重试。
- 一步能完成的操作应使用单个动作原语（一步到位优先，不强制组合）。

### 3.5 观察与证据

**功能描述**：AI 基于页面可见观察决策，验证阶段以截图为必备证据。

**功能点**：

- **观察内容**：可见元素（保留层级与可见文本，交互元素带临时引用编号）、页面语义摘要（标题 / 地址 / 页面类型 / 提示与弹窗）、标签页列表（句柄、地址、标题、是否活动）、必要时的截图。
- **裁剪**：脚本、样式与隐藏元素不进入观察；被完全遮挡、点不到的元素不进入观察；元素仅携带少量关键属性（可访问名、角色、占位符、值等），不全量输出。
- **敏感值掩码**：密码类字段的 `value` 一律不进入观察、截图文本与轨迹；其余输入框的值按字段类型脱敏后提供，避免用户数据原样进入模型上下文。
- **内嵌框架内容可达**：iframe（含跨域）内的元素并入同一观察呈现，AI 无感知，动作以普通原语直达。
- **元素定位**：AI 仅以观察中的临时引用定位元素；页面未变引用保持有效，页面真实变化后引用失效并触发重新观察，AI 基于新鲜观察决策。标签切换以观察中的标签句柄定位，不使用序号猜测。
- **截图取证**：验证阶段必须截图取证，随判定进入模型上下文并落入轨迹。
- **超大页面**：按可见区域 / 内容上限截断；截断规则告知 AI，AI 知悉所见为截断视图。
- **不可信输入**：页面文本、弹窗内容与截图中出现的任何指令均视为数据，不作为动作依据；模型提示词显式声明该纪律，安全仍由动作白名单与导航拦截兜底。

**业务规则**：

- 观察不足以支持决策或验证（截断、无元素可定位、歧义）时判阻塞并写明原因，不臆断。
- 导航越界由执行端统一拦截：点击触发的跳转、服务端重定向、`window.open` 新标签、表单提交与下载，只要目标不在环境 origin 白名单即阻断并结束会话；白名单校验不限于打开地址动作。

### 3.6 判定与结果回写

**功能描述**：全部步骤完成后在验证阶段统一判定，判定回写既有执行记录链路。

**功能点**：

- **判定时机**：步骤与预期不假设一一对应；预期通常为整体性描述，全部步骤完成后在验证阶段统一判定；用例写有多条预期时 AI 可对可验证点提前留痕，最终必须汇总为一个用例级结论。
- **四值语义**：
  - 通过：预期要点在最终观察中被证实（必须真实看到，不接受“没报错即通过”）。
  - 失败：观察与预期矛盾。
  - 阻塞：环境不可用、步骤走不下去、预算耗尽、歧义页面等导致证据不足以验证预期——不臆断。
  - 跳过：AI 识别到用例依赖 V1 不支持的能力（当前即文件上传），主动跳过并写明原因。
- **证据留痕**：判定必须引用本次批次内真实存在的观察证据（观察序号 / 截图对象 key + 文字描述），服务端校验引用存在且属于本用例的验证阶段观察，校验失败不落库并转为阻塞；证据写入执行记录备注。
- **回写**：与手动执行同一执行记录链路，进度与通过率统计自动生效；执行记录来源标记为 AI。
- **统计**：进度统计新增“跳过”计数；跳过计为已执行、不计入通过。
- **人工改判**：随时可通过既有执行记录入口改判，改判记录来源标记为人工；AI 执行的判定结果不属生成物 / 提案，直接生效并计入执行记录、人工可随时改判，不建立提案、不绕过采纳入口（采纳仍是生成类业务数据的唯一写入口）。
- **判定复核**：每批次按不低于 10%（至少 1 条）抽样人工复核，复核结果用于 6.2 的误判率统计与提示词回归。

**业务规则**：

- 每条用例有且仅有一个用例级判定结论。
- 无证据或证据引用校验不通过的判定不得落库。
- 手动标记执行结果不提供“跳过”选项，“跳过”仅由 AI 执行产生。

### 3.7 重试与预算止损

**功能描述**：机械等待、AI 决策重试、熔断止损三层配合，预算为 AI 的自主重试权兜底。

**功能点**：

- **第一层 机械等待**：执行端内建的元素可交互等待（渲染、可点击窗口），不计预算。
- **第二层 决策重试**：动作失败时执行端返回带原因码的失败观察（如不可见、被遮挡、无响应、未找到、超时），AI 自主决定重试、换路或放弃；每次尝试是一次动作下发、占步级预算。
- **第三层 熔断**：步级预算耗尽 → 该步阻塞 → 用例阻塞，证据为耗尽时刻页面状态。
- **预算与止损项**：

| 项 | 默认值 | 语义 |
| ---- | ---- | ---- |
| 步级动作上限 | 50（发起时可临时上调，≤200） | 硬闸：耗尽 → 步阻塞 → 用例阻塞 |
| 拆解步数上限 | 10（无步骤用例） | 防拆解失控 |
| 批次动作总数上限 | 500（发起时可调，≤2000） | 硬闸：耗尽 → 批次终止（已终止） |
| 批次 token 上限 | 3,000,000 | 硬闸：耗尽 → 批次终止，原因写入过程补充记录 |
| 批次成本上限 | 50（计价单位同既有用量统计） | 硬闸：耗尽 → 批次终止，原因写入过程补充记录 |
| 批次总时长 | 4 小时 | 执行侧强制终止 |
| 连续失败停批 | 连续 3 条阻塞 | 自动终止批次并标注原因 |
| 收敛提示 | 步级预算消耗达 80% 时 | 组包注入“请收敛或判阻塞”（软引导） |
| 头铁提示 | 同一动作连续失败 3 次 | 组包注入“建议换路线或止损”（软引导） |

**业务规则**：

- 动作失败不是异常、不是批次错误，不触发批次级错误处理。
- 任何动作下发都计预算，无免费重试；预算的存在即为 AI 自主重试权兜底。
- 步级、批次动作数、token、成本与总时长同时生效，任一先到即终止，终止原因落过程补充记录；批次 token / 成本上限不得只依赖 4 小时时长兜底。
- 通用 AI Task 预算按 `ui_execution` 类型适配器声明的专用 profile 签发，其上限不低于本表批次上限，保证 UI 策略上限先到；通用预算先到的情形视为配置异常并记录。

### 3.8 登录与凭据安全

**功能描述**：凭据在全链路对模型与轨迹不可见。

**功能点**：

- 批次内复用同一浏览器会话；登录由 AI 按环境账号自主决策完成，或由预置动作固化完成（见 3.4）。
- **占位符机制**：账号密码加密存储；模型上下文仅含账号别名、角色与占位符名，明文从不进入；AI 与预置动作的动作参数中密码位置一律写占位符，执行端收到动作后以本地凭据映射替换后执行。
- **最小化下发**：服务端仅下发当前用例引用的账号，按「单批次、单用例、短时」凭据令牌授予，令牌可撤销；用例切换或批次结束时执行端立即清零，不落盘、不写日志、不进入任何回传与截图。
- **共享执行端**：共享实例不持久化任何工作空间数据与凭据，批次间使用隔离的浏览器上下文；凭据访问（授权、使用、撤销）由服务端记录审计。
- 轨迹落库的参数即占位符原文；AI 违规生成疑似明文密码时脱敏打码。
- 验证码、扫码类登录场景 V1 不支持：判阻塞并写明原因。

**业务规则**：

- 模型上下文、轨迹与日志中不得出现密码明文（占位符机制 + 脱敏兜底双层保障）。
- 凭据明文只在执行端内存存在，任何持久化、回传或跨批次复用均视为违规。

### 3.9 批次呈现与轨迹展示

**功能描述**：执行中进度可见、可取消；执行后轨迹与汇总可查。批次呈现与执行详情双端（Web 版 / 桌面版）一致可用——收敛的只是发起入口（见 3.2）。

**功能点**：

- **执行中**：进度经现有 AI 任务 REST 接口呈现（任务详情轮询 + 轨迹 `afterSeq` 游标轮询，≤2s 可见；进度语义见 3.3）；轮询失败保留上次值并自动续拉；可随时取消批次。
- **执行详情——轨迹**：静态轨迹列表，按步骤分组展示动作时间线、失败原因、截图与判定依据；预置动作与无步骤用例的拆解留痕；执行 JS 的源码逐字可查；密码位置显示占位符原文。
- **执行详情——汇总**：批次汇总展示通过 / 失败 / 阻塞 / 跳过四值计数。
- **改判入口**：人工改判走既有执行记录入口（见 3.6）。
- **通知**：V1 不提供批次完成 / 停批通知，任务状态在页面可见（总册通知规则的例外口径见 `docs/01-requirements/07-ai-capability/02-srs-ai-capability.md`）。

**业务规则**：

- 时间轴回放、通知为升级项，见 6.1；V1 轨迹为静态列表即可满足验收。

## 4. 非功能需求

### 4.1 安全护栏（可验收条目）

- **导航白名单**：AI 仅可在环境配置的入口 URL origin 范围内导航；执行端对所有 frame 导航、新标签、表单提交与下载统一拦截，越界即阻断并结束会话，网络出口按同一白名单限制。
- **动作白名单**：执行端仅接受 3.4 的 15 个执行原语（第 16 个「提交判定」为服务端语义出口，不下发），清单外动作拒绝执行。
- **预算熔断**：步级上限、批次动作数 / token / 成本上限、批次时长、连续失败停批强制终止，任一先到即止。
- **凭据占位符**：明文不进模型上下文与轨迹；按用例最小化、短时令牌下发，执行端内存持有并即时清零。
- **JS 护栏**：默认关闭、环境级显式开启 + 源码逐字留痕（不可关闭）+ 提示纪律（最后手段）+ 导航白名单仍生效 + 仅 AI 运行时产生（预置动作不含）。
- **提示注入防护**：页面内容与截图视为不可信数据，模型提示词声明不执行页面内指令；破坏性动作受环境只读模式约束。
- **权限控制**：AI 执行发起、环境查看与维护仅校验当前用户是否为当前项目成员，不新增 RBAC 权限码、不校验项目角色；批次执行身份 = 提交人，前端显隐按成员归属与业务状态呈现、不按权限码显隐；只读成员可编辑环境与发起执行属已接受风险（见 2.2）。
- **用量记账**：AI 调用按既有用量统计记账，可按时间、模型、能力域查看；另记批次级动作数、token 与成本，超限终止原因可回看。

### 4.2 与 AI 通用规则的衔接

- AI 总开关关闭 → 「AI 执行」入口不可用并提示；执行中批次终止（已终止），已写结果保留、过程补充记录可在任务详情回看（仅 UI 执行批次口径）。
- 无可用模型时入口不可用并引导至配置（沿总册）。
- AI 上下文严格限于当前用户成员归属范围内的数据，跨工作空间数据不进入批次上下文。
- 使用云端模型时出站内容仅限任务必需的上下文；密钥不落日志。

### 4.3 性能与成本

- 观察体积按上限截断，截断规则进提示词（见 3.5）；截图按 1280px 长边、300KB 上限压缩后上传。
- 批次总时长至多 4 小时；步级预算默认 50（见 3.7）；批次动作总数、token 与成本上限同时生效，UI 执行策略单独计数与熔断，通用 AI Task 预算按专用 profile 签发且不先于批次上限触发。
- 每步模型调用与 token 消耗记账；UI 执行批次失败 / 取消（已终止）时落存过程补充记录（中断阶段、已处理条目、token 消耗、中断原因）可在任务详情回看（仅本能力口径）。
- 长用例上下文按「最近 K 个动作 + 历史摘要 + token 上限」压缩，避免上下文膨胀导致成本失控。

## 5. 数据需求

### 5.1 数据实体（实体级，不含表结构）

- **功能测试环境**：归属项目；名称（项目内唯一，忽略大小写）、描述、默认标记（项目内唯一）、入口 URL 列表（环境内名称唯一）、账号列表（用户名 / 别名（环境内唯一）/ 角色 / 备注 / 密码密文）、已知数据状态、操作提示、预置动作三态（继承 / 覆盖 / 禁用）、执行参数（视口 / 动作超时 / 是否允许执行 JS（默认关闭）/ 只读模式）。
- **项目级预置动作**：归属项目、每项目一份的默认确定性动作序列，供项目下全部环境继承。
- **AI 执行批次**：复用 AI 任务实体（类型、状态（执行中 → 已结束 / 已终止，本能力不产生待采纳态）、进度、模型、发起人、起止时间、失败原因、失败 / 取消时的过程补充记录（中断阶段、已处理条目、token 消耗、成本、中断原因）），输入为冻结的结构化上下文（用例节点按类型区分、模块锚点、环境内容、步级与批次预算；模型调用前才拼装为正文），结果为批次汇总（通过 / 失败 / 阻塞 / 跳过计数）。
- **动作轨迹**：归属批次、计划与快照用例；批次内全局序号与用例内序号、阶段（前置 / 步骤 N / 验证 / 拆解）、记录类型（动作 / 动作失败 / 判定 / 备注）、动作名、目标引用、参数（占位符原文、JS 源码）、失败原因码、观察摘要、完整观察（失败动作与验证阶段留存）、截图引用、token 消耗。
- **执行端实例**：实例标识、模式（桌面版托管 / 独立部署）、归属用户（共享为空）、在线状态、当前批次、租约到期时间、容量、最后心跳。
- **执行记录扩展**：来源（人工 / AI）；执行结果值新增“跳过”。
- **计划执行环境**：计划关联的功能测试环境 UUID 标识（替代原自由文本）。

### 5.2 既有数据与迁移说明

- 本期不考虑存量自由文本执行环境的转换：`ft_plan.environment` 列改为 UUID 类型、存功能测试环境 ID，存量值不回填；新增 `ft_environment` 表承载环境实体。
- 既有执行记录来源默认为人工；执行结果兼容既有四态，“跳过”为新增值。
- 数据库变更同时交付全量基线（`schema.sql`）与版本化迁移脚本，存量库按迁移脚本顺序升级并附回滚说明（数据库规范 §5）。
- 新增实体满足 C5（`id` / `created_at` / `updated_at` / `is_deleted`、UUID 框架默认策略、无物理外键）与 C9（索引规范）；DDL 与新增错误码号段留详细设计统一分配。

### 6.1 V1 升级项（范围外，后续版本）

时间轴轨迹回放；批次完成 / 停批通知；项目级执行端池与并行多执行端、排队与容量调度；环境数据自动 seed / reset / teardown；逐步确认模式；执行前拆解预览；拖拽 / 富文本专用动作；iframe 内 JS 定位；批量多动作（一次调用多动作）；批次级 AI 自主排序；环境级 JS 助手库；预置动作扩展至非登录场景；画框截图默认化；只读 / 访客角色的「查看 / 编辑环境 / 发起执行」三档权限；批次断线续跑；任务进度与轨迹合并轮询接口。

### 6.2 验收基准（AI 判定可信度）

- **黄金用例集**：不少于 60 条，覆盖登录、增删改查、表单校验、文件上传跳过、环境不可用阻塞、歧义页面、原生弹窗、iframe 内操作与只读模式拦截；每条固定期望结论与关键证据点。
- **执行轮次**：同一模型与提示词版本至少全量执行 3 轮，记录每轮结论。
- **准入门槛**：
  - 误通过率（应失败 / 阻塞却判通过）≤ 3%；
  - 误失败率（应通过却判失败）≤ 5%；
  - 阻塞率 ≤ 20%；
  - 判定可复现率（3 轮结论一致）≥ 95%；
  - 证据引用服务端校验通过率 100%（不允许引用不存在的观察或截图）。
- **回归要求**：模型、提示词场景或判定规则变更须重跑黄金集并留存对比结果；未达门槛不得作为默认启用能力，须先修复或降级为人工确认模式。
- **抽样复核**：每批次不低于 10%（至少 1 条）人工复核，复核结论计入上述指标。
