## 1. 追溯矩阵

### 1.1 总体描述

追溯矩阵是平台级业务能力：对「需求 ↔ 测试资产 ↔ 验证活动」之间的对应关系进行登记、维持与回溯。它回答两类问题——每条需求生出了哪些模块、脑图文档与测试用例、被哪些评审与计划验证过；每个测试资产服务于哪条需求。追溯矩阵独立于承载形态存在：无论入口与视图如何组织，对应关系都是必须持续登记、维持与回溯的事实。

**业务定位**：

- **需求对应关系的账**：登记需求的下游对应与测试资产的来源对应，回答测试资产"为什么存在、为谁而存在"。
- **归属与来源分离**：测试资产的归属（模块树中的位置）由既有业务数据自行维护，可随时移动、重组；来源（服务于哪条需求）不随结构变化——结构变化不得丢失来源，来源对应独立登记、独立回溯。
- **业务结论的地基**：覆盖评估、缺口清单、变更影响均从对应关系推导得出。

**业务价值**：

- **资产来源可治理**：测试资产可回答"为什么存在、服务哪条需求"，避免无来源资产堆积、删改失据。
- **变更可控**：需求变更的影响范围可枚举、可核对，不依赖人工记忆。
- **覆盖有基准**：以需求为基准度量"测到什么程度"，覆盖结论有据可查。
- **验证有归属**：评审与计划验证了哪些需求、验证到什么程度，有据可查。
- **AI 产出可审计**：AI 生成的测试资产可回答从哪来、由谁确认。
- **历史可还原**：历史对应关系与修正痕迹可回溯，满足审计与复盘。

**验收口径**（满足以下四问方视为成立）：

- 发布前：任选一条需求，可一次说清其全部测试支撑与当前状态；
- 任一时点反查：任选测试资产，可说明其来源需求（或明确无来源）、参与的验证活动及其针对的内容版本；
- 需求变更：受影响清单完整、不依赖人工记忆，处理结果有归属；
- 审计与复盘：历史对应关系与修正痕迹可还原。

**与相邻业务域的关系**：

- 需求管理：需求条目是追溯的起点与粒度，管理行为见 `docs/01-requirements/06-requirement-management/02-srs-requirement-management.md`；
- 功能测试：模块、脑图文档、测试用例、测试评审与测试计划的组织与快照机制见 `docs/01-requirements/03-function-testing/02-srs-business-features.md`；
- AI 能力：AI 生成测试资产时按追溯矩阵的要求建立来源对应（`docs/01-requirements/07-ai-capability/03-srs-ai-generation.md`）。

### 1.2 定义与缩写

| 术语 | 定义 |
| ---- | ---- |
| 追溯矩阵 | 登记与回溯需求、测试资产、验证活动之间对应关系的平台级业务能力 |
| 对应关系 | 追溯矩阵登记的关系总称，含来源对应与验证对应两类 |
| 来源对应 | 需求条目与由其生成、派生的模块、脑图文档、测试用例之间的对应 |
| 验证对应 | 测试用例与使用该用例的测试评审、测试计划之间的对应，记录引用时点的内容版本 |
| 结构归属 | 模块 ▸ 脑图文档 ▸ 测试用例的组织关系，由功能测试数据维护，追溯不重复登记 |
| 关系业务事实 | 对应关系上的建立方式、确认与冲突、时效状态与修正记录 |
| 人工修正 | 对建立有误或已不成立的对应关系进行纠正的操作总称，含更正来源、清除关联与恢复 |
| 更正来源 | 对应关系挂错对象时，更正为正确的对象 |
| 清除关联 | 将已不成立的对应关系作废；记录保留、可恢复 |
| 恢复 | 还原已清除的对应关系 |
| 覆盖评估 | 以需求为基准、结合对应关系与验证情况判定覆盖程度的业务结论 |
| 缺口 | 未覆盖需求、无来源用例、未评审用例、未进计划用例四类待补齐事项 |
| 变更影响 | 需求变更后沿对应关系推导出的下游受影响项清单与处理状态 |

### 1.3 对应关系登记与回溯（US-TR-001）

**功能描述**：登记并维持需求与测试资产、验证活动之间的对应关系，支持双向回溯。  
**功能点**：

- **来源对应**：需求与其生成的模块、脑图文档、测试用例之间建立来源对应；由需求可列出全部下游资产，由任一资产可回溯其来源需求。
- **跨模块成立**：资产所在模块、文档与来源需求相互独立；资产在模块树中移动、重组不影响来源对应。
- **验证对应**：测试用例与被其参与的测试评审、测试计划之间建立验证对应，记录引用时点的用例内容版本；由用例可查参与的验证活动，由评审 / 计划可查验证的用例与需求。
- **结构归属解析**：模块 ▸ 文档 ▸ 用例的层级由功能测试数据维护，追溯不重复登记；回溯时须能解析完整层级，保证链路完整。
- **双向回溯**：任一节点均可向上回溯至来源需求、向下下钻至验证活动。

**业务规则**：

- 来源对应与结构归属相互独立：结构调整不得丢失来源对应。
- 验证对应与其引用时点的内容版本绑定：内容后续变化不改变既有验证记录的对象，但须能识别其针对的版本。
- 平台不提供需求删除，需求仅可归档；归档需求的历史对应关系保留可查。

### 1.4 关系可信与人工修正（US-TR-002）

**功能描述**：对应关系携带可核验的业务事实，支持人工修正，修正结果优先。  
**功能点**：

- **关系业务事实**：每条对应关系记录建立方式（AI 建立 / 人工建立）、确认状态（待确认 / 已确认 / 存在冲突）、时效状态（内容变更后是否仍作数）与修正记录（动作、操作人、时间、原因）。
- **更正来源**：对应关系挂错对象时，更正为正确的对象（例如将测试资产的来源需求更正为另一条需求）；更正后该项以人工结论为准。
- **清除关联**：对应关系已不成立时将其作废（例如某用例不再服务任何需求，其后以「无来源用例」出现在缺口清单中）；清除可恢复、历史保留。
- **恢复**：清除有误或业务上恢复时，还原已清除的对应关系。
- **优先规则**：人工修正优先于 AI 判断；已清除或经人工修正的对应关系，AI 不得自动恢复或重建。
- **AI 来源治理**：AI 生成的测试资产在采纳落库时同步建立来源对应；每个 AI 产出必须能回答从哪来、由谁确认。

**业务规则**：

- 时效状态在相关内容版本变化后自动标注，供人工重新确认。
- 已清除的对应关系不参与覆盖评估、缺口清单与变更影响的统计，但保留可查。
- 修正历史保留、不可抹除；更正来源、清除关联与恢复须记录操作人、时间与原因。

### 1.5 覆盖评估与缺口清单（US-TR-003）

**功能描述**：以需求为基准给出覆盖结论，并提供可直接行动的缺口清单。  
**功能点**：

- **覆盖评估**：按需求条目给出覆盖结论（已覆盖 / 部分覆盖 / 未覆盖），结论附判定依据（相关用例与验证情况）并可核验；支持人工复核修正，人工结论优先且不被自动覆盖。
- **缺口清单**：给出未覆盖需求、无来源用例、未评审用例、未进计划用例四类缺口；每项指向可执行的下一步（发起生成、发起评审、加入计划等），动作在对应业务入口完成。
- **待分析口径**：无覆盖结论的需求按「待分析」展示，不计入覆盖与未覆盖统计。

**业务规则**：

- 覆盖结论以需求为粒度；"存在对应关系"不机械等同于已覆盖，须结合验证情况综合判定。
- 已归档需求不作为生成与覆盖评估的有效输入，且不纳入缺口统计。

### 1.6 变更影响与处理（US-TR-004）

**功能描述**：需求变更后给出受影响清单，并追踪处理状态与结果。  
**功能点**：

- **受影响清单**：已确认需求的标题、描述或所属模块变更后，状态转入「已变更」，同时沿对应关系列出受影响的下游对象（模块、脑图文档、测试用例，及其参与的评审 / 计划快照）。
- **处理与状态**：受影响项逐项处理，处理方式包括重新生成、重新评审、同步最新内容与确认无影响等；处理在对应业务入口执行，追溯侧记录处理状态、操作人与理由。
- **刷新**：需求重新确认后可刷新影响标记；已确认无影响的项在刷新后保留处理结果。

**业务规则**：

- 影响标记不阻断下游编辑，下游数据可正常维护。
- 未重新确认的需求不作为 AI 生成的有效输入；刷新前保留原标记并提示。
- 处理动作不直接修改下游内容，追溯只记录状态与依据。

### 1.7 非功能需求

- **可回溯性**：任意时点支持双向回溯（需求 → 资产、资产 → 需求），结构层级可完整解析。
- **历史完整性**：对应关系的人工修正记录与影响处理记录保留；需求归档后历史链路保留可查。
- **隔离与权限**：追溯数据限定在所属项目与工作空间内；查看与修正权限分离，修正、覆盖复核与影响处理需相应授权。
- **降级**：AI 能力未启用时，追溯矩阵的查看能力与既有数据不受影响。

### 1.8 数据需求

**功能描述**：定义追溯矩阵涉及的数据实体及其关系（实体级，不含表结构）。  
**功能点**：

- **对应关系**：来源对应与验证对应两类，记录关系双方对象与引用时点的内容版本；是对应回溯、覆盖与影响结论的唯一事实依据。
- **关系业务事实**：建立方式、确认与冲突、时效状态、修正记录（更正来源 / 清除关联 / 恢复）。
- **覆盖结论**：按需求的覆盖判定、判定依据与人工复核记录。
- **缺口**：四类缺口清单与建议动作。
- **变更影响标记**：受影响项与处理状态、操作人、理由。

**业务规则**：

- 所有实体通过项目归属到工作空间，遵循既有数据隔离约定。
- 对应关系与修正记录不物理删除，以状态与留痕承载生命周期。
