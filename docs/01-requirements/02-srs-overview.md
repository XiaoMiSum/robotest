## 1. 引言

### 1.1 编写目的

本文档定义软件测试平台的功能需求与非功能需求，面向项目经理、业务分析人员、测试工程师及开发团队，确保各方对平台的行为、规则和边界有一致理解。本版本在既有业务功能需求之外，一并完整描述 AI 智能辅助能力域的需求。

### 1.2 范围

平台包含两类用户角色：**系统管理员**和**业务用户**。  

- 系统管理员拥有全局管理权限，可管理用户、工作空间和角色。  
- 业务用户可同时归属多个工作空间，通过切换活跃工作空间在不同工作空间间工作，所有业务操作限定在当前活跃工作空间内。

测试用例以 **模块树（目录/文档）** 组织，每个文档包含一个脑图形式的测试用例集合，支持多人实时协作编辑。  
测试评审和测试计划基于用例的结构化快照进行，支持完整的历史回溯和多次执行/评审记录。

平台在上述业务功能之上提供 **AI 智能辅助能力域**，覆盖五个方向：

1. **智能测试用例生成** — 在脑图中由 AI 生成用例子树、补全步骤、推荐优先级，配套轻量需求池；
2. **AI 辅助评审与覆盖度分析** — 评审快照的完整性检查、评审摘要生成、遗漏测试点分析；
3. **缺陷智能分析与去重** — 缺陷标题优化与等级建议、语义查重、缺陷聚类分析；
4. **全局智能助手（ChatBot）** — 自然语言查询、快捷操作执行、对话式脑图编辑、平台使用指引；
5. **测试计划与风险评估** — 执行顺序推荐、用例规划智能推荐。

AI 功能均为既有业务流程的**增强项**，不改变既有业务规则与状态机；AI 能力不可用时，平台全部既有功能必须不受影响（见 4.4 可靠性需求）。

### 1.3 定义与缩写

| 术语         | 定义                                         |
| ---------- | ------------------------------------------ |
| 活跃工作空间     | 业务用户登录后选择的工作空间，所有业务操作默认在该工作空间上下文中执行        |
| 模块         | 项目内测试用例的组织结构，分为**目录**和**文档**两种节点           |
| 目录         | 仅用于分类的模块节点，不包含测试用例                         |
| 文档         | 关联一个脑图的模块节点，包含若干测试用例                       |
| 脑图文档       | 以思维导图形式组织的测试用例集合，由多个节点组成                   |
| 测试用例（用例节点） | 脑图中被标记为“用例”的节点，具有步骤、预期结果等属性                |
| 快照         | 评审或计划创建时对模块树和文档节点的完整复制，用于固化当时的状态           |
| 关联节点       | 用户在创建评审或计划时显式选择的用例节点                       |
| 关联节点树      | 从快照中裁剪出的最小树形结构，包含所有关联节点、它们的祖先模块/文档节点以及后代节点 |
| 同步         | 手动将评审或计划的快照更新为当前最新模块和用例内容的操作               |
| LLM        | 大语言模型（Large Language Model），平台通过外部或私有化部署的模型服务获得生成能力 |
| AI 网关      | 后端统一封装 LLM 调用的服务层，负责模型路由、Prompt 组装、流式输出、限流与审计 |
| 智能体        | 平台内每个 AI 功能对应的执行单元，其行为由系统提示词模板（角色指令段 + 输出格式约束段）定义，系统管理员可自定义 |
| 系统默认模型     | 多个对话模型配置中被管理员指定的全局默认项（有且仅有一个）；用户未选择或所选模型失效时，以及后台任务与建议类功能，均使用该模型 |
| 需求池        | 项目级的轻量需求条目库（粘贴的需求文本），供 AI 生成/补全/分析时选作上下文，减少重复手动输入 |
| 向量检索       | 将文本转换为向量（Embedding）后按语义相似度检索的能力           |
| 工具调用（Function Calling） | LLM 按预定义的工具清单发起结构化调用，由后端以当前登录用户身份执行的机制 |
| 预览-确认-执行    | AI 涉及写操作时的强制交互模式：先展示将要执行的操作明细，用户确认后才真正执行 |
| 脑图操作指令集     | 一组受限的结构化脑图操作描述（筛选条件 + 动作），AI 只负责将自然语言翻译为指令，执行由前端确定性代码完成 |
| 推荐执行指数      | 综合用例历史缺陷关联数量、优先级、模块风险等因素计算的执行顺序参考分值      |

## 2. 总体描述

### 2.1 用户角色与特征

| 角色    | 职责概述              | 权限边界                         |
| ----- | ----------------- | ---------------------------- |
| 系统管理员 | 平台全局维护            | 拥有系统权限，可访问系统管理功能；可同时归属工作空间 |
| 业务用户  | 所属工作空间内的测试活动管理与执行 | 拥有工作空间权限，所有业务操作限于当前活跃工作空间 |

- 一名用户可同时拥有多个系统角色和多个工作空间角色。
- 系统管理员由系统初始化时预设，不可被删除。
- 业务用户至少归属一个工作空间才能使用业务功能。
- 权限模型采用 RBAC，权限码按作用域分为 `global`（系统级）和 `workspace`（空间级）两类。

AI 能力在此角色模型（系统管理员 / 业务用户，RBAC 权限，`global` / `workspace` 双作用域）基础上补充如下约定：

- AI 功能仅面向**业务用户**开放，且所有 AI 操作严格限定在当前活跃工作空间与当前项目上下文内。
- AI 以当前登录用户的身份与权限执行读写操作，**不拥有任何独立权限**；用户无权执行的操作，AI 同样无权执行。
- 系统管理员可在系统级维护 AI 配置（模型服务地址、密钥、开关）与各智能体的提示词。
- 范围粒度约定：全局智能助手的自然语言查询范围为当前**工作空间**级（与助手全局入口定位一致）；语义查重、缺陷聚类、覆盖度分析等业务内嵌 AI 能力均限定当前**项目**级。

### 2.2 假设与依赖

- 平台账号由系统管理员统一创建，不存在自主注册功能。
- 平台具备基本的日志与审计能力（本文档不展开）。
- 脑图编辑器的前端技术选型及实时协作实现方案不影响业务需求的定义。
- 平台可访问一个兼容主流协议的 LLM 服务（公有云 API 或私有化部署），模型选型不影响业务需求定义。
- 语义检索类需求依赖文本向量化（Embedding）服务提供的向量检索能力。
- LLM 调用存在延迟（秒级）与费用成本，交互设计需明确加载态与流式反馈；具体成本策略由运营决定。
- 业务数据（用例、缺陷等）将作为 Prompt 上下文发送至 LLM 服务，数据出域合规性由部署方通过模型选型（如私有化部署）保障。

### 2.3 实施分期

按价值/成本比排定优先级，供迭代规划参考（非承诺性约束）：

| 梯队 | 需求范围 | 说明 |
| ---- | ---- | ---- |
| 一 | AI 基础设施、用例子树生成、步骤补全、评审摘要 | 复用度最高，快速见效 |
| 二 | 缺陷表单建议、评审一键检查、需求池、遗漏测试点分析（关键词版）、助手使用指引 | 反哺一梯队质量，ChatBot 只读首发 |
| 三 | 缺陷语义查重、遗漏测试点分析（语义升级）、用例规划智能推荐、助手自然语言查询、执行顺序推荐 | 依赖向量检索基建 |
| 四 | 助手快捷操作、对话式脑图编辑、缺陷聚类看板、优先级推荐 | 写操作型 AI，需严格风险管控 |

> 分期依赖说明：3.4.1、3.4.2、3.5.3、3.8.2 中「从需求池选取条目」的功能点依赖需求池（3.4.4，梯队二）交付后启用；梯队一交付时相关功能仅支持手动输入需求文本，不影响主流程可用性。

## 4. 非功能需求

### 4.1 性能需求

- 常规页面首屏加载时间不超过2秒。  
- 工作空间切换后数据刷新应在500毫秒内完成。  
- 脑图文档（含200个以上节点）打开时间不超过1秒。  
- 快照生成操作应在500毫秒内完成（对于200节点规模的文档）。  
- 系统应支持至少100名业务用户同时在线操作。
- AI 生成类请求（用例子树、摘要等）流式输出的首内容返回时间目标值为 3 秒（受外部 LLM 服务影响，为目标值而非硬性门槛）；超过 10 秒未返回首内容时提示用户可取消或重试；单次生成总时长超过 60 秒时允许用户取消。
- 优先级推荐、语义查重等表单内嵌 AI 能力不得阻塞用户的正常输入与提交操作。
- 语义查重检索（不含向量化耗时）应在 500 毫秒内返回。
- 异步分析任务（评审检查、缺陷聚类）执行期间不影响页面其他操作，任务状态可查询。

### 4.2 安全性需求

- 用户身份认证应安全可靠，会话超时后需重新登录。  
- 业务操作必须验证用户所属的活跃工作空间，严格隔离不同工作空间的数据。  
- 登录失败次数过多时应临时锁定账户。  
- 应防范常见的Web安全攻击（如跨站脚本、跨站请求伪造）。  
- 实时协作通道也应进行身份验证和工作空间上下文校验。
- LLM 服务密钥仅存于后端配置，严禁下发前端或写入日志。
- 所有 AI 接口经过与普通业务接口相同的认证、工作空间上下文校验与权限校验；工具调用不得绕过 Service 层业务规则。
- 防范 Prompt 注入：用户输入与业务数据作为上下文时须与系统指令隔离；AI 输出在执行/落库前必须经过结构化校验（schema、枚举、长度）。
- AI 会话与调用审计数据按工作空间隔离；会话的对话内容与生成内容仅本人可见，审计权限用户仅可见 AI 调用审计元数据（用户、功能类型、耗时、token 用量、结果状态），不可见对话内容。

### 4.3 可用性需求

- 脑图编辑器应提供常用键盘快捷键（如Tab/Enter创建子节点，Delete删除节点）。  
- 工作空间切换器应固定在界面明显位置，当前活跃工作空间状态清晰可见。  
- 在快照展示页面，应明确标识“快照版本”和生成时间。  
- 同步操作应提供二次确认，防止误操作。  
- 执行历史和评审历史应支持按时间排序查看。
- 所有 AI 入口有统一的视觉标识；AI 生成的脑图节点落库后保留 AI 标识徽标，用户可持续区分 AI 生成内容与人工内容。
- 生成/分析过程提供明确的加载态与进度反馈，支持取消。
- 所有涉及数据写入的 AI 操作遵循预览-确认-执行模式，且执行后可撤销（脑图内操作）或可追溯（业务对象操作）。
- AI 建议类结果（优先级推荐、等级建议、遗漏测试点）均为非侵入式呈现，用户可忽略。

### 4.4 可靠性需求

- 系统应保证7×24小时可用，计划内维护时间每月不超过2小时。  
- 数据应每日自动备份，支持恢复，数据丢失不超过24小时。
- AI 服务不可用或超时，平台全部既有功能必须完全不受影响；AI 入口自动降级为不可用提示。
- 异步 AI 任务失败必须给出明确的失败原因提示，支持重试。
- 向量索引更新失败不得阻断缺陷的正常创建与修改，允许索引异步补偿。

### 4.5 成本控制需求

- 按用户维度限制 AI 调用频率；系统管理员可查看调用量统计。
- 长文本上下文（快照树、缺陷库）送入模型前应做裁剪与分批，避免不必要的 token 消耗。

## 5. 数据需求

### 5.1 核心数据实体及其关系

- **用户**：存储账号信息、角色及状态，与工作空间为多对多关系。  
- **工作空间**：存储工作空间基本信息，是业务资源隔离的基本单位。  
- **项目**：归属于某个工作空间，包含若干模块和缺陷。  
- **测试用例模块**：形成树形结构，节点分为目录和文档。  
- **脑图节点**：归属于某个文档，形成树形结构，节点可标记为用例节点，用例节点包含测试属性。  
- **测试计划**：归属于项目，包含计划信息，与快照关联。  
- **计划快照**：计划创建时生成的模块和节点副本，与执行记录关联。  
- **测试评审**：归属于项目，包含发起人、参与者列表，与快照关联。  
- **评审快照**：评审创建时生成的模块和节点副本，与评审记录关联。  
- **缺陷**：归属于项目，可关联原始用例和测试计划，具有状态流转和操作日志。

AI 智能辅助能力域引入以下数据实体：

- **需求池条目**：归属项目，存储条目标题、需求文本、来源 URL（仅记录出处，不抓取）、更新人与更新时间。
- **文档需求关联**：脑图文档与需求池条目的关联关系。
- **AI 调用审计**：记录每次 AI 调用的用户、工作空间、项目、功能类型、实际使用的模型、耗时、token 用量与结果状态。
- **AI 会话**：全局助手的会话与消息记录，归属用户，按工作空间隔离。
- **缺陷向量索引**：缺陷标题/描述的语义向量，与缺陷记录一一对应，用于语义查重与聚类。
- **AI 分析结果**：评审检查、评审摘要、缺陷聚类、执行顺序推荐等分析/生成任务的结果快照，含生成时间，可覆盖刷新（评审摘要重复生成覆盖上一份、推荐指数随快照重新同步失效，见对应功能条目）。
- **智能体提示词模板**：仅当系统管理员自定义覆盖时，为对应智能体落库一条覆盖记录（存储自定义的角色指令段、输出格式约束段与格式约束段编辑开关）；默认模板随代码内置，不落库；恢复默认即删除覆盖记录。
- **AI 对话模型配置**：多条对话模型配置记录，每条含显示名、供应商标识、服务地址、密钥（加密存储）、模型名、附加参数、启用状态与是否默认；全系统有且仅有一条默认记录。Embedding 配置保持系统级单一配置，不随本实体多行化。

所有新增表遵循平台数据库规范（C5：必含 `id`、`created_at`、`updated_at`、`is_deleted`（逻辑删除标记），禁止物理外键）；索引设计遵循平台索引规范（C9），缺陷语义检索所需索引的具体类型在详细设计中确定。

### 5.2 数据隔离与生命周期

所有业务数据（项目、用例、计划、评审、缺陷）均通过工作空间归属进行隔离，确保业务用户只能访问其当前活跃工作空间内的数据。

- 全部 AI 相关数据通过工作空间/项目归属隔离，遵循平台统一的数据隔离原则。
- 需求池条目随项目删除而删除，文档与条目的关联随任一方删除而解除；缺陷向量随缺陷删除同步失效（缺陷为逻辑删除，语义查重与聚类检索必须排除已逻辑删除的缺陷）；AI 会话支持用户自行清空。
- AI 调用审计与会话历史的保留期限为系统配置项，超期数据支持归档清理。
- 发送至 LLM 服务的业务数据不在平台外持久化的合规责任由模型服务选型保障（见 2.2）。

### 6.2 附录 B：登录跳转逻辑

用户在登录前，系统首先检查初始化状态：

1. 若系统未初始化（无任何用户）→ 自动跳转至 `/init` 初始化页面
2. 若系统已初始化 → 正常展示登录表单

用户登录成功后，系统根据以下条件决定跳转目标：

1. 若用户拥有工作空间 → 跳转至 `/workspaces`（我的空间页面）
2. 若用户无工作空间：
   - 拥有任意系统权限 → 跳转至 `/admin/dashboard`（系统管理仪表盘）
   - 无系统权限 → 跳转至 `/workspaces`（我的空间页面）
