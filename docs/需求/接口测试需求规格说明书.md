**文档版本**：V1.2
**日期**：2026-08-05
**状态**：起草中

## 1. 引言

### 1.1 编写目的

本文档定义软件测试平台**接口测试**业务域的功能需求与非功能需求，面向项目经理、业务分析人员、测试工程师及开发团队，确保各方对接口测试模块的行为、规则和边界有一致理解。

设计灵感参考 MeterSphere v3.x 接口测试产品形态（`https://metersphere.io/docs/v3.x/user_manual/api_test/intro/`），结合本平台既有的空间管理、功能测试、缺陷管理等能力域进行裁剪与适配；凡与本文档冲突之处，以本文档为准。

### 1.2 范围

本文档覆盖接口测试业务域的完整链路：

1. **快速调试** — 面向开发与联调阶段的单请求快速验证，支持**服务端执行**与**本地执行**两种模式（支持导入 cURL）；
2. **接口管理** — 接口资产的集中管理（新建、导入、引用关系、变更历史）；
3. **Mock 服务** — 模拟接口返回，解除联调依赖；
4. **测试场景** — 多步骤编排的场景级自动化（步骤即取样器，支持 http/jdbc）；
5. **环境管理** — 项目级环境配置（默认配置、数据源、全局变量、全局前置/后置处理器，配置项与 Ryze 对应一致）；
6. **接口测试报告** — 场景执行结果的查看、分享、导出与删除；
7. **公共能力** — 请求参数模型、前置/后置处理器、验证器、内置函数、执行引擎；
8. **导入** — 独立功能：从 GitLab 仓库选择测试类方法，可选择**可执行导入（源码导入）**（解析 `@Test` + `@RyzeTest` 注解测试方法的 resource path yaml 为平台可执行场景，仅导入场景本身）或**元数据导入（仅描述）**（测试类全限定名、类级注解配置、类下测试方法清单与场景描述，仅描述不解析为可执行场景，供仓库流水线执行触发）；
9. **仓库流水线执行** — 平台通过 GitLab API 传递选中的测试类元数据触发该仓库 CI 流水线（完整测试/指定接口测试/指定场景测试），由 GitLab 侧执行测试，平台拉取流水线状态与报告产物生成平台报告；执行对象为元数据导入（仅描述）的场景；
10. **全局资产** — 项目级维护可复用的前置/后置处理器、验证器、提取器资产，快速调试与测试场景中可复制引入使用；
11. **定时任务** — 接口导入与场景执行的统一周期调度（Cron 表达式、执行记录与失败查看），任务归属项目。

不包含（首期范围）：非 HTTP/JDBC 协议支持（首期仅 HTTP/HTTPS 与 JDBC 取样器，数据模型与执行引擎按多协议扩展预留）、Mock 服务独立部署形态、除 GitLab 外其他 CI 平台的集成调度（Jenkins 等，纳入后续梯队评估）；平台不替代 GitLab CI 的流水线定义与管理（流水线在仓库 `.gitlab-ci.yml` 中定义，平台仅提供触发入口与结果回传）。

### 1.3 与既有文档的关系

- 平台总体需求（系统管理、空间管理、功能测试、缺陷管理、AI 能力域）见 `docs/需求/需求规格说明书.md`（V1.1），本文档为接口测试业务域的独立需求基线，两者为并列关系。
- 术语、角色模型（系统管理员 / 业务用户、RBAC 权限、`global` / `workspace` / `project` 作用域）、数据隔离原则等沿用 `docs/需求/需求规格说明书.md` V1.1 定义，本文档不重复描述。
- 本文档新增定义见 1.4 定义与缩写。
- 本文档版本号独立编排：自接口测试业务域需求基线建立即启用 V1.3（直接基于上一版修订），后续沿本文档版本线演进。

### 1.4 定义与缩写

| 术语              | 定义                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 接口定义            | 被测接口的规范化描述（协议、方法、路径、请求参数、响应示例等），作为测试场景与 Mock 服务的资产底座                                                                                 |
| 公共步骤            | 接口定义下维护的可复用请求类步骤集合（http/jdbc 取样器，含请求参数、验证器、前置/后置处理器），供关联场景在配置时选择添加（复制或链接引用）                                                          |
| 仓库流水线执行         | 平台通过 GitLab API 传递选中的测试类元数据触发该仓库 CI 流水线（完整测试/指定接口测试/指定场景测试），由 GitLab 侧执行测试，平台拉取流水线状态与报告产物生成平台报告；执行对象为导入测试类元数据（仅描述）的场景，执行走流水线而非平台执行引擎 |
| 全局资产            | 项目级维护的可复用组件（前置/后置处理器、验证器、提取器），快速调试与测试场景中可复制引入；引入为仅复制，得到独立副本，与源资产无关联                                                             |
| 可执行导入（源码导入）     | 通过 GitLab API 下载源码，解析 `@Test` + `@RyzeTest` 注解的测试方法，将注解 resource path 对应的 yaml 测试场景解析为平台可执行场景的导入方式；仅导入场景本身，不创建平台环境与处理器资产             |
| 元数据导入（仅描述）      | 扫描源码提取测试类元数据（测试类全限定名、类级注解配置、类下测试方法清单）与测试场景描述，不解析为平台可执行场景，产物进入“仓库测试类元数据”，供仓库流水线执行触发                                                   |
| 虚拟包（可选）         | 接口定义被接口场景关联后承担的组织角色：一个接口定义下可挂载多个场景（一对多），作为场景的**可选**组织容器；场景亦可独立存在不归属任何虚拟包                                                             |
| 接口场景            | 多个接口定义与请求（http/jdbc 取样器）按顺序编排而成的步骤序列，用于场景级自动化回归                                                                                      |
| Mock            | 按配置规则模拟接口响应，供依赖方在真实服务不可用时联调                                                                                                          |
| 环境              | 项目级配置集合，融合 Ryze 默认配置（http 默认配置）、数据源、全局变量与全局前置/后置处理器，配置项与 Ryze 对应一致；支持配置多个环境                                                          |
| 环境变量            | 环境级全局变量，与 Ryze 全局变量配置对应一致，在环境内定义、可通过 `${变量名}` 引用的命名值，作用于请求参数、前置/后置处理器等场景                                                             |
| 前置处理器           | 在测试组件（取样器、测试集合）执行前运行的 Ryze 组件，用于数据准备、环境初始化、认证获取；结构含类型、配置、异步、条件等要素（与 Ryze 对应一致），可携带提取器                                                |
| 后置处理器           | 在测试组件执行后运行的 Ryze 组件，用于数据清理、状态恢复、结果验证；结构同前置处理器，执行顺序相反                                                                                 |
| 提取器（extractors） | 从处理器/取样器响应中提取值并存储为变量供后续步骤使用的 Ryze 组件，类型支持 JSONPath、正则、响应头、整响应等提取方式（类型标识以 Ryze 为准）                                                    |
| 验证器（validators） | 对取样器响应（状态码、响应头、响应体、响应时间等）进行校验的 Ryze 断言组件，类型支持 JSON、HTTP、结果三类校验（类型标识以 Ryze 为准），断言失败则该步骤判定失败                                           |
| 全局前置/后置         | 在环境或场景级配置、对所有请求生效的前置/后置处理器                                                                                                           |
| 内置函数            | Ryze 框架内置的数据生成与处理函数（如 `random_string`、`faker`、`timestamp`、`digest`、`uuid` 等），以 `${函数名(参数)}` 语法调用；平台提供快捷使用帮助，实际执行以 Ryze 框架为准          |
| Ryze            | 平台直接引入的测试执行框架，以 JSON/YAML 描述测试场景，测试用例与代码分离；平台执行引擎基于其构建，执行时将平台中保存的接口测试数据解析为 Ryze 标准 JSON 后运行                                          |
| Ryze 标准格式       | 执行引擎可识别的标准 JSON 结构，与 Ryze 框架对应一致（测试集合与步骤的字段结构详见详细设计）；平台场景/调试请求在执行时解析为该格式                                                             |
| 取样器（Sampler）    | Ryze 中执行具体测试逻辑的最小单元（对应平台的一次请求步骤），含步骤配置、提取器、验证器                                                                                       |
| 资源池             | 平台侧执行引擎（基于 Ryze 构建）的运行单元，承载服务端执行的任务；支持并发执行                                                                                           |
| 复制与链接引用         | 场景导入系统请求的两种方式：复制产生独立副本，修改互不影响；链接引用跟随源数据变化（参数值及启用状态可独立调整，见 3.4）                                                                       |
| 变更历史            | 对象（接口/场景）每次保存变更产生的记录，含变更序号                                                                                                           |
| 执行历史            | 对象（场景）每次执行产生的记录，与报告关联                                                                                                                |
| cURL            | 命令行 HTTP 请求工具格式，支持从 Chrome/Charles/Fiddler 等抓包工具导出                                                                                   |

## 2. 总体描述

### 2.1 用户角色与特征

沿用 V1.1 角色模型，补充约定：

- 接口测试业务域面向**业务用户**开放，所有操作严格限定在当前活跃工作空间与当前项目上下文内。
- 权限粒度：接口管理、测试场景、环境管理、全局资产的查看/编辑/删除/执行权限由项目级角色控制（见附录 B）。

### 2.2 假设与依赖

- 被测接口以 HTTP/HTTPS 协议暴露，平台通过标准 HTTP 客户端发起请求，不依赖特定被测试系统框架。
- 平台直接引入 Ryze 测试框架作为执行引擎依赖；调试、场景执行时，平台将自有场景模型解析为 Ryze 标准 JSON 并在服务端执行（转换由平台内部完成，对用户无感）。
- 服务端执行由平台执行引擎（基于 Ryze 构建的资源池）承载，支持并发执行；调试亦支持本地执行模式（由用户本机代理发起）。
- 数据库前置/后置处理器（JDBC）依赖环境管理中配置的数据源；数据源驱动由平台内置常见数据库驱动（MySQL、PostgreSQL、Oracle、SQLServer 等）支持。
- 场景、报告的存储遵循平台数据库规范，接口测试执行历史可能数据量大，需在详细设计中明确清理策略（默认保留90天）。
- 可执行导入与仓库流水线执行依赖目标 GitLab 实例的 API（源码下载、流水线触发、状态与报告产物拉取）与仓库 CI 能力（`.gitlab-ci.yml` 需支持测试范围参数契约）；GitLab 实例网络可达性由部署环境保障。

### 2.3 实施分期

按价值/成本比排定优先级，供迭代规划参考（非承诺性约束）：

| 梯队  | 需求范围                                                                                                    | 说明                           |
| --- | ------------------------------------------------------------------------------------------------------- | ---------------------------- |
| 一   | 快速调试（含服务端执行与本地执行）、请求参数模型、验证器（断言）、环境管理（默认配置/数据源/全局变量/全局前后置处理器）、服务端执行（Ryze 执行引擎接入）与并发调度基础                 | 基础链路，打通「调试 → 执行 → 结果」，支持本地调试 |
| 二   | 接口管理（含文件/Swagger URL 导入）、报告                                                                             | 资产化管理，支持接口回归                 |
| 三   | 测试场景（步骤编排、可选虚拟包、公共步骤、http/jdbc 取样器）、前置/后置处理器、提取器（含调试请求提取变量）、内置函数、全局资产（项目级处理器/验证器/提取器资产库，供快速调试与测试场景复制引入） | 场景级自动化                       |
| 四   | Mock 服务、定时导入、场景定时任务、可执行导入（源码导入）、元数据导入与仓库流水线执行（GitLab CI 触发执行与结果回流）                                      | 联调提效与企业级能力                   |
| 后续  | 其他 CI 平台集成（Jenkins 等）、非 HTTP/JDBC 协议（基于 Ryze 多协议能力扩展）                                                   | 与 CI 平台集成、多协议支持，架构预留，按需评估    |

## 3. 功能需求

### 3.1 快速调试（US-API-001）

**功能描述**：提供面向开发联调阶段的单请求调试能力，快速构造并执行一次 HTTP 请求，查看响应结果，验证通过后可保存为接口定义或调试记录。支持**服务端执行**与**本地执行**两种模式。

**功能点**：

- 新建调试请求：选择协议（HTTP/HTTPS）、请求方法（GET/POST/PUT/DELETE/PATCH/OPTIONS/HEAD/CONNECT）、输入完整 URL；请求头、请求体、前置/后置处理器、提取器、验证器、认证均基于公共能力配置。
- 执行模式切换：
  - **服务端执行（默认）**：由平台执行引擎在服务端发起请求，适用于验证服务端网络策略与接口可达性，执行结果可保存为调试记录；
  - **本地执行**：通过平台提供的本地代理客户端（或浏览器插件）从用户本机发起请求，适用于调试本地环境、绕过服务端网络限制或验证本地代码变更。本地执行结果仅展示，不持久化为平台报告或调试记录（记录仅保存在浏览器本地缓存），不可保存为接口资产。
- 全局资产引入：调试请求可从全局资产库（项目级）复制引入前置/后置处理器、验证器、提取器（提取器从响应中提取变量供后续调试使用）。
- 导入 cURL：粘贴抓包工具（Chrome/Charles/Fiddler）导出的 cURL 命令，自动解析为请求（方法、URL、请求头、请求体）。
- 响应查看：展示状态码、响应头、响应体与响应耗时；响应体支持按格式（JSON/XML/HTML/纯文本）展示。
- 保存：服务端执行的调试请求可保存，保存时填写名称并归属到接口管理模块（新建接口或归属已有接口定义）。
- 调试记录管理：调试页维护历史记录列表，支持搜索、重命名、删除（仅服务端执行的持久化记录）。

**业务规则**：

- 未保存的调试请求执行后仅展示结果，不产生持久化数据；保存后即成为接口定义资产。
- 导入 cURL 仅解析请求描述，不执行 cURL 命令本身，也不执行其中的任何脚本或文件引用。
- 调试请求支持变量引用（`${变量名}`）与内置函数，变量来源为环境变量、提取器或前置处理器提取产生。
- 请求体仅支持一种类型，切换类型时保留已填内容供切换回时恢复。
- 调试执行不产生报告，仅展示本次执行结果；需要留痕时使用测试场景执行。
- 全局资产引入为仅复制：引入的处理器/验证器/提取器为独立副本，与全局资产无关联。
- 本地执行模式不消耗平台执行引擎并发资源，不记录审计日志（仅记录操作行为，不记录请求明细）。

### 3.2 接口管理（US-API-002）

**功能描述**：提供接口资产的集中管理，支持新建、导入、维护与查看引用关系，是测试场景与 Mock 服务的数据底座。

**功能点**：

- 新建接口：填写接口名称、所属模块、协议、请求方法、路径（支持路径参数 `${id}` 占位），并可编辑请求参数、响应示例。
- 导入接口：
  - **文件导入**：支持 Swagger/OpenAPI、Postman Collection、HAR、JMeter、MeterSphere 格式文件解析导入；
  - **Swagger URL 导入**：输入 Swagger/OpenAPI 文档地址，拉取并解析为接口定义；
  - **定时导入**：配置定时任务周期拉取 Swagger URL 并增量更新接口定义（统一任务管理见 3.12）。
- 接口列表：按模块树组织，支持筛选条件（ID、接口名称、所属模块、协议）与视图切换（我关注的 / 我创建的 / 全部）。
- 接口预览（API 预览）：详情页展示接口定义信息、**引用关系**（被哪些场景/Mock 引用）、**虚拟包下挂载的场景**（可选）、**公共步骤**、**变更历史**。
- 调试入口：从接口定义一键进入调试（携带该接口的请求参数）。
- 列表操作：编辑、复制、删除、关注/取消关注。
- 公共步骤：在接口定义下维护一组公共请求步骤（http/jdbc 取样器，含请求参数、验证器、前置/后置处理器），支持新建、编辑、删除、排序；供项目内场景在配置时选择添加。

**业务规则**：

- 接口名称在所属模块内唯一；模块支持多级目录组织。
- 接口定义被场景或 Mock 引用时，禁止直接删除，需先解除引用/关联（平台提示引用方；若为虚拟包关联，可级联解除关联并置空场景的虚拟包标签）。
- 公共步骤仅支持请求类步骤（http/jdbc 取样器），处理器等非请求类步骤不可维护为公共步骤；公共步骤的维护权限同接口管理（项目维护者）。
- 公共步骤被场景链接引用时受删除保护（同接口定义引用保护语义），需先解除引用；若为复制模式则不受影响。
- 复制接口产生独立副本，与原接口无关联。
- 变更历史记录每次保存产生的变更记录并生成变更序号，详情可查看。
- 文件导入需校验格式合法性；格式不兼容的条目跳过并给出失败清单，不阻断整体导入。
- 定时导入的更新采用「接口路径+方法」匹配策略：已存在则覆盖更新，不存在则新增；被手动修改过的接口定义不被定时导入覆盖（导入策略为系统配置项）。

### 3.3 Mock 服务（US-API-003）

**功能描述**：为接口定义创建 Mock 规则，按配置模拟响应，使依赖方在真实服务不可用时正常联调。

**功能点**：

- 创建 Mock：从接口定义创建（继承路径与方法）或独立创建；Mock 归属接口管理模块。
- Mock 规则：配置匹配条件（请求方法、路径、请求头、请求参数）与响应定义（状态码、响应头、响应体，支持变量与内置函数）。支持配置响应延迟时间（模拟慢响应）。
- 跟随 API：开启后 Mock 响应跟随接口定义中配置的响应示例（Mock 自身未配置响应时生效）。
- Mock 调试：在 Mock 配置页直接执行一次请求验证匹配与响应是否符合预期。
- 复制 Mock 地址：一键复制 Mock 的访问地址，供依赖方配置。
- Mock 列表：按接口模块组织，支持启停、编辑、删除。提供命中次数统计与最近命中时间查看。

**业务规则**：

- Mock 地址与真实接口地址同构（同路径、同方法），仅通过平台提供的 Mock 域名/端口区分。
- Mock 匹配按「请求方法 + 路径 + 匹配条件」顺序取第一条命中规则；无命中时返回 404。
- Mock 的响应内容支持变量（环境变量、内置函数）动态生成。
- Mock 启停状态即时生效，不重启服务。
- Mock 访问不要求请求方具备平台登录态（面向依赖方联调），但需防滥用（平台侧限流，如单 Mock 路径 QPS 上限可配置），访问量计入审计日志。

### 3.4 测试场景（US-API-004）

**功能描述**：提供场景级自动化测试能力，覆盖两种数据形态：

- **平台场景数据**：平台内创建或可执行导入解析的可执行场景，将接口、请求按顺序编排为步骤序列（步骤即取样器，支持 http/jdbc 两种类型），支持参数传递，一键执行并生成场景报告，由平台执行引擎在服务端执行；
- **仓库测试类元数据**：从 GitLab 仓库元数据导入的仅描述场景，平台通过 GitLab API 调度该仓库 CI 流水线执行，由 GitLab 侧执行测试并回流结果。

**功能点**：

**导入（从 GitLab 仓库导入，独立功能）**：

- **可执行导入（源码导入）**：解析 `@Test` + `@RyzeTest` 注解的测试方法，将注解 resource path 指向的 yaml 测试场景解析为平台场景数据（产物为平台内可执行场景，进入「平台场景数据」）；导入过程含场景解析（扫描测试方法提取 resource path，定位 `src/test/resources` 下 yaml，解析场景名、场景参数、场景步骤（含 http/jdbc 取样器与验证器）为平台场景，字段映射以 Ryze 为准）、导入预览（展示解析出的场景清单：测试类、测试方法、场景名、步骤数，支持勾选后导入）与场景归属（归属当前项目，按测试类/资源目录结构映射模块组织）。
- **元数据导入（仅描述）**：扫描源码提取测试类元数据（测试类全限定名、类级注解配置、类下测试方法清单）与测试场景描述（场景名称、所属模块、来源路径与测试方法映射、关联接口（虚拟包，可选）、步骤摘要（展示步骤清单供预览，不含完整请求参数）），不解析为平台可执行场景，产物进入「仓库测试类元数据」，供仓库流水线执行触发。平台提供“同步元数据”手动按钮，触发时重新拉取仓库最新元数据；场景执行触发前，平台自动校验元数据是否过期（基于仓库最新 commit 时间），若过期则自动刷新后触发。

**平台场景数据**：

- 场景创建：定义场景名称与模块（模块为虚拟组织概念，沿用功能测试语义）。场景可**关联一个接口定义**作为虚拟包组织标签（**可选**），用于场景分类与检索，不强制要求关联。未关联接口的场景可独立存在并正常执行。关联后接口详情页展示其虚拟包下挂载的场景列表。
- **参数**：场景级定义常量、列表参数。
- **前/后置**：场景级前置/后置处理器，基于公共能力。
- **设置**：Cookie 配置（环境默认配置携带的 Cookie、共享 Cookie、场景变量 Cookie 三种来源及覆盖关系）与步骤执行失败规则（「忽略错误，继续运行」或「停止/结束运行」）。
- **全局资产引入**：场景级前置/后置处理器、步骤级处理器/验证器/提取器均可从全局资产库（平台级）复制引入。
- **场景步骤（步骤即取样器）**：
  - **http 取样器**：支持导入系统请求（从接口定义、其他场景复制或链接引用）、自定义请求（创建不落库的 HTTP 请求步骤，可引用环境自动填充域名或填写完整 URL，支持粘贴 cURL）、添加公共步骤（可从场景已关联接口的公共步骤，或通过公共步骤选择器浏览当前项目下所有接口的公共步骤列表中选择添加；复制/链接引用两种模式，语义同导入系统请求）与验证器；
  - **jdbc 取样器**：创建数据库请求步骤，选择环境中的数据源并编写 SQL 语句，可携带提取器/验证器；用于数据准备、数据校验或生成后续步骤参数。
- **平台内执行**：由平台执行引擎基于 Ryze 在服务端并发执行；执行后生成场景报告。
- **场景控制**：单步骤操作（启用/禁用、执行、复制、删除、在之前/之后插入步骤）、批量操作（批量启用、批量禁用、批量调试、批量删除）与场景级操作（关注、复制链接、查看报告、编辑、执行、复制、创建定时任务、删除）。
- **执行历史与变更历史**：场景保存后自动提供两个标签页（变更历史同 3.2 语义，执行历史见 3.6）。

**仓库测试类元数据**：

- **仓库配置（项目级公共配置）**：项目级维护 GitLab 仓库配置（仓库地址、分支/标签与项目访问令牌（Project Access Token，权限限定该仓库），令牌加密存储），项目内共享；可执行导入与仓库流水线执行均引用该项目级配置。
- **触发执行**：平台通过 GitLab API 将选中的测试类元数据作为流水线参数传递，触发该仓库 CI 流水线：
  - **完整测试**：触发流水线执行仓库内全部测试（不传递范围参数）；
  - **指定接口测试（多个）**：选择多个接口定义，映射其虚拟包下关联场景对应的测试类元数据作为流水线参数；
  - **指定场景测试（多个）**：选择多个场景，映射其来源测试类元数据作为流水线参数；
- **结果回流**：平台通过 GitLab API 拉取流水线状态与报告产物，生成场景报告并记录执行历史（含流水线 ID 与链接）；失败时同步失败日志与流水线链接，支持手动刷新状态。

**业务规则**：

**导入**：

**可执行导入（源码导入）**：

- 仅导入场景本身：yaml 中的 `configelements`（环境配置）与 `!include` 引用的前置/后置处理器不随导入创建平台环境与处理器资产，导入后场景保留引用占位，执行时提示缺失，由用户在平台内配置。
- 失败清单：yaml 格式错误、resource path 对应的 yaml 不存在、注解不完整（缺少 `@Test` 或 `@RyzeTest`）的测试方法跳过并给出失败清单，不阻断整体导入。
- 重复导入：提示用户选择「覆盖」或「跳过」。

**元数据导入**：

- 重复导入：同可执行导入的覆盖/跳过语义。

- 平台提供手动“同步元数据”按钮，刷新仓库中的测试类清单。

- **执行路径互斥**：可执行导入场景为平台可执行场景，走平台内执行；仅元数据导入的场景（仅描述、无可执行内容）走仓库 CI 流水线执行，平台不可直接执行；两种执行路径互不重叠。

**平台场景数据**：

- **复制与链接引用语义**：
  - **复制**：创建当前场景的独立副本，后续修改互不影响；源数据被删除后复制步骤仍可编辑，仅源 ID 置灰无法跳转。
  - **链接引用**：步骤内容（请求参数、验证器、处理器配置）跟随源数据变化同步更新，但当前场景中的**启用状态、参数值**可独立调整。引用的源数据被删除时，引用步骤置灰并仅支持「移除」操作。
  - 链接引用场景时可配置「使用原场景参数」（优先原场景参数 / 优先当前场景参数）与「使用原场景环境」。
- **关联接口（虚拟包，可选）**：
  - 场景可关联**一个**接口定义作为虚拟包组织标签（**可选**），用于场景分类与检索，不强制要求关联。
  - 关联后接口详情页展示其虚拟包下挂载的场景列表。
  - 接口定义被场景关联时不强制禁止删除，但删除时系统提示关联场景列表，用户确认后可级联解除关联关系（场景中的关联标签置空）。
- **添加公共步骤**：
  - 可从场景已关联接口（若有）的公共步骤中选择添加；若场景未关联接口，或需引用其他接口公共步骤，可通过公共步骤选择器浏览当前项目下所有接口的公共步骤列表，选择后以复制或链接引用模式添加。
  - 添加模式为复制或链接引用（二选一），语义同“复制与链接引用语义”。
- **参数优先级**：执行期变量（处理器/提取器产生）> 场景参数 > 环境参数；同名变量时按该优先级取值。执行报告中对每个步骤使用的变量标注来源层级（环境/场景/提取器），便于调试。
- **Cookie 覆盖关系**：共享 Cookie 覆盖环境默认配置 Cookie 与场景变量 Cookie；启用环境默认配置 Cookie 时若请求头亦设置 Cookie，则取两者并集。
- **全局资产引入（仅复制）**：引入的处理器/验证器/提取器为独立副本，与全局资产无关联。
- **场景执行失败规则**：为「停止/结束运行」时，失败步骤后的步骤不再执行，报告中标记未执行；为「忽略错误」时全部步骤执行完毕，报告中标记失败步骤。
- **执行历史保留**：默认保留全部记录；手动删除报告不影响执行历史查看详情；系统按清理策略（默认90天）清理报告后，执行历史详情显示「执行结果被清理」。

**仓库测试类元数据**：

**仓库流水线执行**：

- 触发前置条件：仓库需已定义支持测试范围参数的 `.gitlab-ci.yml`，参数契约（变量名与取值规则）在详细设计中确定；契约不满足时触发失败并提示配置错误。
- 触发范围映射：仅元数据导入的场景参与流水线触发；指定接口测试 = 接口定义 → 虚拟包下关联场景 → 关联的测试类元数据；指定场景测试 = 场景 → 来源测试类元数据（可执行导入场景为平台场景，不参与映射）。
- 资源占用：流水线执行不占用平台执行引擎资源，不参与平台内场景并发队列。
- 结果拉取失败：流水线超时、产物缺失、令牌失效时执行记录标记为「状态未知」并给出 GitLab 流水线链接，支持手动刷新状态。

### 3.5 环境管理（US-API-005）

**功能描述**：项目级维护环境配置，融合 Ryze 框架的默认配置（http 默认配置）、数据源、全局变量与全局前置/后置处理器，配置项与 Ryze 对应一致；支持配置多个环境，使场景可在不同环境（如测试/预发/生产）间切换执行。

**功能点**：

- **环境配置**：维护环境列表，支持新建、复制、编辑、删除、导入、导出；支持配置多个环境。
- **默认配置**：环境级 http 默认配置，配置项与 Ryze 对应一致，执行时合并进 Ryze 标准 JSON，作为请求步骤的默认值。
- **数据源**：配置数据源（数据源名称、驱动、连接 URL、用户名、密码、最大连接数、超时时间），供前置/后置 JDBC 处理器使用；支持连接测试。
- **全局变量**：环境级变量，单个/批量添加、编辑、删除；在请求参数、前置/后置处理器中通过 `${变量名}` 引用，与 Ryze 全局变量配置对应一致。
- **前置/后置**：环境级全局前置/后置处理器，基于公共能力，对环境中所有请求生效。

**业务规则**：

- 环境归属项目，仅当前项目内可见可用；支持配置多个环境，场景执行时选择目标环境。
- 环境配置项与 Ryze 框架对应一致，平台不提供 Ryze 之外的平行配置项；具体字段映射在详细设计中确定。
- 请求步骤引用环境后，URL 中不填域名仅填接口路径（域名来自环境默认配置）。
- 环境导入支持「覆盖」开关：开启时重名环境覆盖，关闭时重名环境跳过（不新增）。
- 环境删除前校验引用：被接口场景引用的环境**禁止删除**（强制保护），需先解除引用。
- 数据源密码等敏感配置加密存储，导出环境时敏感信息脱敏或需授权导出。
- 全局前置/后置与请求自身的同名前置/后置处理器同时存在时均执行（执行顺序遵循 Ryze 处理器层级语义）。
- 环境变量与场景参数、执行期变量同名时按 3.4 参数优先级取值。

### 3.6 接口测试报告（US-API-006）

**功能描述**：集中查看场景执行结果，支持详情查看、分享、导出与删除；报告来源包括平台内执行与仓库流水线执行两种。

**功能点**：

- 报告列表：分页展示场景报告（可筛选执行方式、时间范围）。
- 查看报告：点击报告名称预览报告详情；场景报告点击步骤名称可查看该步骤实际请求与响应内容；仓库流水线执行的报告展示来源标记与流水线链接，步骤级结果来自平台拉取的报告产物。
- 分享报告：**默认禁止分享**，需项目管理员在项目设置-安全策略中开启「允许分享报告」后，用户方可生成分享链接。链接有效期在项目管理-应用设置中配置。
- 导出报告：详情页单个导出；列表页支持勾选批量导出。
- 删除报告：单个删除或勾选批量删除。

**业务规则**：

- 删除报告后不可恢复；报告被系统清理后，执行历史详情显示「执行结果被清理」。
- 分享链接在有效期内可匿名访问（不要求平台登录态），有效期过期后链接失效。
- 报告内容包含敏感信息（请求头 Token、响应体业务数据）时，分享与导出遵循项目的数据安全策略（是否允许分享/导出为项目管理设置项）。
- 仓库流水线执行的报告展示执行方式来源（仓库流水线）与流水线链接；流水线状态拉取失败时报告标记「结果待同步」，可手动刷新。

### 3.7 请求参数与认证（公共需求）

**功能描述**：定义快速调试、接口管理、测试场景自定义请求共用的请求参数模型与认证方式。

**功能点**：

- **请求头**：名称下拉选择（常用头自动补全）+ 值输入，支持单条/批量添加；值支持变量与内置函数。
- **请求体**，类型互斥，支持：
  - `none`：无请求体；
  - `form-data`：键值对，字段类型支持 string / integer / number / array / json / file（文件支持本地上传或关联平台文件）；
  - `x-www-form-urlencoded`：键值对，支持 URL 编码开关；
  - `json` / `xml`：文本编辑器，支持格式化；
  - `raw`：原始文本，可自定义 Content-Type；
  - `binary`：二进制文件。
- **Query 参数**：URL 查询参数键值对，支持变量与内置函数。
- **REST 参数**：路径参数（`{id}` 占位）对应值。
- **认证**：支持 No Auth（无认证）、Basic Auth（用户名/密码）、Digest Auth（用户名/密码）。
- **设置**：连接超时、响应超时、跟随重定向（自动重定向开关）。

**业务规则**：

- 请求体类型切换时保留各类型已填写内容，切回后恢复，不因切换丢失（同一请求下）。
- Query 参数与 URL 中已带查询串同时存在时，执行时合并去重（以参数区为准）。
- 认证信息仅作用于当前请求配置，不随请求保存为明文（存储加密）。
- 路径参数与路径占位符一一对应：未提供值时按字面 `{id}` 发送并在校验提示中告知。
- 跟随重定向关闭时，重定向响应按实际响应展示（状态码 3xx），不自动跳转。
- 执行时该请求模型解析为 Ryze 标准格式，映射规则在详细设计中定义。

### 3.8 前置与后置处理器（公共需求）

**功能描述**：前置/后置处理器以 Ryze 框架为准，在测试组件（取样器、测试集合）执行前/后运行，用于数据准备、环境初始化、认证获取、数据清理、结果验证等预处理/后处理逻辑；支持 http 与 jdbc 两种处理器类型（同取样器）。

**功能点**：

- **处理器结构**：与 Ryze 一致（类型、配置、异步、条件等要素），首期支持 `http` 与 `jdbc` 两种处理器类型，其余协议随多协议扩展预留；具体字段结构详见详细设计。
- **配置位置**：可配置于环境级（项目级）、场景级、步骤级（取样器级），下级继承上级配置并可覆盖。
- **提取器**：处理器可携带提取器，从处理器响应中提取变量供后续步骤使用（如前置登录获取 token）。
- **前置处理器**：执行于测试组件之前，用于数据准备、环境初始化、认证获取、资源预分配。
- **后置处理器**：执行于测试组件之后，用于数据清理、状态恢复、结果验证、通知发送；可访问执行结果与测试过程中生成的变量。
- **全局资产（处理器与提取器）**：项目级维护可复用的前置/后置处理器与提取器资产，供快速调试与测试场景复制引入：
  - 资产管理：新建、编辑、复制、删除、启用/停用；资产类型与结构同本节（http/jdbc 处理器，json/regex/http_header/result 提取器）；
  - 引入使用：快速调试、测试场景（场景级/步骤级）可从资产库选择复制引入。

**业务规则**：

- 执行顺序：前置处理器按「环境级 → 场景级 → 步骤级」依次执行；后置处理器按相反顺序（「步骤级 → 场景级 → 环境级」）执行。
- 任一前置处理器失败则其所属组件不执行并标记失败；后置处理器失败不改变组件本身成败，但记录失败信息。
- 处理器失败与否对执行结果的影响遵循 Ryze 框架语义；多处理器按配置顺序执行。
- 提取器类型以 Ryze 为准，支持 JSONPath、正则、响应头、整响应等提取方式；提取的变量遵循 Ryze 变量作用域。
- JDBC 处理器依赖环境管理中配置的数据源，执行前校验数据源连接，连接失败明确提示数据源不可用。
- 异步处理器不阻塞主流程，其失败仅记录，不影响组件执行结果。
- 条件处理器在条件不满足时跳过该处理器。
- 全局资产为项目级共享：维护权限为项目维护者，项目成员可浏览与复制引入。
- 全局资产引入为仅复制：引入得到独立副本，与源资产无关联；源资产修改/删除不影响已引入副本。
- 全局资产停用后不可再引入，已引入副本不受影响。

### 3.9 断言（公共需求）

**功能描述**：断言以 Ryze 验证器为准，对请求响应进行校验，断言失败则该步骤判定失败。验证器在取样器或处理器执行完成后自动运行，从响应中获取实际值并与预期值比较。

**功能点**：

- **验证器类型**，以 Ryze 为准，支持：
  - JSON 验证器：通过 JSONPath 校验 JSON 响应内容；
  - HTTP 验证器：校验 HTTP 状态码、响应头、响应体；
  - 结果验证器：校验取样器响应结果，如响应时间。
- **验证字段**：指定被校验的响应部位（状态码、响应头、响应体、JSONPath 表达式、响应时间等）。
- **期望值**：期望值，支持单个值或多个值（部分验证规则下生效）。
- **验证规则**，以 Ryze 为准，支持：相等、任意一个相等、不相等、大小比较（大于/小于/大于等于/小于等于）、包含、包含任意一个、不包含、正则匹配、非空、为空、对象匹配；规则与字段的具体标识映射详见详细设计。
- **配置位置**：可配置于取样器级、后置处理器中。
- **扩展**：内置验证器无法满足时，支持基于 Ryze 扩展机制的自定义验证器（预留）。
- **全局验证器资产**：项目级维护可复用的验证器资产（json/http_assertion/result_assertion，结构同本节），供快速调试与测试场景复制引入；引入为仅复制（语义同 3.8 全局资产）。

**业务规则**：

- 多个断言为「且」关系，任一失败则该步骤失败并记录失败断言明细。
- 断言表达式解析失败按断言失败处理，并在报告中给出解析错误提示。
- 断言字段、期望值支持变量引用与函数，在验证前求值。
- 验证规则与多值期望的兼容组合遵循 Ryze 框架语义。
- 全局验证器资产为项目级共享，维护权限为项目维护者，项目成员可浏览与复制引入；引入为仅复制，与源资产无关联。

### 3.10 内置函数与变量引用（公共需求）

**功能描述**：内置函数与变量引用以 Ryze 框架为准，平台提供**快捷使用帮助**功能辅助用户插入与查询，实际执行时直接以 Ryze 框架解析求值。

**功能点**：

- **内置函数**：以 Ryze 内置函数为准，调用语法 `${函数名(参数1, 参数2, ...)}`，覆盖：
  - 安全加密：`digest`（信息摘要，支持 md5/sha1/sha256 等、盐值与大小写参数）、`google2fa`（谷歌验证码）；
  - 数据生成：`random`（随机数）、`random_string`（随机字符串，长度/字符集/大小写可配）、`faker`（JavaFaker 模拟数据，如 `name.fullName`、`internet.emailAddress`、`phoneNumber.cellPhone`，区域可配）、`uuid`；
  - 日期时间：`timestamp`（当前时间戳或格式化日期）、`time_shift`（时间偏移，ISO-8601 偏移量）；
  - 数据处理：`json`（键值对构造 JSON）、`json_read`（JSONPath 读取）、`url_encode`/`url_decode`、`base64_encode`/`base64_decode`、`property`（系统属性）。
- **快捷使用帮助**：平台提供函数浏览与插入辅助（如函数列表、参数说明、使用示例、一键插入到输入位置），帮助用户快速选用 Ryze 函数；帮助内容与 Ryze 框架函数能力保持一致。
- **变量引用**：统一 `${变量名}` 语法，变量定义于环境（项目）级、场景级与步骤级（执行期由提取器/前置处理器产生的变量），子级继承父级变量并可覆盖；支持简单变量、对象变量（`${config.port}`）、数组变量。
- **配置位置**：函数与变量在请求参数、请求头、前置/后置处理器、断言、Mock 响应中均可用。

**业务规则**：

- 函数与变量在请求发送前求值（先执行函数生成变量值，再进行变量替换）；引用不存在的变量时保留字面量并在执行日志中给出警告（不阻断执行）。
- 函数参数为字符串时的写法遵循 Ryze 模板语法（详见详细设计）。
- 函数库为 Ryze 框架内置能力，实际执行以 Ryze 框架为准；平台自身不维护独立函数实现。
- 内置函数无法满足时，支持基于 Ryze 扩展机制的自定义函数（预留）。

### 3.11 执行引擎（公共需求）

**功能描述**：统一承载调试、场景的请求执行，支持两种执行模式：**平台内执行**（由平台直接引入的 Ryze 测试框架在服务端执行，执行时将平台中保存的接口测试数据解析为 Ryze 标准 JSON 后运行）与**仓库流水线执行**（执行发生在远端 GitLab 仓库 CI 流水线，平台通过 GitLab API 传递选中的测试类元数据触发，并负责结果拉取，不经过平台执行引擎）。快速调试额外支持**本地执行**模式。

**功能点**：

- **执行模式**：
  - **平台内执行**：调试、场景均由平台执行引擎（基于 Ryze 构建的资源池）在服务端执行，不依赖用户本机任何服务。**支持多任务并发执行**：系统管理员可设置全局最大并发执行数（默认值 5），同一项目下共享该并发配额；调试请求与场景执行任务统一纳入并发队列管理。
  - **本地执行（仅调试）**：通过平台提供的本地代理客户端（或浏览器插件）从用户本机发起请求，不消耗平台执行引擎并发资源，结果仅本地展示。
  - **仓库流水线执行**：平台通过 GitLab API 传递选中的测试类元数据触发 GitLab 仓库 CI 流水线执行测试，平台拉取流水线状态与报告产物生成报告；不占用平台执行引擎资源。
- **格式转换**（平台内执行）：执行时平台将调试请求、测试场景的平台自有模型解析为 Ryze 标准格式，转换由平台内部完成、对用户无感，不要求用户感知 Ryze 语法；仓库流水线执行的场景为仅描述导入，不参与格式转换，执行在仓库侧。
- **执行结果**：三种执行模式（平台内、本地调试、仓库流水线）中，平台内与仓库流水线的执行结果统一进入报告与执行历史体系；本地调试结果仅展示，不持久化。

**业务规则**：

- **并发控制**：平台内执行支持并发，最大并发数由系统配置项（`api.execution.max-concurrent`）控制，默认 5。超出并发数的任务排队等待，队列长度可配置（默认 100），超出队列长度时拒绝执行并提示。
- 执行超时按请求级「响应超时」配置控制，超时任务标记为超时失败并记录。
- 执行任务量纳入平台审计日志（用户、对象、执行时间、结果；仓库流水线执行另记录流水线 ID 与触发人；本地执行仅记录操作行为）。
- 格式转换失败（平台模型存在 Ryze 无法表达的配置）时执行失败并给出可定位的转换错误信息，不产生部分执行结果。
- 首期启用 Ryze 的 HTTP 与 JDBC 取样器能力；Ryze 支持的其他协议（Redis/WebSocket/Dubbo/Kafka 等）作为多协议扩展预留。
- 扩展约束：自定义验证器、自定义提取器、自定义函数基于 Ryze 扩展机制提供（预留），平台不自行实现与 Ryze 语义不一致的平行能力。

### 3.12 定时任务（US-API-007）

**功能描述**：任务级定时调度，将「接口导入」「场景执行」两类定时任务统一管理：按 Cron 表达式周期触发，记录每次触发结果，支持启停与立即执行；任务归属项目，按项目隔离。

**功能点**：

- **任务类型**：
  - **接口导入任务**：绑定 Swagger/OpenAPI 文档地址，周期拉取并增量更新接口定义（导入策略同 3.2 定时导入）；
  - **场景执行任务**：绑定平台内可执行场景（含可执行导入场景），周期触发场景执行，需指定目标环境。
- **调度配置**：Cron 表达式（支持常用预设：每 5 分钟 / 每小时 / 每天 / 每周 + 自定义），保存时校验表达式合法性并预览下次执行时间。
- **任务管理**：统一任务列表（任务名称、类型、绑定对象、调度表达式、启用状态、上次执行时间与结果、下次执行时间），支持新建、编辑、启停、立即执行、删除、查看执行记录。
- **执行记录**：每次触发（定时或手动）产生一条执行记录：触发时间、触发方式（定时/手动）、执行结果（成功/失败/超时）、失败原因、关联报告（场景执行任务）或导入结果（接口导入任务：新增/更新/失败数）。
- **结果查看**：任务列表展示最近一次执行状态；执行失败记录失败原因，可通过「立即执行」手动补跑。

**业务规则**：

- Cron 表达式校验不通过不可保存；调度精度为分钟级，触发时间按服务器时区计算。
- 同一任务上一次执行未结束时，本次触发跳过（不重复触发、不累计）。
- 定时触发的场景执行进入平台执行引擎并发队列，与手动执行统一排队。
- 场景执行任务的目标环境被删除后，任务执行失败并明确提示。
- **删除保护**：被定时任务绑定的场景禁止直接删除，需先删除任务或解除绑定；被定时导入任务绑定的 Swagger URL 配置也受删除保护，需先删除任务或解除绑定后方可删除配置。
- 任务以创建者身份与权限执行；创建者退出项目后任务停用。
- 停用后不再触发；删除任务不影响已产生的执行记录与报告。
- 接口导入任务的导入策略同 3.2 定时导入（接口路径+方法匹配，手动修改过的接口不被覆盖）。
- 执行失败不自动重试，可通过「立即执行」手动补跑。
- 执行边界：仓库流水线执行场景（仅描述、无可执行内容）不参与定时，保持手动触发。
- 失败通知渠道沿用平台既有消息能力（预留）；平台无消息中心时仅记录失败状态不通知，通知能力在详细设计中确定。

## 4. 非功能需求

### 4.1 性能需求

- 单请求服务端执行的端到端延迟不超过请求本身网络往返 + 2 秒（受被测系统影响，为目标值而非硬性门槛）。
- 平台内执行支持并发（默认 5），并发执行下，单任务执行性能不因并发显著下降（目标值下降不超过 20%）。
- 百级步骤场景从触发到执行完毕（含步骤间参数传递）的总耗时目标值不超过请求总耗时 + 30 秒计算开销；场景编排保存响应时间 < 2 秒。
- 报告列表、接口列表等查询接口在万级数据量下分页响应时间目标值 2 秒内。
- 请求体大小上限与上传文件大小上限为系统配置项（默认 10MB），超限明确提示。

### 4.2 安全性需求

- 接口测试涉及的用户名密码（Basic/Digest Auth）、数据源密码、环境变量中的敏感值、GitLab 项目访问令牌等加密存储，不以下发明文至前端（脱敏展示）。
- 执行请求的目标地址不受平台出网限制策略约束之外的其他限制；Mock 访问需平台侧限流与审计（单路径 QPS 上限可配置，超限返回 429）。
- 跨项目数据隔离：接口定义、场景、环境、报告、全局资产严格按项目隔离，用户仅能访问其有权限的项目数据。
- 报告分享默认禁止，需项目管理员在项目设置中开启；分享链接支持有效期配置与失效，分享内容遵循项目数据安全策略。
- 导入功能（文件导入、Swagger URL 导入）需校验文件类型与内容，防范恶意文件与 SSRF（URL 导入的目标地址白名单或校验策略在详细设计中确定）。

### 4.3 可用性需求

- 快速调试、场景执行均提供明确的加载态与结果反馈；执行失败给出可定位的错误信息（连接失败/超时/断言失败明细）。
- 场景编辑支持步骤级启用/禁用与失败定位，批量调试可直接看到每个步骤的独立结果。
- 变更历史与执行历史为只读追溯信息，展示清晰、可区分来源（手动/导入/定时/同步）。

### 4.4 可靠性需求

- 服务端执行引擎故障不影响平台其他功能（场景/报告查询正常），执行任务失败可重试（手动或配置自动重试次数，默认不自动重试）。
- 定时导入、场景定时任务失败时记录失败原因并支持查看最近一次执行状态。
- GitLab API 调用失败（网络异常、仓库不存在、令牌失效）给出明确错误提示并支持重试。
- 流水线触发失败、结果拉取超时/失败时给出明确提示并支持重试与手动刷新执行状态。
- 报告与执行历史数据量大时按系统配置的清理策略自动清理（默认保留 90 天），清理行为记录日志，清理后历史详情明确展示「执行结果被清理」。

### 4.5 兼容性需求

- 支持主流的 Swagger/OpenAPI 2.0/3.0、Postman Collection v2 格式导入。
- 变量引用语法（`${变量名}`）与内置函数与 Ryze 框架保持一致；外部工具存量资产迁移友好性由后续迭代评估。
- 平台场景模型与 Ryze 标准格式的转换错误可定位，平台自身存储不依赖 Ryze 文档格式。

## 5. 数据需求

### 5.1 新增数据实体

- **接口定义**：协议、方法、路径、模块归属、请求参数（请求头/请求体/Query/REST/认证）、响应示例、**公共步骤**（可复用请求类步骤集合）、变更历史。
- **接口场景**：场景元数据（名称、模块、**关联接口（虚拟包归属，可选）**、参数配置、设置项）、步骤树（请求步骤及导入步骤）、前置/后置处理器、验证器、变更历史。
- **场景步骤**：步骤类型（http 取样器：系统请求/自定义请求/公共步骤添加；jdbc 取样器：数据库请求）、排序、启用状态、复制/链接引用关系标识（含源ID、引用模式）。
- **Mock 定义**：关联接口定义、匹配规则、响应定义（含延迟配置）、启停状态、命中次数统计。
- **环境**：环境名称、默认配置（http 默认配置，与 Ryze 对应一致）、数据源、全局变量、全局前置/后置处理器。
- **调试记录**：用户、请求快照、执行时间、执行模式（服务端/本地），本地执行记录仅存本地缓存。
- **报告**：关联执行对象（场景）、执行方式、结果汇总、步骤级结果明细、分享链接与有效期。
- **执行历史**：关联执行对象（场景）、执行时间、执行方式（平台内/仓库流水线）、结果、报告关联、流水线 ID 与链接（流水线执行时）。
- **GitLab 仓库集成**：仓库地址、分支/标签、项目访问令牌（密文存储）、关联项目、最近导入状态、元数据同步时间、测试类元数据清单（测试类全限定名、类级注解配置、类下测试方法清单，供仓库流水线执行触发）、测试范围参数契约（与 `.gitlab-ci.yml` 约定的变量名与取值规则）。
- **全局资产**：类型（前置处理器/后置处理器/验证器/提取器）、名称、内容配置（对应组件的配置要素，以 Ryze 为准）、启用状态、维护人、维护时间。
- **变更历史**：关联对象（接口/场景）、变更序号、变更内容、变更人、变更时间。
- **定时任务**：任务类型（接口导入/场景执行）、绑定对象（Swagger 文档地址/测试场景）、Cron 表达式、启用状态、执行记录（触发时间、触发方式、结果、失败原因、关联报告或导入结果）、创建者。

所有新增表遵循平台数据库规范：必含 `id`、`created_at`、`updated_at`、`is_deleted`（逻辑删除标记），禁止物理外键；索引设计遵循平台索引规范，高频查询条件（接口路径+方法、报告时间范围、对象引用关系等）需建索引；报告与执行历史等大表按月分区，清理策略默认保留 90 天（可配置）。

> 存储形态说明：平台以自有字段模型存储全部接口测试数据（上表各实体），**不持久化 Ryze 文档**；Ryze 标准 JSON 仅在执行时由平台实时解析生成，随执行快照保留以便结果回溯与转换问题定位。

### 5.2 数据隔离与生命周期

- 接口定义、接口场景、Mock、环境、报告、全局资产、定时任务、GitLab 仓库集成均归属项目，按项目隔离，与平台既有数据隔离原则一致。
- 逻辑删除贯穿全部实体；删除接口定义时其下关联的 Mock 的引用关系同步失效；若场景关联虚拟包，删除接口定义时级联解除场景的虚拟包关联。
- 报告与执行历史保留期限默认为 90 天（系统配置项），超期由系统清理任务清理；清理后执行历史保留元数据、详情置为「执行结果被清理」。
- 分享链接过期即失效，不长期保留可访问的匿名报告。
