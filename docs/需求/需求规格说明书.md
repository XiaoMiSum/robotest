## 1. 引言

### 1.1 编写目的

本文档定义软件测试平台的功能需求与非功能需求，面向项目经理、业务分析人员、测试工程师及开发团队，确保各方对平台的行为、规则和边界有一致理解。本版本在既有业务功能需求之外，一并完整描述 AI 智能辅助能力域的需求。

### 1.2 范围

平台包含两类用户角色：**系统管理员**和**业务用户**。  

- 系统管理员拥有全局管理权限，可管理用户、工作空间和角色。  
- 业务用户可同时归属多个工作空间，通过切换活跃工作空间在不同工作空间间工作，所有业务操作限定在当前活跃工作空间内。

测试用例以 **模块树（目录/文档）** 组织，每个文档包含一个脑图形式的测试用例集合，支持多人实时协作编辑。  
测试评审和测试计划基于用例的结构化快照进行，支持完整的历史回溯和多次执行/评审记录。

平台在上述业务功能之上提供 **AI 智能辅助能力域**，覆盖五个方向：

1. **智能测试用例生成** — 在脑图中由 AI 生成用例子树、补全步骤、推荐优先级，配套轻量需求池；
2. **AI 辅助评审与覆盖度分析** — 评审快照的完整性检查、评审摘要生成、遗漏测试点分析；
3. **缺陷智能分析与去重** — 缺陷标题优化与等级建议、语义查重、缺陷聚类分析；
4. **全局智能助手（ChatBot）** — 自然语言查询、快捷操作执行、对话式脑图编辑、平台使用指引；
5. **测试计划与风险评估** — 执行顺序推荐、用例规划智能推荐。

AI 功能均为既有业务流程的**增强项**，不改变既有业务规则与状态机；AI 能力不可用时，平台全部既有功能必须不受影响（见 4.4 可靠性需求）。

### 1.3 定义与缩写

| 术语         | 定义                                         |
| ---------- | ------------------------------------------ |
| 活跃工作空间     | 业务用户登录后选择的工作空间，所有业务操作默认在该工作空间上下文中执行        |
| 模块         | 项目内测试用例的组织结构，分为**目录**和**文档**两种节点           |
| 目录         | 仅用于分类的模块节点，不包含测试用例                         |
| 文档         | 关联一个脑图的模块节点，包含若干测试用例                       |
| 脑图文档       | 以思维导图形式组织的测试用例集合，由多个节点组成                   |
| 测试用例（用例节点） | 脑图中被标记为“用例”的节点，具有步骤、预期结果等属性                |
| 快照         | 评审或计划创建时对模块树和文档节点的完整复制，用于固化当时的状态           |
| 关联节点       | 用户在创建评审或计划时显式选择的用例节点                       |
| 关联节点树      | 从快照中裁剪出的最小树形结构，包含所有关联节点、它们的祖先模块/文档节点以及后代节点 |
| 同步         | 手动将评审或计划的快照更新为当前最新模块和用例内容的操作               |
| LLM        | 大语言模型（Large Language Model），平台通过外部或私有化部署的模型服务获得生成能力 |
| AI 网关      | 后端统一封装 LLM 调用的服务层，负责模型路由、Prompt 组装、流式输出、限流与审计 |
| 智能体        | 平台内每个 AI 功能对应的执行单元，其行为由系统提示词模板（角色指令段 + 输出格式约束段）定义，系统管理员可自定义 |
| 系统默认模型     | 多个对话模型配置中被管理员指定的全局默认项（有且仅有一个）；用户未选择或所选模型失效时，以及后台任务与建议类功能，均使用该模型 |
| 需求池        | 项目级的轻量需求条目库（粘贴的需求文本），供 AI 生成/补全/分析时选作上下文，减少重复手动输入 |
| 向量检索       | 将文本转换为向量（Embedding）后按语义相似度检索的能力           |
| 工具调用（Function Calling） | LLM 按预定义的工具清单发起结构化调用，由后端以当前登录用户身份执行的机制 |
| 预览-确认-执行    | AI 涉及写操作时的强制交互模式：先展示将要执行的操作明细，用户确认后才真正执行 |
| 脑图操作指令集     | 一组受限的结构化脑图操作描述（筛选条件 + 动作），AI 只负责将自然语言翻译为指令，执行由前端确定性代码完成 |
| 推荐执行指数      | 综合用例历史缺陷关联数量、优先级、模块风险等因素计算的执行顺序参考分值      |

## 2. 总体描述

### 2.1 用户角色与特征

| 角色    | 职责概述              | 权限边界                         |
| ----- | ----------------- | ---------------------------- |
| 系统管理员 | 平台全局维护            | 拥有系统权限，可访问系统管理功能；可同时归属工作空间 |
| 业务用户  | 所属工作空间内的测试活动管理与执行 | 拥有工作空间权限，所有业务操作限于当前活跃工作空间 |

- 一名用户可同时拥有多个系统角色和多个工作空间角色。
- 系统管理员由系统初始化时预设，不可被删除。
- 业务用户至少归属一个工作空间才能使用业务功能。
- 权限模型采用 RBAC，权限码按作用域分为 `global`（系统级）和 `workspace`（空间级）两类。

AI 能力在此角色模型（系统管理员 / 业务用户，RBAC 权限，`global` / `workspace` 双作用域）基础上补充如下约定：

- AI 功能仅面向**业务用户**开放，且所有 AI 操作严格限定在当前活跃工作空间与当前项目上下文内。
- AI 以当前登录用户的身份与权限执行读写操作，**不拥有任何独立权限**；用户无权执行的操作，AI 同样无权执行。
- 系统管理员可在系统级维护 AI 配置（模型服务地址、密钥、开关）与各智能体的提示词。
- 范围粒度约定：全局智能助手的自然语言查询范围为当前**工作空间**级（与助手全局入口定位一致）；语义查重、缺陷聚类、覆盖度分析等业务内嵌 AI 能力均限定当前**项目**级。

### 2.2 假设与依赖

- 平台账号由系统管理员统一创建，不存在自主注册功能。
- 平台具备基本的日志与审计能力（本文档不展开）。
- 脑图编辑器的前端技术选型及实时协作实现方案不影响业务需求的定义。
- 平台可访问一个兼容主流协议的 LLM 服务（公有云 API 或私有化部署），模型选型不影响业务需求定义。
- 语义检索类需求依赖文本向量化（Embedding）服务提供的向量检索能力。
- LLM 调用存在延迟（秒级）与费用成本，交互设计需明确加载态与流式反馈；具体成本策略由运营决定。
- 业务数据（用例、缺陷等）将作为 Prompt 上下文发送至 LLM 服务，数据出域合规性由部署方通过模型选型（如私有化部署）保障。

### 2.3 实施分期

按价值/成本比排定优先级，供迭代规划参考（非承诺性约束）：

| 梯队 | 需求范围 | 说明 |
| ---- | ---- | ---- |
| 一 | AI 基础设施、用例子树生成、步骤补全、评审摘要 | 复用度最高，快速见效 |
| 二 | 缺陷表单建议、评审一键检查、需求池、遗漏测试点分析（关键词版）、助手使用指引 | 反哺一梯队质量，ChatBot 只读首发 |
| 三 | 缺陷语义查重、遗漏测试点分析（语义升级）、用例规划智能推荐、助手自然语言查询、执行顺序推荐 | 依赖向量检索基建 |
| 四 | 助手快捷操作、对话式脑图编辑、缺陷聚类看板、优先级推荐 | 写操作型 AI，需严格风险管控 |

> 分期依赖说明：3.4.1、3.4.2、3.5.3、3.8.2 中「从需求池选取条目」的功能点依赖需求池（3.4.4，梯队二）交付后启用；梯队一交付时相关功能仅支持手动输入需求文本，不影响主流程可用性。

## 3. 功能需求

### 3.1 系统管理模块（拥有系统权限的用户可访问）

拥有任意系统权限的用户可见系统管理功能入口。无系统权限的用户不显示系统管理入口。

#### 3.1.1 用户管理

**功能描述**：管理平台所有账号的生命周期。  
**功能点**：  

- 创建账号：录入用户名、邮箱、初始密码，选择角色。  
- 编辑账号：修改邮箱、角色、密码重置。  
- 禁用/启用账号：禁用后该用户无法登录，历史数据保留。支持批量操作。  
- 查询与筛选：可按用户名、邮箱、状态、角色等条件检索用户。  

**业务规则**：  

- 用户名必须全局唯一，长度3~30字符。  
- 密码仅需 8~64 字符长度，不再要求包含大写、小写、数字、特殊字符中至少三种。
- 系统管理员不能修改自己的角色或禁用自己。  
- 用户的工作空间归属由「全局工作空间管理」维护，用户管理不涉及工作空间归属的设置。

#### 3.1.2 全局工作空间管理

**功能描述**：管理平台内所有工作空间的创建、解散及成员构成。  
**功能点**：  

- 创建工作空间：输入工作空间名称和描述，名称全局唯一，长度2~50字符。  
- 解散工作空间：仅当工作空间下没有任何项目（含归档项目）时允许解散；解散后自动解除所有成员的该工作空间归属。  
- 添加成员：选择目标工作空间，从平台业务用户中多选加入。一个用户可同时属于多个工作空间。  
- 移除成员：解除指定用户与目标工作空间的关系，不影响该用户在其他工作空间的归属。  

**业务规则**：  

- 系统管理员不能被添加为任何工作空间成员。

#### 3.1.3 角色与权限管理

**功能描述**：定义平台角色及其功能权限，并将角色授予用户。  
**功能点**：  

- 定义角色：可创建自定义系统角色或工作空间角色，预置"系统管理员"角色不可删除。
- 权限作用域：权限点分为 `global`（系统级）和 `workspace`（空间级）两类，角色通过 `scope` 字段限定其权限范围。
- 全量权限（full_access）：角色可设置为全量权限，拥有对应作用域下的所有权限码，运行时自动注入。
- 配置权限：以功能模块为单位，通过权限列表勾选可访问的功能点。系统管理员默认拥有所有全局管理权限且不可更改。
- 分配角色：为用户指定一个或多个系统角色，工作空间角色在空间成员管理中设置。

**业务规则**：  

- 角色名称全局唯一。
- 具有全量权限（full_access）的角色，其权限配置面板锁定，不可手动编辑。
- 权限变更后，已登录用户的下次请求即可生效（工作空间权限通过拦截器实时注入）。

#### 3.1.4 系统初始化

**功能描述**：平台首次部署完成后，系统必须经过初始化才能使用。初始化由安装者在登录页自动引导完成。  
**功能点**：

- 初始化检测：访问登录页时自动调用初始化状态接口，后端检查有无任何用户存在。
- 初始化引导：若系统未初始化，登录页自动跳转至初始化页面。
- 设置管理员密码：输入管理员密码（至少 8 位）并确认，提交后系统创建 admin 账号并分配系统管理员角色。
- 初始化防重：若系统已初始化（存在用户），再次调用初始化设置接口返回错误码，禁止重复初始化。

**业务规则**：

- 初始化接口为公开接口，无需认证即可访问。
- admin 账号为系统初始化时自动创建，用户名固定为 `admin`，显示名称为「系统管理员」。
- 初始化完成后跳转至登录页，用户使用 admin 账号及设置的密码登录。
- 系统管理员角色预置 UUID `b0000000-0000-0000-0000-000000000001`，拥有全部系统权限。
- 初始化后可登录进入系统管理模块创建普通用户，也可先创建工作空间后再创建业务用户。

### 3.2 业务功能模块（仅业务用户可访问）

业务用户登录后，如果归属多个工作空间，必须选择一个作为活跃工作空间；如果仅归属一个工作空间，则自动激活。界面提供工作空间切换器，切换后所有业务数据立即刷新至新工作空间上下文。

#### 3.2.1 我的工作空间

**功能描述**：查看用户归属的工作空间列表，切换活跃工作空间，并可修改工作空间基本信息。  
**功能点**：  

- 工作空间列表：显示用户归属的所有工作空间，标注当前活跃工作空间。  
- 切换活跃工作空间：点击非活跃工作空间即可切换，全局状态更新。  
- 修改工作空间信息：进入工作空间详情，可编辑工作空间名称和描述（名称需全局唯一）。  

**业务规则**：  

- 若用户仅归属一个工作空间，可自动激活，工作空间切换器可隐藏。  
- 若用户从当前活跃工作空间中被移除，系统应自动切换到剩余工作空间中的第一个；若无剩余工作空间，则业务功能不可用。

#### 3.2.2 工作空间成员管理（当前活跃工作空间）

**功能描述**：管理当前活跃工作空间的成员构成。  
**功能点**：  

- 查看成员列表：显示当前工作空间所有成员及其角色。  
- 邀请成员：从平台其他业务用户中搜索并邀请加入当前工作空间。若对方已是本工作空间成员则提示。  
- 移除成员：解除某成员与当前工作空间的关系，不可移除自己。  

**业务规则**：  

- 所有操作仅作用于当前活跃工作空间，不影响用户在其他工作空间的归属。

#### 3.2.3 项目管理

**功能描述**：管理当前活跃工作空间下的项目。  
**功能点**：  

- 项目列表：展示当前工作空间所有项目，显示名称、状态、起止时间等信息。  
- 创建项目：输入名称（工作空间内唯一）、描述、起止时间，项目自动归属当前工作空间。  
- 编辑项目：可修改名称、描述、时间等信息，但所属工作空间不可变更。  
- 归档/启封：归档后项目数据变为只读；归档前需确保无进行中的测试计划。支持反归档。  

**业务规则**：  

- 切换活跃工作空间后，项目列表自动刷新。  
- 用户进入项目时，系统需验证该项目属于当前活跃工作空间。

#### 3.2.4 功能测试（项目工作区）

进入项目后，所有功能测试活动均在当前选定的项目内进行，当前活跃工作空间上下文不变。

##### 3.2.4.1 测试用例管理

**模块管理**  

- 项目下可创建无限层级的模块树，节点类型分为**目录**（可包含子目录和文档）和**文档**（不可包含子模块，仅关联一个脑图）。  
- 支持新建、重命名、删除、拖拽排序。删除目录时需目录为空；删除文档将同时删除其内部所有用例数据。  

**脑图实时协作编辑**  

- 打开文档后进入脑图编辑器，支持同时有多名用户编辑同一文档，编辑操作实时同步给其他用户。  
- 脑图由任意节点构成，用户可自由创建、移动、删除节点，并可编辑节点文本、调整层级关系。  
- 节点可被标记为**用例节点**，用例节点额外拥有优先级、前置条件、测试步骤、预期结果、标签等属性。  
- 编辑过程中系统应保证数据一致性，多人操作冲突时以合理策略合并。  

**用例列表视图**  

- 提供列表模式查看当前文档中的所有用例节点，支持按标题、优先级筛选，可在列表中编辑用例属性，并与脑图视图双向同步。  

**关联与引用**  

- 在测试计划或测试评审中，用户可以从模块树中选取具体的用例节点进行关联。  
- 关联完成后，系统生成该时刻的模块和文档快照，以保证后续历史查看不受用例修改影响。

##### 3.2.4.2 测试评审管理

**概述**  
测试评审仅针对测试用例，以脑图快照为基础，支持多位参与者对节点进行标记和评论，同一节点可被多次评审，形成评审记录。

**发起评审**  

- 用户从模块树中选择需评审的用例节点（可跨文档多选），指定发起人（默认自己）和若干参与者（必选至少一人），填写标题和描述。  
- 系统根据所选节点，自动生成当时的模块快照和文档节点快照，评审状态初始为“评审中”。

**评审详情展示**  

- 评审详情以**关联节点树**的形式呈现：仅展示与关联节点相关的模块路径和脑图子树，高亮被标记为关联的用例节点，并显示各节点的最新评审标记状态。  
- 涉及多个文档时，详情页左侧提供快照文档树，点击文档切换对应的快照脑图。  
- 评审列表支持按标题关键字模糊查询与状态筛选。  

**评审操作**  

- 参与者可点击树上的任意节点，进行**标记**（仅用例节点可标记“通过”、“不通过”或重置回“待评审”）或**添加评论**。标记结果回显在节点上。  
- 每次提交生成一条评审记录，系统同步更新该节点的最后标记状态（用于树形视图的快速展示）。  
- 所有参与者的操作实时保存，其他参与者可即时看到最新状态。  

**调整规划用例**  

- 评审未结束（评审中）时，可重新选择关联的用例：支持新增文档、移除文档、调整文档内的用例集合。  
- 系统按差量更新快照：新增文档生成快照，移除文档删除快照（已产生的标记/评论记录保留作审计），保留文档补入快照后新建的节点并重刷关联状态（取消关联的节点保留已有标记，仅不再计入统计）。

**评审记录查看**  

- 对于任意节点，可查看其完整的评审历史，包含历次标记变更和评论。  

**完成评审**  

- 发起人可手动关闭评审，状态变为“已完成”，此后不可再新增或修改评审记录，快照冻结。  
- 仅当全部关联用例评审通过（无待评审、无不通过）时才允许完成评审。

**同步最新用例**  

- 在“评审中”状态下，发起人可执行同步操作。系统根据关联的原始节点ID，用当前最新的模块结构和用例内容更新快照。若某原始节点已被删除，则在快照中标记为“已删除”，其已有评审记录仅可查看。  
- 同步后，保留所有已产生的评审记录。  

**业务规则**：  

- 参与者必须是当前活跃工作空间成员。  
- 发起人不能同时作为参与者。  
- 评审完成后，任何人均只能查看，不能编辑。

##### 3.2.4.3 测试计划管理

**概述**  
测试计划关联测试用例并管理执行过程，基于快照进行，支持多次执行记录，以追踪执行历史。

**创建计划与关联用例**  

- 用户创建计划，输入名称、起止时间、负责人、执行环境、描述等信息。  
- 从模块树中选择需执行的用例节点，系统生成当时的模块和文档快照，并为每个关联的用例节点初始化执行状态为“未执行”。

**计划详情展示**  

- 计划详情以**关联节点树**形式展示，高亮关联的用例节点，并根据最后一次执行结果显示状态图标（通过/失败/阻塞/待执行）。  
- 涉及多个文档时，详情页左侧提供快照文档树，点击文档切换对应的快照脑图。  
- 计划列表支持按名称关键字模糊查询与状态筛选。  

**执行跟踪**  

- 负责人或指定的执行人可点击树上的关联用例节点，标记执行结果（通过/失败/阻塞/待执行）并填写备注，结果回显在节点上。  
- 每次提交生成一条执行记录，系统同步更新该节点的最后执行结果。  
- 同一节点可被多次执行，所有历史记录可追溯。  

**调整规划用例**  

- 计划未结束（新建/进行中）时，可重新选择关联的用例，差量更新规则与测试评审一致；新补入快照的用例初始状态为“待执行”。

**执行历史**  

- 对任一节点可查看其完整的执行记录列表，包含每次结果、执行人和备注。  

**计划状态流转**  

- 计划状态按“新建 → 进行中 → 已完成 → 已关闭”流转。  
- 关闭计划时，系统检查是否有未执行用例，若有则提示。关闭后不可再修改执行结果。  

**同步最新用例**  

- 在“进行中”状态下，负责人可同步快照至最新版本，保留所有已产生的执行记录。已删除的原始节点将在快照中标记，其结果只读。  

**业务规则**：  

- 计划负责人和实际执行人必须是当前工作空间成员。  
- 只有被关联的用例节点才可以被标记执行结果。

##### 3.2.4.4 缺陷管理

**功能描述**：管理项目内发现的缺陷，支持完整生命周期跟踪。  
**功能点**：  

- 提交缺陷：填写标题、严重等级（致命/严重/一般/轻微）、优先级（高/中/低）、详细描述、附件，可关联至当前版本的测试用例和测试计划。  
- 缺陷状态流转：新建 → 已指派 → 修复中 → 已修复 → 已验证 → 关闭，可重新打开。  
- 指派处理人：从当前工作空间成员中选择。  
- 操作记录：每次状态变更或信息更新时记录注释，形成操作历史。  
- 统计视图：按状态、严重等级、处理人等维度展示缺陷分布图表。  

**业务规则**：  

- 处理人必须是当前活跃工作空间成员。  
- 关闭缺陷时必须填写关闭说明。

### 3.3 AI 基础设施（公共需求）

**功能描述**：为所有 AI 功能提供统一的后端服务层与前端交互约定。  
**功能点**：

- AI 配置：系统管理员可配置模型服务地址、密钥、对话模型与 Embedding 模型名、启用开关，并可执行连通性测试；支持从预置的模型供应商清单中选择供应商，选择后自动填充该供应商的默认服务地址，并呈现其**独有配置项**（如思考模式开关）供调整，也可选择通用 OpenAI 兼容模式自由配置；未配置或关闭时，前端隐藏全部 AI 功能入口。
- 多对话模型：系统管理员可同时配置**多个对话模型**（每个模型独立维护供应商、服务地址、密钥、模型名与附加参数），并指定其中一个为**系统默认模型**；每个对话模型可独立执行连通性测试、启用/停用。Embedding 模型保持单一配置，不支持多个。
- 用户切换模型：交互式 AI 功能（全局助手对话、用例生成、步骤补全、评审摘要等用户直接发起的功能）允许用户在已启用的对话模型清单中临时切换本次调用使用的模型；后台异步任务（评审完整性检查、缺陷聚类等）与建议类功能固定使用系统默认模型，保证结果一致性。
- 系统配置项维护：系统管理员可查看并逐项调整全部 AI 系统配置项（限流阈值、相似度阈值、长度限制、保留期限等），配置界面以表单形式完整展示各配置项（含说明与默认值），逐项校验取值范围；未调整的配置项使用系统默认值。
- 智能体：每个 AI 功能对应一个智能体，预置默认系统提示词模板，系统管理员可查看模板内容、自定义覆盖，并可一键恢复默认。模板分为「角色指令段」与「输出格式约束段」两部分：角色指令段可直接编辑；输出格式约束段默认锁定不可编辑，需通过高级开关显式开启编辑（默认关闭）。
- 统一调用通道：所有 AI 请求经后端 AI 网关转发，前端不直连模型服务，密钥不下发至前端。
- 流式输出：生成类功能（用例生成、摘要、对话）支持流式返回，用户可中途取消。
- 调用审计：每次 AI 调用记录用户、工作空间、项目、功能类型、耗时与结果状态，纳入平台审计日志体系。
- 限流保护：按用户维度限制调用频率（阈值为系统配置项），超限时明确提示。

**业务规则**：

- AI 请求与普通业务请求走同一套认证与工作空间上下文校验，上下文标识不得出现在 URL 或请求体中。
- AI 生成的内容在落库前必须经过与人工输入相同的校验规则（长度、枚举值、权限）。
- 自定义提示词仅影响生成内容的风格与质量，不得移除结构化输出要求；若因编辑输出格式约束段导致 AI 输出无法通过结构化校验，按调用失败处理，并在管理端提示检查模板。
- AI 功能开关由启用转为关闭时：进行中的流式生成立即中断并提示用户；进行中的异步任务（评审检查、缺陷聚类等）自动终止并标记为已取消；此前已产出的结果仍可查看。
- 系统默认对话模型有且仅有一个：将某模型设为默认时自动取消原默认；默认模型不允许停用或删除（需先将默认转移至其他模型）；删除或停用某模型后，此前选择该模型的用户自动回退到系统默认模型。
- 用户的模型选择仅在用户本端记忆（浏览器本地），不在服务端持久化；所选模型不存在或不可用时静默回退系统默认模型。用户切换模型不影响其他用户，也不影响系统默认设置。
- 调用审计必须记录本次实际调用的模型，调用量统计支持按模型维度聚合。
- 智能体提示词模板的自定义、恢复默认及格式约束段编辑开关的变更均记录审计日志。
- 更换 Embedding 模型后，存量向量与新模型的向量空间不兼容：系统必须支持对存量数据重新执行向量化并重建语义检索能力；重建完成前，语义查重、缺陷聚类等语义检索能力自动降级为关键词匹配并向用户明示降级状态。

### 3.4 智能测试用例生成

#### 3.4.1 AI 生成用例子树（US-AI-001）

**功能描述**：在脑图编辑器工具栏提供「AI 生成用例」入口，根据用户输入的需求描述或模块名称，生成完整用例子树并挂载到文档根节点下。  
**功能点**：

- 输入需求描述（文本），或从需求池（见 3.4.4）中直接选取需求条目作为输入，减少重复粘贴。
- AI 输出结构化用例树：测试用例节点 → 前置条件 / 执行步骤 / 预期结果子节点，节点类型与平台既有用例节点模型完全一致。
- 生成的节点**直接完成标记**：用例节点自动标记为用例类型并带优先级（P0/P1/P2/P3），其子节点自动分别标记为前置条件、执行步骤、预期结果类型，挂载后无需用户逐个手工标记。
- 生成结果先以预览形式展示，用户确认后一次性挂载到文档根节点下；挂载走脑图既有编辑通道，协同用户实时可见，支持撤销。

**业务规则**：

- 挂载节点固定为文档根节点，不随当前选中节点变化。
- 生成的节点携带「AI 标识」（来源标记字段），在脑图节点上以徽标形式展示，用于区分 AI 生成与手工创建的节点；除该标识外，节点数据模型与手工创建并标记的节点无任何差别，标记（类型、优先级）挂载后可照常手工修改。
- AI 标识仅表示节点由 AI 生成，不影响任何业务规则（评审、计划、执行照常进行）；用户可在节点标记操作中手动移除该标识，移除后不可重新添加（AI 标识仅由 AI 生成动作赋予）；评审/计划快照继承该标识。
- AI 标识作为节点数据的一部分，随节点的复制/剪切粘贴保留到副本（属数据继承，不视为「重新添加」），副本上同样可手动移除。
- 生成过程中文档仍可正常编辑；挂载时若文档根节点已被他人删除，提示用户重新选择。

#### 3.4.2 AI 补全步骤（US-AI-002）

**功能描述**：选中已有用例节点，通过右键菜单「AI 补全步骤」自动补充缺失的前置条件、执行步骤和预期结果。  
**功能点**：

- 上下文取材：当前节点标题、祖先节点路径、同级节点、关联的需求池条目（见 3.4.4）；也可临时粘贴需求文本作为补充上下文。
- 补全结果以预览形式展示，预览中**全部生成节点默认勾选、可逐项取舍**（每个前置条件/执行步骤/预期结果可独立勾选），确认后追加为该用例节点的子节点，并自动标记为前置条件/执行步骤/预期结果类型；已有的前置条件/执行步骤/预期结果子节点保留，不覆盖（仅补缺失项）。

**业务规则**：

- 仅用例类型节点的右键菜单显示该入口。
- 补全生成的子节点同样携带 AI 标识（规则同 3.4.1）。

#### 3.4.3 优先级智能推荐（US-AI-003）

**功能描述**：节点被标记为测试用例时，根据标题自动推荐优先级（P0/P1/P2/P3），点击推荐项即完成标记。  
**功能点**：

- 采用规则 + LLM 混合策略：关键词规则命中时即时给出推荐，未命中时由 LLM 异步推荐；推荐延迟不阻塞用户手工标记。
- 推荐以非侵入式提示呈现（如标记面板内的推荐标签），用户可采纳、忽略或手工另选。

**业务规则**：

- 推荐仅是建议，最终优先级以用户实际选择为准；用户未操作时不自动写入。

#### 3.4.4 轻量需求池（US-AI-004）

**功能描述**：项目级维护一个轻量「需求池」，集中存放需求条目（粘贴的需求文本）。AI 生成、补全、覆盖度分析时从池中选取条目作为上下文，避免用户在各功能入口重复手动输入需求。  
**功能点**：

- 需求条目管理：在项目工作区提供需求池入口，支持新增、编辑、删除、归档/取消归档条目；条目包含标题、内容（Markdown 文本）、可选来源 URL（仅作为出处记录展示，平台不抓取其内容）、状态（active / archived，默认 active）。
- 条目与文档关联：脑图文档可关联一个或多个需求条目作为默认上下文；AI 生成/补全时自动带入关联条目，也可临时改选其他条目。
- 条目复用：需求池条目可在「AI 生成用例」（3.4.1）、「AI 补全步骤」（3.4.2）、「遗漏测试点分析」（3.5.3）、「用例规划智能推荐」（3.8.2）中直接选用。
- 检索：支持按标题关键字查找条目，支持按状态筛选（全部 / 仅 active / 仅 archived）。
- AI 文档拆分（US-AI-019）：需求池页提供「AI 拆分」入口，粘贴整份需求文档后由 AI 按模块/功能拆分为多个需求条目；拆分结果按模块分组预览，可逐条编辑与取舍（勾选）后批量入库；AI 拆分产生的条目携带「AI 标识」徽标。

**业务规则**：

- 需求池归属项目，池内条目仅在当前项目内可见与可用；同项目成员共享查看与选用，条目的编辑、删除、归档与取消归档仅限条目创建人及具备项目管理权限的成员。
- 条目内容长度设上限（系统配置项），超限时明确提示。
- 删除条目不影响已生成的用例；文档与条目的关联随条目删除而解除。
- 条目默认状态为 active；可手动归档（archived），归档后**禁止编辑**，可取消归档恢复为 active。
- 需求池定位为 AI 上下文的轻量载体，状态仅承载 active / archived 两态（流转仅限手动归档/取消归档），不承担完整需求管理职能（无评审流程）。
- **active 过滤**：除需求池管理页列表（支持按状态筛选）外，其余获取需求池条目的场景——需求条目选取器（3.4.1、3.4.2、3.5.3、3.8.2 复用）、文档关联查询、AI 上下文组装——均只可见/选用/组装 active 条目；archived 条目不参与 AI 消费，但其已建立的文档关联记录保留（关联查询时过滤不展示）。
- 需求池为可选而非强制：各消费需求上下文的 AI 功能入口（3.4.1、3.4.2、3.5.3、3.8.2）均同时支持直接粘贴需求文本作为一次性临时上下文；临时粘贴的文本不自动存入需求池（入池仅通过需求池管理页新增或文档关联选用）。
- 需求池条目**不参与语义检索**，条目检索仅按标题关键字匹配；池内条目始终作为 AI 的输入上下文（人工选取或按关联带入），不作为语义检索的目标语料。
- 需求池为常规业务功能，其入口**不随 AI 配置开关隐藏**；AI 不可用时条目管理（新增、编辑、删除、关联）照常可用，仅失去被 AI 功能消费的场景。
- **AI 拆分输入约束（US-AI-019）**：待拆分文档为粘贴文本，长度上限复用「外部文本导入」配置项；超限时截断并提示，不阻塞拆分。拆分输出为「模块 → 需求点[]」，一个需求点 = 一个可测试功能行为（固定细粒度，不提供粗/细切换）；模块归属仅作预览分组展示，**不入库为独立字段**——入库时模块名并入条目标题前缀（如「用户管理 · 新增用户」）。
- **AI 拆分预览与入库（US-AI-019）**：拆分结果先以预览形式按模块分组展示（每条含标题与内容，可逐条编辑、删除），勾选后批量入库；未勾选条目不入库。入库条目标记为 AI 生成（携带 AI 标识），列表展示「AI」徽标（复用 AI 标识规范，可编辑、可归档，不因 AI 生成豁免业务规则）。
- **AI 拆分与闭环（US-AI-019）**：本次范围止于「文档 → 需求条目」拆分入库；「需求 → 用例文档」的生成闭环不在本版本，后续迭代另行评估（拆分条目作为普通 active 条目，天然可被 3.4.1 生成用例选用）。

### 3.5 AI 辅助评审与覆盖度分析

#### 3.5.1 AI 一键检查（US-AI-005）

**功能描述**：评审详情页提供「AI 一键检查」，自动扫描当前快照树中所有用例节点，输出完整性建议并支持定位到对应节点。  
**功能点**：

- 检查维度：缺少前置条件、步骤描述过于笼统、预期结果缺失、相似用例优先级冲突等。
- 检查结果以列表面板展示，每条建议关联具体节点，点击后脑图定位并高亮该节点。
- 大快照（超出单次模型上下文容量）自动分批检查，展示进度；检查为异步任务，用户可离开页面后回来查看结果。

**业务规则**：

- 检查建议仅供参考，不自动修改任何节点或评审标记。
- 仅评审发起人可发起检查并查看检查结果（与附录 A 角色权限矩阵一致）；评审状态为「待评审」或「评审中」时可发起，评审已完成（completed）时不可再发起，同一评审同时只允许一个检查任务在执行。
- 评审离开「评审中」状态（完成或结束）时，进行中的检查任务自动终止并标记为已取消；此前已产出的检查结果仍可查看。评审已完成时，历史检查结果仍可查看（只读，不可重新发起）。

#### 3.5.2 AI 生成评审摘要（US-AI-006）

**功能描述**：评审完成后，一键汇总全部节点的评审标记与评论，生成结构化评审报告。  
**功能点**：

- 统计部分（通过率、不通过率、待评审数、问题分布）由系统精确计算，不依赖 LLM。
- 文字总结部分（主要问题归纳、改进建议）由 LLM 基于评审记录与评论生成。
- 报告以 Markdown 呈现，可复制；重复生成时覆盖上一份。

**业务规则**：

- 仅评审发起人可生成摘要；仅评审状态为「已完成」时可生成；摘要不回写评审记录，不影响快照冻结状态。

#### 3.5.3 遗漏测试点分析（US-AI-007）

**功能描述**：在用例模块页面输入本次迭代的关键需求关键词，AI 对比现有用例库，输出「可能遗漏的测试点」建议。  
**功能点**：

- 输入关键词（多个）、直接粘贴需求文本，或选取需求池条目（见 3.4.4）作为需求输入；系统检索项目内相关用例（关键词匹配，具备向量检索能力后升级为语义匹配）。
- AI 对比需求关键词与现有用例覆盖面，输出遗漏测试点清单及建议归属模块。
- 建议清单支持一键转化为「AI 生成用例子树」（3.4.1）的输入。

**业务规则**：

- 分析范围限定当前项目；建议不自动创建任何用例。

### 3.6 缺陷智能分析与去重

#### 3.6.1 标题优化与等级建议（US-AI-008）

**功能描述**：提交缺陷时，AI 优化标题表述，并根据标题与描述建议严重等级和优先级。  
**功能点**：

- 缺陷表单提供「AI 建议」操作：返回优化后的标题（用户可一键替换或忽略）及建议的严重等级（致命/严重/一般/轻微）与优先级（高/中/低）。
- 建议值必须映射到平台既有枚举，不引入新枚举值。

**业务规则**：

- 建议仅回填表单待用户确认，提交前用户可任意修改；不产生任何自动提交行为。

#### 3.6.2 语义查重（US-AI-009）

**功能描述**：提交缺陷时，基于语义相似度实时检索历史缺陷库，列出可能重复的缺陷，避免重复提交。  
**功能点**：

- 用户点击表单 [AI 建议] 时，系统基于当前标题（及描述）按语义相似度检索本项目历史缺陷，展示疑似重复缺陷卡片（标题、状态、处理人、相似度）；查重与建议并发发起，无独立自动触发。
- 查重范围仅限**未关闭**缺陷（active/resolved/rejected），已关闭（closed）缺陷不参与查重。
- 点击卡片可打开对应缺陷详情；用户确认重复时可放弃提交，或继续提交并在后续流转中标记「重复缺陷」（复用平台既有的 resolution 机制）。
- 标题少于 5 字符时不发起查重；连续触发时以最后一次请求为准。

**业务规则**：

- 缺陷新增、标题/描述修改时同步更新其语义检索数据；存量缺陷通过后台任务一次性回填。
- 查重范围限定当前项目且排除已关闭缺陷；查重不阻断提交，仅提示。

#### 3.6.3 缺陷聚类分析（US-AI-010）

**功能描述**：在缺陷看板页提供「AI 分析」面板，对未关闭缺陷按语义聚类，识别高频模块与根因，以图表展示缺陷分布热点。  
**功能点**：

- 分析范围：当前项目全部未关闭缺陷（active/resolved/rejected）。
- AI 按主题聚类并为每类归纳标签与疑似根因；结合模块、严重等级维度输出分布图表。
- 分析结果附生成时间，支持手动刷新；分析为异步任务。

**业务规则**：

- 分析结果为只读洞察，不修改任何缺陷数据。

### 3.7 全局智能助手（ChatBot）

#### 3.7.1 自然语言查询（US-AI-011）

**功能描述**：通过平台右下角悬浮按钮打开对话面板，用自然语言查询平台数据，AI 返回整理后的结果。  
**功能点**：

- 支持查询范围：当前工作空间内用户可见的评审、计划、缺陷、用例数据（如「我最近一周参与的评审」「未关闭的致命缺陷数量」）。
- AI 通过预定义的只读工具清单调用平台查询接口，以当前用户身份执行，返回结构化结果（列表/数字/链接）。
- 支持多轮对话，保留会话内上下文；会话内容仅本人可见（审计权限用户仅可见调用元数据，见 4.2）。

**业务规则**：

- 工具调用一律经过与普通请求相同的权限校验；用户无权查看的数据，助手不返回。
- 助手不得虚构数据：无法通过工具获得的数据必须明确告知「查询不到」。

#### 3.7.2 快捷操作执行（US-AI-012）

**功能描述**：通过助手以自然语言执行快捷操作（如「在项目X中创建一个P1缺陷，标题为登录超时」），AI 调用后端接口完成并返回结果链接。  
**功能点**：

- 写操作工具采用白名单制，白名单由系统配置维护；首期默认仅开放「创建缺陷」「创建计划草稿」两项低风险操作，不开放删除类操作。
- 强制预览-确认-执行：助手先展示将要执行的操作明细（目标对象、字段值），用户点击确认后才真正执行；执行结果附跳转链接。

**业务规则**：

- 任何写操作不得跳过确认环节；确认超时（时长为系统配置项，默认 5 分钟）或用户取消则放弃执行。
- 写操作与人工操作产生完全相同的审计记录与业务校验。

#### 3.7.3 对话式脑图编辑（US-AI-013）

**功能描述**：在脑图编辑页向助手发出编辑指令（如「为当前用例增加一个步骤：验证短信验证码」），AI 在脑图中新增对应节点。  
**功能点**：

- 助手感知当前页面上下文（当前文档、当前选中节点）。
- 编辑指令翻译为脑图操作指令集，经预览确认后由前端执行，走既有编辑与协同通道，支持撤销；由此新增的节点携带 AI 标识（规则同 3.4.1）。

**业务规则**：

- 仅当前用户对该文档有编辑权限时可用；指令歧义时助手必须追问而非猜测执行。

#### 3.7.4 平台使用指引（US-AI-014）

**功能描述**：新用户可向助手询问平台使用方法（如「如何发起评审？」），AI 返回步骤指引和页面跳转链接。  
**功能点**：

- 基于平台使用文档知识库回答，附带可点击的页面路由链接。
- 超出知识库范围的问题明确告知无法回答，不杜撰功能。

**业务规则**：

- 使用指引为纯只读能力，任何角色的业务用户均可使用。

### 3.8 测试计划与风险评估

#### 3.8.1 执行顺序推荐（US-AI-017）

**功能描述**：计划详情页提供「AI 执行顺序推荐」，为关联用例计算推荐执行指数，并在脑图节点上标注执行顺序建议。  
**功能点**：

- 推荐执行指数由系统按确定性加权模型计算（因子：用例历史关联缺陷数量、用例优先级、所属模块历史缺陷密度），LLM 仅用于生成推荐理由说明。
- 脑图节点以徽标形式标注建议执行顺序；提供按指数排序的用例列表视图。

**业务规则**：

- 仅计划执行人（即计划负责人）可发起计算并查看推荐结果（与附录 A 角色权限矩阵一致）。
- 推荐仅供参考，不改变计划的执行流程与执行记录规则；重新同步快照后需重新计算。

#### 3.8.2 用例规划智能推荐（US-AI-018）

**功能描述**：测试评审「调整用例」与测试计划「调整用例」流程提供 AI 推荐入口——基于已选需求池条目（多选）与直接粘贴的需求文本，AI 检索当前项目用例库，推荐应纳入该评审或计划的用例清单。  
**功能点**：

- 输入需求池条目（见 3.4.4，可多选）或直接粘贴需求文本（可空；条目与文本至少一项非空）作为推荐依据。
- 检索策略：需求上下文关键词语义匹配（具备向量检索能力后启用）；已纳入当前评审/计划的用例不重复推荐（由前端传入排除集）。
- 输出建议用例清单（含所属模块路径与推荐理由），支持一键带入评审/计划的「调整用例」关联流程。

**业务规则**：

- 推荐范围限定当前项目；已规划（已纳入当前评审/计划）的用例从推荐清单中排除，避免重复关联。
- 推荐仅是建议，最终纳入哪些用例由用户在既有「调整用例」关联流程中确认；推荐结果不自动写入任何关联。

## 4. 非功能需求

### 4.1 性能需求

- 常规页面首屏加载时间不超过2秒。  
- 工作空间切换后数据刷新应在500毫秒内完成。  
- 脑图文档（含200个以上节点）打开时间不超过1秒。  
- 快照生成操作应在500毫秒内完成（对于200节点规模的文档）。  
- 系统应支持至少100名业务用户同时在线操作。
- AI 生成类请求（用例子树、摘要等）流式输出的首内容返回时间目标值为 3 秒（受外部 LLM 服务影响，为目标值而非硬性门槛）；超过 10 秒未返回首内容时提示用户可取消或重试；单次生成总时长超过 60 秒时允许用户取消。
- 优先级推荐、语义查重等表单内嵌 AI 能力不得阻塞用户的正常输入与提交操作。
- 语义查重检索（不含向量化耗时）应在 500 毫秒内返回。
- 异步分析任务（评审检查、缺陷聚类）执行期间不影响页面其他操作，任务状态可查询。

### 4.2 安全性需求

- 用户身份认证应安全可靠，会话超时后需重新登录。  
- 业务操作必须验证用户所属的活跃工作空间，严格隔离不同工作空间的数据。  
- 登录失败次数过多时应临时锁定账户。  
- 应防范常见的Web安全攻击（如跨站脚本、跨站请求伪造）。  
- 实时协作通道也应进行身份验证和工作空间上下文校验。
- LLM 服务密钥仅存于后端配置，严禁下发前端或写入日志。
- 所有 AI 接口经过与普通业务接口相同的认证、工作空间上下文校验与权限校验；工具调用不得绕过 Service 层业务规则。
- 防范 Prompt 注入：用户输入与业务数据作为上下文时须与系统指令隔离；AI 输出在执行/落库前必须经过结构化校验（schema、枚举、长度）。
- AI 会话与调用审计数据按工作空间隔离；会话的对话内容与生成内容仅本人可见，审计权限用户仅可见 AI 调用审计元数据（用户、功能类型、耗时、token 用量、结果状态），不可见对话内容。

### 4.3 可用性需求

- 脑图编辑器应提供常用键盘快捷键（如Tab/Enter创建子节点，Delete删除节点）。  
- 工作空间切换器应固定在界面明显位置，当前活跃工作空间状态清晰可见。  
- 在快照展示页面，应明确标识“快照版本”和生成时间。  
- 同步操作应提供二次确认，防止误操作。  
- 执行历史和评审历史应支持按时间排序查看。
- 所有 AI 入口有统一的视觉标识；AI 生成的脑图节点落库后保留 AI 标识徽标，用户可持续区分 AI 生成内容与人工内容。
- 生成/分析过程提供明确的加载态与进度反馈，支持取消。
- 所有涉及数据写入的 AI 操作遵循预览-确认-执行模式，且执行后可撤销（脑图内操作）或可追溯（业务对象操作）。
- AI 建议类结果（优先级推荐、等级建议、遗漏测试点）均为非侵入式呈现，用户可忽略。

### 4.4 可靠性需求

- 系统应保证7×24小时可用，计划内维护时间每月不超过2小时。  
- 数据应每日自动备份，支持恢复，数据丢失不超过24小时。
- AI 服务不可用或超时，平台全部既有功能必须完全不受影响；AI 入口自动降级为不可用提示。
- 异步 AI 任务失败必须给出明确的失败原因提示，支持重试。
- 向量索引更新失败不得阻断缺陷的正常创建与修改，允许索引异步补偿。

### 4.5 成本控制需求

- 按用户维度限制 AI 调用频率；系统管理员可查看调用量统计。
- 长文本上下文（快照树、缺陷库）送入模型前应做裁剪与分批，避免不必要的 token 消耗。

## 5. 数据需求

### 5.1 核心数据实体及其关系

- **用户**：存储账号信息、角色及状态，与工作空间为多对多关系。  
- **工作空间**：存储工作空间基本信息，是业务资源隔离的基本单位。  
- **项目**：归属于某个工作空间，包含若干模块和缺陷。  
- **测试用例模块**：形成树形结构，节点分为目录和文档。  
- **脑图节点**：归属于某个文档，形成树形结构，节点可标记为用例节点，用例节点包含测试属性。  
- **测试计划**：归属于项目，包含计划信息，与快照关联。  
- **计划快照**：计划创建时生成的模块和节点副本，与执行记录关联。  
- **测试评审**：归属于项目，包含发起人、参与者列表，与快照关联。  
- **评审快照**：评审创建时生成的模块和节点副本，与评审记录关联。  
- **缺陷**：归属于项目，可关联原始用例和测试计划，具有状态流转和操作日志。

AI 智能辅助能力域引入以下数据实体：

- **需求池条目**：归属项目，存储条目标题、需求文本、来源 URL（仅记录出处，不抓取）、更新人与更新时间。
- **文档需求关联**：脑图文档与需求池条目的关联关系。
- **AI 调用审计**：记录每次 AI 调用的用户、工作空间、项目、功能类型、实际使用的模型、耗时、token 用量与结果状态。
- **AI 会话**：全局助手的会话与消息记录，归属用户，按工作空间隔离。
- **缺陷向量索引**：缺陷标题/描述的语义向量，与缺陷记录一一对应，用于语义查重与聚类。
- **AI 分析结果**：评审检查、评审摘要、缺陷聚类、执行顺序推荐等分析/生成任务的结果快照，含生成时间，可覆盖刷新（评审摘要重复生成覆盖上一份、推荐指数随快照重新同步失效，见对应功能条目）。
- **智能体提示词模板**：仅当系统管理员自定义覆盖时，为对应智能体落库一条覆盖记录（存储自定义的角色指令段、输出格式约束段与格式约束段编辑开关）；默认模板随代码内置，不落库；恢复默认即删除覆盖记录。
- **AI 对话模型配置**：多条对话模型配置记录，每条含显示名、供应商标识、服务地址、密钥（加密存储）、模型名、附加参数、启用状态与是否默认；全系统有且仅有一条默认记录。Embedding 配置保持系统级单一配置，不随本实体多行化。

所有新增表遵循平台数据库规范（C5：必含 `id`、`created_at`、`updated_at`、`is_deleted`（逻辑删除标记），禁止物理外键）；索引设计遵循平台索引规范（C9），缺陷语义检索所需索引的具体类型在详细设计中确定。

### 5.2 数据隔离与生命周期

所有业务数据（项目、用例、计划、评审、缺陷）均通过工作空间归属进行隔离，确保业务用户只能访问其当前活跃工作空间内的数据。

- 全部 AI 相关数据通过工作空间/项目归属隔离，遵循平台统一的数据隔离原则。
- 需求池条目随项目删除而删除，文档与条目的关联随任一方删除而解除；缺陷向量随缺陷删除同步失效（缺陷为逻辑删除，语义查重与聚类检索必须排除已逻辑删除的缺陷）；AI 会话支持用户自行清空。
- AI 调用审计与会话历史的保留期限为系统配置项，超期数据支持归档清理。
- 发送至 LLM 服务的业务数据不在平台外持久化的合规责任由模型服务选型保障（见 2.2）。

### 6.2 附录 B：登录跳转逻辑

用户在登录前，系统首先检查初始化状态：

1. 若系统未初始化（无任何用户）→ 自动跳转至 `/init` 初始化页面
2. 若系统已初始化 → 正常展示登录表单

用户登录成功后，系统根据以下条件决定跳转目标：

1. 若用户拥有工作空间 → 跳转至 `/workspaces`（我的空间页面）
2. 若用户无工作空间：
   - 拥有任意系统权限 → 跳转至 `/admin/dashboard`（系统管理仪表盘）
   - 无系统权限 → 跳转至 `/workspaces`（我的空间页面）
