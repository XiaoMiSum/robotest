### 3.4 测试场景（US-API-004）

**功能描述**：提供场景级自动化测试能力，覆盖**平台场景数据**：平台内创建的可执行场景，将接口、请求按顺序编排为步骤序列（步骤即取样器，支持 http/jdbc 两种类型），支持参数传递，一键执行并生成场景报告，由平台执行引擎在服务端执行。

**功能点**：

**平台场景数据**：

- 场景创建：定义场景名称、所属模块（模块为项目级统一模块树 project_module，与接口定义共享同一棵树，详见《项目模块与文档管理详细设计说明书》）与优先级（P0/P1/P2/P3，缺省 P2）。
- **参数**：场景级定义常量、列表参数。
- **前/后置**：场景级前置/后置处理器，基于公共能力，在场景编辑器中以独立标签页分别配置前置处理器与后置处理器。
- **全局资产引入**：场景级前置/后置处理器、步骤级处理器/验证器/提取器均可从全局资产库（平台级）复制引入。
- **场景步骤（步骤即取样器）**：
  - **http 取样器**：支持导入系统请求（从接口定义、其他场景复制或链接引用）、自定义请求（创建不落库的 HTTP 请求步骤，可引用环境自动填充域名或填写完整 URL，支持粘贴 cURL）与验证器；
  - **jdbc 取样器**：创建数据库请求步骤，选择环境中的数据源并编写 SQL 语句，可携带提取器/验证器；用于数据准备、数据校验或生成后续步骤参数。
- **平台内执行**：由平台执行引擎基于 Ryze 在服务端并发执行；执行后生成场景报告。
- **场景控制**：单步骤操作（启用/禁用、执行、复制、删除、在之前/之后插入步骤）、批量操作（批量启用、批量禁用、批量调试、批量删除、批量移动）与场景级操作（关注、复制链接、查看报告、编辑、执行、复制、创建定时任务、删除）。
- **执行历史与变更历史**：场景保存后自动提供两个标签页（变更历史同 3.2 语义，执行历史见 3.5）。

**业务规则**：

**平台场景数据**：

- **复制与链接引用语义**：
  - **复制**：以当前场景为模板新建场景，页面预填源场景全部内容供修改，保存后生成独立副本，副本与源后续修改互不影响；源数据被删除后复制步骤仍可编辑，仅源 ID 置灰无法跳转。
  - **链接引用**：步骤内容（请求参数、验证器、处理器配置）跟随源数据变化同步更新，但当前场景中的**启用状态、参数值**可独立调整。引用的源数据被删除时，引用步骤置灰并仅支持「移除」操作。
  - 链接引用场景时可配置「使用原场景参数」（优先原场景参数 / 优先当前场景参数）与「使用原场景环境」。
- **参数优先级**：执行期变量（处理器/提取器产生）> 场景参数 > 环境参数；同名变量时按该优先级取值。执行报告中对每个步骤使用的变量标注来源层级（环境/场景/提取器），便于调试。
- **全局资产引入（仅复制）**：引入的处理器/验证器/提取器为独立副本，与全局资产无关联。
- **场景执行失败语义**：场景不再提供失败规则配置，执行语义固定为「停止运行」：任一步骤失败，后续步骤不再执行并在报告中标记未执行。
- **执行历史保留**：默认保留全部记录；手动删除报告不影响执行历史查看详情；系统按清理策略（默认90天）清理报告后，执行历史详情显示「执行结果被清理」。
