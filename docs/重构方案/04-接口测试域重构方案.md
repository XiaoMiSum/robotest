## 3. 目标结构（防腐层）

```
service/apitest/execution/
  SceneExecutionService(port)
  SceneExecutionLauncher       # execute/run/doRun/finishExecution + ExecutionCancelRegistry
  DraftExecutionService        # debugStep/draftDebugStep/draftExecute/buildDraft*
  ExecutionRecordQueryService  # pageExecutions/pageChangeHistory/*
  SceneDatasetBuilder          # buildSceneDataset/variables/*
service/apitest/execution/ports/
  SuiteBuilder / ResultMapper / SnapshotCapture
service/apitest/execution/adapters/ryze/   # ★ 唯一 import ryze.* 的包
  DebugRyzeConverter / SceneRyzeConverter / RyzeResultAdapter /
  RyzeResultSnapshotConverter / EnvironmentSnapshotFactory
service/apitest/scene/
  SceneServiceImpl + ScenePublishWorkflow + SceneMoveOrchestrator + SceneSnapshotService
service/apitest/environment/
  EnvironmentServiceImpl + EnvironmentValidator + EnvironmentEffectiveSnapshot
service/apitest/schedule/
  ScheduleService + ScheduleTrigger + ExecutionDispatcher（与 07 调度抽象对齐）
```

### 3.1 设计模式应用

| 重构目标 | 设计模式 | 落点 |
| --- | --- | --- |
| 引擎隔离（A1） | **Adapter + Facade（Hexagonal Ports & Adapters）** | `execution/adapters/ryze/` 为唯一 import `ryze.*` 包；编排层仅依赖 `ports/`（`SuiteBuilder`/`ResultMapper`/`SnapshotCapture`） |
| Result 树→报表映射 | Visitor + Builder | `RyzeResultVisitor` 统一遍历（收敛 `toProcessorEntries`/`toAssertionSnapshots`/`toExtractorSnapshots`/`toRequestSnapshot`/`toResponseSnapshot`/`extractChildOutcome`）+ `ReportBuilder` 分步聚合 |
| 转换器/适配族切换 | Strategy + Registry | `SuiteBuilderRegistry`/`ResultMapperRegistry` 按执行类型（debug/scene/schedule）选择实现，消灭 if-else 族 |
| 执行编排（A2） | Command + Template Method | `ExecutionCommand`（execute/cancel/status，取消=命令撤销）；`SceneExecutionLauncher` 固化 run→finish 不变式骨架 |
| 场景发布（A3） | State + Observer | `ScenePublishWorkflow` 状态机；发布完成发 `ScenePublishedEvent` 联动定时/协同 |
| 批量移动（A3） | Command | `SceneMoveOrchestrator` 以命令封装移动+校验+历史，可回滚/幂等 |
| 取消注册（A5） | Registry | `ExecutionCancelRegistry` 单点持有 cancelFlags，单实例约束文档化 |
| 定时/计划触发（A4） | Strategy + Registry | `ExecutionDispatcher` 按触发源（schedule/plan/manual）选择执行策略，与 `07` 调度抽象统一 |
| 草稿/快照组装 | Builder | 请求/响应/断言/提取器快照分步构建，黄金文件字节级验证 |

> 护栏：`adapters/ryze` 引用方向受 ArchUnit 断言；同一 Result 映射只允许一套实现（合并既有 5 个适配类，不得出现第三份，见 §4.1 步骤 2）；单实例约束显式化（见总体计划 §4.4 护栏 3、R5）。

## 4. 重构步骤

### 4.1 执行器拆分（Phase 2 主任务）

1. **黄金文件打底**：固定 5–8 个场景（成功/断言失败/提取器/取消/引擎异常），固化 `RyzeResult→report/snapshot` JSON 字节。
2. **抽纯函数映射**：把 `toProcessorEntries/toAssertionSnapshots/toExtractorSnapshots/toRequestSnapshot/toResponseSnapshot/toReportEntry/extractChildOutcome` 迁入 `adapters/ryze/`，无状态、可单测；**先与已有 `RyzeResultAdapter`/`RyzeResultSnapshotConverter` 做重叠评审**，合并而非新增第三份。
3. **Port 化**：`ResultMapper`/`SnapshotCapture`/`SuiteBuilder` 定义接口，编排层只依赖 Port。
4. **编排拆分**：`SceneExecutionLauncher`/`DraftExecutionService`/`ExecutionRecordQueryService`/`SceneDatasetBuilder` 按 §2.2 方法块迁移。
5. **取消注册表**：`ExecutionCancelRegistry` 单点持有 `cancelFlags`，注释并文档化单实例约束。
6. **收敛校验**：`grep -r "ryze\." service/apitest` 结果必须落在 `adapters/ryze/`（≤2 处例外见验收）。

### 4.2 场景/环境服务拆分（Phase 4）

- `ApiSceneServiceImpl` → 发布状态机 `ScenePublishWorkflow`、`SceneMoveOrchestrator`（V1.2 批量移动）、持久化、查询。
- `ApiEnvironmentServiceImpl` → `EnvironmentValidator`（URL/变量）、`EnvironmentEffectiveSnapshot`、CRUD。

### 4.3 导入与 SSRF

- V1.2 已重构导入解析（cURL 前端解析、`ImportSourceFetcher` url-policy）。本方案**不再动语义**，仅将 `ImportSourceFetcher` 的安全校验纳入 `07` 的安全回归测试清单。

### 4.4 前端（与 `08` 协同）

- `SceneEditorPage`（1846）→ `useSceneDraft`/`useSceneEditor`/`useSceneProcessors` + 子组件。
- `EnvironmentDetailPanel`/`InterfaceEditorPage` 同法；报告组件（`ReportProcessorsTabs` 706/`ReportStepCard` 671）按复用情况收敛。

## 5. 验收标准

- [ ] 黄金文件 diff 为 ∅（拆分前后字节一致）
- [ ] `service/apitest` 中 `ryze.*` 引用仅存在于 `execution/adapters/ryze/`（编排层 ≤2 处、且经评审豁免）
- [ ] `SceneExecutionServiceImpl` ≤ 300 行（仅编排）；`ApiSceneServiceImpl`/`ApiEnvironmentServiceImpl` ≤ 350 行
- [ ] 执行器/映射纯函数单测覆盖关键分支；原有 22 个测试全绿
- [ ] `ExecutionCancelRegistry` 单实例约束在 `docs/架构/` 显式声明
- [ ] 前端 god page 对应项行数下降 ≥50%（与 `08` 联合验收）

## 6. 风险与依赖

| 风险 | 缓解 |
| --- | --- |
| 映射拆分改变快照字节 | 黄金文件字节级比对为硬门禁 |
| `ryze` API 细节只在运行时确定 | 首轮以黄金文件覆盖典型/异常/取消路径，缺库场景先补测再拆 |
| 定时任务与功能测试计划双轨 | 与 `03`、`07` 统一调度抽象后排期，避免双向改动 |
| 单实例约束被误扩展 | 只在文档标注，不引入分布式协调（非本次目标） |
