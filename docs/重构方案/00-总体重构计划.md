**文档版本**：V1.0
**日期**：2026-09-12
**状态**：已发布

## 1. 引言

### 1.1 编写目的

本计划定义软件测试平台整体的技术重构目标、阶段路线、质量门禁与里程碑，作为各业务模块《重构方案》的顶层约束。各模块详细拆分见 `docs/重构方案/01~08`。

### 1.2 范围与原则

- **目标优先级**：可维护性与可读性优先（首要）；可测试性与质量门禁（其次）；性能与架构边界（按需、测量驱动）。
- **策略**：增量、行为保持、每步可回滚。不做大爆炸式重写，不做微服务化。
- **文档同步**：仅当重构改变业务行为、API、数据结构时，按总则 AGENTS 文档闸门先更新 `docs/详细设计/`/`docs/交互设计/` 等；纯结构重排不更新。
- **纪律（C7）**：每个逻辑单元一个 commit，提交格式 `<emoji> <type>(<scope>): <description>`。

### 1.3 定义与缩写

| 术语 | 定义 |
| --- | --- |
| ACL（防腐层） | Ports & Adapters 中隔离外部引擎/框架与本域模型的一层，见 §4.2 |
| 黄金文件测试 | 固定输入产出固化比对（字节级）的回归测试，用于锁定无测试代码 |
| 特征测试 | 按现状行为录制"输入→断言输出"的测试，用于冻结历史行为 |
| C5/C9/C1–C9 | 总则 AGENTS 共享约定（数据库/索引/类型/注释/覆盖率等） |

## 2. 现状与问题总账

### 2.1 规模事实（2026-09-12 实测）

| 维度 | 事实 |
| --- | --- |
| 后端规模 | 596 个 Java 源文件；测试 79 个；核心域（评审/计划/缺陷/需求/管理）近乎零覆盖 |
| 巨型 Service | `SceneExecutionServiceImpl` 1205 行；`TestReviewServiceImpl` 860；`TestPlanServiceImpl` 857；`ApiSceneServiceImpl` 848；`ApiEnvironmentServiceImpl` 764；`BugServiceImpl` 557；`ScheduledTaskRunner` 551；`ApiDebugServiceImpl` 549 |
| 巨型页面 | `SceneEditorPage` 1846；`AiConfigPage` 1360；`EnvironmentDetailPanel` 1330；`CaseMindMap` 1318；`InterfaceEditorPage` 999；`BugDetailPage` 955；`BugListPage` 914 |
| 类型单文件 | `web/src/types/index.ts` 2403 行，无 codegen，前后端契约纯手工 |
| DDL | 单一 `schema.sql` 2010 行，无版本化迁移 |
| 门禁 | 后端无 checkstyle/spotbugs/jacoco；前端有 lint/typecheck/vitest（部分门禁在 `scripts/validate.sh` 落地） |
| 框架 | 基于 migoo-* 系列 starter + 外部 `ryze` 执行引擎；WebSocket（Yjs）协同；mock 子系统自带 Filter 726 行 |

### 2.2 结构性病灶（按风险排序）

| 编号 | 病灶 | 证据 | 风险 |
| --- | --- | --- | --- |
| R1 | **防腐层缺失**：外部引擎 `ryze` 与业务实现散耦合 | 5 个转换/适配类 + 执行器中 ~400 行 result→报表映射 | 引擎升级=全栈重写点 |
| R2 | **AI 横向入侵**：AI 作为能力嵌入各业务域 | `service/ai/` 88 文件、9 个 AI Controller；`RequirementServiceImpl`/`BugServiceImpl`/`TestReviewServiceImpl` 均耦合 ai/apitest | 改动域即波及 AI 链路 |
| R3 | **功能测试域无测试暗区** | 评审/计划/缺陷/需求测试 ≈ 0；`service/project/` 单包承载 5 个业务域 | 老代码不可安全拆分 |
| R4 | **前后端契约手工漂移** | `types/index.ts` 无生成；springdoc 存在未连通前端 | 静默运行期崩溃 |
| R5 | **单实例内存态假设未显式化** | `cancelFlags ConcurrentHashMap`、草稿执行态、Yjs 房间 | 多实例部署语义反转 |
| R6 | **包结构不表达业务域** | `service/project/`、`controller/project/` 混排五域 | 边界不可见、依赖不可控 |
| R7 | **巨型类/页面** | 见 §2.1 | 可读性↓、并行开发冲突 |
| R8 | **领域命名不一致** | `tcase`（用例/计划/评审文档）与 `apitest` 边界模糊 | 领域语言漂移 |

## 3. 阶段路线图

```
Phase0 基线锁定   Phase1 门禁与规则  Phase2 接口测试防腐层  Phase3 功能测试域域化
────────────────  ───────────────  ────────────────────  ─────────────────────
特征/黄金文件    OpenAPI→types CI   execution ACL 收敛    service/project 拆域包
扩写路径基线    ArchUnit 依赖规则   ai/apitest 解耦试点    AI 事件化试点
                                            │
                                           Phase4 巨型类/页面拆分 + 前端工程
                                            Phase5 规模化推广与收尾
```

### 3.1 Phase 0 — 基线锁定（一切的前提，不做任何结构改动）

| 内容 | 做法 | 交付 |
| --- | --- | --- |
| 写路径特征测试 | 评审/计划/缺陷/需求主路径与异常分支，录制现状行为 | 特征用例集 |
| 执行路径黄金文件 | 固定场景固化 `RyzeResult→报表/快照` JSON | `golden/` 基线 |
| 契约基线 | `openapi-typescript` 生成前端类型 + diff 检查先行 | 生成脚本 + CI 检查 |
| 覆盖率维度化 | 引入 jacoco 覆盖聚合，按域展示（不设一刀切红线） | 覆盖报表 |

**验收**：重构前后同一输入产出字节一致；`scripts/validate.sh` 全绿。

### 3.2 Phase 1 — 门禁与规则（先立后破）

- ArchUnit 依赖断言：`ai.*` 禁引用业务域实现、`framework/mock` 禁反向依赖业务包、域间 controller 禁引用他域 service 实现。
- 契约 CI：SpringDoc JSON ⇆ 前端类型漂移检查进 `validate.sh`。
- 低风险机械项（不动行为）：`ErrorCodeConstants` 号段分节、`schema.sql` 分域分节、`web/src/types/index.ts` 按域拆分（保留重导出）。

### 3.3 Phase 2 — 接口测试防腐层（试点A，详见 `04`）

- 黄金文件打底 → 抽纯函数映射 → `ResultMapper` Port 化 → `ryze.*` 引用收敛到 `execution/adapters/ryze/`。
- 同时做 ai 解耦小试点（详见 `06`，与 `03` 的 Review 切片协作）。

### 3.4 Phase 3 — 功能测试域域化（试点B，详见 `03`）

- `service/project/`→ `domain/review|plan|bug|requirement|tcase`，AI 连接收敛为端口/事件。
- 首个切片选 Review（状态机最复杂、耦合最清晰），用 P0 特征冻结。

### 3.5 Phase 4 — 巨型类/页面拆分 + 前端工程（详见 `04`、`08`）

- Service：`SceneExecutionServiceImpl` 随 Phase 2 自然瘦身；`TestPlan`/`TestReview` 随 Phase 3 拆。
- 页面：`SceneEditorPage` 等抽 composables + 子组件；列表页重复按"3 次复制规则"决策，不预设通用基座。

### 3.6 Phase 5 — 规模化推广与收尾

- 将 Phase 2/3 的方法论横向应用到其余域；全量门禁回归；遗漏项回填（§2.2 中的 R5 显式化、R7 剩余项）。

## 4. 核心技术决策

### 4.1 扇门禁技术栈（保持既有形态，不新增主笔框架）

| 能力 | 工具 | 落地位置 |
| --- | --- | --- |
| 依赖规则 | ArchUnit（测试） | 各域 `pom` 增加 `archunit` 依赖 + `DomainDependencyTest` |
| 覆盖率 | JaCoCo | `server/pom.xml` 聚合，按域展示 |
| 契约 | `openapi-typescript` + diff | `web/` 生成脚本 + CI |
| 后端静态 | Checkstyle/SpotBugs（可选，低优） | `server/pom.xml`，不设阻断红线 |

### 4.2 执行引擎防腐层（Phase 2 目标形态）

```
service/apitest/execution/             ← 编排层：无引擎知识
  SceneExecutionService（Port）
  DraftExecutionService
  ExecutionRecordQueryService
service/apitest/execution/ports/       ← 定义 Port
  SuiteBuilder / ResultMapper / SnapshotCapture
service/apitest/execution/adapters/ryze/  ← 防腐层：仅此包 import ryze.*
  DebugRyzeConverter / SceneRyzeConverter / RyzeResultAdapter /
  RyzeResultSnapshotConverter / EnvironmentSnapshotFactory
```

### 4.3 域化形态（Phase 3 目标形态）

`service/project/` 拆出自治包，并以"端口/事件"替代域间直连：

```
domain/review|plan|bug|requirement|tcase
  ├── state flow（评审/计划状态机）
  ├── 领域事件（如 ReviewCompletedEvent → AI 评审消费者）
  └── 对外端口仅暴露 Service 接口 + DTO
```

### 4.4 设计模式使用原则与护栏

重构使用设计模式**只为解决具体的"变化轴"**，禁止为"优雅"堆模式（YAGNI 反噬）。本项目约定五类高频变化轴与 GO-TO 模式：

| 变化轴 | GO-TO 模式 | 本仓库落点 |
| --- | --- | --- |
| 外部引擎/框架隔离 | Adapter + Facade（六边形：Ports & Adapters） | `execution/adapters/ryze`（`04`）、AI Provider（`06`） |
| 状态流转 | State | 评审/计划/缺陷/邀请/场景发布状态机（`03`/`05`/`02`/`04`） |
| 跨域横向能力 | Observer（领域事件）+ 端口 | AI 评审/聚类、计划联动（`03`/`05`/`06`） |
| 算法族/能力族切换 | Strategy + Registry | Ryze 转换器、Provider、调度 Handler、C4 解析（`04`/`06`/`07`/`02`） |
| 复杂对象构建 | Builder | 报告/快照/评审快照聚合（`04`/`03`） |
| 树状结构遍历 | Composite + Visitor | 测试用例树、场景步骤、Ryze 结果树→报表（`03`/`04`） |

**护栏（对全部 01–08 模块生效）：**

1. 模式落点必须"命名即位置"（模式名体现在类名/包名，如 `ReviewWorkflow` 状态集合），并有对应单测（C8）；"为什么选该模式"以 C6 注释说明。
2. 同一变化轴只允许一套模式实现，禁止与散写 if-else 并存。
3. ArchUnit 断言模式边界（如 `adapters/ryze` 引用方向、`domain/*` 对 `service.ai` 实现依赖为 0），防止绕过。
4. 超出上表六轴的新模式须在方案评审中说明收益与取舍。
5. 前端遵循框架惯例：composables = 自定义 Hook（逻辑复用）、provide/inject = 复合组件上下文、Pinia store = Observer 单例；不引入 Service Locator / 全局多例滥用。

各模块《重构方案》的"设计模式应用"小节给出逐目标映射与落点（见 `01`–`08`）。

## 5. 风险矩阵

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 无测试老域被拆崩 | 高 | Phase 0 特征/黄金冻结先行 |
| AI 耦合切断引发链路回归 | 高 | Review 切片试点 + 事件化异步兜底 |
| 契约漂移静默破坏 | 中 | Phase 1 契约 CI 先行 |
| 拆分后职责仍糊 | 中 | ACL/域包显式化，ArchUnit 锁方向 |
| 范围失控 | 高 | 每 Phase 独立验收、独立 commit，P2/P3 后评审是否继续 |

## 6. 里程碑与依赖

| 里程碑 | 依赖 | 说明 |
| --- | --- | --- |
| M0 Phase 0 基线 | 无 | 全量特征/黄金测试就绪 |

## 7. 验收标准（全局）

- `service/apitest/` 中 `ryze.*` import 收敛到 ≤2 处；`service/project/` 出现独立域包。
- ArchUnit 依赖禁令 0 违反；`scripts/validate.sh` 全绿；新建代码续用 C1–C9。
- 后续引擎/框架升级预估成本降至"只动防腐层"量级。
- 每个模块方案完成其"验收标准"列的核对项。
- 各模块"设计模式应用"小节列出的模式落点均已落地：命名即位置（模式名→类存在）、有对应单测、ArchUnit 模式边界断言 0 违反（§4.4 护栏 1–3）。
