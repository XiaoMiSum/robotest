**日期**：2026-09-23

## 1. 空间管理相关接口（/api/workspace）

以下接口操作当前活跃工作空间内的资源，所有接口必须携带请求头 `X-Active-Workspace: <workspace_id>`。

### 1.1 获取当前工作空间详情

- **路径**：`GET /api/workspace`

- **响应**：
  
  ```json
  {
  "id": 1,
  "name": "电商平台测试",
  "description": "负责电商平台相关测试",
  "workspaceRole": "admin",
  "defaultProjectId": 10,
  "defaultProjectName": "核心功能测试",
  "memberCount": 15,
  "projectCount": 5,
  "status": "active",
  "createdByName": "张三",
  "createdAt": "2026-01-01T00:00:00Z"
  }
  ```

- `createdByName`：根据 `ws_workspace.created_by` 回查 `sys_user.name`，姓名为空时回退 `username`；历史数据无创建人或用户已删除时为 `null`，前端展示 `—`。
- `GET`、`PUT` 与默认项目设置接口复用相同响应结构。

### 1.2 更新当前工作空间信息

- **路径**：`PUT /api/workspace`

- **权限**：仅空间管理员（`workspaceRole` 对应预置 `workspace_admin` 角色 ID）可操作。

- **请求体**：
  
  ```json
  {
  "name": "电商平台测试(更新)",
  "description": "新的描述"
  }
  ```

- **校验**：`name` 全局唯一，2~50字符。

- **响应**：更新后的工作空间信息。

### 1.3 设置个人默认项目

- **路径**：`PUT /api/workspace/default-project`
- **请求体**：`{ "projectId": 10 }`，若为 null 则清除个人默认项目。
- **校验**：projectId 若不为 null，必须属于当前活跃工作空间且状态为 active。
- **处理**：更新 workspace_user.default_project_id。
- **响应**：更新后的当前工作空间上下文信息（与 GET /api/workspace 响应结构一致）。

### 1.4 获取成员列表

- **路径**：`GET /api/workspace/members`

- **请求参数**：`keyword`（可选，匹配姓名、用户名或邮箱）、`workspaceRole`（可选，空间角色 UUID）、`pageNo`、`pageSize`

- **响应**：
  
  ```json
  {
  "list": [
    {
      "userId": 1,
      "username": "zhangsan",
      "name": "张三",
      "email": "zhangsan@example.com",
      "avatarUrl": "...",
      "workspaceRole": "admin",
      "joinedAt": "2026-01-15T10:30:00Z"
    }
  ],
  "total": 8
  }
  ```

- `name` 为用户展示姓名，成员列表主标题优先使用该字段，缺失时回退 `username`。
- 成员按 `joined_at DESC, id DESC` 稳定排序。
- `workspaceRole` 为空时不附加角色条件；组合查询复用索引 `idx_ws_user_ws_role(workspace_id, workspace_role)`。

### 1.5 直接添加成员

- **路径**：`POST /api/workspace/members`
- **权限**：仅空间管理员可操作。
- **请求体**：`{ "userIds": [3, 4] }`
- **校验**：被邀请用户必须存在且为活跃状态；已在当前工作空间的用户跳过。
- **处理**：批量插入 workspace_user，默认引用预置 `workspace_member` 角色 ID。
- **响应**：`{ "successCount": 1, "skippedUserIds": [4] }`

### 1.6 更新成员角色

- **路径**：`PUT /api/workspace/members/:userId`
- **权限**：仅空间管理员可操作。
- **请求体**：`{ "workspaceRole": "admin" }`
- **校验**：降级操作需检查不能移除最后一位管理员。

### 1.7 移除成员

- **路径**：`DELETE /api/workspace/members/:userId`
- **权限**：空间管理员可移除其他成员；普通成员可自行退出。
- **校验**：不能移除空间最后一位管理员。

### 1.8 创建邀请链接

- **路径**：`POST /api/workspace/invitations`

- **权限**：仅空间管理员可操作。

- **请求体**：
  
  ```json
  {
  "expiresAt": "2026-12-31T23:59:59",
  "maxUses": 50
  }
  ```

  > `expiresAt` 使用用户选择的业务本地时间，采用无时区的 ISO LocalDateTime 字符串（例如 `2026-12-31T23:59:59`）。前端不得将浏览器 `Date` 直接序列化为 UTC `Z` 字符串；服务端按收到的本地时间值保存和判断过期。

- **处理**：生成唯一随机 token（64位字符），插入 workspace_invitation 表。

- **响应**：
  
  ```json
  {
  "id": 1,
  "token": "a1b2c3d4e5f6...",
  "expiresAt": "2026-12-31T23:59:59",
  "maxUses": 50,
  "useCount": 0,
  "status": "active",
  "createdAt": "2026-07-04T10:00:00Z"
  }
  ```
  
  > 说明：前端根据 token 自行拼接邀请链接 `${baseUrl}/join?token=${token}`。

### 1.9 获取邀请链接列表

- **路径**：`GET /api/workspace/invitations`
- **权限**：空间管理员。
- **请求参数**：`pageNo`（可选，默认 1）、`pageSize`（可选，默认 20，最大 100）。
- **响应**：`data` 使用分页结构，完整 token 不进入列表响应：
  ```json
  {
    "list": [
      {
        "id": "uuid-invitation",
        "tokenPreview": "a1b2…ef01",
        "effectiveStatus": "active",
        "status": "active",
        "expiresAt": "2026-12-31T23:59:59",
        "maxUses": 50,
        "useCount": 0,
        "createdAt": "2026-07-04T10:00:00Z"
      }
    ],
    "total": 8
  }
  ```

- `tokenPreview`：token 前 4 位 + `…` + 后 4 位；长度不足 8 位时原样返回。
- `effectiveStatus`：`active`、`exhausted`、`expired`、`revoked`，由邀请状态机和当前服务端时间计算。
- `status` 保留落库状态 `active/revoked`，用于兼容既有调用方。

### 1.10 按需获取邀请复制链接

- **路径**：`POST /api/workspace/invitations/:id/copy-link`
- **权限**：空间管理员。
- **处理**：
  - 校验邀请链接存在且属于当前活跃工作空间。
  - 已撤销时返回 `INVITATION_REVOKED`；已过期时返回 `INVITATION_EXPIRED`。
  - 达到使用上限但未过期时仍允许复制，与交互设计一致。
- **响应**：
  ```json
  {
    "token": "完整 token"
  }
  ```
  前端根据 token 拼接 `${origin}/join?token=${token}`，并在复制文本中附带当前登录用户的 `username` 作为邀请人后写入剪贴板。

### 1.11 撤销邀请链接

- **路径**：`PUT /api/workspace/invitations/:id/revoke`
- **权限**：空间管理员。
- **处理**：更新 status='revoked'。

### 1.12 获取项目列表

- **路径**：`GET /api/workspace/projects`

- **请求参数**：`keyword`、`status`、`pageNo`、`pageSize`

- **响应**：
  
  ```json
  {
  "list": [
    {
      "id": 1,
      "name": "用户中心改版",
      "description": "用户中心模块重构测试",
      "status": "active",
      "isDefault": true,
      "startTime": "2026-08-01T00:00:00Z",
      "endTime": "2026-09-01T00:00:00Z",
      "createdBy": { "id": 1, "name": "张三" },
      "createdAt": "2026-07-01T00:00:00Z"
    }
  ],
  "total": 12
  }
  ```

### 1.13 创建项目

- **路径**：`POST /api/workspace/projects`
- **权限**：所有工作空间成员均可创建。
- **请求体**：`{ "name": "...", "description": "...", "startTime": "...", "endTime": "..." }`
- **校验**：name 工作空间内唯一；startTime 不晚于 endTime。
- **响应**：201，返回创建的项目信息。

### 1.14 获取项目详情

- **路径**：`GET /api/workspace/projects/:id`
- **校验**：项目必须属于当前活跃工作空间。

### 1.15 更新项目

- **路径**：`PUT /api/workspace/projects/:id`
- **权限**：空间管理员或项目创建者可操作。
- **校验**：已归档项目不可编辑。

### 1.16 归档/启封项目

- **路径**：`POST /api/workspace/projects/:id/archive`
- **权限**：空间管理员。
- **请求体**：`{ "archived": true }`
- **校验**：归档前检查无进行中的计划。
- **处理**：若归档项目是任一用户的个人默认项目，自动清除。

### 1.17 删除项目

- **路径**：`DELETE /api/workspace/projects/:id`
- **权限**：仅空间管理员。
- **校验**：项目下不能有任何数据。
- **处理**：若删除的项目是任一用户的个人默认项目，自动清除。


## 2. 项目归档/删除联动

- 项目归档或删除时，系统自动遍历 workspace_user 表，将引用该项目的所有 default_project_id 置为 null。
- 被清除默认项目的用户在项目列表页将看不到默认高亮标识。


## 3. 邀请成员流程

### 3.1 直接添加流程

管理员在成员管理页面搜索平台已有用户，选择后提交，后端批量插入 workspace_user，默认引用预置 `workspace_member` 角色 ID。

### 3.2 邀请链接流程

1. 管理员创建邀请链接，复制 URL 发送给目标用户。
2. 目标用户访问邀请链接，前端调用验证接口，展示工作空间信息和加入表单。
3. 用户输入邮箱后，前端调用 `POST /api/workspace/invitations/check-email`：
   - 邮箱已注册 → 显示密码输入框，提示用户输入密码验证身份。
   - 邮箱未注册 → 显示姓名和密码输入框，提示用户填写信息创建账号。
4. 用户提交表单后调用 `POST /api/workspace/invitations/join`：
   - 新用户 → 使用 `name`、`email`、`password` 创建用户 → 加入空间 → 生成 Token → 直接登录进入项目列表页。
   - 已有用户 → 验证密码 → 加入空间 → 生成 Token → 直接登录进入项目列表页。
   - 已在空间 → 提示"您已是该工作空间成员"，同时生成 Token 直接登录。
5. 整个流程无需跳转到登录页面，用户提交后即完成加入和登录。

**路由**：`/workspace/:workspaceId`

通过顶部动态菜单“空间信息”进入。展示当前工作空间基础资料、创建人、成员数与项目数；管理员可编辑名称和描述。

**路由**：`/workspace/members`

页面视觉基准为 `web/demos/workspace/members.html`，保留“成员列表 / 邀请链接”标签页。Demo 中纵向并列的两张卡片分别作为两个标签页内容。

**成员列表标签页交互说明**：

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 搜索成员 | 输入姓名/邮箱 | 300ms 防抖后请求后端，保留角色筛选 |
| 筛选角色 | 选择真实空间角色 | 页码重置为 1，刷新成员列表 |
| 邀请成员 | 点击页头[邀请成员] | 远程搜索、多选、默认成员角色 |
| 更新角色 | 点击[改角色] → 选择角色 | 标签切换为下拉框，选择后立即保存 |
| 移除成员 | 点击[移除] | 二次确认；最后一位管理员禁止移除 |
| 自行退出 | 点击自己行的[退出] | 确认后退出空间并跳转“我的空间” |

**邀请链接标签页交互说明**（仅管理员可见）：

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 生成链接 | 点击[生成链接] | 设置过期时间、最大次数 → 成功后显示完整 URL |
| 复制行链接 | 点击[复制] | 调用按需复制接口获取完整 token → 写入剪贴板 |
| 复制邀请链接 | 点击页头[复制邀请链接] | 复制最近一个有效邀请；无可用链接时提示 |
| 失效链接 | 点击[失效] | 二次确认 → 状态变为“已失效” |

- 列表仅返回 `tokenPreview` 和 `effectiveStatus`，完整 token 不随列表下发。
- `effectiveStatus` 区分有效、已达上限、已过期、已失效；仅有效状态参与页头快捷复制。
