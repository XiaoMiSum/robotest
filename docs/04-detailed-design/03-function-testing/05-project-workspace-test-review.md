## 1. 测试评审管理接口

### 1.1 获取评审列表

- **路径**：`GET /api/project/reviews`

- **参数**：`status`（可选，new/in_progress/completed/rejected）、`keyword`（可选，标题模糊匹配）、`pageNo`（默认 1）、`pageSize`（默认 20）

- **响应**：
  
  ```json
  {
  "list": [
    {
      "id": "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e01",
      "title": "登录模块评审",
      "status": "in_progress",
      "initiator": { "id": "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e10", "name": "张三" },
      "participantCount": 3,
      "participants": [
        { "id": "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e11", "name": "李四", "avatarUrl": "https://cdn.example.com/a.png" }
      ],
      "createdAt": "2026-07-01T10:00:00Z",
      "totalAssociated": 10,
      "reviewed": 8,
      "passed": 6,
      "progressPercent": 80.0,
      "passRate": 60.0
    }
  ],
  "total": 10
  }
  ```

- **进度字段**：`totalAssociated` 为关联用例总数，`passed` 为通过数，`reviewed` 为已评审数（总数 − 待评审数，供列表进度列展示 `已评审/关联总数`）；`progressPercent` =（总数 − 待评审数）/ 总数，`passRate` = 通过数 / 总数，两者均为 0–100 的百分数，后端四舍五入保留两位，前端通过率列再取一位小数展示。后端按本页评审 ID 批量查询关联用例快照聚合计算，避免逐行 N+1。
- **参与者名单**：`participants` 按 `participant_ids` 去重后批量查询用户（保序，缺失用户跳过），返回头像堆展示所需的 `id`/`name`/`avatarUrl`；`participantCount` 仍为参与者数量（未去重）。
- **状态取值**：`new`（待评审）/ `in_progress`（进行中）/ `completed`（已通过）/ `rejected`（已驳回），展示文案映射见 `docs/05-interaction-design/03-function-testing/05-workspace-ui-test-review.md` 1.1。
- **前端调用**：评审列表页的查询、筛选与分页均走本接口（`status`、`keyword`、`pageNo`、`pageSize` 由页面维护）。

### 1.2 创建评审

- **路径**：`POST /api/project/reviews`

- **请求体**：
  
  ```json
  {
  "title": "登录模块评审",
  "description": "...",
  "participantIds": ["6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e11", "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e12"],
  "selectedNodes": [
    { "documentId": "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e20", "caseIds": ["6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e21", "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e22"] }
  ]
  }
  ```

- **校验**：`title` 非空、`participantIds` 非空、`selectedNodes` 非空且每个 `caseIds` 非空；参与者必须是当前工作空间成员。前端创建表单另做校验：标题必填（上限 200 字）、至少选择一个参与者、至少关联一个用例，未满足时拦截并提示。
- **处理**：生成模块快照和节点快照（完整拷贝节点属性），按 `caseIds` 标记 `is_associated`，初始化评审状态为 new（待评审），发起人默认为当前用户；首次标记成功后自动转入 in_progress（见 1.6）。
- **响应**：201，返回评审基本信息（结构同 1.3）。
- **前端**：创建成功后关闭弹窗并跳转至该评审详情页 `/workspace/projects/reviews/:id`。

### 1.3 获取评审详情

- **路径**：`GET /api/project/reviews/:id`
- **响应**：`{ "id", "title", "description", "status", "initiator": { "id", "name" }, "participantIds", "createdAt" }`。
- **前端**：详情页首屏与进度、快照模块树并行加载（见 1.4、1.10）；标记成功后仅重拉详情与进度，避免整页重载导致脑图丢失选中态。

### 1.4 获取评审进度

- **路径**：`GET /api/project/reviews/:id/progress`
- **响应**：
  
  ```json
  {
  "totalAssociated": 10,
  "passed": 6,
  "failed": 2,
  "pending": 2,
  "progressPercent": 80.0
  }
  ```

- **口径**：`totalAssociated` 为已关联 case 快照数；`last_mark` 为 `pass` 计入 `passed`、`fail` 计入 `failed`、空值计入 `pending`；`progressPercent` =（总数 − 待评审数）/ 总数 × 100，保留两位。
- **前端**：详情页页头进度条与「通过 / 不通过 / 待评审 / 共 N」统计取自本接口；标记成功后刷新；[完成评审] 的可用门槛为 `pending === 0 && failed === 0`（全部通过）。

### 1.5 获取评审快照树

- **路径**：`GET /api/project/reviews/:id/modules`
- **参数**：`documentId`（可选，按文档过滤）
- **响应**：裁剪后的节点树数组，数组元素为嵌套的根节点对象，字段为 `id`、`originalNodeId`、`parentId`、`title`、`type`、`priority`、`isAssociated`、`lastMark`、`lastReviewerId`、`lastReviewedAt`、`sortOrder`、`children`；节点为完整拷贝属性，其中 `isAssociated` 标识是否为规划用例，`lastMark` 取 `pass`/`fail` 或 `null`（待评审）。
- **前端**：详情页脑图始终传入当前选中文档的 `documentId` 加载单文档快照；不传时后端返回多文档多根，页面不使用该形态。

### 1.6 提交评审记录

- **路径**：`POST /api/project/reviews/:id/records`

- **请求体**：
  
  ```json
  {
  "snapshotNodeId": "6f1a2c3e-8b41-4d2a-9c66-1a2b3c4d5e21",
  "operationType": "mark",
  "mark": "pass",
  "comment": "步骤清晰"
  }
  ```

- **处理**：新增 test_review_record，更新 test_review_node_snapshot 的 last_mark、last_reviewer_id、last_reviewed_at。仅 type='case' 节点可标记，所有节点均可评论；`operationType` 取 `mark` / `comment`，提交评论时只传 `comment`。
- **mark 取值**：`pass` / `fail` / `pending`。pending 表示重置回待评审，仅为 API 交互值，落库时 last_mark 置 NULL（即初始态）；前端工具栏提供“通过/不通过/待评审”三态标记，标记结果以徽标形式回显在节点右侧。
- **前端校验**：选中节点非 case 类型时拦截并提示“仅用例节点可标记评审结果”。
- **状态校验**：评审进入终态（completed/rejected）时拒绝，返回语义化错误码 1000011026（“评审已完成，无法执行该操作”）；待评审（new）状态下首次标记成功后评审自动转入 in_progress。

### 1.7 获取节点评审记录

- **路径**：`GET /api/project/reviews/:id/nodes/:nodeId/records`
- **响应**：该节点的所有标记和评论历史，按 `createdAt` 升序，每条含 `id`、`snapshotNodeId`、`reviewerId`、`reviewerName`、`operationType`、`mark`、`comment`、`createdAt`。
- **前端**：[评论] 打开“评审记录”抽屉时拉取；空列表展示“暂无评论或标记记录”。

### 1.8 完成评审

- **路径**：`POST /api/project/reviews/:id/complete`
- **权限**：仅发起人（非发起人返回错误码 1000011012）。
- **前端校验**：详情页要求待评审数与不通过数均为 0（全部通过）才允许提交，否则按钮置灰并以 tooltip 提示“全部用例评审通过后才能完成评审”；列表页不再提供 [完成] 入口（视觉基准 `web/demos/project/reviews.html` 裁剪，完成评审统一由详情页承载）。
- **处理**：状态变更为 completed，快照冻结；终态幂等（重复完成仍返回 completed）。

### 1.9 同步最新用例

- **路径**：`POST /api/project/reviews/:id/sync`
- **权限**：发起人，评审未完成（new/in_progress）；评审进入终态（completed/rejected）后快照已定格，返回错误码 1000011026。
- **处理**：根据 original_node_id 匹配当前节点，更新快照属性；已删除节点标记 is_deleted=1；保留评审记录不变。
- **前端**：二次确认（“同步将更新快照节点属性，已有标记不受影响”）→ 成功后重新拉取详情、进度与快照模块树，并重载脑图。

### 1.10 获取模块快照树

- **路径**：`GET /api/project/reviews/:id/module-tree`
- **响应**：模块快照树（目录/文档层级，含 `id`、`parentId`、`name`、`type`、`sortOrder`、`children`），供详情页左侧文档树展示与多文档切换（选中文档后以 documentId 调用 1.5 加载单文档快照脑图）。
- **前端**：加载后默认选中首个文档；同步或移除用例后重载，当前文档已被移除时回退到首个文档。

### 1.11 获取规划用例

- **路径**：`GET /api/project/reviews/:id/cases`
- **响应**：`[{ "documentId": "...", "caseIds": ["..."] }]`，以原始文档/节点 ID 表示当前关联的用例，供调整弹窗回显预选。

### 1.12 调整规划用例

- **路径**：`PUT /api/project/reviews/:id/cases`
- **前置**：评审未完成（new/in_progress，不限发起人）；评审进入终态（completed/rejected）返回错误码 1000011026。
- **请求体**：`{ "selectedNodes": [{ "documentId": "...", "caseIds": ["..."] }] }`（与创建评审的 selectedNodes 同构，为全量覆盖式提交）。
- **处理**：差量更新快照——新增文档生成模块/节点快照；移除文档删除其快照并自底向上清理空目录快照（标记/评论记录保留作审计）；保留文档补全快照后新增的节点并按新选择重刷 is_associated（取消关联的节点保留已有标记，仅退出统计）。快照节点插入按父链先序递归执行，保证父子映射完整。
- **前端**：详情页 [调整用例] 打开 CaseSelector 并以 1.11 结果回显，确认后提交；成功后刷新详情与脑图。脑图内 [移除用例] 亦复用本接口：从当前规划中剔除单个用例，所属文档无剩余用例时整文档移除。

### 1.13 删除评审

- **路径**：`DELETE /api/project/reviews/:id`
- **权限**：仅发起人（非发起人返回错误码 1000011012），任意状态可删。
- **处理**：无物理外键，事务中显式级联删除评审记录、节点快照、模块快照后删除评审本体。
- **前端**：列表页操作列 [删除]（所有行均展示入口，越权由后端拒绝）→ 二次确认 → 删除成功后刷新列表。


### 1.14 驳回评审

- **路径**：`POST /api/project/reviews/:id/reject`
- **权限**：仅发起人，状态为 new/in_progress；进入终态后返回错误码 1000011018（“仅待评审或进行中的评审可驳回”）。
- **处理**：状态变更为 rejected（已驳回），快照冻结，标记/调整/同步/完成入口收敛；事务提交后发布评审生命周期事件；记录项目活动 `REVIEW_REJECTED`。
- **前端**：详情页页头 [驳回]（二次确认，位于活跃态操作组内，发起人身份由后端校验）；列表页该行状态展示已驳回，操作为 [查看][重新发起]。


### 1.15 重新发起评审

- **路径**：`POST /api/project/reviews/:id/reopen`
- **权限**：仅发起人，状态为 rejected；非已驳回状态返回错误码 1000011019（“仅已驳回的评审可重新发起”）。
- **处理**：状态回退为 in_progress，快照、标记与评论全部保留，参与者可继续评审；不改动快照数据，不触发取消钩子。再次完成仍需满足全部通过门槛。
- **前端**：详情页仅当状态为 rejected 且当前用户为发起人时展示 [重新发起]（二次确认后原地刷新）；列表页 rejected 行展示 [重新发起]（二次确认后刷新列表）。


## 2. 快照生成与裁剪

评审或计划创建时，递归复制所需路径的 test_case_module 和涉及文档的全部 test_case_node。节点所有字段原样复制到快照表，is_associated 根据用户选择的 caseIds 标记。裁剪展示时根据关联节点向上追溯祖先、向下加载后代，构建最小树，返回嵌套的根节点对象。


### 2.1 评审列表页（功能测试 - 测试评审）

**路由**：`/workspace/projects/reviews`（`meta.title` 测试评审、`mode` project，无独立菜单项）

列表同时作为功能测试页的子模块渲染：功能测试页左侧菜单选中“测试评审”时展示，地址为 `/workspace/projects/functional-testing?tab=reviews`（菜单挂载于功能测试页，权限 `case:view`）。视觉与结构验收基准 `web/demos/project/reviews.html`，页面结构与列口径见 `docs/05-interaction-design/03-function-testing/05-workspace-ui-test-review.md` 1.1。

**页面布局**：

```
┌───────────────────────────────────────────────────────────────────┐
│  测试评审                                            [+ 发起评审]  │
│  用例评审与评审结论跟踪                                             │
├───────────────────────────────────────────────────────────────────┤
│ [搜索标题][状态: 全部 ▼][查询][重置]                共 N 场评审      │
│ 标题(副行:关联用例 N 条)│发起人│  状态  │   进度   │通过率│参与者│创建时间│  操作   │
│ 登录模块用例评审        │ 张三 │●进行中 │[━] 8/10 │ 40% │头像堆│06-15 10:00│[进入][删除]│
│ 支付模块用例评审        │ 李四 │●已通过 │[━]10/10 │100% │头像堆│06-10 09:30│[查看][删除]│
│ 履约模块用例评审        │ 周敏 │●已驳回 │[━]10/10 │ 70% │头像堆│06-08 14:00│[查看][重新发起][删除]│
├───────────────────────────────────────────────────────────────────┤
│ 共 N 场 · 每页 20 条                             ‹  1  2  3  ›    │
└───────────────────────────────────────────────────────────────────┘
```

**交互说明**：

| 操作   | 触发方式     | 反馈                                            |
| ---- | -------- | --------------------------------------------- |
| 筛选   | 标题关键字回车/清空即查询；状态下拉选择后点[查询]；[重置] | 重置清空条件并回到首页，其余查询在触发时刷新列表            |
| 分页   | 点击页码     | 按当前筛选条件加载对应页（每页 20 条，仅切换页码，不提供每页条数切换） |
| 发起评审 | 点击[发起评审] | 弹出创建表单：标题（必填，≤200 字）、描述、参与者（多选成员）、关联用例（打开CaseSelector弹窗）；校验至少一个参与者与一个用例，创建成功跳转详情页 |
| 进入评审 | 点击[进入]   | 跳转至评审详情页（new/in_progress）              |
| 查看详情 | 点击[查看]   | 跳转至评审详情页（completed/rejected）           |
| 重新发起 | 点击[重新发起] | 二次确认 → rejected 回到 in_progress，列表刷新   |
| 删除   | 点击[删除]   | 二次确认 → 级联删除评审记录与快照（发起人身份由后端校验），列表刷新 |

**状态分支**：加载中卡片内 loading；空数据展示“暂无评审”；查询/删除/重新发起失败以错误消息提示。通过率列待评审显示 `—`，已通过绿色加粗、已驳回红色；进度条进行中橙色、已驳回红色、其余默认色；参与者头像堆最多 3 个 +「+N」，发起人置顶品牌色，无参与者显示 `—`。


### 2.2 评审详情页

**路由**：`/workspace/projects/reviews/:reviewId`（`meta.title` 评审详情、`mode` project）

**页面布局**：

```
┌────────────────────────────────────────────────────────────────────┐
│ 测试评审 › 登录模块评审                                              │
│ ┌────────────────────────────────────────────────────────────────┐ │
│ │ 登录模块评审 [进行中]   [━━━]  通过 6  不通过 2  待评审 2  共 10  │ │
│ │                             [调整用例][同步用例][驳回][完成评审]  │ │
│ ├─────────────┬──────────────────────────────────────────────────┤ │
│ │ 快照文档  只读│  [✅通过][❌不通过][❓待评审][💬评论][🗑移除用例]   │ │
│ │ ▾ 评审目录   │                                                  │ │
│ │   📄 文档 A  │        快照脑图（只读，禁用画布编辑）               │ │
│ │   📄 文档 B  │        节点右侧徽标回显标记 ✅/❌                    │ │
│ │             │        右键：标记三态 / 添加评论 / 从评审中移除       │ │
│ └─────────────┴──────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

页头为面包屑 + 单行标题区：面包屑「测试评审 › 标题」，点击「测试评审」返回功能测试页并激活测试评审子模块（`?tab=reviews`）；标题区含标题、状态标签、进度条与分色统计（通过绿 / 不通过红 / 待评审橙 / 共 N），右侧为操作按钮组。活跃态（new/in_progress）展示 [调整用例][同步用例][驳回][完成评审]，已驳回且当前用户为发起人时展示 [重新发起]，已通过无操作按钮。

详情页使用独立的评审脑图组件（`ReviewMindMap`，只读画布），快照树数据以嵌套根节点对象形式返回，节点显示评审状态徽标。页面未选用文档时右侧展示“请在左侧选择一个文档”，快照树为空时展示“暂无快照文档”。

**交互说明**：

| 操作       | 触发方式            | 反馈                 |
| -------- | --------------- | ------------------ |
| 标记通过/不通过/待评审 | 选中节点 → 工具栏三态按钮或右键菜单 | 提交评审记录，节点徽标与页头进度实时刷新      |
| 添加评论     | 选中节点 → 工具栏[💬评论]或右键「添加评论」 | 打开“评审记录”抽屉，输入提交（Enter 发送，≤500 字）        |
| 查看评审历史   | 打开“评审记录”抽屉        | 按时间展示标记变更和评论列表，空态“暂无评论或标记记录”        |
| 移除用例     | 工具栏[🗑移除用例]或右键「从评审中移除」（活跃态 + 已关联 case 节点） | 二次确认 → 从规划中剔除该用例并重载快照树/脑图/进度，标记记录保留作审计 |
| 调整用例     | 点击[调整用例]          | CaseSelector 回显当前规划 → 确认后全量覆盖更新并刷新      |
| 完成评审     | 点击[完成评审]（发起人身份由后端校验） | 二次确认 → 状态变更为已通过（completed，需全部通过，否则按钮置灰并 tooltip 提示）    |
| 驳回评审     | 点击[驳回]（活跃态展示，发起人身份由后端校验） | 二次确认 → 状态变更为已驳回（rejected），活跃态操作组收起                        |
| 重新发起     | 点击[重新发起]（仅 rejected 且当前用户为发起人可见） | 二次确认 → 已驳回回到进行中（in_progress），标记保留      |
| 同步用例     | 点击[同步用例]（发起人身份由后端校验） | 确认 → 更新快照属性，重载详情、快照树与脑图，保留评审记录 |
| 切换文档     | 点击左侧文档树节点        | 右侧脑图切换为该文档的快照（目录点击仅展开/收起，未选中文档时不切换） |

**状态分支**：页面加载中整体 loading；详情/进度/快照树任一加载失败以错误消息提示；评审进入终态（completed/rejected）后操作组收起（已通过无操作按钮，已驳回仅 [重新发起]），标记/调整/同步由后端状态机拦截并返回错误码 1000011026；非发起人执行发起人专属动作由后端返回错误码 1000011012。
