## 1. 环境变量管理

环境变量**随环境整体聚合提交**：变量列表嵌入环境配置，通过环境的创建与更新接口（环境管理分册 `docs/04-detailed-design/05-api-testing/18-environment-management-env.md` 1.3 / 1.4）整体提交，写入主表 `variables` JSONB 列；环境详情接口（同上 1.2）随环境配置返回完整变量列表（变量值明文返回）。

环境管理**不提供独立的变量接口**：路由表中不存在变量的新增、批量替换、单独导入 / 导出等路径，面板内变量行的增删改在 [保存全部]（新建 / 复制态为 [创建]）时随聚合载荷一次写入；变量的导入 / 导出复用环境级导出（同上 1.9）与导入（同上 1.10），变量值随环境 JSON 明文落地。当前实现中变量仅在环境详情面板维护，未提供从调试结果或执行报告一键写入环境变量的入口。

### 1.1 变量定义与校验

`variables` 数组元素结构：

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| name | VARCHAR(100) | 是 | 变量名（仅字母/数字/下划线 `[A-Za-z0-9_]+`，同环境内不得重名） |
| value | TEXT | 否 | 变量值（明文存取、明文展示，为空表示未配置） |
| description | VARCHAR(500) | 否 | 变量描述 |

详情响应在上述三字段外返回 `hasValue`：`value` 明文返回，未配置值时 `value` 为 `null` 且 `hasValue = false`。

校验前后端同规则，任一不通过即拒绝本次保存（整批提交、不落部分数据）：

- 变量名必填、仅字母 / 数字 / 下划线、长度不超过 100，同环境内唯一；
- 描述可选，长度不超过 500；
- 前端在提交前逐行校验，失败以 Toast 提示「变量 xxx：变量名已存在」「变量 xxx：变量名仅允许字母、数字与下划线」等并阻止提交；后端以验证注解与聚合归一化复验，重名或格式非法以校验错误拒绝。

### 1.2 作用域与引用语法

- **作用域**：环境变量是**环境级**变量，随所属环境生效，作用于该环境下的调试与场景执行；执行时未指定环境则回退项目默认环境，指定环境与默认环境均缺失时以空变量集执行（调试与场景执行共用同一环境快照口径）。
- **引用语法**：统一使用 Ryze 原生 `${变量名}` 形式，不使用 `env:` / `var:` 前缀；变量值中可嵌套 `${...}`，由执行引擎在运行时求值。详情面板「变量」页签固定提示 `引用语法：${变量名}，如 ${BASE_URL}`。
- **层级关系**：环境变量是执行期最低优先级的业务变量（仅高于内置函数），解析链见 3；各层级承载位置与覆盖关系的完整定义见 `docs/04-detailed-design/05-api-testing/15-test-scenario-variable.md` 3.1。

### 1.3 前端编辑与状态

| 项 | 行为 |
| ---- | ---- |
| 编辑器 | 「变量」页签复用键值表 `KeyValueTable`：变量名 / 值 / 描述三列，无启用列（变量无启用语义），表头 [＋ 新增] 显式建行 |
| 排序 | 展示按变量名升序（仅展示顺序，不改变存储顺序）；页签计数只统计变量名非空的行 |
| 提交过滤 | 变量名为空的行不提交、不计数 |
| 空态 | 有编辑权限：「暂无变量，点击表头 [＋ 新增]」；无编辑权限：「暂无变量」 |
| 权限 | 无 `api-env:edit` 时整表只读，[＋ 新增] 与 [保存全部] 不渲染；详情加载失败展示「环境详情加载失败」并提供 [重试]（页面入口与权限口径见 `docs/04-detailed-design/05-api-testing/17-environment-management-overview.md` 1.4） |


## 2. HTTP 配置与数据源管理

HTTP 配置与数据源**随环境整体聚合提交**：通过环境的创建 / 更新接口（环境管理分册 `docs/04-detailed-design/05-api-testing/18-environment-management-env.md` 1.3 / 1.4）一次性整体提交，分别写入主表 `http_configs` / `data_sources` JSONB 列；环境详情接口（同上 1.2）随环境配置返回完整 HTTP 配置与数据源列表。**不提供独立的 HTTP 配置 / 数据源新增、更新、删除接口**，面板内的增删改在提交时整体写入；连接测试为请求体传入完整配置的免保存试连（见同上 1.7 / 1.8）。

`http_configs` 数组元素结构：

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| name | VARCHAR(100) | 是 | 配置名称 |
| refName | VARCHAR(100) | 是 | 引用名称（对应 Ryze `refName`，步骤中按引用名选用配置） |
| baseUrl | VARCHAR(2000) | 是 | Base URL |
| headers | JSON | 否 | 公共请求头（配置级默认请求头）`[{key, value, enabled}]` |
| isDefault | BOOLEAN | 否 | 是否默认（同一环境内至多一个；为 true 时清除其余 HTTP 配置的 `isDefault`，缺省 false） |

- **公共请求头**：前端提交时剔除 key 与 value 均为空的行，`enabled` 标记随行存储；执行装配请求头时跳过 `enabled = false` 的行，步骤级同名请求头覆盖环境级默认值（见 `docs/04-detailed-design/05-api-testing/14-test-scenario-step.md`）。
- **默认配置**：前端面板以开关设置 `isDefault`，配置列表将默认项置顶；执行期未显式指定引用时取 `isDefault = true` 的配置，环境内未设默认则取第一条。
- **无超时等可配置项**：前端 HTTP 表单仅含名称、引用名、Base URL、设为默认与公共请求头，不含超时 / 重定向 / SSL 配置；执行与试连的超时、重定向、SSL 校验为固定值（见 `docs/04-detailed-design/05-api-testing/17-environment-management-overview.md` 2.1.2）。

`data_sources` 数组元素结构：

| 字段 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| name | VARCHAR(100) | 是 | 数据源名称 |
| refName | VARCHAR(100) | 是 | 引用名称（对应 Ryze `refName`） |
| driver | VARCHAR(100) | 是 | JDBC 驱动类名；Redis 数据源以 `-` 占位驱动满足必填，连接测试按 `redis://` 协议识别 |
| url | VARCHAR(500) | 是 | JDBC 连接 URL / Redis `redis://[password@]host:port/db` |
| connectionProperties | JSON | 否 | 附加连接参数（缺省 `{}`） |
| maxPoolSize | INT | 否 | 引擎侧连接复用上限（为空默认 5，见 4） |
| isDefault | BOOLEAN | 否 | 是否默认（同一环境内至多一个；为 true 时清除其余数据源的 `isDefault`，缺省 false） |

请求体中的 `headers` 结构同环境创建请求（环境管理分册 1.3）。数据源随详情返回，导出时整段排除、导入时被忽略，环境导入后需重新配置（见同上 1.9 / 1.10）。

## 3. 变量解析优先级

环境变量与场景变量、步骤级变量、步骤提取器变量、运行时覆盖同名时，按从低到高优先级取值（与 `docs/04-detailed-design/05-api-testing/15-test-scenario-variable.md` 3.1 一致）：

```
内置函数 < 环境变量 < 场景变量 < 步骤级变量 < 步骤提取器变量 < 运行时覆盖
```

环境变量作为次低优先级，仅高于内置函数；场景级、步骤级同名变量依次覆盖环境变量。参数优先级的规则依据见 `docs/02-high-level-design/05-api-testing/06-hld-api-test-scenario.md` 3.2 与 `docs/01-requirements/05-api-testing/10-api-srs-project-settings.md` 1.1。


## 4. 数据源连接池

平台侧不自建数据源连接池，连接复用由执行引擎按数据源配置管理：

- `maxPoolSize`（缺省 5）在执行装配时写入引擎 JDBC 配置元件的 `max_active`，由引擎侧决定连接复用行为；该字段对 Redis 数据源无意义。
- 连接测试为**一次性建连、用毕即释放**：JDBC 通过 `DriverManager` 建连（登录超时 10s，仅放行随服务打包的驱动，见环境管理分册 `docs/04-detailed-design/05-api-testing/18-environment-management-env.md` 1.7）；Redis 按 `redis://` / `rediss://` 协议识别，发送 `PING` 验证后关闭连接与客户端，不复用长连接。
- Redis 取样器执行属多协议扩展预留，届时再评估长连接复用策略。

## 5. 数据源连接池

连接池口径见 4，实现注意点：

- 数据源连接失败通过 `ServiceExceptionUtil.get(ErrorCodeConstants.API_DATASOURCE_CONN_FAILED)` 抛出（错误码 1000017403），前端映射为「数据源连接失败」并附后端冒号后的原因展示；连接测试失败不影响环境的保存与删除。
- 连接测试请求体传当前表单值、不落库，平台侧不存在按「环境 + 数据源」缓存的连接对象，环境更新或数据源删除无需释放连接。
- 试连结果内联显示在 [连接测试] 按钮旁（成功展示状态码 / 数据库版本与耗时，失败展示原因），切换配置或数据源即清空结果，失败可直接重试；环境未创建（面板新建态）时 [连接测试] 置灰并提示「创建环境后可测试连接」。


## 6. 敏感数据加密

- 环境变量值明文存储、明文展示：无敏感值概念（无类型与加密链路），详情与导出均返回明文，执行装配直接读取明文值，无解密环节。
- 数据源凭据直接写入连接 URL，不在表单中独立存储（前端以「用户名/密码通过 URL 设置」提示）；环境导出时数据源段整段排除，导入端亦不消费该段（见环境管理分册 `docs/04-detailed-design/05-api-testing/18-environment-management-env.md` 1.9 / 1.10）。
