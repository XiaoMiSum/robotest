## 1. 工作空间管理接口

> 本节接口统一挂载在 `/api/admin/workspaces` 下，路径中的 `:id` / `:userId` 为 UUID；响应示例仅展示 `data` 字段内容（通用分页与响应结构见 `docs/00-spec/20-contracts/01-api.md`）。

### 1.1 获取工作空间列表

- **路径**：`GET /api/admin/workspaces`
- **权限**：`workspace:view`；另兼容 `user:view`、`role:view`，供数据概览与角色管理页的空间筛选入口复用。
- **请求参数**：

| 参数       | 类型     | 必填  | 说明                                     |
| -------- | ------ | --- | -------------------------------------- |
| keyword  | string | 否   | 按名称模糊搜索                                |
| status   | string | 否   | `active` / `dissolved`，不传返回全部；展示口径：活跃 / 归档（列表页默认 `active`） |
| pageNo   | int    | 否   | 页码，默认 1                                |
| pageSize | int    | 否   | 每页数量，默认 20，最大 100                      |

- **排序**：按创建时间倒序。
- **响应**：
  
  ```json
  {
  "list": [
    {
      "id": "6f1d2b8e-4c3a-4f5e-9a7d-1b2c3d4e5f60",
      "name": "电商平台测试",
      "description": "负责电商平台相关测试",
      "memberCount": 15,
      "projectCount": 5,
      "status": "active",
      "createdByName": "zhangsan",
      "createdAt": "2026-01-01T00:00:00Z"
    }
  ],
  "total": 12
  }
  ```

- **字段说明**：`createdByName`（String，可空）由 `created_by` 批量回查 `sys_user.username`，历史数据无创建人时为 `null`（前端展示 `—`）。列表页当前不展示创建人列，该字段由详情页信息区展示；详情接口 `GET /api/admin/workspaces/:id` 返回同样的字段集合。

### 1.2 创建工作空间

- **路径**：`POST /api/admin/workspaces`
- **权限**：`workspace:create`
- **请求体**：`{ "name": "新项目工作空间", "description": "工作空间描述", "adminUserId": "uuid" }`
- **校验**：`name` 必填，2~50 字符，全局唯一（重复返回 `1000001004`）；`description` 可选，最长 500 字符（前端输入限制 200）；`adminUserId` 必填，指定的管理员必须存在（`1000003001`）且为启用状态（`1000001010`）。
- **处理**：写入当前登录用户为 `created_by`（见 2）；空间落库后立即将 `adminUserId` 绑定为空间管理员成员（创建即绑定，保证「至少保留一个空间管理员」从源头成立；先校验管理员后插库，避免半成品数据）。空间管理员角色由后端赋预置管理员角色，请求体不接受角色指定。
- **响应**：新建工作空间的 ID（UUID 字符串），HTTP 200；前端凭该 ID 跳转详情页。

### 1.3 获取工作空间详情

- **路径**：`GET /api/admin/workspaces/:id`
- **权限**：`workspace:view`
- **响应**：工作空间基本信息（字段同 1.1），含 `createdByName`；成员列表由 1.6 的独立分页接口提供，不在详情响应中嵌套分页结果。

### 1.4 更新工作空间

- **路径**：`PUT /api/admin/workspaces/:id`
- **权限**：`workspace:edit`
- **请求体**：可更新 `name`（2~50 字符）、`description`（最长 500 字符），两者均可选。
- **校验**：名称唯一性，重复返回 `1000001004`；已归档（`status='dissolved'`）的工作空间不可编辑（返回 `1000010033`）。
- **说明**：部分更新，只写入实际传入的字段，不触碰 `created_by`（见 2）。

### 1.5 归档工作空间

- **路径**：`DELETE /api/admin/workspaces/:id`
- **权限**：`workspace:delete`
- **前置校验**：仅存在性校验（不存在返回 `1000003002`）；**不校验项目与成员**——归档不要求空间下没有项目，也不解除成员归属。
- **处理逻辑**：更新 `status='dissolved'` 将空间置为冻结态；**成员行保留**，供重新启用后原样还原。
- **响应**：成功提示。

### 1.6 获取工作空间成员

- **路径**：`GET /api/admin/workspaces/:id/members`

- **权限**：`workspace:view`

- **请求参数**：`pageNo`、`pageSize`

- **排序**：按加入时间倒序。

- **响应**：
  
  ```json
  {
  "list": [
    {
      "userId": "1d8a2f16-0f2b-4a4c-8f9c-5b6e7a8d9c01",
      "username": "zhangsan",
      "name": "张三",
      "email": "zhangsan@example.com",
      "avatarUrl": null,
      "workspaceRole": "c0000000-0000-0000-0000-000000000001",
      "joinedAt": "2026-01-15T10:30:00Z"
    }
  ],
  "total": 8
  }
  ```

- **字段说明**：`name` 为用户姓名；`avatarUrl` 为头像地址（可空）；`workspaceRole` 为 workspace 类型角色 ID（UUID）。

### 1.7 添加成员

- **路径**：`POST /api/admin/workspaces/:id/members`

- **权限**：`workspace:manage-members`

- **请求体**：
  
  ```json
  {
  "members": [
    { "userId": "1d8a2f16-0f2b-4a4c-8f9c-5b6e7a8d9c01", "workspaceRole": "c0000000-0000-0000-0000-000000000001" },
    { "userId": "2e7b3c27-1a3d-4b5e-9c8d-6f7a8b9c0d12", "workspaceRole": "c0000000-0000-0000-0000-000000000002" }
  ]
  }
  ```

- **校验**：`userId` 必填；用户不存在或非活跃时静默跳过（不报错）；已在本工作空间的用户跳过并计入返回列表；`workspaceRole` 未传时默认预置 `workspace_member` 角色 ID，服务端不校验角色 ID 取值范围（角色选项由前端从 workspace 类型角色列表获取）；归档空间拒绝操作（`1000010033`）。

- **响应**：被跳过的用户 ID 列表（重复添加的用户）；不存在或非活跃的用户直接忽略，不出现在返回中。

### 1.8 更新成员角色

- **路径**：`PUT /api/admin/workspaces/:id/members/:userId`
- **权限**：`workspace:manage-members`
- **请求体**：`{ "workspaceRole": "c0000000-0000-0000-0000-000000000001" }`（必填）
- **校验**：降级唯一管理员时阻止（`1000001009`）；归档空间拒绝操作（`1000010033`）。

### 1.9 移除成员

- **路径**：`DELETE /api/admin/workspaces/:id/members/:userId`
- **权限**：`workspace:manage-members`
- **校验**：不能移除空间最后一位管理员（`1000001009`）；归档空间拒绝操作（`1000010033`）。
- **响应**：成功提示。

### 1.10 重新启用工作空间（归档恢复）

- **路径**：`POST /api/admin/workspaces/:id/restore`
- **权限**：`workspace:delete`
- **校验**：工作空间不存在返回 `1000003002`；**必须处于已归档状态**（`status='dissolved'`），活跃空间调用返回 `1000010034`。
- **处理逻辑**：将 `status` 置回 `active`；归档期间保留的成员行原样生效，无需重新添加。
- **响应**：成功提示，前端刷新详情状态与操作入口。


## 2. 空间创建人写入与回填

- `POST /api/admin/workspaces`：Controller 通过 `@AuthenticationPrincipal LoginUser` 取当前用户 ID 传入 Service（仅传参，不含业务逻辑，C2），`createWorkspace` 写入 `created_by`。
- `getWorkspacePage` / `getWorkspaceDetail`：收集 `created_by` 集合后 `userMapper` 批量回查用户名，回填 `createdByName`；`created_by` 为 null 时置 null。
- 遵循部分更新原则（C11）：更新空间时**不触碰** `created_by`。

## 3. 前端设计

### 3.1 路由与菜单

| 页面 | 路径 | name | meta.title | 菜单配置 |
| --- | --- | --- | --- | --- |
| 空间列表 | `/admin/workspaces` | `AdminWorkspaces` | 工作空间管理 | label `空间管理`、icon `OfficeBuilding`、order 30、section `组织与权限`、permission `workspace:view` |
| 空间详情 | `/admin/workspaces/:id` | `AdminWorkspaceDetail` | 工作空间详情 | 不挂菜单项，经列表页或直接输入 URL 进入 |

- `/admin` 分组路由挂 `requiresAuth` + `requiresAdmin` 守卫：无 token 跳转登录页；权限列表未加载时先拉取，具备系统角色或系统级权限（存在 `user:` / `workspace:` / `role:` 前缀权限）才放行，否则重定向 `/`。
- 侧边栏菜单按 `workspace:view` 过滤（见 `web/src/router/index.ts`、`web/src/stores/nav.ts`）。
- 详情页面包屑由页面自绘：`空间管理`（链接回 `/admin/workspaces`）→ 当前空间名称。

```
│ 空间名称   │ 描述    │ 状态   │ 成员 │ 项目 │创建时间 │ 操作   │
│ (链接)     │ 空显示—│ ● 活跃 │  15  │  5   │ datetime│ 查看详情│

```

- **头部**：标题「空间管理」+ 副标题「平台内全部工作空间及其规模」；「新建空间」按钮仅在拥有 `workspace:create` 时渲染，无权限时按钮与对话框整体不出现。
- **筛选工具栏**：状态分段控件（活跃 / 归档），默认 `active`，点击即查询并回到第 1 页（后端无按状态计数接口，分段不展示计数）；关键字输入框（占位「搜索空间名称」，回车或「查询」触发，查询时回到第 1 页）；「重置」清空关键字并恢复 `status=active`、`pageNo=1`；工具栏右侧固定提示「按创建时间倒序」。
- **表格列**：空间名称（主链接）、描述（空显示 `—`，超长省略并悬浮提示）、状态（圆点 + 文案，活跃绿 / 归档灰）、成员、项目、创建时间（`formatDateTime` 按浏览器时区展示）、操作（查看详情）；整行可点击进入详情。
- **分页**：每页 10 / 20 / 50 / 100，默认 20，布局 `total, sizes, prev, pager, next`；翻页直接加载，切换页大小回到第 1 页重新加载。
- **新建对话框**（`web/src/components/workspace/WorkspaceCreateDialog.vue`）：名称（必填、去空格后 2~50 字符，上限 50）、管理员（必填，远程搜索仅活跃用户，默认当前登录用户）、描述（可选，最多 200 字符）；提交成功提示「工作空间已创建」，关闭对话框并跳转新空间详情；失败按错误消息提示。
- **错误分支**：列表加载失败弹出「加载工作空间列表失败」消息，表格保留空数据态。

### 3.3 空间详情页

> 实现：`web/src/pages/admin/WorkspaceDetailPage.vue` + `web/src/composables/admin/useWorkspaceDetail.ts`

```
空间管理 › 电商平台测试
电商平台测试  ● 活跃
空间 ID 6f1d2b8e-… · 创建于 2026-01-01 08:00            [归档空间]

┌ 空间信息 ─────────────────────────────────────────────────────┐
│ 空间名称 [电商平台测试____]   创建人 [zhangsan    ]（只读）   │
│ 描述     [multiline________________________]                  │
│ (成员 15)  (项目 5)                         [重置] [保存修改] │
└───────────────────────────────────────────────────────────────┘
┌ 成员列表   8 人                          [＋ 添加用户] ──────┐
│ 用户 | 空间角色 | 加入时间 | 操作（改角色 移除）              │
│ (头像+用户名) (标签)  (datetime)                             │
│                                        共 8 条  20/页  ‹ 1 › │
└───────────────────────────────────────────────────────────────┘
```

- **页头**：面包屑（空间管理 → 空间名称）；标题行 = 空间名称 + 状态点标（活跃绿 / 归档灰）；副行展示空间 ID（等宽字体）与创建时间；右侧操作按钮——活跃态为红色「归档空间」，归档态为「重新启用」。
- **空间信息卡片**：空间名称（必填、2~50 字符校验）、创建人（只读，展示 `createdByName`，空显示 `—`）、描述（textarea，200 字符计数）；下方统计徽章「成员 N」「项目 N」；底部「重置」「保存修改」操作，保存成功提示「已保存」并用响应回填详情，失败按错误消息提示。
- **成员列表卡片**：标题 + 「N 人」计数，右侧「添加用户」按钮；列为用户（头像 + 用户名）、空间角色（标签展示，按预置角色 ID 区分管理员并高亮）、加入时间、操作（改角色 / 移除）；分页每页 20 / 50 / 100，默认 20，按加入时间倒序，翻页或切换页大小直接触发加载。
  - **改角色**：点击后就地切换为下拉框（自动展开），选择即提交；成功提示「角色已更新」，失败提示并刷新列表回滚显示。
  - **移除**：`ElMessageBox.confirm` 确认后调用删除，成功提示「已移除」并刷新成员列表与详情统计。
  - **添加用户对话框**：远程搜索用户（用户名 / 邮箱，多选，保留已选项），每个已选用户分配空间角色（默认取 workspace 类型角色列表首项）；未选用户提交时提示「请至少选择一个用户」；成功提示「成员已添加」并刷新成员与详情。
- **角色选项**：来自 `GET /api/admin/roles`（`type=workspace`），加载失败不阻塞页面，角色标签回退为「管理员 / 成员 / 未知」。
- **归档流程**：点击「归档空间」→ 输入空间名称确认（提示归档后转只读、成员与数据保留、可随时重新启用）→ `DELETE /api/admin/workspaces/:id` → 成功提示「空间已归档」并返回列表页。
- **重新启用**：点击后直接调用 `POST /api/admin/workspaces/:id/restore`，无确认弹窗（恢复可逆、误触成本低）；成功提示「空间已重新启用」并刷新详情状态与操作入口。

### 3.4 状态分支

| 场景 | 行为 |
| --- | --- |
| 列表加载中 | 表格 `v-loading` 遮罩 |
| 列表为空 | Element Plus 表格默认空态 |
| 列表加载失败 | 「加载工作空间列表失败」错误消息，表格保持空数据态 |
| 无 `workspace:create` | 「新建空间」按钮与对话框不渲染 |
| 详情加载中 | 空间信息卡片 `v-loading` 遮罩 |
| 详情加载失败 | 错误消息提示，页面保留「工作空间详情」占位标题与空 ID 行 |
| 已归档（`dissolved`） | 整页只读：信息表单 `disabled`、隐藏「重置 / 保存修改」、隐藏「添加用户」与成员操作列，页头仅留「重新启用」；成员列表与统计徽章照常展示 |
| 活跃（`active`） | 信息表单可编辑，页头为「归档空间」 |
| 成员操作被后端拒绝 | 按错误码消息提示（最后一位管理员 `1000001009`、归档空间 `1000010033`），并刷新成员列表 |

### 3.5 权限口径

| 入口 | 前端挂载 | 后端 `@PreAuthorize` |
| --- | --- | --- |
| 侧边栏「空间管理」菜单 | `workspace:view` | — |
| 列表页「新建空间」按钮与对话框 | `workspace:create` | `workspace:create` |
| 列表查询 | 仅受 `/admin` 守卫约束 | `workspace:view`（兼容 `user:view`、`role:view`） |
| 详情查询、成员查询 | 仅受 `/admin` 守卫约束 | `workspace:view` |
| 详情信息保存 | 不做前端权限隐藏 | `workspace:edit` |
| 归档 / 重新启用 | 不做前端权限隐藏 | `workspace:delete` |
| 添加成员 / 改角色 / 移除成员 | 不做前端权限隐藏 | `workspace:manage-members` |

> 本模块两个页面中，前端按权限码显式挂载的只有菜单项与「新建空间」入口；详情页的保存、归档、重新启用与成员维护按钮不做前端权限隐藏，越权调用由后端拦截并以错误消息反馈。
