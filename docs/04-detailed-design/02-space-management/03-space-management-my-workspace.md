## 1. 数据设计变更

### 1.1 最近访问时间

`ws_user` 新增 `last_accessed_at TIMESTAMP NULL`，记录当前用户最近一次成功进入对应工作空间的时间。存量记录保持 `NULL`，不得用当前时间伪造历史访问顺序；列表排序时将空值置于末尾。

```sql
ALTER TABLE ws_user ADD COLUMN last_accessed_at TIMESTAMP NULL;
CREATE INDEX idx_ws_user_user_last_accessed
    ON ws_user (user_id, last_accessed_at DESC)
    WHERE is_deleted = FALSE;
```

`ws_user` 现有唯一索引与普通索引共 4 个，新增后共 5 个，符合 C9；不新增物理外键。

### 1.2 用例统计索引

工作空间用例数按“项目 → 用例文档 → `type='case'` 节点”聚合。为覆盖文档范围与用例类型组合查询，新增联合索引：

```sql
CREATE INDEX idx_test_case_node_document_type
    ON test_case_node (document_id, type)
    WHERE is_deleted = FALSE;
```

统计口径：项目、文档、节点均排除逻辑删除记录；项目统计包含活跃与已归档项目；用例仅统计 `test_case_node.type = 'case'` 的节点。

### 1.3 全量建库同步

上述字段与索引同步写入 `server/src/main/resources/db/schema.sql`。存量环境执行 1.1、1.2 的 DDL；全量建库直接以更新后的 `schema.sql` 为准。

## 2. 我的空间接口（/api/workspaces）

### 2.1 获取我的工作空间列表

- **路径**：`GET /api/workspaces`
- **上下文**：该接口用于选择空间，不携带 `X-Active-Workspace`；认证通过 `Authorization: Bearer <token>` 头传递。
- **请求参数**：

| 参数     | 类型   | 必填 | 默认值 | 说明 |
| -------- | ------ | ---- | ------ | ---- |
| keyword  | string | 否   | 空     | 工作空间名称，不区分大小写的包含匹配，长度不超过 50 |
| scope    | string | 否   | `all`  | `all`（全部）、`managed`（我管理的活跃空间）、`archived`（已归档空间） |
| pageNo   | int    | 否   | 1      | 页码，小于 1 返回参数校验错误 `1000001001` |
| pageSize | int    | 否   | 12     | 每页数量，1~100，越界返回参数校验错误 `1000001001` |

- **范围规则**：
  - `all`：当前用户全部未删除成员关系，包含 `active` 与 `dissolved` 工作空间。
  - `managed`：`workspaceRole = 预置管理员角色ID` 且工作空间状态为 `active`。
  - `archived`：工作空间状态为 `dissolved`。
- **计数规则**：数量统计由独立的 `GET /api/workspaces/counts` 接口提供，忽略当前选中的 `scope`，但应用当前 `keyword`，分别返回全部、我管理的、已归档的真实总数；列表接口的 `total` 为当前 `keyword + scope` 组合后的总数。
- **排序规则**：`lastAccessedAt DESC NULLS LAST → joinedAt DESC → createdAt DESC → id ASC`，保证最近访问优先及分页稳定。
- **响应**：

  ```json
  {
    "list": [
      {
        "id": "8f3a21c4-0000-0000-0000-000000000001",
        "name": "质量中台",
        "description": "核心业务线质量保障与用例资产沉淀",
        "workspaceRole": "c0000000-0000-0000-0000-000000000001",
        "workspaceRoleName": "管理员",
        "defaultProjectId": "90000000-0000-0000-0000-000000000010",
        "defaultProjectName": "核心功能测试",
        "memberCount": 24,
        "projectCount": 6,
        "testCaseCount": 1024,
        "status": "active",
        "createdAt": "2026-09-18T02:24:00Z",
        "lastAccessedAt": "2026-09-23T08:30:00Z"
      }
    ],
    "total": 6
  }
  ```

- **统计与查询要求**：
  - 角色名称取 `sys_role.name`，卡片展示真实角色名称；预置角色显示“管理员”“成员”。
  - 成员数为工作空间下未删除的 `ws_user` 关联数；项目数为未删除项目数；用例数按 1.2 口径聚合。
  - 分页数据、分段计数与当前页统计采用固定数量的批量聚合查询，禁止逐卡片查询形成 N+1。
  - 所有自定义 SQL 显式过滤 `is_deleted`。
  - 非法 `scope` 返回参数校验错误 `1000001001`。

### 2.2 获取我的空间数量统计

- **路径**：`GET /api/workspaces/counts`
- **上下文**：该接口用于选择空间，不携带 `X-Active-Workspace`；认证通过 `Authorization: Bearer <token>` 头传递。
- **请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| ---- | ---- | ---- | ---- |
| keyword | string | 否 | 与列表接口一致的工作空间名称包含匹配条件 |

- **响应**：

  ```json
  {
    "all": 6,
    "managed": 2,
    "archived": 1
  }
  ```

- **规则**：统计当前用户全部未删除成员关系，忽略当前列表 `scope`；`all` 包含活跃与已归档空间，`managed` 为当前用户担任管理员的活跃空间，`archived` 为已归档空间。

### 2.3 设置最近活跃工作空间

- **路径**：`PUT /api/workspaces/active`
- **请求头**：
  - `Authorization: Bearer <token>`
  - `X-Active-Workspace: <目标 workspaceId>`
- **请求体**：无。
- **说明**：上下文标识仅通过请求头传递，禁止在 URL 或请求体中出现 `workspaceId`（C4）。
- **处理**：
  1. 校验用户、目标工作空间及成员关系。
  2. 目标工作空间状态为 `dissolved` 时返回 `1000010033`，不得保存为活跃空间。
  3. 在同一事务内以部分更新方式写入 `sys_user.last_active_workspace_id` 与对应 `ws_user.last_accessed_at`（C11）。
  4. 重复进入同一空间时刷新最近访问时间。

### 2.4 创建工作空间

“我的空间”页不新增创建接口，复用系统管理接口：

- **路径**：`POST /api/admin/workspaces`
- **权限**：`workspace:create`
- **请求体**：

  ```json
  {
    "name": "质量中台",
    "description": "核心业务线质量保障",
    "adminUserId": "默认当前用户ID，可改为其他活跃用户ID"
  }
  ```

- **规则**：名称全局唯一，长度 2~50 字符；描述可选，最多 500 字符；`adminUserId` 必填且必须为存在且状态活跃的用户，由后端赋预置空间管理员角色（请求体不接受角色指定）。创建成功后关闭弹窗、提示“工作空间已创建”，并清空关键词与范围筛选后重新加载列表；当前用户被指定为管理员时，新空间按最近访问/加入时间进入列表。
- **前端入口**：仅具备 `workspace:create` 权限时展示页头[新建空间]按钮、空态[新建空间]按钮与网格末尾[新建工作空间]卡片，并挂载创建弹窗，避免普通业务用户触发 403。弹窗字段与校验见 4.5。

## 3. 工作空间切换流程

1. 用户在“我的空间”页面点击状态为 `active` 的卡片（原生 `button`，点击或键盘 Enter/Space 均可触发）。
2. 前端通过 `X-Active-Workspace` 调用 `PUT /api/workspaces/active`；切换请求进行中时忽略后续重复点击；请求失败时通过消息提示错误，不更新本地活跃空间或跳转。
3. 后端校验成员关系与空间状态，更新最近活跃空间及访问时间。
4. 前端更新全局 `activeWorkspaceId` 与工作空间角色。
5. 前端根据卡片中的默认项目信息决定跳转目标：
   - 有默认项目 → 设置 `activeProjectId` 并进入项目仪表盘 `/workspace/projects/dashboard`。
   - 无默认项目 → 清除 `activeProjectId` 并进入项目列表 `/workspace/projects`。
6. 顶部动态菜单切换为工作空间模式（空间信息、成员管理、项目列表）。

已归档卡片渲染为不可交互的文章元素，不触发上述流程，不调用偏好接口、不更新本地状态、不跳转。

## 4. 我的空间页面设计

### 4.1 页面结构

路由为 `/workspaces`（name `Workspaces`，`meta.title` 为“我的空间”，`meta.mode` 为 `none`，不挂载任何顶部菜单项），站点根路径 `/` 重定向到该页。布局基准为 `web/demos/workspace/list.html`：

```text
┌──────────────────────────────────────────────────────────────┐
│ 我的空间                                      [新建空间]     │
│ 选择一个工作空间开始协作，或创建新的空间                    │
├──────────────────────────────────────────────────────────────┤
│ [全部（N）][我管理的（N）][已归档（N）] [搜索空间名称]         │
│                                           按最近访问排序      │
├──────────────────────────────────────────────────────────────┤
│ [文件夹] 管理员                  [文件夹] 成员                 │
│ 质量中台                        供应链测试组                  │
│ 描述……                          描述……                       │
│ 24 成员  6 项目  1,024 用例       17 成员  4 项目  736 用例    │
├──────────────────────────────────────────────────────────────┤
│                      分页（超出单页时显示）                   │
└──────────────────────────────────────────────────────────────┘
```

- 页头下方为白底工具栏卡片，左侧为范围分段组与搜索框（范围按钮在前），右侧为“按最近访问排序”提示。
- 卡片区为自适应网格（`repeat(auto-fill, minmax(300px, 1fr))`），创建卡片位于网格末尾。
- 分页使用 `el-pagination`，布局为 `total, sizes, prev, pager, next`，每页可选 12 / 24 / 48 条（默认 12），仅在非首次加载、无加载错误且 `total` 大于每页数量时显示。

### 4.2 卡片规则

- 活跃空间使用文件夹图标；管理员角色的图标为品牌蓝，普通成员为中性深灰。
- 右上角展示真实角色名称，不使用“我管理”替代角色名；角色名为空时按预置角色回退为“管理员”“成员”。
- 描述最多显示两行，描述为空时展示“暂无描述”；成员、项目、用例数使用真实数据并按千分位格式化。
- 卡片为可聚焦的原生按钮，点击或键盘 Enter/Space 均可进入，携带“进入工作空间：×××”的无障碍标签。
- 已归档卡片同时展示“已归档”文字与“只读”提示，保留真实角色名称和统计，渲染为不可交互元素，不响应点击。
- 当前活跃空间展示“当前空间”角标并标记 `aria-current`，卡片描边使用主色，与普通卡片明确区分。

### 4.3 查询与分页

- 名称输入 300ms 防抖查询；Enter 立即查询（300ms 内重复触发同条件立即查询不重复发请求）；清空立即查询。
- 切换 `scope` 时页码重置为 1；关键词变化同样重置页码；切换每页数量时页码重置为 1。
- 每次加载并行请求列表与分段计数接口，计数随当前 `keyword` 变化，忽略当前 `scope`。
- 请求竞态以递增请求序号忽略过期响应与过期错误，避免旧结果或旧错误覆盖新筛选结果。
- 空结果区分“从未归属空间”与“当前筛选无匹配结果”（关键词非空或范围非“全部”即视为存在筛选）。
- 创建成功后清空关键词、范围复位为“全部”、页码复位为 1 并重新加载列表。

### 4.4 状态覆盖

| 状态 | 展示与行为 |
| ---- | ---------- |
| 首次加载 | 6 张卡片骨架屏，范围按钮与搜索框禁用 |
| 刷新 | 保留已展示内容，顶部显示“正在刷新工作空间列表…” |
| 无任何空间 | 空态提示“暂无归属的工作空间，请联系管理员”；有创建权限时提供[新建空间]按钮，无权限时提示联系管理员分配 |
| 搜索/筛选无结果 | 提示“未找到匹配的工作空间，请调整名称或切换空间范围”，并提供[清除筛选]操作 |
| 加载失败 | 消息提示后端错误信息；无数据时整页错误态并提供[重试]，已有数据时保留列表并在顶部错误横幅提供[重试] |
| 已归档 | 只读卡片，不进入空间 |
| 切换中 | 忽略重复点击；偏好接口失败提示错误并停留本页 |
| 创建中 | 弹窗提交按钮 loading、取消按钮禁用，阻止重复提交 |

### 4.5 新建空间对话框

- 入口：页头[新建空间]按钮、空态[新建空间]按钮、网格末尾[新建工作空间]卡片，均需 `workspace:create` 权限；弹窗标题“新建工作空间”，宽 480px。
- 字段与校验：

| 字段 | 控件 | 必填 | 校验规则 |
| ---- | ---- | ---- | -------- |
| 名称 | 单行输入，最多 50 字符并显示计数 | 是 | 不能为空（纯空格视为未填）；长度 2~50 字符，失焦校验 |
| 管理员 | 远程搜索下拉，仅活跃用户 | 是 | 必选；默认当前登录用户，输入姓名调用 `GET /api/admin/users/simple` 搜索，结果与当前用户、已选项去重合并，搜索失败回退到已合并选项 |
| 描述 | 3 行文本域，最多 200 字符并显示计数 | 否 | 超过 200 字符提示 |

- 提交：校验通过后调用 `POST /api/admin/workspaces`，成功提示“工作空间已创建”并关闭弹窗、清空筛选刷新列表（见 4.3）；校验或接口失败提示错误并停留在弹窗；提交期间确定按钮 loading、取消按钮禁用。
- 每次打开弹窗时重置表单与校验状态，管理员复位为当前用户。

## 5. 实施与验证

### 5.1 主要修改范围

- 后端：工作空间列表查询 DTO/Service/Mapper、活跃空间接口、实体字段、数据库索引、相关单元测试。
- 前端：工作空间列表类型与 service、页面局部组合式逻辑、卡片与创建弹窗组件、管理端创建流程复用、单元测试。
- 文档：需求、概要设计、详细设计、交互设计与全局导航说明同步。

### 5.2 测试要点（C8 ≥ 70%）

- 列表：关键词、三种 scope、分段计数、真实角色名称、真实成员/项目/用例统计、逻辑删除、最近访问排序与稳定分页。
- 切换：活跃空间成功、偏好失败不跳转、重复点击防重入、默认项目/无默认项目分流、归档空间拒绝。
- 前端：防抖与竞态、分页与每页数量切换（12/24/48，页码重置）、角色文案、创建权限显隐、归档卡片不可进入、创建弹窗字段校验与创建成功清空筛选刷新。
- 规范：无新增外部依赖；无物理外键；数据更新仅写本次变更字段；上下文 ID 不进入 URL 或请求体。
