## 1. 空间管理相关接口（/api/workspace）

以下接口操作当前活跃工作空间内的资源，所有接口必须携带请求头 `X-Active-Workspace: <workspace_id>`。

### 1.1 获取当前工作空间详情

- **路径**：`GET /api/workspace`

- **响应**：
  
  ```json
  {
  "id": "3f9a1c2e-6d4b-4a51-9f8c-2b7e0d1a4c60",
  "name": "电商平台测试",
  "description": "负责电商平台相关测试",
  "workspaceRole": "c0000000-0000-0000-0000-000000000001",
  "defaultProjectId": "7a2f5c18-0f9d-4c3b-8e64-1d5a9b3c7e02",
  "defaultProjectName": "核心功能测试",
  "memberCount": 15,
  "projectCount": 5,
  "status": "active",
  "createdByName": "张三",
  "createdAt": "2026-01-01T00:00:00Z"
  }
  ```

- `workspaceRole` 为当前用户在该空间内的角色 UUID：预置管理员角色 `c0000000-0000-0000-0000-000000000001`，预置成员角色 `c0000000-0000-0000-0000-000000000002`；前端据此判断管理员权限。
- `createdByName`：根据 `ws_workspace.created_by` 回查 `sys_user.name`，姓名为空时回退 `username`；历史数据无创建人或用户已删除时为 `null`，前端展示 `—`。
- `GET`、`PUT` 与默认项目设置接口复用相同响应结构。

### 1.2 更新当前工作空间信息

- **路径**：`PUT /api/workspace`

- **权限**：仅空间管理员可操作（服务端校验当前用户 `workspaceRole` 为预置管理员角色）；前端名称、描述输入框与[保存修改]按钮按权限码 `ws-info:edit` 显隐，“空间信息”菜单按 `ws-info:view` 显隐。

- **请求体**：
  
  ```json
  {
  "name": "电商平台测试(更新)",
  "description": "新的描述"
  }
  ```

- **校验**：`name` 全局唯一，2~50 字符；`description` 最多 500 字符；前端提交前去除首尾空白。

- **响应**：更新后的工作空间信息（结构同 1.1），前端同时刷新顶栏空间名称。

### 1.3 设置个人默认项目

- **路径**：`PUT /api/workspace/default-project`
- **请求体**：`{ "projectId": "7a2f5c18-0f9d-4c3b-8e64-1d5a9b3c7e02" }`，若为 null 则清除个人默认项目。
- **校验**：projectId 若不为 null，必须属于当前活跃工作空间且状态为 active。
- **处理**：更新 workspace_user.default_project_id。
- **响应**：更新后的当前工作空间上下文信息（与 GET /api/workspace 响应结构一致）。

### 1.4 获取成员列表

- **路径**：`GET /api/workspace/members`

- **请求参数**：`keyword`（可选，匹配姓名、用户名或邮箱）、`workspaceRole`（可选，空间角色 UUID）、`pageNo`、`pageSize`

- **响应**：
  
  ```json
  {
  "list": [
    {
      "userId": "6b1d9f70-3c2a-4e8b-9a45-7f2c1d8e5b30",
      "username": "zhangsan",
      "name": "张三",
      "email": "zhangsan@example.com",
      "avatarUrl": "...",
      "workspaceRole": "c0000000-0000-0000-0000-000000000001",
      "joinedAt": "2026-01-15T10:30:00Z"
    }
  ],
  "total": 8
  }
  ```

- `name` 为用户展示姓名，成员列表主标题优先使用该字段，缺失时回退 `username`。
- 邮箱按权限脱敏：空间管理员看到完整邮箱，普通成员（含查看自己的行）看到 `u***@example.com` 形式的脱敏值。
- 成员按 `joined_at DESC, id DESC` 稳定排序。
- `workspaceRole` 为空时不附加角色条件；组合查询复用索引 `idx_ws_user_ws_role(workspace_id, workspace_role)`。

### 1.5 直接添加成员

- **路径**：`POST /api/workspace/members`
- **权限**：仅空间管理员可操作（服务端校验空间管理员身份）；前端[邀请成员]按钮按权限码 `ws-member:manage` 显隐。
- **请求体**：
  
  ```json
  {
  "members": [
    { "userId": "6b1d9f70-3c2a-4e8b-9a45-7f2c1d8e5b30", "workspaceRole": "c0000000-0000-0000-0000-000000000002" }
  ]
  }
  ```
- **校验**：`userId` 必填；用户不存在或非活跃状态时静默跳过（不计入 `skippedUserIds`）；已在当前工作空间的用户跳过并计入 `skippedUserIds`。
- **处理**：逐条插入 workspace_user；`workspaceRole` 缺省时回退预置 `workspace_member` 角色 `c0000000-0000-0000-0000-000000000002`，前端提交时固定携带该角色。
- **响应**：`{ "successCount": 1, "skippedUserIds": ["9c4b7e12-8d5a-4f36-b1c0-2e7a6d4f8b91"] }`

### 1.6 更新成员角色

- **路径**：`PUT /api/workspace/members/:userId`（`userId` 为成员用户 UUID）
- **权限**：仅空间管理员可操作。
- **请求体**：`{ "workspaceRole": "c0000000-0000-0000-0000-000000000001" }`
- **校验**：目标成员为管理员且新角色非管理员时，检查不能移除最后一位管理员。
- **响应**：空数据；成功后前端就地更新该行角色标签并提示“角色已更新”，失败则提示错误并重新拉取列表。

### 1.7 移除成员

- **路径**：`DELETE /api/workspace/members/:userId`
- **权限**：空间管理员可移除其他成员；普通成员可自行退出。
- **校验**：被移除对象为管理员时，不能移除空间最后一位管理员。
- **响应**：空数据；移除他人后刷新成员列表，本人退出时清空活跃空间并跳转“我的空间”。

### 1.8 创建邀请链接

- **路径**：`POST /api/workspace/invitations`

- **权限**：仅空间管理员可操作；前端[生成链接]按钮按权限码 `ws-invitation:manage` 显隐。

- **请求体**：
  
  ```json
  {
  "expiresAt": "2026-12-31T23:59:59",
  "maxUses": 50
  }
  ```

  > 请求中的 `expiresAt` 使用无时区 ISO LocalDateTime 墙钟值，由服务端持久化适配层按既定服务器时区转换为 UTC，并且只转换一次；响应中的 `expiresAt` 使用带 `Z` 的 UTC ISO-8601 字符串。`expiresAt`、`maxUses` 均可为 null（永不过期 / 不限次数），前端控件限制最大使用次数为 1–10000。

- **处理**：生成唯一随机 token（64位字符），插入 workspace_invitation 表。

- **响应**：
  
  ```json
  {
  "id": "b51f0c7d-9a3e-4d62-8c10-4f7b2e9a6d35",
  "token": "a1b2c3d4e5f6...",
  "expiresAt": "2026-12-31T23:59:59Z",
  "maxUses": 50,
  "useCount": 0,
  "status": "active",
  "createdAt": "2026-07-04T10:00:00Z"
  }
  ```
  
  > 说明：前端根据 token 自行拼接邀请链接 `${baseUrl}/join?token=${token}`。

### 1.9 获取邀请链接列表

- **路径**：`GET /api/workspace/invitations`
- **权限**：空间管理员（服务端校验）；前端卡片与按钮按 `ws-invitation:manage` 显隐。
- **请求参数**：`pageNo`（可选，默认 1）、`pageSize`（可选，默认 20，最大 100）。
- **响应**：`data` 使用分页结构，完整 token 不进入列表响应：
  ```json
  {
    "list": [
      {
        "id": "uuid-invitation",
        "tokenPreview": "a1b2…ef01",
        "effectiveStatus": "active",
        "status": "active",
        "expiresAt": "2026-12-31T23:59:59Z",
        "maxUses": 50,
        "useCount": 0,
        "createdAt": "2026-07-04T10:00:00Z"
      }
    ],
    "total": 8
  }
  ```

- `tokenPreview`：token 前 4 位 + `…` + 后 4 位；长度不超过 8 位时原样返回。
- `effectiveStatus`：`active`、`exhausted`、`expired`、`revoked`，由邀请状态机和当前服务端时间计算。
- `status` 保留落库状态 `active/revoked`，用于兼容既有调用方。
- 列表按 `created_at DESC` 排序；页头“复制邀请链接”取当前列表中第一条 `effectiveStatus=active` 的记录。

### 1.10 按需获取邀请复制链接

- **路径**：`POST /api/workspace/invitations/:id/copy-link`
- **权限**：空间管理员。
- **处理**：
  - 校验邀请链接存在且属于当前活跃工作空间。
  - 已撤销时返回 `INVITATION_REVOKED`；已过期时返回 `INVITATION_EXPIRED`。
  - 达到使用上限但未过期时仍允许复制，与交互设计一致。
- **响应**：
  ```json
  {
    "token": "完整 token"
  }
  ```
  前端根据 token 拼接 `${origin}/join?token=${token}`，复制文本为多行分享文案，包含标题、当前空间名称、当前登录用户的 `username`（邀请人）、邀请链接与使用说明（已达上限的邀请替换为名额提示）后写入剪贴板。

### 1.11 撤销邀请链接

- **路径**：`PUT /api/workspace/invitations/:id/revoke`
- **权限**：空间管理员。
- **处理**：更新 status='revoked'，前端二次确认后调用并刷新列表。

### 1.12 获取项目列表

- **路径**：`GET /api/workspace/projects`

- **请求参数**：`keyword`（项目名称或描述包含匹配）、`status`（`active` 或 `archived`）、`pageNo`、`pageSize`
- **默认筛选**：`status=active`、`pageSize=20`；列表按 `updated_at DESC, id DESC` 稳定排序，前端滚动加载时递增 `pageNo` 并追加结果（按项目 id 去重）。
- **响应结构**：使用标准分页结构 `PageResult<ProjectRespDTO>`，不将状态数量或页面状态塞入列表响应。

- **响应**：
  
  ```json
  {
  "list": [
    {
      "id": "7a2f5c18-0f9d-4c3b-8e64-1d5a9b3c7e02",
      "name": "用户中心改版",
      "description": "用户中心模块重构测试",
      "status": "active",
      "isDefault": true,
      "startTime": "2026-08-01T00:00:00Z",
      "endTime": "2026-09-01T00:00:00Z",
      "createdBy": { "id": "6b1d9f70-3c2a-4e8b-9a45-7f2c1d8e5b30", "name": "张三" },
      "createdAt": "2026-07-01T00:00:00Z"
    }
  ],
  "total": 12
  }
  ```

#### 1.12.1 获取项目状态数量

- **路径**：`GET /api/workspace/projects/counts`
- **请求头**：`X-Active-Workspace: <当前工作空间ID>`
- **请求参数**：`keyword`（可选，与列表接口使用相同的名称或描述匹配口径）
- **响应**：

  ```json
  {
    "active": 5,
    "archived": 1
  }
  ```

- **统计规则**：统计当前工作空间全部未删除项目，应用 `keyword`，忽略当前选中的 `status`；不得从当前分页列表推导数量。
- **权限**：仅当前工作空间成员可访问。

### 1.13 创建项目

- **路径**：`POST /api/workspace/projects`
- **权限**：所有工作空间成员均可创建；前端[新建项目]、[创建第一个项目]与网格末尾的新建卡片按权限码 `project:create` 显隐。
- **请求体**：`{ "name": "...", "description": "...", "startTime": "...", "endTime": "..." }`
- **校验**：`name` 必填（前端限 100 字符）且工作空间内唯一；`startTime` 不晚于 `endTime`；描述与起止时间可空。
- **响应**：201，返回创建的项目信息。

### 1.14 更新项目

- **路径**：`PUT /api/workspace/projects/:id`
- **权限**：空间管理员或项目创建者可操作（前端[编辑]按钮同口径，仅活跃项目显示）。
- **校验**：已归档项目不可编辑。

### 1.15 归档/启封项目

- **路径**：`POST /api/workspace/projects/:id/archive`
- **权限**：空间管理员。
- **请求体**：`{ "archived": true }`
- **校验**：归档前检查无进行中的计划。
- **处理**：若归档项目是任一用户的个人默认项目，自动清除；启封仅将状态恢复为 active。

### 1.16 删除项目

- **路径**：`DELETE /api/workspace/projects/:id`
- **权限**：仅空间管理员。
- **处理**：删除项目记录，并自动清除引用该项目的个人默认项目设置。

### 1.17 获取空间角色选项

- **路径**：`GET /api/workspace/roles`
- **权限**：`ws-member:view`（服务端 `@PreAuthorize`；工作空间角色权限由拦截器注入）。
- **说明**：返回全部 `type=workspace` 角色的扁平列表，供成员列表的角色标签、筛选和改角色下拉使用；空间侧页面不再访问 `/api/admin/roles`（安全规范 §3.1，见 `docs/00-spec/40-security/01-security.md`）。
- **响应**（`data`）：与 `GET /api/admin/roles` 相同的角色对象数组（`id`/`name`/`type`/`isSystem`/`userCount`）。
- **请求头**：需 `X-Active-Workspace`（上下文标识不进 URL，C4）。

### 1.18 搜索候选用户（添加成员）

- **路径**：`GET /api/workspace/members/candidates`
- **参数**：`keyword`（可选，匹配姓名或用户名后返回启用用户）。
- **权限**：`ws-member:manage`（服务端 `@PreAuthorize`）。
- **说明**：添加成员弹窗的用户远程搜索；空间侧替代 `/api/admin/users/simple`，仅返回 `id`/`name`，不返回邮箱。
- **响应**（`data`）：`[{ "id": "uuid", "name": "张三" }]`


## 2. 项目归档/删除联动

- 项目归档或删除时，系统自动遍历 workspace_user 表，将引用该项目的所有 default_project_id 置为 null。
- 被清除默认项目的用户在项目列表页将看不到默认高亮标识。


## 3. 邀请成员流程

### 3.1 直接添加流程

管理员在成员管理页面通过远程搜索选择平台已有用户（搜索防抖 300ms，匹配姓名、用户名或邮箱），可多选，提交后逐条插入 workspace_user，角色固定为预置 `workspace_member`（服务端在角色缺省时回退同一预置角色）。已在空间中的用户被跳过；提交成功后提示“成功添加 N 人”（含跳过人数说明）并刷新成员列表。

### 3.2 邀请链接流程

1. 管理员创建邀请链接，复制 URL 发送给目标用户。
2. 目标用户访问邀请链接，前端调用验证接口，展示工作空间信息和加入表单。
3. 用户输入邮箱后，前端调用 `POST /api/workspace/invitations/check-email`：
   - 邮箱已注册 → 显示密码输入框，提示用户输入密码验证身份。
   - 邮箱未注册 → 显示姓名和密码输入框，提示用户填写信息创建账号。
4. 用户提交表单后调用 `POST /api/workspace/invitations/join`：
   - 新用户 → 使用 `name`、`email`、`password` 创建用户 → 加入空间 → 生成 Token → 直接登录进入项目列表页。
   - 已有用户 → 验证密码 → 加入空间 → 生成 Token → 直接登录进入项目列表页。
   - 已在空间 → 提示“您已是该工作空间成员”，同时生成 Token 直接登录。
5. 整个流程无需跳转到登录页面，用户提交后即完成加入和登录；表单校验密码长度 8–64 字符，页面提供[返回登录]入口。


### 3.3 工作空间详情页

**路由**：`/workspace/:workspaceId`（菜单“空间信息”，权限码 `ws-info:view`，order 10）

通过顶部动态菜单“空间信息”进入。展示当前工作空间基础资料、创建人、成员数与项目数；具备 `ws-info:edit` 权限时可编辑名称和描述并保存。

**页面布局**：

```text
┌────────────────────────────────────────────────────────┐
│ 空间信息 · 空间基础资料与运行统计                       │
├────────────────────────┬───────────────────────────────┤
│ [成员 15 人]            │ [项目 5 个]                   │
├────────────────────────┴───────────────────────────────┤
│ 基础信息                                               │
│ 名称 [电商平台测试__________]  空间 ID [3f9a1c2e… 只读] │
│ 描述 [负责电商相关测试_________________________] 0/500  │
│ 创建人 张三                创建时间 2026-01-01 08:00    │
│                                          [保存修改]    │
└────────────────────────────────────────────────────────┘
```

**交互说明**：

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 查看成员 | 点击成员统计卡 | 跳转 `/workspace/members` |
| 查看项目 | 点击项目统计卡 | 跳转 `/workspace/projects` |
| 编辑信息 | 修改名称/描述 → [保存修改]（`ws-info:edit`） | 必填与 2–50 字符校验 → 提交 `PUT /api/workspace` → 成功提示“已保存”并同步顶栏空间名称；失败提示错误 |
| 无编辑权限 | 无 `ws-info:edit` | 名称、描述输入框禁用，不渲染[保存修改]按钮 |

**状态分支**：进入页面整页 loading；加载失败弹出错误提示，统计卡显示 0、创建人显示 `—`、创建时间显示为空；空间 ID 与描述字数为只读/上限展示。

### 3.4 成员管理页

**路由**：`/workspace/members`（菜单“成员管理”，权限码 `ws-member:view`，order 20）

页面视觉基准为 `web/demos/workspace/members.html`：页头之下左右并排展示“成员列表 / 邀请链接”两张内容卡片，两卡等高拉伸，表头与表尾对齐同一水平线；卡片即内容面板，不使用 `border-card`，也不额外嵌套 `el-card` 容器；卡片工具栏与表格之间以 1px 分割线分隔，卡片标题、工具栏、表格首列文字与分页对齐同一左基线（`--card-pad`），表格与卡片容器之间不留边距。桌面端页面沿内容白卡高度链路取固定视口高度，两卡填满该高度，数据超出时仅在表体内部纵向滚动，表头与分页保持固定；窗口宽度 ≤900px 时两卡纵向堆叠、高度不再固定并恢复页面级滚动，缺少邀请管理权限时只渲染成员列表卡片且占满整行。

```text
┌───────────────────────────────────────────────────────────────────────────────────────────┐
│ 成员管理                                             [邀请成员] [生成链接] [复制邀请链接] │
│ 管理空间成员与角色，通过邀请链接扩招                                                      │
├──────────────────────────────────┬────────────────────────────────────────────────────────┤
│ 成员列表 24 人                   │ 邀请链接                                               │
│ [姓名 / 邮箱] [全部角色 ▾]       │ 通过链接加入的成员按默认角色进入                       │
```

- 页头操作按层级排列：`邀请成员` 为主按钮（`ws-member:manage`），`生成链接` 为次按钮（`ws-invitation:manage`），`复制邀请链接` 为无边框快捷按钮（`ws-invitation:manage`）；三者按权限显示，邀请链接卡片内不重复放置生成按钮。
- 进入页面同时拉取角色选项、成员列表与邀请列表；邀请列表等待权限就绪后再判定，无邀请管理权限时不请求、不渲染邀请卡片。

**成员列表卡片交互说明**：

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 搜索成员 | 输入姓名/邮箱（占位“姓名 / 邮箱”） | 300ms 防抖后请求后端，保留角色筛选，页码重置为 1；清空立即刷新 |
| 筛选角色 | 选择真实空间角色（占位“全部角色”，可清空） | 页码重置为 1，刷新成员列表 |
| 邀请成员 | 点击页头[邀请成员] | 弹窗远程搜索（占位“输入姓名、用户名或邮箱搜索”，300ms 防抖）多选，默认成员角色；提交后提示成功/跳过并刷新列表 |
| 更新角色 | 点击[改角色] → 选择角色 | 角色标签切换为下拉框，选择后立即保存；成功提示“角色已更新”，失败提示错误并重新拉取列表 |
| 移除成员 | 点击[移除] | 二次确认；最后一位管理员禁止移除（服务端校验），成功后刷新列表 |
| 自行退出 | 点击自己行的[退出] | 确认后退出空间、清空活跃空间并跳转“我的空间” `/workspaces` |

- 表格列：用户（头像 + 姓名/用户名 + 邮箱副行）、角色、加入时间、操作（改角色 / 移除或退出，操作列固定右侧）；非管理员看到的邮箱为脱敏值。
- 空态与异常：加载失败显示“成员列表加载失败”与[重新加载]；有筛选条件显示“暂无符合条件的成员”；无筛选时按权限显示“暂无成员，点击右上角「邀请成员」邀请加入”或“暂无成员”。
- 分页：页脚“共 N 人 · 每页 20 条”，prev / pager / next（页码按钮最多 5 个）。

**邀请链接卡片交互说明**（卡片按权限码 `ws-invitation:manage` 显隐，数据侧另要求空间管理员）：

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 生成链接 | 点击页头[生成链接] | 设置过期时间（datetime，留空永不过期）、最大次数（1–10000，留空不限）→ 成功后“邀请链接已创建”弹窗展示完整 URL |
| 复制行链接 | 点击[复制]（有效、已达上限） | 调用按需复制接口获取完整 token → 拼接 `/join?token=` → 分享文案写入剪贴板；已过期、已失效为禁用态 |
| 复制邀请链接 | 点击页头[复制邀请链接] | 复制最近一个有效邀请；无可用链接时提示“暂无可复制的有效邀请链接” |
| 失效链接 | 点击[失效]（有效、已达上限） | 二次确认 → 状态变为“已失效”并刷新列表 |

- 表格列：邀请链接（`join/<tokenPreview>`）、使用次数（`7 / 20`，不限显示“不限”）、过期时间（空显示“永不过期”）、状态、创建时间、操作。
- 卡片标题为“邀请链接”，副文案“通过链接加入的成员按默认角色进入”；页脚“共 N 条 · 每页 20 条”；空态引导“暂无邀请链接，点击右上角「生成链接」创建第一个邀请”；加载失败显示“邀请链接加载失败”与[重新加载]。
- 列表仅返回 `tokenPreview` 和 `effectiveStatus`，完整 token 不随列表下发。
- `effectiveStatus` 区分有效、已达上限、已过期、已失效；仅有效状态参与页头快捷复制。


### 3.5 项目列表页

**路由**：`/workspace/projects`（菜单“项目列表”，权限码 `project:view`，order 30）

**交互说明**：

**状态分支**：

- 首次加载：6 张骨架卡片；刷新中：列表上方提示“正在刷新项目列表…”。
- 加载失败且无数据：错误态展示错误信息、“请检查网络连接后重试”与[重试]；已有数据时以列表上方横幅展示错误并可[重试]。
- 空间无项目且无筛选：欢迎引导空态；筛选无命中：“未找到匹配的项目”与[清除筛选]。
- 滚动加载：接近底部（IntersectionObserver，rootMargin 240px）自动追加下一页，展示“继续向下滚动加载更多项目 / 正在加载更多项目… / 没有更多项目”。
