## 1. 向量重建任务（管理端触发，基础设施已定义入口）

`embedding_rebuild` 任务由保存 AI 配置时自动创建（基础设施 3.3.2），无独立业务接口；该任务为**全局任务**（`workspace_id` / `project_id` 为空），不适用项目级通用任务接口（基础设施 3.5），进度查询与失败重试经管理端专用接口（基础设施 3.3.5），管理端配置页展示。

## 2. 向量全量重建任务（embedding_rebuild）

触发：向量基建首次上线（存量回填）、Embedding 模型或维度变更（基础设施 3.3.2 自动创建）。执行步骤：

1. 置 `semanticSearch = degraded`（任务存在即降级，无需额外标记）；
2. 维度变更时：`DROP INDEX idx_*_hnsw` → `TRUNCATE ai_bug_embedding / ai_case_embedding`（向量数据无保留价值，源数据可再生）→ `ALTER TABLE … ALTER COLUMN embedding TYPE vector(N)` → 重建 HNSW 索引（空表建索引，后续增量写入自动维护）；
3. 分批回填：逐项目扫描未关闭缺陷与全部 case 节点，批量 50 条文本/次调用 Embedding 批接口（`input` 数组），UPSERT；每批更新 progress（按对象总数比例）并检查取消；
4. 单条失败跳过并计数（留给 4.1 补偿任务兜底），失败率超 20% 任务置 failed；
5. 任务 success → 降级自动解除；任务 **failed / cancelled（含 AI 总开关关闭的联动取消）时向量数据不完整，语义检索维持 degraded**（基础设施 4.10 状态计算含「最近一次重建为 failed / cancelled」条件），由系统管理员经管理端重试接口（基础设施 3.3.5）重新发起，重试不限发起人。

重建执行期间 4.1 的增量写入与补偿任务跳过（重建互斥），成功后由补偿任务追平空窗期变更；重建 failed / cancelled 后互斥解除，补偿任务恢复运行并持续增量修复缺口，但 `degraded` 须待一次重建 `success` 才解除（状态解除以整库重建完成为准，不以补偿进度为准）。任务取消（管理员更换配置重新触发时旧任务先取消）遵循基础设施 4.6 协作式取消。
