## 1. 空间信息页面

**路由**：`/workspace/:workspaceId`

通过业务端顶部动态菜单[空间信息]进入。页面展示当前活跃工作空间的基础资料与已有统计信息，具备 `ws-info:edit` 权限的用户可编辑名称和描述。

> 视觉布局基准：`web/demos/workspace/info.html`。本次仅优化样式与信息排布，不扩展功能。Demo 中现有接口未提供的创建人、编辑模式、放弃修改、用例数、未关闭缺陷及趋势数据均不实现；统计区只展示当前接口已有的成员数和项目数，不使用占位数据。

### 1.1 页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 空间信息                                                    │
│ 空间基础资料与运行统计                                      │
├──────────────────────────────┬───────────────────────────────┤
│ [成员]                      │ [项目]                         │
│ 24 人                       │ 6 个                           │
├──────────────────────────────┴───────────────────────────────┤
│ 基础信息                                                     │
│ 名称 [质量中台________________]  空间 ID [ws_…____________]  │
│ 描述 [核心业务线质量保障与用例资产沉淀___________________]  │
│ 创建时间 2026-09-18 10:24                                   │
├──────────────────────────────────────────────────────────────┤
│                                      [保存修改]              │
└──────────────────────────────────────────────────────────────┘
```

- 页头标题、描述、间距和字号与演示稿一致。
- 成员、项目采用 KPI 卡片；卡片数据分别来自 `memberCount`、`projectCount`。
- 基础信息使用单张全宽卡片，不再限制为 720px 窄卡。
- 名称与空间 ID 桌面端双列、窄屏单列；空间 ID 只读并使用等宽字体。
- 描述使用多行输入框，创建时间作为只读元数据展示。
- 保留现有[保存修改]按钮及其权限、校验和反馈逻辑，仅将按钮移动至卡片底部操作区。

### 1.2 交互说明

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 编辑信息 | 具备 `ws-info:edit` 权限的用户修改名称或描述 | 输入项可编辑；无权限时保持禁用 |
| 保存 | 点击[保存修改] | 执行现有表单校验与保存接口，成功/失败沿用 Toast 反馈 |
| 加载 | 进入页面 | 保留现有加载遮罩 |
| 加载失败 | 空间信息请求失败 | 保留现有错误提示 |

### 1.3 视觉与状态要求

- 使用全局设计变量中的中性色、品牌色、阴影、圆角和间距，不硬编码主题色。
- KPI 卡片与基础信息卡均使用 1px Neutral-200 描边、低对比阴影和 8px 圆角。
- 页面标题 20px/650，说明文字 13px；KPI 数值使用 30px/650 和等宽数字。
- 输入框、按钮、禁用态沿用 Element Plus 现有行为，仅调整信息层级和布局。
- 窄屏下 KPI 卡片与表单双列区域降为单列，操作按钮允许换行。
- 尊重 `prefers-reduced-motion`，不在本页引入 JavaScript 滚动控制。

### 1.4 功能边界

- 不新增“编辑模式”状态及“放弃修改”操作。
- 不新增创建人、用例数、缺陷数或趋势统计。
- 不修改工作空间上下文初始化、权限判断、API 请求、表单规则或保存流程。
- 不修改服务端、数据库和路由契约。
