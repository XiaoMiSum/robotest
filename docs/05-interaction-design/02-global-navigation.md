# 软件测试平台——全局导航与菜单交互系统设计

**文档版本**：V1.0
**日期**：2026-09-23
**状态**：已发布

---

## 1. 概述

本文档定义软件测试平台的全局导航结构、菜单系统及核心交互流程。平台划分为两种顶层模式——**管理模式**和**业务模式**，业务模式进一步细分为**工作空间模式**和**项目模式**。业务模式采用统一的顶部导航栏 + 动态内容区布局；管理模式在顶部导航栏基础上增加**左侧分组侧栏**承载管理端菜单（见 3.1、7.1）。

## 2. 顶部导航栏布局

顶部导航栏固定高度48px，全平台统一，从左至右依次为：

| 位置     | 组件          | 说明             |
| ------ | ----------- | -------------- |
| 最左侧    | 平台Logo      | 固定显示，根据当前模式跳转对应首页：系统管理模式下进入系统管理数据概览，项目模式下进入项目仪表盘，其他情况进入工作空间列表 |

| Logo右侧 | 动态菜单区       | **仅业务模式**：根据当前模式/上下文动态变化；无活动工作空间时显示引导提示"请选择一个工作空间"。管理模式下顶栏不渲染动态菜单，Logo 右侧改为「系统管理」模式标签，菜单移至左侧分组侧栏（见 3.1） |

| 右侧     | 我的项目（图标+文字） | 默认隐藏，进入项目后显示   |

| 右侧     | 消息通知（图标+文字） | 始终显示，未读红点      |
| 右侧     | 用户头像+名称     | 始终显示，下拉菜单含修改密码、退出登录   |

> 下表中 emoji 仅为图标示意标记，实际实现使用 Element Plus 图标库对应图标（与全局智能助手交互设计 9.11 措辞一致：正文 ASCII 示意图中的 emoji 仅为标记，不引入 emoji 图标）。

| 图标   | 功能                 | 始终可见 | 说明                   |

## 3. 模式与动态菜单映射

### 3.1 管理模式

**触发**：点击"🔧 系统管理"图标（需 `hasSystemPermission`）。

| 元素   | 状态变化               |
| ---- | ------------------ |
| 顶栏 | Logo 右侧显示「系统管理」模式标签；顶栏动态菜单区不渲染；「🔧 系统管理」高亮激活态 |
| 左侧分组侧栏 | 显示管理端菜单，按分组呈现：**概览**（数据概览，置顶无分组标题）→ **组织与权限**（用户管理、角色管理、空间管理）→ **平台配置**（AI 配置）；菜单项按权限过滤，无权限项不展示，过滤后为空的分组整体隐藏 |
| 主内容区 | 渲染管理模式内容区（系统管理功能页面，路由切换） |

> 管理端菜单与业务顶栏动态菜单共享同一注册表：路由注册时声明菜单元信息（名称、图标、排序、分组、权限码），导航层按当前模式取回并过滤（机制见 `docs/03-architecture/03-navigation-architecture.md`）。

### 3.2 工作空间模式

**触发**：通过"我的空间"页面选中一个空间。

| 元素   | 状态变化               |
| ---- | ------------------ |
| 动态菜单 | 切换为：空间信息、成员管理、项目列表 |
| 空间管理 | 显示（需 `hasWorkspaceAccess`） |
| 主内容区 | 渲染工作空间面板（空间管理功能页面） |

### 3.3 项目模式

**触发**：在工作空间面板中通过项目列表进入具体项目。

| 元素   | 状态变化            |
| ---- | ------------------- |
| 动态菜单 | 切换为：功能测试、缺陷管理、接口测试 |
| 主内容区 | 渲染项目面板（项目内功能页面） |

> 功能测试为顶部菜单入口，页面内部采用侧边栏布局组织子模块（测试用例、测试评审、测试计划、需求池）。接口测试同为顶部菜单入口，页面内部侧边栏组织子模块，并在侧边栏末尾提供「项目设置」分组（平台级框架，见 3.5）。

### 3.4 未选中空间

| 元素   | 状态变化              |
| ---- | ------------------ |
| 动态菜单 | 显示引导提示"请选择一个工作空间" |

### 3.5 项目设置（平台级框架）

各业务域页面内部侧边栏**末尾**统一提供「项目设置」分组，作为平台级项目配置入口。设置框架由平台层统一建设，各业务域共享同一入口与权限模型：

| 规则 | 说明 |
| ---- | ---- |
| 域归属过滤 | 每个配置项标注业务域归属（`common` 通用 / `api_test` 接口测试 / `func_test` 功能测试）；侧边栏仅展示 `common` 与当前业务域归属的配置项，其他业务域专属项不可见、不可改，跨域配置互不干扰 |
| 路由前缀 | `/workspace/projects/settings/*`，跨业务域一致；前端路由与后端 API 路径相互独立 |
| 权限 | 查看为项目成员；维护（增删改）为项目维护者 |
| 分组呈现 | 分组标题「项目设置」固定位于侧边栏末尾，以分隔线与业务功能区分隔 |

接口测试域在项目设置下展示配置项：环境管理（`/workspace/projects/settings/environments`）、全局资产（`/workspace/projects/settings/assets`）。框架规则见《项目设置交互设计》（`docs/05-interaction-design/01-readme.md`）；环境管理、全局资产的页面交互见各自分册。

## 4. 核心交互流程

### 4.1 登录后跳转

```
用户登录成功
  → 检查 hasWorkspace 字段
  → 若 hasWorkspace=true：跳转至 /workspaces（我的空间页面）
  → 若 hasWorkspace=false：
      → 检查 hasSystemPermission（拥有任意系统权限）
      → 若 true：跳转至 /admin/dashboard（系统管理数据概览）
      → 若 false：跳转至 /workspaces（我的空间页面）
```

### 4.2 进入管理模式

```
点击「🔧 系统管理」图标（需 hasSystemPermission）
  → 路由跳转至 /admin/dashboard
  → 顶栏 Logo 右侧切换为「系统管理」模式标签，动态菜单区不渲染
  → 左侧分组侧栏渲染管理端菜单（按权限过滤）：
      概览：数据概览（置顶）
      组织与权限：用户管理、角色管理、空间管理
      平台配置：AI 配置
  → 主内容区渲染管理模式内容区（随路由切换页面）
```

### 4.3 选择工作空间

```
点击[我的空间]
  → 路由跳转至 /workspaces
  → 页面以卡片网格展示当前用户归属空间
  → 支持名称检索、范围筛选、最近访问排序与分页
  → 点击活跃空间卡片
  → 通过 X-Active-Workspace 记录目标空间并设置活跃空间 ID
  → 有默认项目时进入项目仪表盘，否则进入项目列表
  → 动态菜单切换为：空间信息、成员管理、项目列表
  → 显示[空间管理]入口（需 hasWorkspaceAccess）
```

已归档卡片只读，不进入选择流程。

### 4.4 进入项目

```
在工作空间面板中点击某项目（或通过项目选择页进入）
  → 动态菜单切换为：功能测试、缺陷管理、接口测试
  → 主内容区渲染项目面板
  → 功能测试内部侧边栏子模块：测试用例、测试评审、测试计划、需求池
  → 接口测试内部侧边栏子模块：快速调试、接口管理、Mock 服务、测试场景、接口测试报告、定时任务 + 「项目设置」分组（见 3.5）
```

### 4.5 返回空间

```
点击「⚙ 空间管理」图标 或 动态菜单中的「项目列表」
  → 退出项目面板
  → 动态菜单恢复为：空间信息、成员管理、项目列表
  → 主内容区恢复工作空间面板
```

### 4.6 从管理模式返回业务模式

```
在管理模式下点击「📁 我的空间」选择空间
  → 退出管理模式
  → 恢复对应业务模式的菜单和图标状态
  → 取消「🔧 系统管理」高亮
```

## 5. 页面设计

### 5.1 我的空间页面

**路由**：`/workspaces`

**触发**：点击顶部导航栏[我的空间]。

**页面布局**：以 `web/demos/workspace/list.html` 为基准。页头展示标题、说明与按权限显隐的[新建空间]；工具栏提供名称搜索、“全部 / 我管理的 / 已归档”分段筛选及最近访问排序说明；主体使用工作空间卡片网格，末尾在有创建权限时展示虚线创建卡片。详细设计见 `docs/05-interaction-design/16-space-ui-my-workspace.md`。

**数据与分页**：后端接口 `GET /api/workspaces` 支持 `keyword`、`scope`、`pageNo`、`pageSize`，返回当前范围列表、总数及三个范围计数。前端默认每页 20 条，超过单页容量时显示 Element Plus 分页器。

**卡片交互**：

- 每张卡片显示空间名称、描述、真实角色名称、成员数、项目数、用例数与归档状态；预置角色显示“管理员/成员”，不显示“我管理”。
- 当前活跃空间卡片有明确活跃态标识；已归档卡片只读且不可进入。
- 点击活跃卡片：设置活跃空间ID与角色，并通过 `X-Active-Workspace` 记录最近访问 → 有默认项目时进入项目仪表盘，否则进入项目列表。
- 卡片使用可聚焦按钮，支持 Enter/Space；检索、筛选与分页状态相互保持。

### 5.2 消息通知弹窗

**触发**：点击“🔔 消息”图标。

**内容**：下拉面板展示最近通知列表，点击可查看详情或标记已读。

## 8. 状态管理

全局导航状态通过 Pinia store 统一管理：

- **currentMode**：'admin' | 'workspace' | 'project' | 'none'——当前所处的顶层模式，**由当前路由 `meta.mode` 派生**（命令式切换会造成路由与模式双真相源漂移，已废弃）
- **activeWorkspaceId**：当前活跃空间ID
- **activeProjectId**：当前活跃项目ID
- **workspaceList**：用户归属空间列表（分页缓存）
- **dynamicMenuItems**：业务模式顶栏菜单——按 currentMode 从路由注册表取菜单元信息，再按权限过滤、按 order 排序
- **adminSidebarSections**：管理模式左侧侧栏——同一路由注册表按 section 连续分组，权限过滤后为空的组不产生
- **visibleIcons**：根据 currentMode 计算属性控制各图标的显隐和高亮

各图标组件通过响应式状态控制显隐和高亮，动态菜单与侧栏菜单均由路由注册表派生（机制见 `docs/03-architecture/03-navigation-architecture.md`）。
