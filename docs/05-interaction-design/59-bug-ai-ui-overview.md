## 1. 总体布局

AI 能力嵌入缺陷管理既有页面，均随 `aiEnabled` 显隐：

| 页面 | 新增内容 |
| ---- | ---- |
| 缺陷新建/编辑表单 | 标题输入框内嵌 [✨AI 建议] 按钮；点击后标题下方展示 AI 结果面板（建议 + 疑似重复缺陷合一） |
| 缺陷看板页 | [✨AI 分析] 聚类分析抽屉 |

> **零影响约束（通用规范 2.7）**：AI 建议区、聚类分析抽屉均为既有缺陷表单/看板的附加区域；`aiEnabled = false` 时全部隐藏，表单字段布局与看板回退 V1.0 形态。建议/查重为异步非阻塞（不占用提交按钮、不校验其结果），AI 失败或降级时缺陷创建、编辑、流转等既有主流程完全不受影响。

## 5. 通用交互模式总结

### 5.1 弹窗类型

| 类型 | 使用场景 |
| ---- | ---- |
| 抽屉 | 疑似重复缺陷的详情查看（不离开表单）；聚类分析（右侧滑出，无遮罩，不阻断列表操作） |
| Toast | 建议调用失败轻提示、限流提示 |

### 5.2 加载状态

- 同步建议：按钮 loading，不阻塞表单；
- 查重随 [AI 建议] 触发：面板查重区独立 loading（结果渐入），不阻塞表单；
- 异步聚类：进度条 + 轮询，离开页面任务不中断。

### 5.3 非侵入原则

本域全部 AI 能力（建议、查重、聚类）均为建议/洞察性质：不弹模态窗、不阻塞输入与提交、不自动修改数据；失败仅轻提示，缺陷业务主流程完全不受影响。
