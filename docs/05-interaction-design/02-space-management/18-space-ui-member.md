## 1. 工作空间成员管理

**路由**：`/workspace/members`

通过业务端顶部动态菜单[成员管理]进入，所有数据与操作均作用于当前活跃工作空间。

> 视觉与可见交互基准：`web/demos/workspace/members.html`。页头之下左右并排展示“成员列表 / 邀请链接”两张内容卡片，两卡等高拉伸，表头与表尾对齐同一水平线；卡片即内容面板，不使用 `border-card`，也不额外嵌套外层容器卡片。

### 1.1 页面整体结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 成员管理                        [复制邀请链接][生成链接][邀请成员] │
│ 管理空间成员与角色，通过邀请链接扩招                        │
├────────────────────────────────┬─────────────────────────────┤
│ 成员列表 24 人   [姓名 / 邮箱] [全部角色 ▾] │ 邀请链接 3 条              │
│ 用户    角色    加入时间   操作            │ 链接    使用次数  状态   操作│
│ 张三    [管理员] 2026-01-15  改角色 移除   │ join/8f3a… 7 / 20  有效  复制│
│ …                                        │ …                           │
├────────────────────────────────┴─────────────────────────────┤
│ 共 24 人 · 每页 20 条                              [1] [2] [›] │
└──────────────────────────────────────────────────────────────┘
```

- 页头展示标题、说明和操作按钮，操作按钮按权限显示。
- 两张卡片按栅格并排（各占一列）并等高拉伸，表头与表尾对齐同一水平线；卡片由标题区、工具栏与表格区组成，分页贴卡片底部，卡片以 1px 边框、圆角与浅阴影区分内容域；不使用 `border-card`，不嵌套 `el-card` 容器，卡片内沿用表格、加载、空态及分页能力。
- 桌面端页面沿内容白卡的高度链路取固定视口高度，两卡填满该高度；数据超出可视区时仅在表体内部纵向滚动，页面不产生外层滚动条，表头与分页保持固定不动。
- 卡片标题右侧展示辅助说明：成员卡片为成员总数，邀请卡片为“通过链接加入的成员按默认角色进入”。
- 卡片工具栏与表格之间以 1px 分割线分隔；卡片标题、工具栏、表格首列文字与分页对齐同一左基线（卡片内边距 `--card-pad`）。表格与卡片容器之间不留边距，表格贴合卡片左右边缘。
- 卡片载入使用淡入上移过渡动画（设计令牌 `--transition-base`），动画遵循 `prefers-reduced-motion: reduce` 关闭。
- 页头操作按层级排列：`邀请成员` 为主按钮，`生成链接` 为描边次按钮，`复制邀请链接` 为无边框快捷按钮；三者按权限显示，邀请链接卡片内不重复放置生成按钮。
- 窄屏时两卡纵向堆叠，筛选器换行，表格允许横向滚动，页头按钮允许换行，页面恢复整体滚动。
- 普通后端时间和邀请链接 `expiresAt` 统一使用 `formatDateTime` 展示；邀请链接创建时提交无时区墙钟值，由后端持久化适配层统一转换为 UTC。

### 1.2 成员列表卡片

```text
┌──────────────────────────────────────────────────────────────┐
│ 成员列表 24 人                  [姓名 / 邮箱] [全部角色 ▾]   │
├──────────────┬──────────┬──────────────┬─────────────────────┤
│ 用户         │ 角色     │ 加入时间     │ 操作                │
├──────────────┼──────────┼──────────────┼─────────────────────┤
│ 头像 姓名    │ [角色]   │ 时间         │ 改角色  移除        │
│      邮箱    │          │              │                     │
├──────────────┴──────────┴──────────────┴─────────────────────┤
│ 共 24 人 · 每页 20 条                              1  2  ›   │
└──────────────────────────────────────────────────────────────┘
```

#### 筛选与搜索

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 搜索成员 | 在“姓名 / 邮箱”输入关键字 | 300ms 防抖后请求后端；清空输入立即刷新 |
| 筛选角色 | 选择具体空间角色 | 页码重置为 1 并立即刷新 |
| 重置筛选 | 清空关键字或选择“全部角色” | 保持两项条件实时组合生效 |
| 分页 | 切换页码 | 保留当前关键字和角色条件 |

#### 成员操作

| 操作 | 权限 | 交互与反馈 |
| ---- | ---- | ---- |
| 邀请成员 | `ws-member:manage` | 点击页头[邀请成员]打开远程搜索、多选弹窗；搜索防抖 300ms |
| 确认邀请 | `ws-member:manage` | 新成员默认使用预置成员角色；成功提示成功与跳过数量 |
| 改角色 | `ws-member:manage` | 角色列平时显示真实角色标签；点击[改角色]后切换为下拉框，选择后立即保存 |
| 取消改角色 | `ws-member:manage` | 关闭下拉框不修改原角色 |
| 移除成员 | `ws-member:manage` | 点击[移除]后二次确认；最后一位管理员禁止移除 |
| 自行退出 | 所有当前成员 | 自己一行显示[退出]；确认后退出空间并返回“我的空间” |

- 用户头像优先使用 `avatarUrl`，无头像时使用用户名首字符。
- 管理员角色使用品牌色标签，其他角色使用中性色标签；名称来自真实角色列表。
- 普通成员查看时邮箱沿用后端脱敏结果，不在前端自行推断敏感信息。

### 1.3 邀请链接卡片

仅具备 `ws-invitation:manage` 权限时显示。

```text
┌──────────────────────────────────────────────────────────────┐
│ 邀请链接  通过链接加入的成员按默认角色进入       [生成链接] │
├──────────────┬──────────┬──────────┬──────┬──────────┬──────┤
│ 邀请链接     │ 使用次数 │ 过期时间 │ 状态 │ 创建时间 │ 操作 │
├──────────────┼──────────┼──────────┼──────┼──────────┼──────┤
│ join/8f3a…  │ 7 / 20   │ 时间     │ 有效 │ 时间     │复制 失效│
└──────────────┴──────────┴──────────┴──────┴──────────┴──────┘
```

#### 状态与操作

| 有效状态 | 展示 | 复制 | 失效操作 |
| ---- | ---- | ---- | ---- |
| `active` | 绿色“有效” | 可用 | 可用 |
| `exhausted` | 中性色“已达上限” | 可用 | 可用 |
| `expired` | 红色“已过期” | 禁用 | 隐藏 |
| `revoked` | 中性色“已失效” | 禁用 | 隐藏 |

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 生成链接 | 点击[生成链接] | 设置过期时间和最大次数；创建成功后展示完整 URL 及复制按钮 |
| 复制行链接 | 点击有效或已达上限行的[复制] | 按需获取完整 token → 复制工作空间、完整 URL 与加入说明 → Toast 提示 |
| 复制邀请链接 | 点击页头[复制邀请链接] | 复制最近一个有效邀请及描述信息；无可复制链接时明确提示 |
| 失效链接 | 点击[失效] | 二次确认后撤销，状态变为“已失效” |
| 查看列表 | 查看邀请链接卡片 | 展示脱敏链接预览，不在列表响应中下发完整 token |

- 列表中的链接只显示 token 前后片段。
- 状态列使用固定列宽，不随表格剩余空间拉伸；其余列按 `min-width` 分配余量。
- 所有邀请复制入口统一写入以下纯文本结构，工作空间名称缺失时使用“当前工作空间”：

  ```text
  【RoboTest 工作空间邀请】
  工作空间：质量中台
  邀请人：qa-admin
  邀请链接：https://example.com/join?token=...
  说明：打开链接后按页面提示完成身份验证并加入工作空间。
  ```

- 邀请人使用当前登录用户的 `username`；该字段不新增后端响应，也不代表历史邀请的实际创建者。
- 已达使用上限的邀请在说明中追加上限提醒；弹窗继续展示原始 URL。
- 完整 token 仅在创建成功响应或用户明确点击复制时返回给有权管理员。
- 已过期和已失效链接不得通过复制接口重新获取完整 token。
- 达到使用上限但未过期的链接按 Demo 允许复制，但页头快捷复制只选择 `active` 状态。

### 1.4 权限与异常状态

- 无 `ws-member:manage` 权限时隐藏[邀请成员]、[改角色]和他人行的[移除]。
- 无 `ws-invitation:manage` 权限时隐藏页头[复制邀请链接]及整个邀请链接卡片，页面只展示成员列表卡片并占满整行。
- 页面挂载即同时加载角色选项、成员列表与邀请链接列表；权限列表异步拉取时先等其就绪再判定是否请求邀请列表，避免硬刷新或深链进入时漏拉。
- 加载期间保留表格加载遮罩；空列表使用统一空态组件展示，不使用纯文字占位。
- 成员列表空态区分筛选是否命中：有筛选条件时提示「暂无符合条件的成员」并保留当前筛选条件；无筛选条件时提示「暂无成员」，具备 `ws-member:manage` 时附「点击右上角「邀请成员」邀请加入」引导。
- 邀请链接列表空态提示「暂无邀请链接，点击右上角「生成链接」创建第一个邀请」。
- 搜索无结果时保留当前筛选条件并展示空表，不重置为全部数据。
- 接口失败使用 Toast 提示；列表请求失败且无数据时，空表进一步展示加载失败空态与[重新加载]按钮，避免失败被误读成「无数据」。成员请求和用户搜索需丢弃过期响应，避免慢请求覆盖新结果。
- 复制、失效、退出等操作按钮在请求期间避免重复触发。

### 1.5 数据与安全边界

- 成员列表支持 `keyword`、`workspaceRole`、`pageNo`、`pageSize`。
- 邀请链接列表返回 `tokenPreview` 与 `effectiveStatus`，不返回完整 token。
- 完整 token 通过管理员专用按需复制接口获取，并校验邀请链接属于当前活跃空间。
- 所有上下文标识继续通过 `X-Active-Workspace` 请求头传递，不出现在页面 URL 或请求体。
- 不新增数据库表或索引；角色筛选复用现有 `(workspace_id, workspace_role)` 索引。
