**文档版本**：V1.0  
**日期**：2026-11-25  
**状态**：起草中

---

## 1. 概述

AI 任务中心是项目内全部 AI 任务的统一入口，任务统一经 `POST /api/ai/tasks` 提交、`GET /api/ai/tasks/{id}` 查询，执行过程经轨迹接口（`GET /api/ai/tasks/{id}/executions/{executionId}/events`）与实时通道呈现；任务详情展示执行过程、计划步骤、轨迹，并提供提案产物与审核结果的只读查看，不提供任何审核操作。提案的采纳、编辑后采纳与驳回统一在各业务面板完成：需求导入在需求管理页的导入结果审核区（见 `docs/05-interaction-design/03-function-testing/07-requirement-ui.md`），AI 评审在评审详情页 AI 评审面板（见 `docs/05-interaction-design/03-function-testing/05-workspace-ui-test-review.md`），用例优化与脑图生成用例在脑图面板（见 `docs/05-interaction-design/07-ai-capability/07-assisted-features-ui.md`）。执行编排归 AI、写库编排归应用层的双平面机制见 `docs/02-high-level-design/07-ai-capability/03-hld-ai-task.md`。

**路由**：任务中心 `/workspace/projects/ai/tasks`；任务详情 `/workspace/projects/ai/tasks/:taskId`（任务中心的子路由）

**入口**：不占顶部动态菜单，由顶部导航栏常驻的 AI 任务指示器承载——项目模式下常驻显示（不占动态菜单位、不按权限码过滤），角标展示进行中（`running`）任务数，点击进入本页，供用户感知并回看任务进度（导航布局见 `docs/05-interaction-design/02-global-navigation.md` §2）。

AI 未启用或未配置模型时，任务入口与本页内容按总册 4.5 隐藏或降级提示。

| 区块 | 交互 |

- 空态：无任务 → 「暂无 AI 任务」+ 各能力入口引导；

```
│ 步数 23/40 · 时长 94s · tokens 4600/200000                         │

├──────────────────────────────────────────────────────────────────┤
│ 计划步骤（AI 规划，随轨迹更新）                                     │
│  ● 解析需求   ● 生成模块结构   ◐ 生成脑图文档                      │
│  ○ 标记用例节点  ○ 填充用例属性                                    │
├──────────────────────────────────────────────────────────────────┤
│ 轨迹：展开查看决策、工具调用与结果摘要（游标增量 / 实时推送）        │
│ 提案与结果（只读）：沿用审核面板信息布局，展示提案产物、确认状态、    │
│                   驳回原因与采纳结果；上一个/下一个切换，无审核按钮   │
└──────────────────────────────────────────────────────────────────┘
```

| 区块 | 交互 |
| ---- | ---- |
| 面包屑 | 内容区顶部「AI 任务中心 › 任务详情」：点「AI 任务中心」回列表（筛选与页码保活），「任务详情」为当前页项不可点，遵循《面包屑导航规范》（`docs/00-spec/50-ui/05-breadcrumb.md`，UI-BC-01）；从能力页跳转而来时经浏览器返回恢复来源页上下文 |
| 任务标题 | 面包屑与页头展示 `title`（创建时生成，存量空则按类型名兜底），超长省略 + tooltip |
| 任务级结果 | `closed` 态在状态徽标旁展示聚合标识：全部采纳「已采纳」、全部驳回「已驳回」、混合「部分采纳」，由 `proposals[].confirmStatus` 派生（`pending / not_applicable` 不参与统计） |
| 执行区 | 步数与预算消耗、当前步骤、终止原因与错误码；按 `GET /api/ai/tasks/{id}` 2 秒轮询，仅 `running`（进行中）继续，状态非进行中即停止 |
| 计划步骤 | 展示 AI 在执行开始产出的计划步骤快照（`plan`，可见思考产物）：当前步骤高亮、完成步骤打勾、终止原因标红；步骤由 AI 自主规划，不承诺固定序列 |
| 轨迹区 | 「展开轨迹」按游标增量拉取（`events?afterSeq=`），实时通道推送时即时合并；轨迹只增不改，可回看与复制 |
| 决策详情展开 | 点击「AI 决策」事件行展开详情区，分「请求摘要 / 模型响应」两段，复用折叠 JSON 展示与复制；数据来自 `detail.rawRequest` / `detail.rawResponse`，不另发请求；字段缺失或为空展示「暂无原始数据」空态 |
| 模型响应 content | 先尝试解析为 JSON（含剥离 Markdown 代码围栏后重试）：成功按结构化节点折叠展示，失败保留原文字符串；只处理顶层 `content`，存储仍为原文、不截断；复制按钮复制展示内容，所见即所得 |
| 操作 | `running` 可终止（二次确认）；`aborted` 可再次执行（产生新执行实例与新提案）；`proposals_ready` / `closed` 均可查看提案产物与审核结果，但不渲染采纳 / 驳回 / 编辑后采纳等审核动作，提案处置入口在对应业务面板。`case_optimize` / `mindmap_case_generation` / `review_case_review` 三类任务仅 `aborted` 态显示「再次执行」，`running` / `proposals_ready` / `closed` 不显示 |
| 提案与结果 | 有提案时渲染只读审核面板（见 2.3），展示提案产物、确认状态、驳回原因与采纳结果；支持上一个/下一个切换，不提供审核操作；`aborted` 且无提案时不渲染 |

### 2.3 提案与审核结果只读查看（AiProposalReviewPanel 只读模式，页内渲染）

任务详情页下半区复用 `AiProposalReviewPanel` 的信息展示结构：同一套提案头、导航、明细字段、对比、来源引用与警示渲染；任务详情仅关闭审核操作（采纳、修改后采纳、驳回、回执、编辑弹窗）。待处置任务的实际审核在对应业务面板完成。

```
┌──────────────────────────────────────────────────────────────────┐
│ 需求导入 / 用例优化 / ...                       已处理 N / 共 M     │
│ [上一个] 第 2 / 3 条 [下一个]                                      │
│ 需求建议  登录验证码                                   [待采纳]     │
│ 模块/来源/描述/字段/对比/排序/来源引用/警示（按需加载）              │
│ （只读查看，无审核操作按钮）                                       │
└──────────────────────────────────────────────────────────────────┘
```

| 区块 | 交互 |
| ---- | ---- |
| 面板头 | 复用 `AiProposalReviewPanel` 头部信息：任务类型标题、已处理/共计；只读模式不显示操作入口 |
| 导航 | 多条提案时显示“上一个 / 下一个”与当前位置；切换时按 `proposalKey` 按需加载当前提案完整内容，已加载内容缓存复用 |
| 产物明细 | 复用同一面板的明细区域：`kind`、标题、确认状态、驳回原因、描述、结构化字段、来源引用、既有 vs 建议对照、排序项与警示标记；描述按 Markdown 只读渲染，与需求导入审核区共用同一展示组件 |
| 只读边界 | 不渲染采纳、编辑后采纳、驳回、批量选择、确认回执、编辑弹窗等动作；`proposals_ready` 状态仅表示业务面板仍可处置，详情页同步展示待采纳状态与产物 |
| 状态分支 | 明细加载中局部 loading；加载失败提示并提供重试，不阻塞其他提案；内容为空展示「暂无明细」 |

### 2.4 状态分支

- 详情页加载：骨架屏；任务不存在或不属于当前项目 → 404 提示 + 返回任务中心；
- 任务终止：详情页展示终止原因与错误码（用户中止 / 预算耗尽 / 执行错误），再次执行产生新执行实例与新提案；`case_optimize` / `mindmap_case_generation` / `review_case_review` 三类任务仅 `aborted` 态提供再次执行，`proposals_ready` / `closed` 的原任务保留只读查看，重新发起在业务入口按原输入新建任务；
- 任务待采纳：展示提案产物与审核结果（待采纳状态），可展开查看明细；详情页不提供审核动作，实际处置在对应业务面板完成；
- 任务已结束：展示任务级结果标识与只读提案回看卡片区，逐条标记已采纳 / 已驳回并展示驳回原因与产物明细；
- 无提案：不渲染提案回看区；`proposals_ready` 空提案显示空态说明，`closed` / `aborted` 按无提案处理；
- 明细加载失败：卡片内提示并提供重试，已加载明细保留缓存。

## 3. 核心交互流程

### 3.1 任务生命周期

```mermaid
flowchart LR
  R[running 执行中] --> W[waiting_confirmation 挂起]
  W --> R
  R --> P[proposals_ready 待采纳]
  R --> A[aborted 已终止]
  W --> A
  A -- 再次执行 --> R
  P --> C[closed 已结束]
```

> 状态非 `running`（进行中）即停止详情轮询；心跳超时或预算耗尽的执行由服务端清扫置 `aborted`（1000018117 / 1000018127），前端以最新查询结果为准。

### 3.2 执行过程与提案回看时序

```mermaid
sequenceDiagram
  participant U as 用户
  participant P as 能力页面
  participant T as AI 任务
  participant D as 任务详情页
  U->>P: 发起 AI 操作（导入 / 生成 / 分析）
  P->>T: 提交任务，返回 taskId + executionId
  P->>D: 跳转 /workspace/projects/ai/tasks/:taskId
  loop 2s 轮询至执行终态（轨迹并行增量拉取 / 实时通道推送）
    T-->>D: status / 步数与预算消耗 / plan
  end
  D-->>U: 执行区展示（可终止）
  T-->>D: proposals_ready
  D-->>U: 展示提案产物与审核结果（只读）
  U->>D: 展开提案卡片查看产物明细
  D->>T: 首次展开按 proposalKey 获取完整产物明细
```

## 4. 视觉与状态要求

- 计划步骤与执行区高亮：`--color-primary-500` 体系；完成步骤 `--color-success`、终止标红 `--color-danger`、挂起 `--color-info`、已结束中性灰 `--color-neutral-400`；
- 状态徽标与终止原因悬浮层遵循《视觉设计》4.1 状态色与中性色体系；
- 提案明细警示标记用 `--color-warning`（疑似重复）与 `--color-danger`（来源已变更）图标 + 文字，不单靠颜色表意。

## 5. 状态管理

- Pinia store `aiTask`：任务详情 2 秒轮询（`GET /api/ai/tasks/{id}`），仅 `running`（进行中）继续，状态非进行中即停止，随详情页路由进入/离开启停；轨迹事件增量拉取（`events?afterSeq=`，实时通道推送时即时合并）；任务中心列表与筛选条件；顶栏指示器进行中任务数（`GET /api/ai/tasks/running-count`，15 秒轮询，仅项目模式时装载、不按权限码过滤，任务提交/终止/再次执行后即时刷新）；
- 跨页面任务进度联动：能力页通过 `aiTask` 订阅自己提交的 `taskId`，跳转详情页后由详情页接管轮询，返回来源页时回调刷新来源列表；
- 提案与审核结果回看卡片的展开态与已加载产物明细存组件本地，离开详情页释放；提案确认状态与 `note`（驳回原因）随详情一并缓存供只读查看；已加载项重复展开不重复请求。
