# 软件测试平台——AI 缺陷分析

**文档版本**：V1.0  
**日期**：2026-10-03  
**状态**：起草中

---

## 1. 概述

缺陷分析面向缺陷管理模块提供新建缺陷实时建议，其中一并给出重复缺陷检测（`docs/01-requirements/07-ai-capability/05-srs-ai-defect-analysis.md`）。承载形态为新建缺陷表单建议区。建议入口对项目成员常驻可见，不按权限码过滤；建议与检测范围限于当前项目。视觉遵循《视觉设计》（`docs/05-interaction-design/03-visual-design.md`）。

## 2. 页面设计

### 2.2 新建缺陷表单建议区

| 组件 | 交互 |
| ---- | ---- |
| 「AI 建议」入口按钮 | 挂在提交缺陷页标题输入框尾部（append，图标 + 「AI 建议」）：AI 未启用时不渲染挂载内容、输入组按无 append 形态收口；标题为空时禁用置灰，填入标题后启用并以呼吸光晕 + 魔棒微晃作闪烁提示；点击发起实时建议 **SSE 流式请求**（按钮转 loading 至连接关闭，期间无总超时，后端 15s 心跳保活），按标题 / 已填重现步骤 / 所属模块一次性返回全部建议与疑似重复缺陷；请求失败或流中断轻提示原因且不阻塞录入，可再次点击重试 |
| SuggestBadge | 基于标题（及已填重现步骤、所属模块），为优化后标题、重现步骤、缺陷类型、严重等级、优先级、所属模块、关联用例、关键词给出建议值，行内标记展示（标题建议挂标题输入框下方、重现步骤建议挂编辑器下方、关联用例建议挂「选择用例」按钮旁，其余沿用侧栏表单项行内）；点击一键采纳；用户已填值与建议不一致时以用户值为准，不覆盖（标题与重现步骤经点击采纳后写入，属用户主动动作） |
| DuplicateSuggestList | 建议区内展示同请求返回的疑似重复缺陷（短 ID、标题、状态、相似依据，按相似度排序），点击短 ID 跳转查看；无命中或向量未就绪时不渲染列表、不作提示；检测结果仅作建议，不自动合并、不改状态 |

### 2.3 状态分支

- **向量未就绪或请求失败**：`duplicates` 为空，不渲染列表、不作提示，字段建议照常展示；
- **无命中**：不渲染列表，字段建议照常展示；
- **实时建议失败**：轻提示失败原因，不自动重试，用户可再次点击「AI 建议」触发；不影响表单其余填写与提交；失败含三种形态——流建立前同步校验失败（输入非法 / 无可用模型）、流内 `error` 事件（模型调用失败）、**连接中断**（网络断开或中间层断连，loading 结束并提示可重试）；
- **AI 未启用**：入口隐藏（总册 4.5）。

## 3. 核心交互流程

### 3.1 新建缺陷建议（含重复缺陷检测）

```mermaid
sequenceDiagram
  participant U as 用户
  participant F as 新建缺陷表单
  participant S as 建议服务
  U->>F: 填写标题后点击「AI 建议」
  F->>S: 一次 SSE 请求（标题 / 已填重现步骤 / 所属模块）
  S->>S: 装配模块与用例候选，检索同项目相似缺陷
  S-->>F: progress（可选）
  alt 建议生成成功
    S-->>F: done（字段建议 + 疑似重复缺陷）
    alt 存在疑似重复
      F-->>U: 建议区内渲染列表（短 ID / 标题 / 状态 / 相似依据）
      U->>F: 点击跳转查看 / 采纳建议继续填写
    else 无命中或向量未就绪
      F-->>U: 不渲染列表，字段建议照常展示
    end
  else 前置校验失败 / 流内 error / 连接中断
    S-->>F: 同步错误 / error 事件 / 断连
    F-->>U: 轻提示原因，可再次点击重试
  end
  Note over F: 建议与检测仅作建议，不自动合并、不改任何缺陷状态
```

## 4. 视觉与状态要求

- 建议值标记（SuggestBadge）用 `--color-primary-*` 浅底徽标 + 图标，区别于用户已填值；
- 疑似重复列表用 `--color-neutral-*` 边框分隔条目，高相似项前置并以 `--color-warning` 图标标注（不单靠颜色表意）；
- 相似度仅作排序信号，百分比展示不对外承诺阈值。

## 5. 状态管理

- 新建表单建议与重复检测结果同属一次建议结果，存组件本地，提交后释放；
- 重复检测不再单独触发，结果随建议 `done` 事件一并写入；用户填写值始终优先于建议值。
