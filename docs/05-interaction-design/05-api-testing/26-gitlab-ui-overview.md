## 1. 概述

### 1.1 模块范围

GitLab 集成是接口测试域的横向扩展能力，交互上落在四处而非独立的一套页面：

1. **GitLab 集成页**——项目设置下的子模块，承载仓库配置维护与工程导入（详见分册）；
2. **场景执行入口**——`platform` 导入场景复用既有双入口（列表行内 [执行] 直接触发与编排页顶部 [运行]）；`gitlab_ci` 场景行内 [执行] 直接触发流水线，详情为独立只读视图、顶部 [流水线运行]；
3. **场景展示适配**——场景列表展示来源徽标与源状态徽标，`gitlab_ci` 场景不进入编排页（页面形态详见场景交互分册 `docs/05-interaction-design/05-api-testing/08-scenario-ui-overview.md`）；
4. **定时任务表单**——任务类型新增「GitLab 同步」分支，交互遵循既有任务管理页框架。

### 1.2 侧边栏菜单与路由

GitLab 集成是项目设置分组下的子模块，与环境管理同组，由侧边栏切换并以 `?tab=gitlab` 同步记录；刷新或外部改写 query 时按当前可见权限还原，tab 不可见时回落到首个可见子模块。菜单项图标沿用 `docs/05-interaction-design/02-global-navigation.md` 的图标集。

| 权限码 | 控制范围 |
| ---- | ---- |
| `api-env:view` | 仓库配置查询、连通性测试 |
| `api-env:edit` | 仓库配置创建、更新、删除 |
| `api-scene:view` | 项目扫描与解析预览、导入进度、执行状态查询 |
| `api-scene:edit` | 执行导入 |
| `api-scene:execute` | 执行入口触发执行：列表行内 [执行] / 页面 [运行]（`gitlab_ci` 来源场景触发流水线） |
| `api-timer:view` / `api-timer:edit` | 「GitLab 同步」任务类型的查询与维护，沿用既有定时任务权限码 |

无 `api-env:view` 与 `api-scene:view` 任一权限时，菜单项不展示；有其一但缺编辑权限时，页内只读可见、操作按钮按权限隐藏。

### 1.3 与既有页面的关系

| 页面 | 变更性质 |
| ---- | ---- |
| 项目设置框架 | 新增一个子模块入口，框架规则不变 |
| 测试场景列表 / 编辑页 | 列表新增来源徽标与源状态徽标及 [来源] 筛选；`platform` 导入场景复用编排页；`gitlab_ci` 场景使用独立只读详情视图，不进入编排页 |
| 定时任务管理页 | 任务类型新增一个取值，列表、表单、执行记录抽屉结构不变 |
| 测试报告列表 / 详情 | 报告结构不变，详情内按场景标注执行引擎 |

## 2. 通用交互模式

| 模式 | 规则 |
| ---- | ---- |
| 单按钮执行 | 执行入口不提供引擎下拉：`platform` 场景点击即按平台引擎执行；`gitlab_ci` 场景点击即触发流水线，只读视图动作文案为「流水线运行」 |
| 异步提交 + 轮询 | 导入与 GitLab 同步均为异步，前端提交后轮询进度，不使用长连接 |
| 凭据只写不读 | 令牌输入框回显掩码，编辑时不回填原值，接口不返回明文 |
| 只读回显派生信息 | 导入模式、仓库路径、分支等创建后锁定的字段以只读文本呈现，不渲染为禁用输入框 |
| 错误就近展示 | 业务错误在触发处行内展示错误码与人话提示，网络类错误统一 Toast |
