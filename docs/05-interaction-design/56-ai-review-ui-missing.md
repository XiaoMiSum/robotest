## 1. 覆盖确认作业与遗漏点处置（US-AI-007）

**入口**：需求工作流条目工作台——条目推进到「覆盖确认 coverage」阶段时自动发起推进作业，或作业卡 [运行作业] 手动发起/重跑（交互见 `docs/05-interaction-design/52-ai-case-ui-pool.md` 1.3.2 / 1.3.3）。**用例模块页的「遗漏分析」抽屉入口不复存在**；作业为异步任务，固定系统默认模型、不提供对话模型选择器；分析范围 = 条目血缘用例 ∪ 血缘文档下的用例（血缘是候选范围的唯一事实源）。

### 1.1 发起作业

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 自动发起 | 推进/跳过/回退进入覆盖确认阶段 | 作业卡出现并 2 秒轮询；AI 不可用时 Toast「AI 不可用，作业未发起」，阶段操作照常成功 |
| 手动发起 / 重跑 | 作业卡 [运行作业] / [重跑作业] | 可选附加需求文本（弹窗，仅本次作业使用，不入池，`n/20000` 计数）→ [开始分析] 创建作业；同类型进行中提示「已有进行中作业」 |
| 取消 / 重试 | 作业卡 [取消] / 失败后 [重试] | 取消中断任务（已产出不保留）；失败展示原因 |
| 附加文本 | 弹窗内粘贴 | 与条目内容合并为需求描述块，超预算截断并计 warnings |

- 作业成功 → 遗漏点逐条物化为**遗漏点（gap）提案**进入提案队列；同批次旧未处置遗漏点提案被替代；与已驳回/已采纳提案内容重复的点被指纹抑制不再出现。

### 1.2 遗漏点提案处置（三选一）

遗漏点提案行内提供三个动作（提案队列区块，样式区别于普通提案）：

```
┌──────────────────────────────────────────────────────┐
│ 遗漏点（5）                     作业成功 · 10:02     │
│ ☑ 短信验证码超时后重新发送  → 登录模块/验证码登录     │
│   需求提及验证码有效期5分钟，现有用例未覆盖超时重发    │
│   [转为用例] [标记不覆盖] [忽略]                      │
│ ☑ 并发支付幂等             → 支付模块/收银台         │
│   …                                                  │
│ 已忽略 2 条（仍待处理）· [显示]                       │
└──────────────────────────────────────────────────────┘
```

| 处置 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 转为用例 | 点击 [转为用例] | 弹落位选择（同 `docs/05-interaction-design/49-ai-case-ui-generation.md` 1.1：AI 自主 / 指定文档 + 可编辑的拼接文本，默认带入该点标题与描述）→ [开始生成] 发起用例设计作业，成功后提案置**已采纳**，Toast「已发起用例设计作业」；同类型作业进行中时提示并稍后重试；AI 不可用时按钮禁用 |
| 标记不覆盖 | 点击 [标记不覆盖] | 弹窗**必填理由**（≤500，缺失内联红字）→ 置**已驳回**（resolution = 不覆盖），留痕可查 |
| 忽略 | 点击 [忽略] | 本地隐藏（会话内），提案**保持待处置**——仍计入出口证据、仍显示「已忽略 n 条（仍待处理）· [显示]」；确需通过本阶段时经阶段时间线 [跳过]（必填原因）留痕绕过 |
| 批量处置 | 勾选多条 → [批量驳回] | 同普通提案（忽略无批量语义） |

### 1.3 状态分支

- **候选为空**（条目尚无血缘用例/文档）：作业照常执行，按「全部未覆盖」产出遗漏点（产出上限不变），卡片提示「未关联既有用例，结果基于需求推导」；建议引导先在血缘面板手动关联或在用例设计阶段生成用例；
- **作业失败**：作业卡展示原因 + [重试]，提案区保持原状；
- **AI 不可用**：[运行作业] 与 [转为用例] 禁用并提示，已有遗漏点仍可标记不覆盖/忽略；
- **全部处置完毕**：遗漏点区块呈空态（或仅剩已忽略项），出口证据满足后 [推进] 亮起进入评审就绪阶段；
- **并发变更**：他人先处置同条提案 → 提交返回提案状态非法 Toast，队列刷新。
