**文档版本**：V1.0  
**日期**：2026-10-03  
**状态**：起草中

## 1. 概述

需求列表为功能测试模块侧栏首位子项（链路上游：需求 → 用例 → 缺陷），与测试用例、测试评审、测试计划并列于功能测试壳层；另含新建需求页、需求详情与编辑页两个过程页（不入侧栏），以及导入对话框一个跨页浮层；导入任务的执行过程与提案审核统一在任务详情页（`docs/05-interaction-design/07-ai-capability/03-ai-task-ui.md`）完成。视觉与状态色遵循《视觉设计》（`docs/05-interaction-design/03-visual-design.md`），不另行定义颜色值。

| 页面 / 浮层 | 路由或形态 | 职责 |
| ---- | ---- | ---- |
| 需求列表子项 | `/workspace/projects/functional-testing?tab=requirements`（功能测试侧栏首位） | 检索、筛选、确认、归档与导入入口；按 `requirement:view` 显隐 |
| 新建需求页 | `/workspace/projects/requirements/create` | 手工录入需求条目，创建成功后进入详情页 |
| 需求详情与编辑页 | `/workspace/projects/requirements/:requirementId` | 属性、描述、来源附件与变更记录页签 |
| 导入对话框 | 列表子项浮层 | 文件选择与预校验，提交后跳转任务详情页 |
| AI 导入审核区 | 任务详情页内（`/workspace/projects/ai/tasks/:taskId`） | 建议逐条/批量采纳，含系统版本预填 |

> 旧路径 `/workspace/projects/requirements` 重定向至 `/workspace/projects/functional-testing?tab=requirements`。

**入口显隐**按权限点过滤：侧栏「需求列表」子项在 `requirement:view` 存在时可见；`requirement:view` 可见列表子项与详情；`requirement:create` 显示「新建需求」「导入需求」；`requirement:edit` 显示「编辑」与「取消归档」；`requirement:confirm` 显示「确认」「归档」。AI 总开关关闭或未配置模型时，「导入需求」入口隐藏（总册 4.5，`docs/01-requirements/07-ai-capability/02-srs-ai-capability.md`）。

## 2. 页面设计

### 2.1 需求列表子项

**路由**：`/workspace/projects/functional-testing?tab=requirements`（功能测试侧栏首位子项）

#### 2.1.1 布局

```
┌──────────┬────────────────────────────────────────────────────────┐
│ 需求列表  │ 需求列表           [＋ 新建需求] [⇪ 导入需求]             │
│ 测试用例  ├────────────────────────────────────────────────────────┤
│ 测试评审  │ 状态▾ 所属模块▾ 负责人▾ 版本▾  关键词[____] [查询] [重置] (2)│
│ 测试计划  ├────────────────────────────────────────────────────────┤
│          │ 编号 │ 标题 │ 所属模块 │ 版本 │ 状态 │ …  │ 操作  │
│          │REQ-001│…  │ 登录模块 │ V2.3 │已确认│ …  │详情… │
│          ├────────────────────────────────────────────────────────┤
│          │ 共 42 条    每页 [20▾]     < 1  2  3 >                   │
└──────────┴────────────────────────────────────────────────────────┘
  左侧为功能测试侧栏（「需求列表」当前高亮，按 requirement:view 显隐）
```

> 筛选工具栏与分页条置于内容卡片内，以 1px 分割线与表格分隔、各自持有 `14px 20px` 留白，表格左右贴合卡片边缘（`UI-SC-10`）；筛选工具栏右端常驻当前结果总数「共 N 条」，分页条左端显示「共 N 条 · 每页 N 条」。

#### 2.1.2 交互说明

| 区块 | 交互 |
| ---- | ---- |
| 功能测试侧栏 | 展示「需求列表 / 测试用例 / 测试评审 / 测试计划」子项，当前项高亮；地址栏同步 `?tab`，刷新与分享保持所在子项；「需求列表」按 `requirement:view` 过滤，无权限时不显示该项 |
| 工具栏 | 「新建需求」进入新建需求页（见 2.5）；「导入需求」打开导入对话框（见 2.3） |
| 筛选栏 | 状态、所属模块、负责人、版本四项下拉 + 关键词；入口角标显示已设置条件数；关键词输入 1 秒防抖自动查询；「查询」按当前条件刷新，「重置」清空全部条件并恢复第 1 页 |
| 状态徽标 | `draft` 草稿 / `confirmed` 已确认 / `changed` 已变更 / `archived` 已归档 |
| 标题列 | 点击进入详情页；标题超长截断，悬浮完整显示 |
| 行操作 | 「详情」进详情；「确认」仅 `draft / changed` 可用；「更多」含「编辑」「归档」「取消归档」——「归档」非归档态可用（需二次确认、下拉项保持 warning 色），「取消归档」仅归档态可用；操作列整体右对齐 |
| 分页 | 20 / 50 / 100 每页可切；筛选条件与页码在返回列表时保留 |

#### 2.1.3 状态分支

- **空态**：项目内无需求 → 引导区提示「暂无需求」+「新建需求」「导入需求」按钮；带筛选条件且无匹配 → 「无匹配结果」+「重置筛选」；
- **加载**：首屏显示表格骨架屏（筛选工具栏随卡片常驻可见），筛选刷新时整卡 loading 遮罩；
- **错误**：列表加载失败 → 错误提示条 +「重试」；不展示空态以避免误导；
- **权限不足**：无 `requirement:view` 时不显示「需求列表」子项；无写权限时隐藏对应操作列按钮，只读浏览。

### 2.2 需求详情与编辑页

**路由**：`/workspace/projects/requirements/:requirementId`

#### 2.2.1 布局

页面骨架与新建需求页（见 2.5）一致：页头吸顶、标题跨双栏、左栏描述、右栏 360px 属性卡片容器；卡片容器带「属性 | 变更记录」两个页签，页面按**查看态**与**编辑态**两种模式整体切换。描述父容器与属性卡片共用按窗口动态计算的高度（剩余可用空间的 90%，见 2.5.2），两态、两栏同高。

```
┌──────────────────────────────────────────────────────────────────┐
│ 功能测试 › 需求列表 › 登录验证码    [编辑]           │ [AI 生成用例]      │ [确认][更多▾] │ ← 页头吸顶，操作区按频次分组
│                                              编辑态 → [取消] [保存] │
├──────────────────────────────────────────────────────────────────┤
│ REQ-001  [登录验证码____________________] ≤300 字符      [已确认]    │ ← 编辑态：标题全宽输入框
├──────────────────────────────────────────┬────────────────────────┤
│ 描述（父容器高度按窗口动态取剩余可用空间    │ [属性 | 变更记录] 页签     │
│  90%，同 2.5.2，两态同高）                │ 属性：同款表单控件，查看态  │
│  查看态：Markdown 渲染                    │ 禁用、编辑态启用           │
│  编辑态：Markdown 编辑器（无 label）       │ 变更记录：时间线，页签首次  │
│ 来源附件（存在时展示）                     │ 激活时加载，含「加载更多」  │
│                                          │ （卡片与描述同高）          │
└──────────────────────────────────────────┴────────────────────────┘
  断点：≤1024px 回流 标题 → 属性（2 行）→ 描述；≤640px 单列（同 2.5.1）
```

#### 2.2.2 交互说明

| 区块 | 交互 |
| ---- | ---- |
| 页头操作区 | 与面包屑同一行右对齐，页头吸顶并以 `Neutral-200` 分割线压底（同 2.5.2）；查看态按操作频次分三组、组间以竖线分隔：①「编辑」（link 类型、主色）②「AI 生成用例」③「确认」（主按钮）与「更多」下拉（内含「归档 / 取消归档」，触发钮 warning plain）；编辑态仅展示「取消」（左）与「保存」（右，主按钮） |
| 编辑入口 | `requirement:edit` 且非归档时显示「编辑」（link 类型、主色）；点击整页进入编辑态：标题变为输入框、描述变为编辑器、属性表单解锁；编辑期间隐藏状态流转与 AI 操作按钮 |
| 标题 | 查看态为纯文本（编号 + 标题 + 状态徽标），编辑态为全宽输入框，≤300 字符、必填，不提供行内快捷编辑 |
| 属性栏 | 「属性」页签：**同一组表单控件贯穿两态**——查看态整体禁用（不更换组件），点「编辑」启用；字段与新建页一致（模块树可搜索、版本 ≤50 字符、优先级分段控件、负责人可搜索、标签回车创建；模块与负责人仅支持改为非空值，不提供清空）；来源恒为只读行 |
| 保存 | 「保存」一次性提交标题、描述与属性变更，**仅提交变更字段**，成功 toast 并退出编辑态；标题为空提示「请输入需求标题」，版本超 50 字符即时拦截（1000018010）；「取消」放弃本地改动恢复服务端当前值 |
| 状态流转 | 修改标题、描述或所属模块且变更前为 `confirmed` → 保存成功后流转 `changed`；仅改版本、负责人、优先级、标签等属性不触发流转 |
| 确认 | `draft / changed` 显示「确认」；确认成功流转 `confirmed` |
| 归档 / 取消归档 | 入口在「更多」下拉内；归档需二次确认；归档后不显示「编辑」，全页保持查看态，「更多」仅剩「取消归档」；取消归档恢复至归档前状态 |
| 来源附件 | 预览与下载；附件不存在时降级提示（1000018011） |
| 变更记录 | 属性卡片容器第二页签：按时间倒序展示字段级变更与状态流转；页签首次激活时才加载，支持「加载更多」分页 |
| AI 生成用例 | `ai:task` 可见，位于第②组（两侧竖线分隔）；仅 `confirmed` 条目可发起，其余置灰并提示；按钮取短名，悬浮 tooltip 说明"对已选需求生成模块、脑图用例文档与测试用例"、未勾选时提示「请先勾选需求」；提交后打开生成配置对话框 |

#### 2.2.3 状态分支

- **条目不存在**（越权或已删除）→ 404 提示 + 返回列表；
- **归档只读**：不显示「编辑」与写按钮，全页为查看态，属性控件禁用；
- **权限不足**：无 `requirement:edit` 不显示「编辑」，属性控件禁用；无 `requirement:confirm` 隐藏「确认 / 归档」；
- **编辑中断**：保存失败展示错误消息并保留已填内容可重试；「取消」或离开页面放弃本地改动；
- **并发编辑**：保存冲突时提示「该需求已被他人更新」，提供「查看最新」刷新后重编辑。

### 2.3 导入对话框与任务执行

#### 2.3.1 流程与交互

1. **文件选择**：点击或拖拽上传；支持 Markdown、Word 文档与图片附件（多模态），单文件不超过 20MB；前端预校验类型（1000018006）、大小（1000018007）、空文件（1000018008），不满足即时提示、不发请求；
2. **提交**：返回 `taskId`，关闭对话框并跳转任务详情页（`/workspace/projects/ai/tasks/:taskId`，执行与审核一体）；同项目已有进行中导入任务时拒绝（1000018013），提示「存在进行中的导入任务」并提供任务中心入口；
3. **执行区**（任务详情页上半区）：步数与预算消耗 + 当前步骤，按通用任务口径 2 秒轮询；执行中可「终止」；已终止展示原因摘要 +「再次执行」，原始文件保留；
4. **完成**：任务 `proposals_ready` 同页下半区展开审核区（见 2.4）。

#### 2.3.2 状态分支

- 预校验失败（即时提示，不关闭对话框）；
- 重复提交被拒（1000018013，引导任务中心）；
- 任务终止（原因 + 再次执行，可返回任务中心稍后继续）；
- 网络异常（执行轮询中断 → 「连接中断，恢复中…」，自动续轮询）。

#### 2.4.1 布局

```
┌──────────────────────────────────────────────────────────────────┐
│ 导入结果审核            版本[V2.3____]（识别依据：…）  ⓘ 可修改/清空│
├──────────────────────────────────────────────────────────────────┤
│ ☐ REQ建议1  登录验证码   模块：登录模块   来源：P3 §2.1 [定位]      │
│ ☐ REQ建议2  订单超时     模块：订单模块   来源：P5 §3.2 [定位]      │
│   …                                                             │
├──────────────────────────────────────────────────────────────────┤
│ [批量采纳] [全部驳回]                      已选 N 条 / 共 M 条     │
└──────────────────────────────────────────────────────────────────┘
```

#### 2.4.2 交互说明

| 区块 | 交互 |
| ---- | ---- |
| 版本输入框 | 预填 AI 从文档识别的被测业务系统版本，悬浮展示识别依据引语；可修改、可清空；识别不到时为空并提示「未识别到版本，采纳后可手工补录」 |
| 建议列表 | 每条含标题、描述、所属模块与来源原文定位；支持逐条「采纳」「修改后采纳」「驳回（可附反馈）」 |
| 批量操作 | 全选/半选勾选后「批量采纳」「全部驳回」 |
| 确认落库 | 采纳项生成 `REQ-` 编号、进入 `confirmed`，`systemVersion` 取面板当前值；完成后刷新列表并展示回执（逐项成败），失败项可单项重试 |

#### 2.4.3 状态分支

- 无提案（解析未产出建议）→ 空态说明 +「返回任务中心」；
- 全部驳回 → 回执「已全部驳回，未创建需求」；
- 部分采纳失败 → 回执逐项成败 + 单项重试；
- 任务终止（无提案）→ 从任务中心再次执行。

**路由**：`/workspace/projects/requirements/create`（由列表页工具栏与空态引导进入，不入顶部菜单）

#### 2.5.1 布局

#### 2.5.2 交互说明

| 区块 | 交互 |
| ---- | ---- |
| 面包屑 | 「功能测试 › 需求列表」→「新建需求」三级结构（UI-BC-01），回退入口是唯一可点击项 |
| 操作区 | 与面包屑同一行右对齐，页头吸顶并以 `Neutral-200` 分割线压底，「取消」在左、「创建」在右（主按钮）；「取消」返回需求列表；「创建」同创建交互 |
| 标题 | 无 label，跨双栏全宽，控件高 32px；必填，超 300 字符即时校验；必填缺失由失焦 / 提交时校验提示表达，不显示星号 |
| 所属模块 | 右栏树形单选下拉（支持搜索），仅展示模块目录（文档不承载需求），可清空，可选 |
| 版本 / 优先级 / 负责人 / 标签 | 均在右栏，可选；版本超 50 字符即时校验；**优先级为分段控件**（高 / 中 / 低，可清空回未设置）；负责人取当前工作空间成员；标签支持回车创建 |
| 描述 | 无 label，左栏主视觉区；Markdown 编辑器，可选；高度取剩余可用空间的 90%（窗口缩放实时跟随，最小 320px）；工具栏最右侧「预览」按钮将编辑器最大化为 70% 视口宽高的带遮罩浮层（正文撑满浮层宽度），点遮罩或按 Esc 退出 |
| 栏位与响应式 | 右栏 360px、左栏 flex:1；**属性字段整体由无投影卡片容器包裹**（容器内距沿用组件默认，窄屏回流时容器随属性栏整体移动），**卡片容器与描述编辑器等高齐平**（窗口过矮、属性内容高于编辑器时以内容高度为准）；控件统一 32px 高；字段内 `--space-sm`、字段间 `--space-md`、分区间 `--space-xl`；校验错误文案固定占位，出现 / 消失不推挤布局；≤1024px 回流为 标题 → 属性（2 行）→ 描述，≤640px 单列 |
| 创建 | 校验通过后提交，成功 toast 并进入该需求详情页；失败展示错误消息并停留本页 |

#### 2.5.3 状态分支

- **校验失败**：必填缺失或超长 → 表单即时提示，不发请求；
- **创建失败**：错误消息提示，保留已填内容可修改重试；
- **模块树加载失败**：模块下拉为空数组，不阻塞其余字段录入；
- **窄屏降级**：≤1024px 右栏回流为属性 2 行并置于描述之前（保持「标题 → 属性 → 描述」的原有先后），≤640px 单列；字段、校验与操作按钮不删减。

## 3. 核心交互流程

### 3.1 导入与采纳

```mermaid
sequenceDiagram
  participant U as 用户
  participant P as 需求列表页
  participant T as AI 任务
  participant D as 任务详情页
  U->>P: 点击「导入需求」，选择文件
  P->>P: 前端预校验（类型 / 大小 / 空文件）
  P->>T: 提交导入任务，返回 taskId
  P->>D: 跳转 /workspace/projects/ai/tasks/:taskId
  T-->>D: 执行轮询（2s）
  T-->>D: proposals_ready，展开审核区
  U->>D: 核对版本预填（可改可清空），逐条或批量采纳
  D->>D: 落库（编号生成、confirmed）→ 刷新列表 → 展示回执
  Note over D: aborted → 原因 + 再次执行；重复提交 → 1000018013
```

### 3.2 需求状态流转

```mermaid
flowchart LR
  A[draft] --确认--> B[confirmed]
  B --修改标题/描述/所属模块--> C[changed]
  B --仅改版本/负责人/优先级/标签--> B
  C --确认--> B
  A --归档--> D[archived 只读]
  B --归档--> D
  C --归档--> D
  D --取消归档--> E[恢复归档前状态]
  E --> B
```

## 4. 视觉与状态要求

- 状态徽标：`draft` → `--color-info`；`confirmed` → `--color-success`；`changed` → `--color-warning`；`archived` → `--color-neutral-400`；口径见《视觉设计》4.1 状态色；
- 主操作（新建、导入、确认）用 Element Plus 主按钮（`--color-primary-500` 体系）；归档等收敛操作用文字按钮 + danger 确认；
- 新建需求页优先级分段控件沿用缺陷优先级色：高 → `--color-priority-p1`（橙）、中 → `--color-priority-p2`（蓝）、低 → `--color-priority-p3`（灰），与列表、详情口径一致；
- 错误提示条底色 `--color-danger-light`，AI 关闭提示条底色 `--color-warning-light`；空态、加载态遵循《视觉设计》中性色体系（`--color-neutral-*`）。

## 5. 状态管理

- Pinia store `requirement`：列表分页与筛选条件（返回列表保活）、详情缓存、导入任务引用与拆解记录；
- 复用 `aiTask` store 订阅任务执行（2 秒轮询、`aborted / closed` 态停止），跳转任务详情页后由该页接管轮询，返回列表时回调刷新列表与审核区数据；
- 关键词输入 1 秒防抖自动查询；写操作按钮提交期间 loading 防重复点击；
- 审核区采纳回执仅存组件本地状态，离开详情页即释放，任务提案状态以服务端采纳结果为准；
- 当前子项由功能测试壳层地址栏 `?tab` 承载（需求列表为 `requirements`），不入 store。
