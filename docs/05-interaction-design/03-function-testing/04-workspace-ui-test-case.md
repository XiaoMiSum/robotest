## 1. 测试用例子模块

选中“测试用例”菜单后，右侧进一步分为左右结构：左侧模块树 + 右侧脑图编辑器。

### 1.2 交互说明

**顶部工具条**：单行排布、不换行、无横向滚动，左对齐，常驻于脑图编辑区上方，不随画布滚动。工具条按全屏状态切换形态：非全屏时脑图编辑类功能收进下拉——`[编辑 ▾]`（撤销 Ctrl+Z、重做 Ctrl+Y｜新建下级节点 Tab、新建同级节点 Enter、编辑内容 F2｜删除节点 Delete），`[排版 ▾]`（6 个模板 + 恢复自动排版）；全屏时恢复全部按钮平铺（撤销/重做｜节点操作：下级、同级、编辑、删除｜排版模板与恢复排版｜节点类型与清除标记｜优先级：P0–P3）。新建下级节点、新建同级节点、编辑内容、删除节点仅在选中节点时激活，未选中时编辑下拉与全屏平铺按钮同步置灰；撤销/重做仍按历史可用性置灰。类型标记（用例 / 前置 / 步骤 / 预期 / 取消标记）与优先级 P0–P3 同样仅在选中节点时激活，未选中时置灰；右键菜单等级组同步置灰。用例业务功能中的类型标记与 P0–P3 在两种形态下均平铺；AI 优化与关联需求统一收拢到用例节点悬浮窗。工具条最右侧常驻「AI覆盖雷达」仅图标按钮（title / aria-label 为「AI覆盖雷达」，不受全屏形态切换影响，悬浮提示「扫描需求测试用例覆盖率并补齐缺漏」），点击先按当前文档查最近一次生成任务：命中直接打开面板回显进度或结果，未命中才经「选择需求」单选弹窗打开 AI 生成面板，交互见 `docs/05-interaction-design/07-ai-capability/07-assisted-features-ui.md` 2.5；AI 未启用或未配置模型时按钮隐藏（置灰原因优先展示）。功能组之间以竖分隔线分隔。排版入口不回显布局名称文本，当前模板由悬浮提示给出；**工具条所有按钮与下拉入口一律带悬浮提示**：图标型给出功能名与快捷键，下拉项内名称与快捷键左右分开、快捷键右对齐，文字型按钮（类型标记、P0–P3）给出操作语义，删除项以警示色呈现。

**模块树交互**：展开/折叠点击箭头；选中文档点击节点加载脑图；新建右键或[+新建]输入名称；重命名双击或右键；拖拽移动节点；删除右键或Delete键二次确认。模块树区域数据超出可视区时仅树内纵向滚动（搜索与新建工具条常驻），纵、横向视觉滚动条按 `UI-SC-03` 隐藏，滚轮与键盘滚动能力保留。

**脑图编辑器**：新建下级节点 Tab；新建同级节点 Enter；编辑文本双击；移动拖拽；删除 Delete；标记用例/优先级顶部工具条或右键菜单；缩放 Ctrl+=/-/0 或工具栏按钮；抓手模式工具栏切换或按 H 键。

**节点 AI 标识**：AI 生成的用例节点（`type=case` 且 `aiGenerated=true`）在紫色「用例」徽标右侧紧邻显示青色「AI」文字徽标，人工创建的用例与其他类型节点不显示；徽标随节点数据同步、不提供点击交互，视觉规格见 `docs/05-interaction-design/03-visual-design.md` 第 5 节。

**节点悬浮窗**：左键单击 `type=case` 节点，在选中态更新的同时在节点下方展开悬浮窗；非用例节点不展开，双击节点仍进入文本编辑。悬浮窗提供三项入口，点击后收起悬浮窗并交由对应的对话框 / 面板承接：

```
[AI 图标]（悬浮提示「AI 优化」）
🔗 关联需求
```

- 视觉：两个入口水平并排、均为透明背景按钮，不展示卡片底色、边框与阴影；AI 优化仅显示统一 AI 图标、以成功色与周期性闪烁强调，功能名由悬浮提示与 `aria-label` 承担；关联需求保留图标 + 文字并使用主色调文字；禁用入口置灰。
- 定位与关闭：悬浮窗按选中节点的屏幕渲染框定位；点击窗外画布或另一节点、按 Esc、滚轮滚动、唤起右键菜单时关闭；点击另一用例节点则先关旧窗再在新节点旁展开。
- 状态分支：AI 优化的隐藏 / 置灰规则见 `docs/05-interaction-design/07-ai-capability/07-assisted-features-ui.md` 2.3；关联项复用「选择需求」选取器，打开前按节点 `requirementId` 查需求详情回显，加载与错误状态由选取器自身反馈。
- 结果复用：点击 [AI 优化] 时，按该节点查询最近一次任务（项目内任意成员发起的任务均可复用），未完成时回显任务进度或已有提案，已产出提案 / 已处理完毕时展示任务提案并提供「重新执行」，已终止时展示原因与「再次执行」；无任务时才发起。仅取最近一次任务，不依赖文档会话（详见 `docs/05-interaction-design/07-ai-capability/07-assisted-features-ui.md` 2.4）。
- 入口收拢：顶部工具条不再提供 AI 优化、关联需求按钮；已关联需求的用例仍可从悬浮窗重新打开选取器，修改或清空已有关联。

**关联需求**：需求条目经「选择需求」选取器弹窗维护，用例关联为**单选**（选取器默认多选，评审 / 计划场景保持多选），悬浮窗 [关联需求] 作用于**当前用例节点**：仅 `type=case` 的节点展开悬浮窗，入口始终可用；打开前按节点 `requirementId` 查需求详情回显，确认后写入节点 `requirementId` 并随脑图变更自动保存，空选择表示清空关联。关联不再有独立的保存成功提示，失败经服务端错误帧以消息提示。选取器仅列出已确认（`confirmed`）需求，草稿 / 已变更 / 已归档需求不展示。选取器行内 [明细] 就近冒泡展示条目 Markdown 正文（仅正文，不联动勾选），明细弹窗按共享选取器统一加宽以便阅读。

**脑图组件详细设计**参见《脑图组件实现设计文档》。

### 1.3 模块树与编辑器加载反馈

项目统一模块树（左侧）与脑图编辑器（右侧）承担各自的数据加载，加载与失败反馈遵循 `docs/00-spec/50-ui/02-page-development.md` 的 `UI-PAGE-11`：

| 区域 | 状态 | 表现 |
| ---- | ---- | ---- |
| 模块树 | 名称可达性 | 目录/文档节点名称按列宽截断时，悬停与键盘聚焦均可查看全文（可聚焦标识与 `el-tooltip` hover/focus 触发，焦点态清晰）；点击节点仍按既有规则展开目录或加载文档，重命名、删除、拖拽等行为不变 |
| 模块树 | 加载中 | 首次加载显示树区加载占位，保留搜索/新建工具条 |
| 模块树 | 加载失败 | 统一使用 `ElMessage.error` 提示；**无已加载节点**时树区展示错误占位与 [重试]，不展示误导空态；**已有已加载节点**时（如刷新失败）保留当前树与展开状态，在树区展示可见错误反馈与 [重试]，不清空已加载数据。多人协同的定时静默刷新失败不提示、不展示错误态，等待下一轮自愈 |
| 模块树 | 空态 | 无模块时显示「暂无模块，点击[新建]创建」；搜索过滤无结果显示「无匹配的目录 / 文档」，与加载失败区分 |
| 脑图编辑器 | 加载中 | 选中文档后编辑区显示加载遮罩，工具条暂不可用 |
| 脑图编辑器 | 加载失败 | 统一使用 `ElMessage.error` 提示；文档节点加载或脑图初始化失败时，编辑区展示错误占位与 [重试]（重试沿用当前文档重新初始化），不展示误导空白画布；已加载成功的脑图在后续协同/保存中的失败按既有反馈处理 |
| 脑图编辑器 | 未选中 | 左侧未选中文档时展示「请在左侧模块树中选择一个文档」空态，与加载失败区分 |

> 模块树为接口管理、场景管理、测试用例三页共享组件，上述名称可达性与加载失败反馈在三页统一生效；脑图加载失败反馈仅作用于用例页编辑器，不改变节点编辑、Yjs 协同、持久化、AI 建议与关联需求等核心行为。
