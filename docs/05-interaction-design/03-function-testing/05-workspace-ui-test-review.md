## 1. 测试评审子模块

选中“测试评审”菜单后，右侧展示评审列表或评审详情。

### 1.1 评审列表页

> 视觉与结构对齐验收基准 `prototype/project/reviews.html`（页头 + 单卡片：toolbar / 表格 / 分页一体）。基准裁剪与保留口径：基准无 [查询][重置]、无 [删除]，两者为现状能力故保留（删除入口仅存在于列表）；基准无 [完成]，完成评审统一由详情页承载；基准的「驳回」入口不存在，新增至详情页页头（见 1.2）。

```
┌────────────────────────────────────────────────────────────────┐
│  测试评审                                        [+ 发起评审]   │
│  用例评审与评审结论跟踪                                          │
├────────────────────────────────────────────────────────────────┤
│ [搜索标题][状态: 全部/待评审/进行中/已通过/已驳回 ▼][查询][重置] 共 N 场评审 │
│ 标题(副行:关联需求 N 项 · 关联用例 N 条)│发起人│状态│进度│通过率│参与者│创建时间│操作 │
│ 下单模块用例评审        │ 张明 │●进行中│[━━] 18/30│40% │头像堆│…│[进入]│
│ 履约配送用例评审        │ 周敏 │●已驳回│[━━] 35/35│62.9%│头像堆│…│[查看][重新发起]│
└────────────────────────────────────────────────────────────────┘
```

**状态展示映射**（接口状态值 → 展示文案，点标圆点配色随文案；列表与详情页共用）：

| 状态值 | 展示文案 | 点标 |
| --- | --- | --- |
| `new` | 待评审 | 中性灰 |
| `in_progress` | 进行中 | 橙色（含光晕） |
| `completed` | 已通过 | 绿色 |
| `rejected` | 已驳回 | 红色 |

> 详情页基准 `prototype/project/review-detail.html` 中该状态写作「评审中」，与列表基准文案冲突，统一取列表基准「进行中」；需求文档中的「评审已完成（completed）」表述对应展示文案「已通过」。

查询区：标题关键字输入框（回车即查）+ 状态下拉（全部/待评审/进行中/已通过/已驳回）+ [查询]/[重置]按钮，重置清空条件并回到首页；工具栏右侧计数「共 N 场评审」，分页区左侧「共 N 场 · 每页 20 条」。

**表格高度**：表格为固定高度，高度沿页面高度链路取窗口剩余可用空间（`height="100%"`，随窗口缩放与查询栏占位动态变化），数据超出时仅在表体内部滚动，表头、查询工具栏与分页条固定不动；纵向视觉滚动条按 `UI-SC-05` 组件级策略隐藏，横向视觉滚动条保留显示，滚轮与横向滚动能力保留。

列表列与口径：

- **标题**：主行标题 + 副行「关联需求 N 项 · 关联用例 N 条」（`requirementCount` / `totalAssociated`，无关联需求时只展示关联用例），点击进入详情；
- **进度**：进度条 + `已评审/关联总数`（`reviewed`/`totalAssociated`）；进行中橙色、已驳回红色、其余默认色；
- **通过率**：待评审显示 `—`；进行中常规展示、已通过绿色加粗、已驳回红色；
- **参与者**：头像堆（最多展示 3 个 + 「+N」），取头像图或姓名首字，发起人在列内时用品牌色；无参与者显示 `—`；
- **操作**：[编辑]（仅发起人，`new`/`in_progress`）、[进入]（`new`/`in_progress`）、[查看]（`completed`/`rejected`）、[重新发起]（仅 `rejected`，二次确认后回到 `in_progress`）、[删除]（保留项，二次确认，仅发起人，后端校验）。

点击[发起评审]弹出创建表单：标题、描述、参与者（多选成员）、关联需求（需求选取器，多选，仅列已确认需求）。提交后跳转至评审详情页，新建评审默认待评审状态，首次标记后自动转入进行中；所选需求无用例时允许创建空评审。

**列表样板交互**：

- 标题主行按实际列宽单行省略，不按固定字符数截断；悬停或键盘聚焦可查看完整标题，焦点可见，键盘可进入详情。关联需求 / 用例副行独立展示。
- 首次加载显示加载反馈，成功前不展示「暂无评审」。首次失败同时展示页面内错误、统一消息提示及「重新加载」入口。
- 筛选、翻页或刷新失败保留上次成功的数据及总数，明确提示「刷新失败，当前显示上次加载的数据」；重试使用当前条件和页码，成功后清除错误。过期响应或错误不得覆盖较新的请求状态。
- 成功且无数据时，无筛选条件显示「暂无评审」及「发起评审」入口；有标题关键字或状态条件时显示「没有符合条件的评审」及「重置筛选」入口。重置清空条件并回到首页查询。
- 页头与单工作区布局沿用本节定义，筛选控件在窄屏可换行，表头和分页常驻，静态工作区无悬停抬升反馈。视觉基线见 `docs/05-interaction-design/03-visual-design.md`。

### 1.2 评审详情页

```
┌──────────────────────────────────────────────────────────────────┐
│ 测试评审 › 登录模块评审  需求[REQ-01] [进行中] [━进度━] 通过n … [完成评审] │
├──────────┬───────────────────────────────────────────────────────┤
│ 快照文档树│   快照脑图 (只读)                                      │
│ (多文档   │   节点右侧徽标回显评审标记 ✓通过/✕不通过                 │
│  点击切换) │   点击用例节点展开悬浮窗：                              │
│           │   通过/不通过/待评审/评论（透明背景 link）               │
└──────────┴───────────────────────────────────────────────────────┘
```

**详情页交互**：

- 页头收拢为单条无边框横条：左侧面包屑「测试评审 › 标题」（元素本身仍只承担定位与回退，点击「测试评审」返回功能测试页并激活 `?tab=reviews`），右侧为同行独立容器，依次承载关联需求标签、状态标签（按 1.1 状态展示映射：待评审/进行中/已通过/已驳回）、进度条与分色统计（通过绿/不通过红/待评审橙/共 N）及操作按钮（带图标；主操作实心、次要操作 plain）；当前页名称由面包屑末段承担，不另设独立标题卡片，超宽时页头单行横向滚动、不换行；标记成功后进度实时刷新。
- 左侧为快照文档树（目录/文档层级），点击文档切换右侧对应文档的快照脑图，支持多文档评审；默认选中首个文档。
- 快照文档树数据超出可视区时仅树内纵向滚动（卡片 header 固定），视觉滚动条按 `UI-SC-03` 隐藏，滚轮与键盘滚动能力保留。
- [调整用例]（评审未完成可用）：打开 CaseSelector 弹窗并回显当前规划的用例，确认后差量更新快照（可增删文档与用例）。
- [同步用例]：同步成功后自动重载快照树与脑图。
- [完成评审]：仅当待评审与不通过均为 0（全部通过）时可用，否则置灰并 tooltip 提示；确认后状态变更为已通过（`completed`）。
- [驳回]（新增，仅 `new`/`in_progress` 可见，仅发起人，后端强校验）：二次确认后状态变更为已驳回（`rejected`），快照冻结、标记/调整/同步入口收起。
- [重新发起]（仅 `rejected` 可见，仅发起人）：二次确认后状态回到进行中（`in_progress`），既有标记与评论保留，参与者可继续评审；再次完成仍需全部通过。
- 评审标记三态：通过/不通过/待评审（重置），结果以彩色徽标回显在节点右侧；左键单击 `case` 节点在节点下方展开悬浮窗（入口水平并排、透明背景、`link` 类型按钮），点[评论]打开“评审记录”抽屉（头像气泡列表 + 底部固定输入区，Enter 发送）；非 case 节点不展开悬浮窗。脑图不设顶部工具栏与右键菜单。
- 点面包屑「测试评审」回到功能测试页并自动激活“测试评审”子模块（`?tab=reviews`）。

**移除已选用例**（评审未完成时可用）：

- **入口**（一处）：左键单击脑图中的 `case` 节点展开悬浮窗，[移除用例] 按钮位于 [评论] 按钮右侧；不设顶部工具栏与右键菜单。
- **触发条件**：
  - 悬浮窗仅 `case` 节点展开（步骤/前置条件/文档/目录节点不展开悬浮窗）；
  - 评审进入终态（`completed` 已通过 / `rejected` 已驳回）时 `removable` 为假、入口不展示，与 [调整用例] 的入口条件一致；后端强校验兜底（终态抛业务异常）。
- **交互流程**：
  1. 脑图中左键单击一个已关联的用例节点，展开悬浮窗；
  2. 点击悬浮窗 [移除用例]；
  3. 二次确认弹窗「确定从该评审中移除用例『用例标题』吗？移除后该用例及其评审标记将不再展示，历史标记记录保留作审计。」；
  4. 确认后调用规划用例更新接口（全量覆盖式）：从当前规划中剔除该用例，若所属文档无剩余用例则整文档移除；
  5. 成功 Toast「已移除用例」→ 脑图重载（该文档快照刷新）、进度条与统计实时刷新；
  6. 取消或失败：关闭弹窗 / 错误 Toast，界面不变。
- **边界与约束**：
  - 移除仅删除快照节点，评审标记/评论记录保留作审计（与调整用例行为一致）；
  - 移除后快照树同步重载：若整文档被移除，左侧文档树对应条目消失，当前选中文档回退到首个文档；
  - 移除入口仅在 `case` 节点悬浮窗内且 `removable` 为真时展示；未关联用例点击后由接口侧拦截提示，界面不变。

详情页复用脑图组件（`mode='review'`），不设顶部工具栏与右键菜单，评审操作入口由用例节点悬浮窗承载。

### 1.3 编辑评审与关联需求变化重规划

**入口与表单**：

- 列表操作列 [编辑] 仅发起人且评审为 `new`/`in_progress` 时展示；点击后先加载评审详情，用标题、描述、参与者、关联需求回填编辑弹窗（复用创建表单的字段与校验，按钮文案改「保存」）。
- 提交仅发送发生变化的字段；未改动关联需求时按普通保存处理。

**关联需求变化提示**：

- 提交时用表单中的 `requirementIds` 与详情返回的 `requirementIds` 做集合比较（忽略顺序）；不同则以警告图标弹出确认框，文案为「检测到关联需求发生变化，是否重新规划测试用例？」，标题「编辑评审」，确认按钮「重新规划」，取消按钮「仅保存」。
- 选择「重新规划」：提交时附带 `replan=true`，提示「已保存，正在后台重新规划测试用例」；选择「仅保存」：不附带该参数，提示「已保存」，既有规划用例与评审标记保持不变。
- 取消确认框本身等价于放弃本次编辑，不提交任何字段。

**异步状态反馈**：

- 确认重新规划后仅提示「已保存，正在后台重新规划测试用例」并关闭弹窗，不轮询任务状态、不自动刷新列表；用户自行刷新后按新快照查看关联用例数与进度等统计。
- 评审记录与标记始终保留，不因重规划清空；后台任务失败仅由服务端记录日志，前端不再展示完成或失败提示。

### 1.4 AI 评审

**入口**：评审详情页页头操作组提供仅图标的 AI 评审按钮（title / aria-label 为「AI 评审」），仅评审为 `new` / `in_progress` 且 AI 可用（`available = true`）时展示；已通过 / 已驳回或 AI 未启用时隐藏。入口与既有操作并列，不改变原操作组的显隐规则。

**发起与复用**：点击后按当前评审 id 查询最近一次 `review_case_review` 任务：命中则直接打开 AI 评审面板回显进度 / 提案 / 终止原因，不再弹出确认；未命中才发起新任务。命中任务的执行中（`running`）态仅回显进度，不新建任务或执行；已终止（`aborted`）沿用原任务新建执行实例；已产出提案（`proposals_ready`）或已结束（`closed`）时「重新执行」按原评审输入新建任务，原任务及其提案、采纳记录保留只读回看。查询失败只提示错误、不自动发起。超过 10 秒未完成时展示进行中状态与任务详情入口，不阻塞当前页面操作。

```
┌──────────────────────────────────────────────────────────────────┐
│ AI 评审 · 登录模块评审           关联用例 N 条  [进度 / 失败原因]      │
├──────────────────────────────────────────────────────────────────┤
│ ▸ TC-001 获取验证码   [不通过]  理由：缺少错误分支预期                  │
│   问题：预期不完整 · 获取验证码 › 步骤 2        来源：REQ-001 ↗         │
│                                          [驳回]        [采纳]          │
│ ▸ TC-002 登录成功     [通过]    理由：覆盖主要路径                     │
├──────────────────────────────────────────────────────────────────┤
│                                          [再次执行] [关闭]           │
└──────────────────────────────────────────────────────────────────┘
```

**交互说明**：

| 操作 | 触发方式 | 反馈 |
| ---- | ---- | ---- |
| 打开面板 | 点击页头 AI 评审图标按钮 | 先查最近任务，命中按状态回显；未命中发起新任务 |
| 采纳 | 卡片 [采纳] | 按建议标记写入评审记录并更新脑图徽标与进度统计，卡片转为只读 |
| 驳回 | 卡片 [驳回] | 填写原因后提交，仅记录驳回原因，不写回标记 |
| 再次执行 | 面板底部 [再次执行]（任务已终止 `aborted` 态） | 沿用原任务新建执行实例，面板回显新进度 |
| 重新执行 | 面板底部 [重新执行]（`proposals_ready` / `closed` 态） | 按原评审输入新建任务，原任务与提案保留只读回看；执行中不提供该动作 |
| 关闭 | 面板底部 [关闭] | 关闭面板，评审页面保持不变 |
| 任务详情 | 任务详情页（AI 任务中心）只回看执行过程与提案，不提供采纳 / 驳回；处置统一在本面板完成 |

**处置动作呈现**：待处置卡片底部仅保留 [驳回] 与 [采纳]，右对齐且顺序为 [驳回] → [采纳]；两者均为 `link` 类型按钮，[驳回] 用危险色、[采纳] 用成功色（配色引用 `docs/05-interaction-design/03-visual-design.md`），不提供编辑后采纳入口。

**状态分支**：任务进行中展示进度与步骤、不提供 [再次执行]；无规划用例时不发起并提示；任务中止展示原因与 [再次执行]（沿用原任务新建执行实例）；`proposals_ready` / `closed` 展示 [重新执行]（按原输入新建任务、原任务只读保留）；提案按处置状态分区，已采纳 / 已驳回只读回看；节点在提案产出后被移除时该项标红提示且处置失败，其余项继续；评审进入终态后入口隐藏、既有提案不可处置；非项目成员的越权请求由后端拒绝并提示；查询 / 提交失败以错误消息提示，加载中显示面板 loading。
